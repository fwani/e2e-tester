# 디자인 준수 계약 — 통합 화면 artboard 를 새로 만들고 6종을 대체한다

**기능**: 007 · 요구사항 FR-254 ~ FR-255
**상위 규약**: `specs/002-defect-fix-design-conformance/contracts/design-conformance.md`
(DC-001 ~ DC-012). 이 문서는 그것을 **대체하지 않고 이어받는다** — 007 이 확정 디자인을
갱신하기 때문에 필요한 추가 절차만 적는다.

> **DC-001 은 그대로 살아 있다 — 확정 디자인은 해석 대상이 아니다.**
> 007 이 하는 일은 "해석해도 된다" 가 아니라 "**해석 대상을 새로 만들고 승인받는다**" 다.

---

## 1. 왜 새 artboard 가 필요한가

002 §1 의 화면 대응표는 `canvas.json` 의 8개 artboard 가 8개 **독립 화면**에 1:1
대응한다고 정했다 (DC-008). 007 은 그 중 6개를 **하나의 화면의 일곱 상태**로 합친다.
그러면 1:1 대응이 성립하지 않고, 기존 artboard 중 하나를 기준으로 삼아도 나머지 다섯이
기준 없이 남는다.

clarify 에서 사용자가 고른 것이 이 길이다 — **새 artboard 를 만들어 확정 디자인을 갱신한다.**

---

## 2. 새 artboard

| 항목 | 값 |
|---|---|
| 파일 | `docs/design/Workbench.dc.html` |
| 기준 크기 | 1440 × 900 |
| 정의 대상 | 일곱 국면을 **하나의 껍데기의 상태로** (FR-254a) |
| 상태 표현 | 하나의 파일 안에 국면별 변형을 나란히 둔다. 국면마다 파일을 만들지 않는다 |
| `canvas.json` | 새 artboard 항목을 추가하고 대체되는 6종의 상태를 표시한다 |

**국면마다 artboard 를 만들지 않는 이유**: 그러면 007 이 고치려는 것(국면마다 다른 화면)이
확정 디자인 층에 그대로 재생산된다. 하나의 껍데기 + 국면별 상태가 이 기능의 주장이므로
확정 디자인도 그 형태여야 한다.

## 3. 대체 관계 기록 (FR-254b)

**위치**: `specs/007-unify-test-screens/design-conformance/replacement-map.md`

기존 artboard 를 **조용히 폐기하지 않는다.** 6종의 모든 영역이 어디로 갔는지 적는다.

**형식**

```markdown
| 기존 artboard | 영역 | 새 위치 | 판정 | 근거 |
|---|---|---|---|---|
| Main.dc.html | 헤더 60px | ① 헤더 | 그대로 | 5종 공통값 |
| Main.dc.html | 74px 띠 | ② 국면 띠 | 그대로 | 5종 공통값 |
| Main.dc.html | 우측 460px Step 패널 | ③ 우 | 그대로 | 3종 공통값 |
| AiRecord.dc.html | 우측 540px (Step + 진행 로그) | ③ 우 460px + 좌측 국면 보조 | **분리** | 로그는 대상 앱과 함께 봐야 한다 (FR-218e) |
| RunResult.dc.html | 우측 640px 산출물 | ③ 좌 (대상 앱 영역) | **이동** | 미러가 있던 자리 (FR-244) |
| StepInspector.dc.html | 640×1140 독립 | Step 상세 겹침 640px | 편입 | 대체되지 않는다 |
| … | | | | |
```

**판정 값은 넷뿐이다**: `그대로` / `이동` / `분리` / `옮기지 않음`.

`옮기지 않음` 은 **이유가 필수**다. 이유를 댈 수 없으면 그것은 요소를 잃은 것이며 DC-007
위반이다.

**빠짐없음의 검사**: 기존 6종의 `<div>` 총계와 인라인 `<svg>` 총계를 세어(002 §3 이 같은
방법을 썼다 — 8종 합계 div 677 · svg 98) 대체 관계 표가 그 전부를 다루는지 확인한다.

## 4. 대조 기록 (DC-012 이어받음)

**위치**: `specs/007-unify-test-screens/design-conformance/Workbench.md`

002 §4 의 형식과 6개 축(구조 / 컴포넌트 / 치수 / 타이포·색 / 상태 / 가감)을 그대로 쓴다.
**국면마다 `상태` 축의 행을 갖는다** — 일곱 국면이 하나의 화면이므로 상태가 일곱이다.

| 칸 | 채우는 주체 |
|---|---|
| `축` · `항목` · `기준값` | 스크립트가 `Workbench.dc.html` 에서 기계적으로 추출 |
| `관측값` · `판정` · `비고` | **사람이 채운다** |

> 002 §4 의 문장을 그대로 옮긴다 — **"구현자가 자기 구현을 판정하면 대조가 아니라 자기
> 확인이다."** 007 도 예외가 아니다.

**완료 판정**: `불일치` · `미판정` 이 0건.

## 5. 승인 절차 (FR-254c)

새 artboard 는 만든 즉시 확정 디자인이 **되지 않는다.**

```
초안 작성 ──▶ 승인 대상 목록 제시 ──▶ 사람 승인 ──▶ 확정 디자인 ──▶ 대조 가능
   (구현)         (research R8 A1~A5)      (사람)        (갱신)
```

1. 초안의 값은 **기존 6종에서 기계적으로 추출한 것만** 쓴다.
2. 초안이 새로 정하는 값은 `research.md` R8 의 A1~A5 목록으로 **따로 제시한다.**
3. 승인 요청을 `docs/PENDING-HUMAN-VERIFICATION.md` 에 등록한다.
4. **승인 전 상태를 문서가 밝힌다.** 대조 기록의 첫 줄에 「이 artboard 는 승인 대기 중이며
   대조 기준으로 확정되지 않았다」를 남긴다.

**승인 전에 구현을 멈추지 않는 이유**: 초안의 값이 기존 6종에서 온 것이므로 승인이 바꿀
여지가 A1~A5 다섯 항목에 한정된다. 그 다섯이 바뀌면 고칠 범위도 그 다섯이다. 반대로 승인을
기다리며 멈추면 이 기능이 진행되지 않는다.

**승인이 거절되거나 A1~A5 가 바뀌면**: 대조 기록과 구현을 그 값으로 고친다. 초안을 근거로
"이미 만들었으니 이대로 두자" 고 하지 않는다 — 그것이 DC-001 위반의 전형이다.

## 6. 정의되지 않은 상태 (DC-009 이어받음)

**위치**: `specs/007-unify-test-screens/design-conformance/undefined-states.md`

002 의 파일을 고치지 않고 007 용 파일을 새로 둔다 — 002 의 기록은 그 라운드의 판정이고,
007 이 그것을 덮어쓰면 왜 그렇게 정했는지의 이력이 사라진다.

**002 의 기록 중 007 이 승계하는 것** (근거를 다시 적지 않고 참조한다):

| 화면 | 상태 | 007 에서의 취급 |
|---|---|---|
| StepInspector | 겹침 표시 | 그대로 승계 — 모든 국면에서 우측 겹침 640px |
| RunResult | PASS 상태 | 그대로 승계 — 같은 구조에 색만 |
| RunResult | 건너뛴 Step | 단일 Step 행으로 흡수 (FR-226) |
| RunResult | TRACE 탭 | 그대로 승계 — 비활성 + 이유 (FR-246) |
| AiRecord | AI 수행 실패 | 국면 보조 영역으로 이동, **상시 표시** (FR-218f) |
| RunnerPaused | 검토(review) 상태 | 국면 `paused` 의 런타임 조건으로 흡수 (C2) |
| 전 화면 | 창이 기준 폭보다 좁을 때 | 그대로 승계 (DC-011) |

**007 이 새로 기록해야 하는 것** (최소 목록):

| 상태 | 근거로 삼을 표현 |
|---|---|
| 「기록됨」 결말 표식 | `RunnerPaused.dc.html` 미실행 행의 2px 실선 + 흐린 색 (research R4) |
| 국면 보조 영역이 빈 국면 | 자리를 차지하지 않는다. 세션 4종의 170px 는 내용이 있을 때의 값이다 |
| 「이 결과 이후 정의가 바뀌었습니다」 알림 | 002 §3 의 경고 노랑 `#F5D000` / `#FFF9D6` (research R3) |
| 결과 국면에서 Step DSL 이 매칭되지 않은 행 | 빈 칸. 다른 칸을 당기지 않는다 (FR-223) |
| 결과 국면의 좌측 산출물이 남는 폭 전부를 차지 | `RunResult.dc.html` 의 640px 은 고정 배치의 값이다 (FR-218a) |
| 국면 알약 7종의 색 역할 | 002 §3 의 색 역할표 — PASS `#2E9455` · FAIL `#D9502F` · AI `#7C4DDB` · 강조 `#F5D000` · 중립 `#EFEBE0` |

목록은 최소다. 구현 중 발견되는 상태를 모두 이 파일에 추가한다. **근거를 댈 수 없는 결정은
해석이고 DC-001 위반이다.**

## 7. 002 규약에서 그대로 유지되는 금지 목록

| 금지 | 이유 |
|---|---|
| dc.html 에 없는 값을 토큰으로 만들기 | 002 가 고친 결함 |
| "더 나은" 간격·정렬로 바꾸기 | DC-001 |
| dc.html 에 없는 요소 추가, 있는 요소 제거 | DC-007 |
| 반응형으로 재배치 | DC-011 — 최소 기준 폭 유지하고 스크롤 |
| SVG 를 아이콘 라이브러리로 대체 | 대체는 해석이다 |

**007 이 추가하는 금지 하나**:

| 금지 | 이유 |
|---|---|
| 승인되지 않은 초안 artboard 를 근거로 "확정 디자인대로 만들었다" 고 판정하기 | §5 — 초안은 대조 기준이 아니다 |
