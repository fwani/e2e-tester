# Data Model — 저장된 테스트를 고치는 길

**Feature**: 006-edit-saved-test | **Date**: 2026-09-07

**이 기능은 Step DSL 을 바꾸지 않는다** (헌법 원칙 I). 아래 표를 전수 작성한 결과 새 필드가
하나도 필요하지 않았다. 새로 생기는 것은 **편집 연산**과 **정의 조회/저장 뷰** 둘뿐이며, 둘 다
저장되지 않는 전송·연산 모델이다.

---

## 1. 편집 가능 표 (전수)

명세 Assumptions 의 기준 하나 — **살아 있는 페이지가 필요한가** — 로 모든 필드를 갈랐다.
이것이 research Q2 의 해소다.

### `Test` 수준

| 필드 | 브라우저 없이 편집 | 근거 |
|---|---|---|
| `name` | ✅ 가능 | 문자열. FR-186. 지금도 `PATCH /api/tests/{id}` 로 된다 |
| `id` | ❌ 불가 (편집 대상 아님) | 파일 이름·실행 결과·비밀 값이 이것으로 묶여 있다. 이름 변경과 식별자 변경은 다른 일이다 |
| `dsl_version` | ❌ 불가 | 제품이 정한다 |
| `authoring_mode` | ❌ 불가 | 어떻게 만들어졌는지의 기록이다. 편집으로 바뀌면 기록이 아니다 |
| `start_url` | ✅ 가능 | 문자열(URL 형식 검증). 대상 앱 접속 없이 검증된다 |
| `browser` | ❌ 불가 (범위 밖) | 프로젝트 설정에 속한다. 이 기능에서 다루지 않는다 |
| `variables` | ⚠️ 파생 | 직접 편집하지 않는다. Step 이 참조하는 이름에서 **파생**한다 (R5) |
| `steps` | ✅ 가능 | 아래 표 |
| `ai_instruction` | ❌ 불가 (읽기 전용) | 명세 「하지 않는 것」 |
| `created_at` | ❌ 불가 | 기록 |
| `updated_at` | ⚠️ 자동 | 저장 시 서버가 갱신한다 |

### `Step` 수준

| 필드 | 브라우저 없이 편집 | 근거 |
|---|---|---|
| `id` | ❌ 불가 | 참조 키. 순서는 목록 순서가 표현한다 |
| `type` | ❌ 불가 | `update_step` 주석이 이유를 적어 두었다 — 종류가 바뀌면 대상 요소의 의미도 바뀌므로 그것은 삭제와 삽입이다. 편집으로 위장하면 후보 묶음이 엉뚱한 종류에 남는다 |
| `label` | ✅ 가능 | 표시 이름. FR-183 |
| `author` | ❌ 불가 | 출처 기록 (원칙 I: 출처는 메타데이터이며 실행을 바꾸지 않는다) |
| `tab` | ✅ 가능 | 정수. FR-183. `update_step` 에 인자를 더한다 (R3 후단) |
| `timeout_ms` | ✅ 가능 | 정수(1~60000). FR-183 |
| `frame_url` | ❌ 불가 (범위 밖) | 프레임 진단 정보. 손으로 고칠 값이 아니다 |
| `value` (fill·select) | ✅ 가능 | 문자열. 단 민감 참조 규칙(§4) 적용 |
| `url` (navigate) | ✅ 가능 | URL 형식 검증 |
| `target` / `drop_target` | ❌ **불가** | **살아 있는 페이지가 필요하다.** 후보 수집·검증이 실제 요소에서만 된다. FR-187 제외 결정(R6)의 근거이자 그 결정이 적용되는 자리 |
| `assertion.kind` / `.match` | ❌ 불가 (범위 밖) | 검증 Step 의 종류 변경은 삭제·재추가로 다룬다 |
| `assertion.value` | ✅ 가능 | 기대값 문자열. 실행 없이 고칠 수 있다 |
| `assertion.target` | ❌ 불가 | `target` 과 같은 이유 |

**결론**: 기준 하나로 전부 갈렸다. 갈리지 않던 유일한 항목이 locator 후보였고 FR-187 로
정리됐다. `frame_url`·`assertion.kind` 는 원리적으로 불가한 것이 아니라 **범위 밖**으로 두는
것이며, 그 사실을 화면에서 구분해 보여야 한다 (FR-191).

## 2. 편집 연산 (`EditOp`) — 신규, 전송 전용

저장 요청이 실어 보내는 것. 서버가 이것을 `itb.execution.step_edits` 로 적용한다.
**저장되지 않는다** — 정의 파일에는 적용 결과만 남는다.

| 연산 | 필드 | 적용 함수 | 검증 |
|---|---|---|---|
| `update` | `step_id`, `label?`, `value?`, `timeout_ms?`, `tab?` | `update_step()` | 최소 한 필드. 알 수 없는 `step_id` → 404 계열. 값을 갖지 않는 종류에 `value` → 400 |
| `delete` | `step_id` | `delete_step()` | 알 수 없는 `step_id` 거절 |
| `reorder` | `order: [step_id...]` | `reorder_steps()` | 현재 집합과 정확히 일치해야 한다. 부분 적용하지 않는다 |
| `set_name` | `name` | (Test 수준) | 1~200자 |
| `set_start_url` | `url` | (Test 수준) | URL 형식 |
| `set_assertion_value` | `step_id`, `value` | `update_step()` 확장 아님 — 별 연산 | 대상이 `assertion` Step 인지 확인 |

**적용 규칙**

- 목록 순서대로 적용한다. 하나라도 실패하면 **전부 적용하지 않는다** — 절반 적용된 정의는
  사용자가 의도한 어떤 상태도 아니다 (`ReorderMismatchError` 주석의 판단과 같다).
- `current_step_index = 0` 으로 부른다. 실행 위치가 없으므로 "이미 실행된 구간" 경고가 하나도
  생기지 않는다. `step_edits` 를 고치지 않고 그대로 쓰는 근거다 (R3).
- 같은 `step_id` 에 대한 `update` 는 화면이 하나로 합쳐 보낸다. 서버는 여러 개가 와도 순서대로
  적용하므로 결과는 같다.
- 연산 개수가 곧 **저장하지 않은 변경 건수**다 (FR-189). 되돌리기는 목록에서 빼는 것이다
  (FR-190).

## 3. 정의 조회 뷰 (`DefinitionView`) — 신규, 응답 전용

| 필드 | 뜻 |
|---|---|
| `test` | 저장된 `Test` 그대로. 기존 모델이며 바뀌지 않는다 |
| `revision` | 정의 파일 내용의 SHA-256 (앞 16자). 저장 요청이 되돌려 보낸다 (R4) |
| `editable` | 지금 편집할 수 있는가 |
| `blocked_by` | 편집할 수 없는 이유. `running`(실행 중) 하나로 시작한다. `null` 이면 편집 가능 |
| `blocking_session_id` | `blocked_by == "running"` 일 때 그 세션. 화면의 「실행 중인 세션 보기」가 쓴다 (R9) |
| `locked_fields` | 이 화면에서 고칠 수 없는 필드의 목록과 각각의 이유 문구 키. FR-191 이 요구하는 구분을 화면이 하드코딩하지 않게 한다 |

**`revision` 을 `Test` 에 넣지 않는 이유**: `Test` 는 저장되는 DSL 모델이다. 파일 해시는
파일의 성질이고 정의의 내용이 아니다. 넣으면 저장할 때 자기 해시를 자기 안에 적는 순환이 된다.

## 4. 검증 규칙 (저장 시점)

순서대로 판정하고, 처음 걸린 것에서 멈춘다. 모두 **경계에서** 한다 (FR-211, 조직 보안 요건).

| # | 규칙 | 위반 시 |
|---|---|---|
| V1 | 요청 형태 — 알 수 없는 필드 거절(`extra="forbid"`), 연산 목록 1건 이상 | 400 |
| V2 | `revision` 일치 — 불일치면 외부에서 파일이 바뀐 것이다 | 409 + 현재 정의를 함께 준다 (FR-209) |
| V3 | 실행 중 아님 — `reservation_for_test(test_id)` 가 비어 있어야 한다 | 409 + `session_id` (FR-207, R9) |
| V4 | 연산 적용 — `step_edits` 가 던지는 것을 그대로 옮긴다 | 400/404 |
| V5 | Step 1개 이상 | 400 (FR-197) |
| V6 | 민감 참조 규칙 — 민감 변수를 참조하던 값을 평문 리터럴로 바꿀 수 없다 | 400 (FR-213) |
| V7 | `Test` 모델 검증 — 스키마·Step id 유일성·URL 형식·길이 | 400 (FR-196) |
| V8 | 변수 파생 — 참조된 이름으로 `variables` 를 다시 만든다. 기존 민감 표시는 유지된다 | 강등되면 버그 (FR-214, R5) |
| V9 | 정의되지 않은 참조 경고 — 막지 않고 응답에 경고로 싣는다 | 200 + `warnings` (FR-216) |

**V6 의 판정**: "민감 변수를 참조하던 값" 이란 편집 **전** 값이 `{{NAME}}` 이고 그 `NAME` 이
`variables` 에서 `sensitive: true` 인 경우다. 그 값을 평문으로 바꾸려는 편집만 거절한다.
비민감 변수 참조를 평문으로 바꾸는 것은 정상 편집이다.

## 5. 화면 쪽 상태 (편집 초안)

저장소에 남지 않는다. 새로고침·탭 닫기는 브라우저 기본 이탈 확인으로 막는다 (R8).

| 상태 | 뜻 |
|---|---|
| `loaded` | `DefinitionView` — 서버에서 받은 저장된 정의와 `revision` |
| `ops` | 누적된 편집 연산 목록. 길이가 변경 건수다 |
| `preview` | `loaded.test` 에 `ops` 를 화면에서 얕게 적용한 표시용 값. **판정하지 않는다** — 규칙의 주인은 서버다 |
| `selected` | 지목된 Step id. 진입점이 넘긴 값으로 시작한다 (FR-180) |
| `saving` | 저장 요청 진행 중. 연타를 막는다 |
| `savedAt` | 마지막 저장 시각. 있으면 「변경 저장」, 없으면 「저장」 (005 FR-155·FR-156 어휘 재사용) |

**`preview` 가 판정하지 않는다는 것의 뜻**: 화면은 "이 Step 종류는 값을 갖지 않는다" 를 스스로
결정하지 않는다. 그 사실은 생성된 타입(`step.d.ts`)에서 오고, 최종 판정은 서버가 한다. 화면이
판정하면 R3 이 없애려던 두 벌이 다시 생긴다.

## 6. 세션 생성 필드 하나 (`pause_before_index`)

| 필드 | 뜻 |
|---|---|
| `pause_before_index` | `mode: "replay"` 에서만 쓴다. 러너가 이 인덱스의 Step 을 **실행하기 전에** 기존 `PAUSED` 로 들어간다. `null` 이면 지금과 같다 |

- 새 상태를 만들지 않는다. `RunEngine._pace(next_index)` 가 이미 Step 경계마다 불리고, 004 의
  `한 스텝씩` 이 같은 자리에서 `Command.PAUSE` 를 적용한다 (R7)
- 범위 검증: `0 <= pause_before_index < len(steps)`. 벗어나면 400
- `0` 이면 아무 Step 도 실행하지 않고 첫 Step 앞에서 멈춘다 — 시작 주소만 열린 상태다

## 7. 불변식

1. **편집은 정의만 바꾼다.** 정의 편집 경로는 브라우저를 만들지 않고, 열려 있는 브라우저에
   어떤 명령도 보내지 않는다. `step_edits` 가 이미 구조적으로 그것을 보장한다 (그 모듈은
   Playwright 를 임포트하지 않는다)
2. **편집 경로에 언어모델이 없다.** 신규 엔드포인트 어디에서도 작성(authoring) 계층을 부르지
   않는다 (원칙 II, FR-210)
3. **locator 후보는 편집 요청 모델에 존재하지 않는다.** 구조적으로 손댈 수 없다 (원칙 IV, R6)
4. **평문 민감 값을 받는 필드가 없다.** 값 필드에는 참조만 들어온다 (FR-212·FR-215, R10)
5. **저장은 원자적이다.** 부분 저장된 정의 파일이 생기지 않는다 (기존 `atomic.write_text`)
6. **저장 경로는 하나다.** 세션 저장과 정의 저장이 모두 `repo.write_test()` 로 수렴한다
