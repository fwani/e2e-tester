# Data Model — AI 의 손이 어디에 있는지 보인다 (024)

이 기능은 **저장되는 것을 하나도 만들지 않는다.** 여기서 정의하는 것은 전부 흘러가는
값이다 — 세션 안에서만 살고, 디스크에 남지 않으며, 테스트 자산의 일부가 아니다.

그 사실이 이 문서의 가장 중요한 내용이다. 저장 스키마가 바뀌지 않으므로 헌법 원칙 I·V
가 걸리는 자리가 없다.

---

## 1. 바뀌지 않는 것 — 먼저 못 박는다

| | 바뀌는가 |
|---|---|
| Step DSL 스키마 | **아니다** |
| 저장 형식 (YAML) | **아니다** |
| 실행 결과 기록 (`RunResult`) | **아니다** |
| Playwright 내보내기 | **아니다** |
| 후보 수집·우선순위 전략 | **아니다** |
| 기존 세션 이벤트의 모양 | **아니다** |

새로 생기는 것은 **실행 기록의 선택 필드 하나**와 **세션 이벤트 하나**다.

---

## 2. 조작 자리 (`ElementRect`)

AI 가 지금 다룬 요소가 대상 화면에서 차지하는 영역.

```
ElementRect
  x       : float   대상 화면 좌표. 왼쪽
  y       : float   대상 화면 좌표. 위쪽
  width   : float   > 0
  height  : float   > 0
```

### 좌표계

**미러 프레임의 `width`·`height` 와 같은 계**다 — 주 프레임 뷰포트 기준의 CSS 픽셀.
iframe 안의 요소여도 같다.

이 규정이 이 기능 전체를 지탱한다. 화면은 이 좌표를 프레임이 실어 온 근거
(`pageScale`·`offsetTop`)로만 변환하며, 두 기준을 맞추려고 추정하는 자리를 만들지
않는다 (FR-003).

### 유효성

- 너비 또는 높이가 0 이하면 **자리가 없는 것으로 본다.** 그릴 자리가 없다.
- 값이 수치가 아니면(NaN·무한대) 자리가 없는 것으로 본다.
- **화면 밖의 음수 좌표는 유효하다.** 스크롤 위에 있는 요소가 그렇다 — 자리가 없는
  것이 아니라 보이지 않는 것이며, 그리지 않는 판정은 화면이 한다 (research R8).

## 3. 실행 기록에 실린다 (`StepExecution.rect`)

```
StepExecution
  resolved_candidate : str | None      (기존)
  attempts           : list[...]       (기존)
  disagreement       : list[str]       (기존)
  tab_wait_ms        : int             (기존)
  element_wait_ms    : int             (기존)
  tab                : int             (기존)
  rect               : ElementRect | None    ← 024
```

### 왜 여기인가

`StepExecution` 은 이미 「Step 하나를 실행한 기록」이며 성공 경로에서도 진단 정보를
남긴다. 자리는 그 기록의 하나다 — 실행기가 **실제로 채택한 요소**에서 읽은 값이므로,
다른 어디에서 읽어도 같다는 보장이 없다 (research R1).

### `None` 인 경우

| 경우 | 왜 |
|---|---|
| 요소를 대상으로 하지 않는 Step (이동·탭 닫기) | 잴 요소가 없다 |
| 요소가 보이지 않아 경계 상자가 나오지 않는다 | 자리가 없다 |
| 측정이 실패했다 | 표시는 곁가지다. 실행을 멈추지 않는다 (FR-006) |

**`None` 은 정상 값이다.** 자리를 모르는 것과 자리가 없는 것을 구별하지 않는다 — 둘 다
「그리지 않는다」로 귀결되므로 구별할 이유가 없다.

## 4. 실패에도 자리가 실린다 (`StepFailure.rect`)

```
StepFailure
  message          (기존)
  attempts         (기존)
  tab_wait_ms      (기존)
  code             (기존)
  element_wait_ms  (기존)
  rect : ElementRect | None    ← 024
```

요소는 찾았는데 동작이 실패한 경우(가려짐·비활성·시간 초과), 자리는 존재한다. 그것이
명세 US2 가 실제로 겨냥하는 경우다 (research R2).

요소 자체를 찾지 못한 실패에서는 `None` 이다.

## 5. 세션 이벤트 `ai_focus`

```
ai_focus
  tab    : int             어느 탭의 자리인가
  rect   : ElementRect     자리 (없으면 이벤트를 보내지 않는다)
  status : "done" | "failed"
  label  : str             Step 의 이름표와 같은 값
```

### 필드마다의 규정

| 필드 | 규정 |
|---|---|
| `tab` | 화면이 지금 보고 있는 탭과 다르면 그리지 않는다 (FR-018) |
| `rect` | **필수.** 자리가 없으면 이벤트 자체를 보내지 않는다 (FR-010) |
| `status` | 둘뿐이다. 「수행 중」은 없다 (research R2) |
| `label` | 화면이 진행 문구와 짝지어 읽기 위한 것 (FR-009) |

### 왜 「없음」을 나타내는 값이 없는가

자리가 없으면 **보내지 않는다.** 「자리 없음」을 실어 보내면 화면이 그 이벤트를 받고
지난 표시를 지울지 판단해야 하고, 그 판단은 수명이 이미 하고 있다 (research R6).

### 싣지 않는 것

- **프레임 번호** — 그림과 맞추지 않는다 (research R6).
- **요소 참조·CSS 경로** — 화면이 쓸 일이 없다. 화면 구조를 내보낼 이유가 없다.
- **실패 사유** — 이미 진행 문구와 막힘 안내가 나른다. 여기서 또 나르면 같은 사실의
  출처가 둘이 된다.

### 어느 세션에서 나가는가

**AI 작성 세션에서만.** 재생 세션에서는 한 건도 나가지 않는다 (FR-007·SC-006). 이것은
규칙이 아니라 구조다 — 발행 지점이 AI 작성 전용 모듈 안에만 있다 (research R5).

## 6. 도구 쪽 통로 (`FocusSink`)

```
ProgressSink = (str) → Awaitable[None]              (기존)
FocusSink    = (FocusNotice) → Awaitable[None]      ← 024

FocusNotice
  tab    : int
  rect   : ElementRect
  status : "done" | "failed"
  label  : str
```

`ProgressSink` 와 나란한 선택 통로다. 없으면 아무것도 알리지 않고, 나머지는 지금과 같이
동작한다.

### 왜 진행 통로와 나누는가

진행 통로는 **자리를 모르는 자리에서도** 불린다 — 화면 살펴보기, Step 편집, 막힘 신고.
한 통로로 묶으면 그 호출마다 「자리 없음」을 넘기게 되고, 「자리를 모른다」와 「자리가
없다」가 같은 모양이 된다 (research R4).

## 7. 화면 쪽 상태

### 받은 알림 하나 (`FocusMark`)

```
FocusMark
  tab     : number
  rect    : { x, y, width, height }     대상 화면 좌표
  status  : "done" | "failed"
  label   : string
  at      : number                      받은 시각. 수명 계산의 기준
```

**한 개만 갖는다.** 새 알림이 오면 덮어쓴다 (FR-014). 목록으로 쌓지 않는다.

### 수명

```
FOCUS_MARK_TTL_MS = 2500        (frontend/src/lib/focusMark.ts)
```

화면이 센다. 지난 표시는 스스로 사라진다 (research R6).

**판정 함수와 같은 파일에 있다.** 수명은 판정의 한 줄이고(「표시할 시간이 지났다」),
상수만 다른 곳에 두면 표의 한 줄이 코드에서 멀어진다.

### 표시 좌표 (`DisplayRect`)

정변환의 결과. 이미지 표시 영역 기준의 픽셀.

```
DisplayRect
  left, top, width, height : number
```

`null` 이면 그리지 않는다 — 그리지 않는 조건 전부가 이 `null` 하나로 모인다
(research R8).

### 미러 컴포넌트가 받는 것

```
focus?: { rect: TargetRect; status: "done" | "failed"; label: string } | null
```

**대상 화면 좌표로 받는다.** 구현에서 갈라진 자리이므로 명시해 둔다.

| 무엇 | 어디가 하는가 | 왜 |
|---|---|---|
| **그릴지 말지** | 화면 (`lib/focusMark.ts`) | 판정이 한 곳에 모여야 한다 (FR-316) |
| **좌표를 옮기는 일** | 미러 컴포넌트 | 변환에 `<img>` 의 자연 크기·표시 크기가 필요하고, 그 둘을 아는 곳이 거기뿐이다 |

설계 단계에서는 판정과 변환을 함께 바깥에 두려 했으나, 변환의 입력(`DisplayBox`)을
컴포넌트만 읽을 수 있어 나눴다. **국면을 보는 것과 자기가 그리는 그림의 크기를 아는 것은
다른 일이다** — FR-316 이 금지하는 것은 앞쪽이다.

## 8. 상태 전이

```
        알림 도착 (rect 있음)
              │
              ▼
        ┌──────────┐   새 알림    ┌──────────┐
        │  표시 중  │ ──────────▶ │  표시 중  │   (앞의 것은 사라진다)
        └──────────┘             └──────────┘
              │
              │ 2.5초 경과 · 프레임 끊김 · 미러 중단 · 탭 전환 · 화면 재접속
              ▼
        ┌──────────┐
        │  없음     │
        └──────────┘
```

「없음」에서 「없음」으로 가는 전이는 없다. 자리 없는 알림은 애초에 오지 않는다.

**화면을 새로 고치면 「없음」에서 시작한다.** 지나간 자리를 복원하지 않는다 — 흘러가는
표시이며, 다시 붙었을 때 과거를 지금처럼 보이게 하면 안 된다.
