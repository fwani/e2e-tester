## 0. 전제

```bash
# 백엔드 (루프백만 바인딩)
cd backend && uv run uvicorn itb.api.app:app --host 127.0.0.1 --port 4320

# 프론트엔드
cd frontend && npm run dev            # http://127.0.0.1:4310
```

**손 검증에는 대상 앱이 필요 없다.** 이 기능은 브라우저를 열지 않는다 — §2 의 이야기 5
(실행 중 세션)만 예외다.

> **주의**: §2 는 실제 홈 디렉터리의 `~/.local/share/itb/` 를 건드린다. 자기 프로젝트를 쓰기
> 싫으면 `XDG_DATA_HOME` 과 `XDG_CONFIG_HOME` 을 임시 디렉터리로 지정해 백엔드를 띄운다.
>
> ```bash
> export XDG_DATA_HOME=/tmp/itb-012/data XDG_CONFIG_HOME=/tmp/itb-012/config
> ```

## 1. 자동 검증

```bash
# 백엔드
cd backend && uv run ruff check src/ tests/
cd backend && uv run lint-imports
cd backend && uv run python -m itb.schema.export --check     # 오류 코드 2개 추가 → 생성물 갱신 필요
cd backend && uv run pytest -m "not browser" -q
cd backend && uv run pytest -q

# 프론트엔드
cd frontend && npx tsc --noEmit && npx vitest run
```

**`--check` 가 실패하면** `ErrorCode` 에 `PROJECT_IN_USE`·`PROJECT_DELETE_FAILED` 를 더하고
`frontend/src/types/generated/error-response.d.ts` 를 다시 만들지 않은 것이다. 생성물은 커밋
대상이다 (헌법 Cross-language schema duty).

```bash
cd frontend && npm run gen:types
```

## 2. 손 검증 — 여섯 이야기

각 이야기는 **끝까지 갔을 때 무엇이 보여야 하는가**로 판정한다.

### 이야기 1 — 이름을 고친다 (US1 · FR-399~408 · SC-614·SC-615)

1. 프로젝트를 하나 만든다. 이름 `임시`.
2. 프로젝트 선택 화면 목록에서 그 줄의 이름을 누르고 `결제 회귀` 로 고쳐 `Enter`.

**보여야 하는 것**

- 확인 창이 **뜨지 않는다.** 조작 두 번(누르기 → 확정)으로 끝난다 (SC-614).
- 그 줄의 이름이 즉시 바뀐다. **목록의 순서는 그대로다** (research R2).
- 백엔드를 껐다 켜고 목록을 다시 열어도 `결제 회귀` 다 (SC-615).

```bash
grep name ~/.local/share/itb/projects/임시/itb-project.yaml   # 결제 회귀
grep -A2 임시 ~/.config/itb/registry.json                      # name 도 갱신, last_opened_at 은 그대로
```

**막히면**: 파일만 바뀌고 레지스트리가 그대로면 FR-401 미충족이다. 순서가 바뀌었으면
`remember()` 를 쓴 것이다 (research R2).

### 이야기 2 — 빈 이름은 거절된다 (FR-403)

이름 칸을 비우고 `Enter`.

**보여야 하는 것**: 저장되지 않고, 그 자리에 왜 안 되는지 한 줄이 뜬다. 입력 칸은 열린 채다.
`Esc` 를 누르면 원래 이름으로 돌아간다.

### 이야기 3 — 삭제는 휴지통으로 간다 (US2 · FR-409~415 · SC-616·SC-617)

1. 프로젝트를 만들고 테스트를 하나 저장한다.
2. 목록에서 그 줄의 「삭제」를 누른다.

**보여야 하는 것 (확인 단계)**

- 프로젝트 이름·경로·저장된 테스트 수가 보인다.
- **「휴지통으로 옮깁니다 · 되돌릴 수 있습니다」** 가 보인다.
- 이 시점에 **디스크는 아무것도 바뀌지 않았다** (SC-617):
  ```bash
  ls ~/.local/share/itb/projects/     # 그대로 있다
  ls ~/.local/share/itb/trash/ 2>/dev/null   # 비었거나 없다
  ```
- 「취소」를 누르면 목록이 그대로다 (FR-412).

**보여야 하는 것 (확인 후)**

- 줄이 목록에서 사라진다.
- **옮겨진 위치가 화면에 그대로 표시된다** (FR-410). 자동으로 사라지지 않는다.
- 그 위치에 자산이 온전하다 (SC-616):
  ```bash
  ls ~/.local/share/itb/trash/*/tests/     # TC-001-*.yaml 이 그대로
  ```
- 화면이 알려 준 디렉터리를 `~/.local/share/itb/projects/` 로 되돌리면 목록에 다시 나타난다.

### 이야기 4 — 같은 이름을 두 번 지워도 덮어쓰지 않는다 (FR-415 · SC-619)

같은 이름의 프로젝트를 두 개 만들어 연달아 삭제한다.

**보여야 하는 것**: `~/.local/share/itb/trash/` 에 **두 항목이 각각** 있다. 첫 번째의
`tests/` 가 그대로다.

### 이야기 5 — 실행 중이면 삭제되지 않는다 (FR-417 · SC-621)

1. 프로젝트를 열고 테스트를 하나 실행해 브라우저를 띄운 채로 둔다.
2. 프로젝트 선택 화면으로 가서 그 프로젝트를 삭제한다.

**보여야 하는 것**: 삭제되지 않고 그 줄에 「실행 중인 브라우저가 있어…」 와 무엇을 먼저
해야 하는지가 뜬다. **브라우저는 닫히지 않고 세션도 살아 있다** (SC-621). 목록에도 그대로다.

### 이야기 6 — 두 조작을 구분한다 (US3 · FR-422~425 · SC-620)

목록에서 「삭제」와 「목록에서 치우기」의 설명을 각각 읽는다.

**보여야 하는 것**: 두 설명 모두 **디스크의 파일이 어떻게 되는지**를 말한다. 접근 불가로
표시된 줄(디렉터리를 밖에서 지운 프로젝트)에는 「삭제」가 **없고** 「목록에서 치우기」만 있다.
외부 위치 프로젝트를 삭제하려 하면 확인 단계에 「도구 바깥에서 만든 위치」가 표시된다.

## 3. 회귀 — 깨지지 않아야 하는 것

| 확인 | 방법 |
|---|---|
| 관리 위치 프로젝트를 「목록에서 치우기」 하면 여전히 스캔에 다시 걸린다 | 치운 뒤 목록 새로 고침 → 다시 나타난다. **이것이 정상이며 012 가 바꾸지 않는다** |
| 휴지통이 목록에 나타나지 않는다 (FR-421) | 삭제 후 목록 새로 고침 → 휴지통 항목이 줄로 뜨지 않는다 |
| 프로젝트 만들기·열기가 그대로다 | 이야기 1 의 1단계가 곧 이 검증이다 |
| 이름을 고쳐도 테스트가 그대로 열린다 (FR-400) | 이름 변경 후 프로젝트를 열어 테스트 목록·정의를 본다 |
| 옮기기 실패 시 목록에 남는다 (FR-414 · SC-618) | 프로젝트 디렉터리를 읽기 전용으로 만든 뒤 삭제 시도 → 오류가 뜨고 목록에 그대로, 자산도 원래 자리 |
