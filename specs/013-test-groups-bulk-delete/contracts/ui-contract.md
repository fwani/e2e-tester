# UI 계약 — 테스트 목록의 선택·그룹

**Feature**: 013-test-groups-bulk-delete | **화면**: `frontend/src/pages/TestList.tsx`

이 화면은 **조작 권한표(`lib/capabilities.ts`) 밖**이다 — `capabilityOf` 를 한 번도 부르지
않고, 권한표는 국면(Phase) 축을 요구하는데 목록은 그 축 밖에 있다. 012 가 `ProjectSetup` 에서
한 판단을 그대로 따른다: **표에 편입하지 않되 표가 지키는 원칙은 지킨다** — 조작이 지금 왜
안 되는지 화면이 말한다 (research R8).

시각 언어는 008 이 정한 것을 그대로 쓴다. **새 클래스를 만들지 않는다.**

---

## UC-013-01 — 체크 칸은 행 누름과 갈라 둔다

011 이 Step 목록에서 정한 규칙이다. 행을 누르는 것은 **지목·열기**이고, 체크 칸은 **삭제·이동
대상 고르기**다. 두 동작을 한 자리에 두면 열려던 사용자가 삭제 대상을 고른다.

| 자리 | 조작 |
|---|---|
| 행 왼쪽 끝 체크 칸 | 대상 고르기 |
| 행 본문 | 열기 (기존 그대로) |
| 행 오른쪽 조작들 | 실행·편집·이름 변경·삭제 (기존 그대로) |

**행 하나 삭제는 그대로 남는다** (FR-435). 복수 삭제가 한 개를 지우는 일을 더 번거롭게 만들지
않는다.

---

## UC-013-02 — 선택 띠는 고른 것이 있을 때만 나타난다

목록 위에 띠 하나가 붙는다. 고른 것이 0개면 **그리지 않는다** — 늘 떠 있으면 그룹도 복수
삭제도 쓰지 않는 사용자에게 자리를 뺏는다 (SC-627).

띠가 담는 것:

| 항목 | 규칙 |
|---|---|
| 「N개 선택됨」 | 개수를 **숫자로** 말한다 |
| 「보이는 것 전부 선택」 / 「선택 해제」 | 대상은 **지금 화면에 보이는 것**이다 (FR-428) |
| 「그룹으로 옮기기」 | 그룹이 하나도 없으면 그리지 않는다 |
| 「선택한 항목 삭제」 | — |

**「전체 선택」이 걸러진 것까지 고르면 안 되는 이유**: 사용자가 검색어로 좁힌 뒤 전체 선택을
누르면, 보지 못한 테스트가 삭제 대상이 된다 (SC-625).

---

## UC-013-03 — 걸러 보기가 바뀌면 선택도 따라간다

검색어나 그룹 걸러 보기가 바뀌어 어떤 행이 화면에서 사라지면 **그 행은 선택에서도 빠진다**
(FR-429). 개수 표시가 즉시 그것을 반영한다.

**보이지 않는 것이 선택에 남으면** 사용자는 무엇을 지웠는지 볼 수 없는 삭제를 하게 된다.

## UC-013-04 — 확인은 목록 바로 아래에서, 이름으로 말한다

011 의 `BulkDeleteConfirm` 을 **재사용하지 않는다.** 그 부품은 `deleteManyConfirm(indices)` 로
**Step 번호의 범위**를 말하는데, 테스트는 순서 없는 집합이라 「범위」가 성립하지 않는다
(research R7). 관용어만 잇고 부품은 새로 만든다.

확인 띠가 담는 것:

| 항목 | 근거 |
|---|---|
| 개수와 **이름** (예: 「로그인 · 회원가입 외 3개를 지웁니다」) | 개수만 있으면 어느 것인지 알 수 없다 (FR-430) |
| **「휴지통으로 옮깁니다 · 되돌릴 수 있습니다」** | FR-437b |
| 「지우기」 · 「돌아가기」 | 돌아가기가 기본 — 포커스를 여기에 둔다 |

**확인 전에는 어떤 요청도 보내지 않는다** (FR-431 · SC-624 의 전제).

겹침 대화상자를 쓰지 않는 것은 011·012 와 같은 근거다 — 대상이 화면에서 사라지면 무엇을
지우려던 것인지 다시 확인해야 한다.

## UC-013-05 — 완료 표시는 되돌리는 방법을 남긴다

삭제가 끝나면 목록 위에 알림이 남는다.

```
3개를 휴지통으로 옮겼습니다.
/Users/me/.local/share/itb/trash/20260910-143000-USER-001-로그인
/Users/me/.local/share/itb/trash/20260910-143000-USER-003-회원가입
…
되돌리려면 각 폴더의 .yaml 을 프로젝트의 tests/ 로 옮기세요.
```

**자동으로 사라지지 않는다** (012 UC-012-04 와 같은 규칙) — 사라지면 되돌리는 방법이 함께
사라진다. 경로는 `mono` 로, 잘리지 않게 표시한다.

여러 개일 때 경로가 길어지므로 **접었다 펼 수 있게** 한다. 다만 **기본은 펼친 상태**다 —
접어 두면 사용자가 되돌리는 방법을 못 본 채 알림을 닫는다.

## UC-013-06 — 그룹은 목록을 묶고 걸러 본다

| 자리 | 무엇 |
|---|---|
| 목록 위 그룹 띠 | 「전체」 + 그룹별 칩(이름 + 개수). 누르면 그 그룹만 (FR-441) |
| 목록 안 | 그룹별 소제목 아래에 그 그룹의 행들 (FR-440) |
| 「그룹 없음」 | 마지막에 온다. 그룹 없는 테스트가 없으면 그리지 않는다 |

**그룹이 하나도 없으면 그룹 띠도 소제목도 그리지 않는다** (SC-627). 목록은 이 기능 이전과
같은 모습이다.

**`groups[].count` 는 걸러 보기 전 개수다** — 걸러 본 상태에서도 다른 그룹의 개수를 보고
그리로 갈 수 있어야 한다.

**그룹 정의가 없는 접두어**(사용자가 그룹을 지웠거나 파일을 손으로 옮긴 경우)는 접두어를
이름 삼아 보여주고 **정의가 없다는 사실**을 함께 표시한다. 목록을 막지 않는다.

## UC-013-07 — 거절 사유는 그 자리에서 말한다

| 상태 | 화면 |
|---|---|
| 고른 것이 0개 | 「선택한 항목 삭제」를 그리지 않는다 (띠 자체가 없다) |
| 409 `TEST_IN_USE` | 목록 위에 「실행 중인 테스트가 있어…」 + `next_action`. **선택은 그대로 남는다** |
| 500 `TEST_DELETE_FAILED` | 「옮기지 못했습니다」 + **「전부 원래 자리에 있습니다」** |
| 500 `TEST_DELETE_PARTIAL` | 「일부가 휴지통에 남았습니다」 + 어느 것이 어디에 있는지 |

`TEST_DELETE_FAILED` 문구에 **「원래 자리에 있습니다」가 반드시 들어간다.** 실패 후 사용자가
가장 먼저 묻는 것이 「내 테스트는 어떻게 됐나」이고, 그 답이 계약상 확정되어 있다
(api-contract §3 불변식).

거절 뒤 **선택을 비우지 않는다** — 사용자가 다시 고르게 만들면 실행을 멈추고 돌아온 뜻이
없어진다.

기존 `ErrorNotice` 를 쓴다. 새 오류 표시 부품을 만들지 않는다.

## UC-013-08 — 그룹 만들기·이름 변경·없애기

| 조작 | 자리 | 확인 |
|---|---|---|
| 그룹 만들기 | 그룹 띠 끝의 「+ 그룹」 | 없음 — 되돌릴 수 있다 |
| 그룹 이름 변경 | 그룹 칩에서 제자리 편집 | 없음 (012 의 프로젝트 이름 변경과 같은 관용어) |
| 그룹 없애기 | 그룹 칩의 조작 | **있음** — 「테스트 N개가 그룹 없음으로 돌아가고 식별자가 `TC-###` 로 바뀝니다」 |

**그룹 만들기는 두 칸이다** — 이름(「사용자관리 테스트」)과 접두어(`USER`). 접두어 칸은
왜 필요한지 한 줄로 말한다: 「테스트 식별자에 들어갑니다 (예: `USER-001`)」.

**그룹 없애기에만 확인이 있는 이유**: 그것만이 **자산을 움직인다**. 그 안의 테스트들의 파일
이름과 산출물 디렉터리가 바뀐다. 이름 변경은 프로젝트 파일 한 줄이라 되돌리면 그만이다.

**그룹을 없애도 테스트는 지우지 않는다** (FR-451). 확인 문구가 그 사실을 명시한다 —
「지워지지 않습니다」.
