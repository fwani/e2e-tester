# Contract: 조작 자리 알림

**Feature**: 024-ai-focus-overlay | **Date**: 2026-09-28

이 문서는 **001 `contracts/websocket.md` 를 확장한다.** 기존 계약을 고치지 않는다 — AI
이벤트 표에 줄 하나가 더해질 뿐이다.

| 001 계약 | 이 문서에서 |
|---|---|
| 서버 → 클라이언트 단방향 | **유지.** 이 이벤트도 서버가 보내기만 한다 |
| AI 이벤트는 작성 세션에서만 나간다 | **유지.** 이 이벤트도 같다 (§4) |
| `ai_progress { message }` | **유지.** 이 이벤트가 대체하지 않는다 (§3) |

---

## §1. 이벤트

```
ai_focus
```

AI 가 요소 하나를 조작했고, **그 요소가 화면에서 차지한 자리를 제품이 안다**는 사실.

### 페이로드

| 필드 | 형 | 필수 | 뜻 |
|---|---|---|---|
| `tab` | int | ● | 어느 탭의 자리인가. 0 이 첫 탭 |
| `rect` | object | ● | 자리 (§2) |
| `status` | `"done"` \| `"failed"` | ● | 조작이 성공했는가 |
| `label` | string | ● | Step 의 이름표와 같은 값 |

이벤트 봉투(`type`·`seq`·`at` 등)는 기존 세션 이벤트와 같다.

```json
{
  "type": "ai_focus",
  "tab": 0,
  "rect": { "x": 412, "y": 268, "width": 96, "height": 36 },
  "status": "done",
  "label": "로그인 버튼 클릭"
}
```

### 보내지 않는 경우

**자리를 모르면 이 이벤트가 나가지 않는다.** 「자리 없음」을 나타내는 값은 없다.

| 경우 | 왜 |
|---|---|
| 요소를 찾지 못해 실패했다 | 잴 것이 없었다 |
| 가리키는 자리가 하나로 좁혀지지 않아 거절했다 | 어느 것인지 **제품도 모른다** |
| 요소가 보이지 않아 경계 상자가 나오지 않았다 | 자리가 없다 |
| 요소를 대상으로 하지 않는 동작 (이동·탭 닫기) | 잴 요소가 없다 |
| 화면을 살펴보는 중 | 대상이 하나가 아니다 |
| 자리 측정 자체가 실패했다 | 모르는 것을 보내지 않는다 |

마지막 줄이 중요하다 — **측정 실패가 작성을 멈추지 않는다.** 알림이 빠질 뿐이다.

## §2. `rect` — 좌표계 규정

```
rect: { x: number, y: number, width: number, height: number }
```

**`mirror_frame` 의 `width`·`height` 와 같은 계**다. 주 프레임 뷰포트 기준 CSS 픽셀.

- iframe 안의 요소여도 주 프레임 기준으로 환산되어 나간다.
- `width`·`height` 는 **항상 0 보다 크다.** 0 이면 이벤트를 보내지 않는다.
- `x`·`y` 는 **음수일 수 있다.** 스크롤 위에 있는 요소가 그렇다. 받는 쪽이 그릴지 말지를
  정한다 — 서버는 화면 안으로 밀어 넣지 않는다.

### 받는 쪽의 변환

`mirror_frame` 이 실어 온 `pageScale`·`offsetTop` 과 이미지의 자연 크기·표시 크기로
변환한다. 이 변환은 **미러 조작의 좌표 변환과 서로의 역**이어야 한다 (010
`contracts/mirror-control.md` §4 의 역변환).

## §3. `ai_progress` 와의 관계

**둘은 나란한 이벤트이며 어느 쪽도 다른 쪽을 대체하지 않는다.**

| | `ai_progress` | `ai_focus` |
|---|---|---|
| 무엇 | 쌓이는 이력 | 지금 하나뿐인 상태 |
| 언제 | 동작 **전**과 **후** | 동작 **후**, 자리를 알 때만 |
| 자리를 모를 때 | 그래도 나간다 | 나가지 않는다 |
| 받는 쪽이 하는 일 | 턴 단위로 모아 보여 준다 | 마지막 하나만 그린다 |

`ai_focus` 를 무시하는 클라이언트는 **지금까지와 똑같이 동작한다.** 진행 정보가 하나도
줄지 않는다 (024 FR-023·FR-026).

### 순서 보장

같은 동작에 대한 `ai_progress`(완료·실패)와 `ai_focus` 는 **순서가 정해지지 않는다.**
받는 쪽은 둘을 짝지어 기다리면 안 된다 — 각자 독립적으로 처리한다. `label` 이 같은
값이므로 화면이 나란히 읽을 수는 있다.

---

## §4. 어느 세션에서 나가는가

**AI 작성 세션에서만 나간다.**

재생(`replay`) 세션에서 이 이벤트가 관측되면 **헌법 원칙 II 위반**이며, 001 이 `ai_*`
이벤트 전체에 대해 세운 규칙(SC-006)이 이 이벤트에도 그대로 적용된다.

이것은 런타임 조건이 아니라 **구조**다 — 발행 지점이 AI 작성 전용 모듈 안에만 존재한다.
재생 실행기는 자리를 값으로 돌려받지만 그것을 어디에도 보내지 않는다.

---

## §5. 하위 호환

| 어느 쪽이 낡았나 | 결과 |
|---|---|
| 클라이언트가 이 이벤트를 모른다 | 알 수 없는 이벤트로 무시한다. 작성 정상 동작 |
| 서버가 이 이벤트를 안 보낸다 | 테두리가 없다. 그 밖에는 지금과 같다 |

**필수 필드가 빠진 이벤트를 받으면 무시한다.** 부분적으로 해석해 그리지 않는다 — 좌표가
하나라도 없으면 그린 자리가 틀린다.
