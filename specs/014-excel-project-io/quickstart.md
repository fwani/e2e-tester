# Quickstart — 엑셀로 프로젝트 내보내기·가져오기

**Feature**: `014-excel-project-io` | **Date**: 2026-09-10

이 기능이 실제로 동작하는지 손으로 확인하는 방법. 계약과 데이터 모델의 세부는
[contracts/rest-api.md](contracts/rest-api.md) 와 [data-model.md](data-model.md) 를 본다.

---

## 0. 준비

```bash
# 백엔드
cd backend && uv sync

# 프론트엔드
cd frontend && npm ci
```

**실제 자산을 건드리지 않는다.** 아래 모든 확인은 임시 디렉터리에서 한다.

```bash
export XDG_DATA_HOME="$(mktemp -d)"
export XDG_CONFIG_HOME="$(mktemp -d)"
```

이 두 줄을 빼먹으면 `~/.local/share/itb/projects` 의 진짜 프로젝트에 초안이 만들어진다.

```bash
# 백엔드 (터미널 1)
cd backend && uv run uvicorn itb.api.app:app --reload --port 8000

# 프론트엔드 (터미널 2)
cd frontend && npm run dev
```

## 1. 자동 검증 — 먼저 이것부터

```bash
# ★ 헌법 원칙 II (NON-NEGOTIABLE). itb.portability 가 authoring/llm 에 닿지 않는지
cd backend && uv run lint-imports

cd backend && uv run ruff check src/ tests/
cd backend && uv run pytest
cd backend && uv run python -m itb.schema.export --check   # 스키마 드리프트
cd frontend && npx tsc --noEmit && npm test -- --run
```

**`lint-imports` 와 `schema.export --check` 를 건너뛰지 않는다.** 전자는 이 기능이 원칙 II 를
지키는지 증명하는 유일한 자동 검사이고, 후자는 `Test` 에 필드를 더한 뒤 산출물을 재생성해
커밋했는지 본다. 둘 다 CI 가 막는 것이라 여기서 놓치면 나중에 막힌다.

기능별로 좁혀 돌릴 때:

```bash
cd backend && uv run pytest tests/unit/test_sheet_name.py tests/unit/test_excel_columns.py
cd backend && uv run pytest tests/contract/test_excel_export_api.py \
                            tests/contract/test_excel_import_api.py \
                            tests/contract/test_drafts_api.py
cd backend && uv run pytest tests/integration/test_import_atomicity.py \
                            tests/integration/test_export_no_secrets.py
cd backend && uv run pytest tests/e2e/test_us7_excel_export.py \
                            tests/e2e/test_us8_excel_import.py \
                            tests/e2e/test_us9_draft_recording.py
cd frontend && npm test -- --run ImportPreview DraftList ExcelExport
```

## 2. 손으로 확인하는 세 이야기

먼저 확인용 프로젝트를 만든다 — 그룹 2개, 미그룹 테스트 몇 개, 실행 결과가 섞여 있어야 한다.

### 이야기 1 — 내보내기 (US1)

1. 프로젝트를 열고 테스트 목록 화면으로 간다
2. 「엑셀로 내보내기」를 누른다 → 파일이 내려받아진다
3. 파일을 엑셀·구글 시트·LibreOffice 중 하나로 연다

**보아야 할 것**

| 확인 | 기대 |
|---|---|
| 시트 수 | 그룹 수 + 1 (`그룹 없음`). 테스트가 없는 그룹도 시트가 있다 |
| 시트 순서 | `그룹 없음` 이 맨 앞, 그 뒤는 프로젝트에 그룹이 만들어진 순서 |
| 머리글 | `TC ID · 대상기능 · 테스트항목 · 수행자 · 수행 절차 · 기대 결과 · 결과` 7개, 이 순서 |
| 행 정렬 | 시트 안에서 TC ID 순 |
| 수행 절차 / 기대 결과 | 번호가 매겨진 여러 줄. 검증 스텝은 「기대 결과」 쪽에만 있다 |
| 결과 칸 | 통과 `P` · 실패 `F` · 미실행 빈 칸 · 부분 통과와 중지는 각각 별도 표기 |
| 머리글 행 | 고정되어 아래로 스크롤해도 보인다 |

**민감값 확인** — 이것이 SC-008 이다.

```bash
# 민감 변수를 쓰는 테스트가 있는 프로젝트를 내보낸 뒤
cd "$(mktemp -d)" && unzip -q ~/Downloads/<받은파일>.xlsx
grep -ri "<실제 비밀 값>" . && echo "❌ 누출" || echo "✅ 없음"
```

`{{SECRET_LOGIN_PW}}` 같은 **참조**는 보여야 하고, 그 값은 보이면 안 된다.

**수식 주입 확인** — 테스트 이름을 `=1+1` 로 바꾼 뒤 내보내 연다.
셀이 `2` 로 계산되면 실패다. `=1+1` 이 글자 그대로 보여야 한다.

### 이야기 2 — 가져오기 (US2)

확인용 스프레드시트를 만든다. 시트 3개:

| 시트 | 내용 |
|---|---|
| `그룹 없음` | TC ID 가 `TC-001`,`TC-002` 인 행 2개 |
| `회원` | TC ID 가 `USER-001`~`USER-003` 인 행 3개. **그중 하나는 `USER-001` 을 중복해서 쓴다** |
| `데이터관리` | TC ID 칸을 **전부 비운다** (접두어를 정할 수 없는 시트) |

그리고 대상기능이 빈 행 하나, 완전히 빈 행 하나를 아무 시트에나 섞는다.

1. 프로젝트를 연 상태에서 「엑셀에서 가져오기」 → 파일 선택
2. **미리보기가 뜬다.** 여기서 확인할 것:
   - 만들 그룹 수·초안 수가 맞는가
   - `데이터관리` 시트에 **접두어 입력 칸**이 나타나는가 (FR-022a)
   - `USER-001` 중복이 「번호가 바뀜」으로 표시되는가 (FR-023b)
   - 대상기능이 빈 행이 「건너뜀」으로, 시트 이름과 행 번호와 함께 나오는가
3. **여기서 「취소」를 먼저 눌러 본다.** 프로젝트에 아무 변화가 없어야 한다 (FR-016)
4. 다시 열어 `데이터관리` 에 `DATA` 를 넣고 확정
5. 테스트 목록에 초안이 나타난다. **테스트와 구분되어 보여야 한다** (FR-027)

**접두어 비우기** — `데이터관리` 칸을 비우고 확정하면 그 시트가 통째로 건너뛰어지고,
완료 알림이 그 사실을 알려야 한다 (FR-022b).

**기존 그룹과 이름 충돌** — 프로젝트에 `USER`="사용자관리" 를 미리 만들어 두고 위 파일을
가져온다. 그룹 이름이 `사용자관리` 그대로여야 하고, 미리보기가 `회원` 과 다르다고 알려야 한다
(FR-024a). **이름이 `회원` 으로 바뀌면 실패다.**

**전부-아니면-전무** — 확정 도중 실패를 만들어 본다(예: `drafts/` 를 읽기 전용으로).
그룹도 초안도 하나도 남지 않아야 한다 (FR-025). 자동 검증은
`tests/integration/test_import_atomicity.py` 가 한다.

**수용량 거절** — 테스트가 이미 990개인 프로젝트에 초안 50건짜리 파일을 가져온다.
아무것도 만들어지지 않고, 필요한 수와 남은 수를 함께 알려야 한다 (FR-036b).

**상한 거절** — 시트 300개짜리 파일, 100MB 를 넘는 파일, `.xlsx` 가 아닌 파일,
`.xlsx` 확장자를 붙인 손상된 파일. 넷 다 해석을 시작하기 전에 거절하고 무엇이 잘못됐는지
알려야 한다.

### 이야기 3 — 초안을 녹화로 완성한다 (US3)

1. 초안 목록에서 하나를 골라 「녹화 시작」
2. **AI 작성 화면이 열리고 지시문 칸이 이미 채워져 있다** — 제목·설명·수행자·절차·기대 결과
   (FR-031). 빈 칸으로 열리면 실패다
3. 문장을 조금 고쳐 본다. 고친 것이 실제로 쓰여야 한다
4. 녹화하고 저장한다

**확인할 것**

| 확인 | 기대 |
|---|---|
| 부여된 TC ID | 초안의 희망 번호와 같다 (그 번호가 비어 있었다면) |
| 초안 목록 | 그 초안이 사라진다 (FR-033) |
| 테스트 목록 | 정식 테스트로 나타난다 |
| 다시 내보내기 | 그 테스트의 「테스트항목」·「수행자」 칸이 초안에 있던 값 그대로다 — **왕복이 이어진다** |

**희망 번호가 이미 쓰였을 때** — 녹화하는 사이에 다른 테스트가 그 번호를 가져가게 만든다.
저장은 성공하되 다른 번호를 받고, **그 사실을 사용자에게 알려야 한다** (FR-032).
조용히 다른 번호를 주면 실패다.

**버리기** — 녹화를 시작했다가 저장하지 않고 버린다. 초안이 그대로 남아야 한다 (FR-033).

**AI 가 막힐 때** — 기존과 똑같이 사람이 이어받을 수 있어야 하고, 그렇게 완성한 테스트는
손으로 만든 것과 저장 형식이 같아야 한다 (FR-034).

### 이야기 4 — 엑셀에서 새 프로젝트 (US2 후반)

1. 프로젝트를 모두 닫고 프로젝트 목록 화면으로 간다
2. 「엑셀에서 새 프로젝트」 → 파일 선택
3. 프로젝트 이름(파일 이름이 기본값으로 채워져 있어야 한다)·시작 URL·저장 위치를 입력
4. 확정하면 새 프로젝트가 만들어지고 **그 프로젝트가 열린 상태**가 된다

**실패 시** — 도중에 실패를 만들면 만들다 만 프로젝트가 남지 않아야 하고,
프로젝트 목록에도 나타나지 않아야 한다 (FR-014c).

## 3. 회귀 — 이 기능이 깨뜨리지 말아야 할 것

| # | 확인 | 왜 |
|---|---|---|
| 1 | **기존 프로젝트가 그대로 열리고 테스트가 그대로 읽힌다** | `Test` 에 필드를 더했다. 옛 파일에 그 필드가 없어도 읽혀야 한다 (research R11). **이것을 가장 먼저 한다** |
| 2 | 저장된 테스트를 실행하면 결과가 전과 같다 | 재생 경로를 건드리지 않았다 (원칙 II) |
| 3 | 「번호 정리」가 전과 같이 동작한다 | `MAX_TEST_NUMBER` 리팩터가 닿은 곳이다. 초안이 있는 상태에서도 돌려 본다 |
| 4 | 초안이 있는 상태에서 새 테스트를 만들면 번호가 겹치지 않는다 | 초안은 번호를 예약하지 않는다 (FR-032) |
| 5 | 그룹 만들기·이름 바꾸기·없애기가 전과 같다 | 가져오기가 같은 그룹 구조를 쓴다 |
| 6 | 복수 삭제·그룹 이동이 전과 같다 | `test_moves.run_all` 을 함께 쓴다 |
| 7 | 「Playwright 로 내보내기」 버튼이 여전히 비활성이고 사유가 붙어 있다 | 릴리스 게이트 RG-1 은 이 기능이 해소하지 않는다. 두 「내보내기」가 헷갈리지 않아야 한다 |
| 8 | 세션 파일 업로드가 전과 같다 | 새 업로드 경로가 기존 것을 건드리지 않는다 |

## 4. 사람이 판정해야 하는 것

아래는 자동 검사가 대신할 수 없다. `docs/PENDING-HUMAN-VERIFICATION.md` 에 등록한다.

- 내보낸 파일을 **엑셀·구글 시트·LibreOffice 세 도구로 각각 열어** 별도 변환 없이 표로 읽히는가 (SC-003)
- 결과 칸의 서식이 통과·실패·미실행을 눈으로 구분되게 하는가 (US4)
- 열 너비가 내용에 맞아 「수행 절차」의 여러 줄이 읽을 만한가 (US4)
- 미리보기가 시트 수십 개일 때도 읽히는가
- 지시문 미리 채우기의 문장이 AI 가 이해할 만한 형태인가 (실제 녹화 성공률로 판단)
