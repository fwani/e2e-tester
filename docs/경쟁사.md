BrowserStack은 이미 Recorder, 자연어 Step 생성, 자연어 Test Case 자동화, 편집, self-healing까지 상당 부분 갖추고 있습니다. ### 경쟁 포지션을 단순화하면

| 제품 | 가장 강한 영역 |
|---|---|
| **Playwright** | 개발자 중심 E2E 자동화 엔진 |
| **Promptwright** | 자연어/Recording → 실행 가능한 테스트 코드 |
| **BrowserStack** | **완성형 Enterprise Low-code Testing Platform** |
| **제안 제품** | **Human + AI Interactive Test Authoring** |

여기서 중요한 건 **BrowserStack과 기능 개수로 경쟁하면 불리하다**는 겁니다.

BrowserStack은 이미 recorder가 click, input뿐 아니라 iframe, Shadow DOM, multiple tab, drag & drop, canvas 등 상당히 넓은 interaction을 지원하고, Cloud 실행, 실제 디바이스, reporting, self-healing까지 가지고 있습니다.  [oai_citation:3‡BrowserStack](https://www.browserstack.com/docs/low-code-automation/test-recording/record-actions?utm_source=chatgpt.com)

따라서 우리 제품의 경쟁 포인트는 기능의 **폭**이 아니라 테스트를 만드는 **경험**이어야 합니다.

### 가장 중요한 차별점

예를 들어 BrowserStack도 현재 자연어로:

> `"프로젝트를 생성하고 삭제해"`

같은 작업을 테스트로 자동화할 수 있고, Agentic Testing에서는 자연어 요구사항 → Test Case → 실제 Browser 자동화 → 검증 → 실패 시 healing까지 수행합니다. 다만 Agentic Testing은 현재 Alpha입니다.  [oai_citation:4‡BrowserStack](https://www.browserstack.com/docs/low-code-automation/test-recording/browserstack-ai/agentic-testing?utm_source=chatgpt.com)

우리는 UX를 다르게 가져가는 겁니다.

```text
                 테스트 작성 시작

             ┌────────┴────────┐
             ▼                 ▼
           Human               AI
          Recording       자연어 수행
             │                 │
             └────────┬────────┘
                      ▼
                  Test Step
                      │
                ▶ 실행하면서
                      │
                      ▼
                   PAUSE
                      │
          ┌───────────┼───────────┐
          ▼           ▼           ▼
        삭제         Human         AI
                     수정        "이거 해줘"
          │           │           │
          └───────────┼───────────┘
                      ▼
                   RESUME
                      │
                      ▼
                 테스트 완성
                      │
                      ▼
             Deterministic Test
                      │
                      ▼
                 Playwright
```

즉 **AI가 테스트를 대신 만들어주는 제품**보다는,

> **AI와 사람이 하나의 살아있는 Browser Session을 공유하면서 테스트를 함께 작성하는 제품**

으로 정의하는 게 좋습니다.

특히 `Pause → 현재 상태 유지 → Human/AI Takeover → 수정 → Resume`이 실제로 매끄럽게 구현된다면 이게 PRD에서 **Primary Differentiator**가 되어야 합니다.

그리고 두 번째 차별점은 **AI를 Authoring에 쓰되 Replay에서는 제거하는 것**입니다. BrowserStack의 AI Interaction은 replay 시에도 AI가 prompt를 다시 해석하는 반면, 제안 제품은 성공한 AI 행동을 가능한 한 deterministic Playwright Step으로 compile한다는 철학입니다.  [oai_citation:5‡BrowserStack](https://www.browserstack.com/docs/low-code-automation/test-recording/browserstack-ai/ai-interactions?utm_source=chatgpt.com)

그래서 PRD 경쟁 전략을 한 문장으로 쓰면:

> **BrowserStack이 "AI가 테스트 자동화를 대신 수행하는 플랫폼"이라면, 본 제품은 "사람과 AI가 실시간으로 테스트를 함께 작성하고 수정하며, 그 결과를 재현 가능한 Playwright 테스트 자산으로 만드는 Interactive Test IDE"를 지향한다.**

이 포지션이면 앞서 만든 PRD의 **3번 Interactive Edit가 부가기능이 아니라 제품의 핵심**이 됩니다.
