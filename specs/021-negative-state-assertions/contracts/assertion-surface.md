# Contract: 검증 표면

**Feature**: 021 | **권위 정의**: [data-model.md §2](../data-model.md)

검증 조건이 드러나는 네 표면의 계약이다. **§2 의 형태 규칙이 유일한 출처**이고, 아래 넷은
그것을 옮겨 적지 않고 **그대로 위임한다.** 규칙을 복제하는 표면이 생기면 둘이 갈릴 때
어느 쪽이 맞는지 판단할 수 없다.

---

## 1. 도메인 (권위)

검증 조건의 형태 검사는 도메인 모델 한 곳에서 한다. 나머지 표면은 자기 검사를 따로 갖지
않고 이 검사의 오류를 사용자 문구로 옮기기만 한다.

**불변식**

- 부정 비교(`not_equals` · `not_contains`)는 `text` · `url` 에서만 유효하다
- 부정 비교에는 비어 있지 않은 비교 값이 필요하다
- `enabled` · `disabled` 는 대상이 필수이고 비교 값을 갖지 않는다
- 기존 두 비교 방식(`equals` · `contains`)의 허용 범위는 **변경하지 않는다**

---

## 2. HTTP API — 검증 Step 추가

기존 엔드포인트를 그대로 쓴다. **새 엔드포인트를 만들지 않는다.**

요청 본문의 종류·비교 방식 필드는 도메인 열거형을 그대로 참조하므로, 도메인에 값을 더하면
API 가 함께 넓어진다. 손으로 옮겨 적는 목록을 API 계층에 두지 않는다.

| 상황 | 응답 |
|---|---|
| 형태 규칙 위반 | 400. 도메인 검사 메시지를 사용자 문구로 옮긴다 |
| 대상 요소를 찾지 못함 | 400. **Step 을 만들지 않는다** (기존 규칙 유지) |
| 상태 검증인데 대상이 조작 가능 여부를 가질 수 없는 요소 | 201. **Step 은 만들고 경고를 함께 싣는다** ([data-model §5](../data-model.md)) |

## 3. 작성 도구 (AI 경로)

**도구를 늘리지 않는다.** 도구 표면은 계약이고(`TOOL_NAMES` 16종 · `STEP_PRODUCING_TOOLS`
9종), 검증 종류가 늘었다고 도구가 늘면 Step 종류와의 1:1 대응이 깨진다. 새 어휘는 기존
검증 도구의 **인자 값**으로 들어간다.

**도구 설명에 반영할 것**

- 종류 목록에 `enabled` · `disabled` 추가
- 비교 방식에 `not_equals` · `not_contains` 추가
- 값을 쓰지 않는 종류에 부정 비교를 줄 수 없다는 제약

**작성 지침(시스템 프롬프트)에 반영할 것**

020 이 「기대와 달라도 기록하고 값을 바꾸어 다시 시도하지 마라」를 넣은 자리에, 부정
검증에 대한 같은 취지의 문장을 더한다.

> 부정 검증이 통과하지 않는다고 **조건을 긍정형으로 뒤집지 마라.** 「`오류` 가 없어야 한다」가
> 실패했다면 그것은 결함 후보이지 조건이 틀린 것이 아니다.

이 문장이 없으면 020 이 막은 것과 같은 일이 부정형에서 되풀이된다 — 모델에게는 조건을
뒤집어 통과시키는 것이 가장 쉬운 길이다.

## 4. 화면

### 4.1 검증 추가 폼

- 종류 6개를 한국어 문구와 짧은 설명으로 보인다. **비활성 항목을 두지 않는다** — 범위 외
  기능을 회색으로 보여 주는 것은 「곧 생긴다」는 약속처럼 읽힌다
- 비교 방식 4개는 값을 쓰는 종류를 골랐을 때만 나타난다
- **부정 비교를 고르면 한계를 함께 보인다** (FR-026): 조건이 참이 되면 즉시 통과하므로
  늦게 나타나는 것을 놓칠 수 있고, 먼저 화면이 안정되었음을 확인하는 검증을 앞에 두는 것이
  좋다는 안내

### 4.2 Step 목록 요약 — **선결 조건**

지금 요약은 종류를 영문 원문으로 찍고 비교 방식을 보이지 않는다. 그대로 두고 부정형을
노출하면 **「`오류` 가 있어야 한다」와 「`오류` 가 없어야 한다」가 목록에서 똑같이 보인다.**

| | 지금 | 되어야 하는 것 |
|---|---|---|
| 종류 | `text` | 텍스트 |
| 비교 방식 | 표시 없음 | 포함하지 않음 |
| 예 | `text 오류` | 텍스트가 `오류` 를 포함하지 않음 |

한국어 문구는 한곳에 모아 두고 폼·목록·상세가 같은 출처를 읽는다. 세 곳이 각자 문구를
만들면 같은 검증이 화면마다 다르게 불린다.
