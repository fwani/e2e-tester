# 계약 — 실행과 결과의 변화 (020)

**적용 범위**: `itb.execution.runner` · `itb.domain.run_result` · 결과 화면.

---

## 1. 실행 중단 규칙 — 무엇이 멈추고 무엇이 멈추지 않는가

`Runner.run_step()` 의 반환값은 **「계속 진행할지」**다 (001 FR-049). 020 은 그 판단을
Step 종류로 가른다.

| Step 종류 | 결과 | 반환 | `failed_index` | 뒤 Step |
|---|---|---|---|---|
| 검증 (`assertion`) | 실패 | **`True` (계속)** | **설정 안 함** | 실행된다 |
| 검증 | 통과 | `True` | — | 실행된다 |
| 동작 (그 외 8종) | 실패 | `False` (중단) | 설정 | `NOT_RUN` |
| 동작 | 통과 | `True` | — | 실행된다 |

**`failed_index` 를 설정하지 않는 것이 계약의 핵심이다.** 그 값의 뜻은 「실패한 Step」이
아니라 **「실행이 멈춘 자리」**이며, 재시도·건너뛰기·인수 UI 가 그 자리를 근거로 동작한다.
검증 실패는 멈추지 않으므로 멈춘 자리가 아니다. 설정하면 여러 검증이 실패할 때 마지막
것이 「멈춘 자리」가 되어 재시도가 엉뚱한 곳으로 간다.

`_failure_tab` 도 같은 이유로 설정하지 않는다.

### 바뀌지 않는 것

- `step_failed` · `step_finished` 이벤트는 검증 실패에서도 지금과 같이 나간다.
- 화면 캡처는 지금과 같이 찍힌다.
- 중지 요청·일시정지·세션 유실 처리는 그대로다. **계속 진행 규칙이 중지를 무시하지
  않는다** (US6 AS-5) — 중지는 루프 본문이 Step 사이에서 보고, 계속 진행은 Step 하나의
  결과일 뿐이다.

## 2. 결말 판정 — 변경 없음

`decide_outcome()` 은 **한 글자도 바뀌지 않는다.**

```
1. 세션 유실   → FAIL
2. 중지 요청   → STOPPED
3. 실패 건너뜀 → PARTIAL_PASS
4. FAIL 있음   → FAIL        ← 검증 실패가 여기 걸린다
5. 그 외       → PASS
```

FR-036(검증 실패로 계속 진행해도 결말은 실패)은 4번 규칙으로 **자동 충족**된다.
`Outcome` enum 에 값을 더하지 않는다 (FR-021).

---

## 3. 검증 실패의 분류

### 순수 함수

```
classify_assertion(step: Step, result: StepResult) -> AssertionClass | None
counts_by_class(steps: list[Step], results: list[StepResult]) -> dict[AssertionClass, int]
```

판정표는 [data-model.md §3](../data-model.md) 에 있다.

**저장**: `StepResult.assertion_class` 에 넣는다. 결과 파일만으로 분류를 읽을 수 있어야
한다 — 정의가 나중에 바뀌어도 어제 실행의 분류는 그때의 사실이어야 한다.

**집계**: 저장하지 않고 그때그때 센다.

## 4. 결과 화면의 제시 규칙 (FR-019·FR-020·FR-022)

| 분류 | 순서 | 강조 |
|---|---|---|
| `regression` | **맨 위** | 가장 강하게 — 오늘 새로 깨진 것 |
| `known_defect` | 그 다음 | 약하게 — 이미 아는 것 |
| `resolved` | 안내로 | 「표시를 걷어낼 수 있습니다」 |

요약줄 예:

```
실패 3건 — 회귀 1 · 알려진 결함 2      해소 1건
```

**0건인 분류는 싣지 않는다.** 없는 것을 0으로 표시하면 읽을 것이 늘기만 한다 (FR-013 과
같은 판단).

---

## 5. Step 화면의 표시 (FR-014·FR-015)

| 자리 | 표시 |
|---|---|
| Step 목록 행 | 결함 후보임을 나타내는 칩. `Badges.tsx` 의 `.chip` 변형을 쓴다 — 새 시각 요소를 만들지 않는다 (008 확정 디자인) |
| Step 상세 | 기대값(`assertion.value`)과 작성 시점 관찰값(`mismatch.observed`)을 나란히. 잘린 경우 그 사실을 표시 |
| Step 상세 | 표시를 걷어내는 조작 (FR-027) |

**민감값**: `mismatch.observed` 는 저장 시점에 이미 스크러빙됐다. 화면이 다시 거르지
않는다 — 거르는 곳이 둘이면 어느 쪽이 기준인지 말할 수 없다.

---

## 6. 호환

| 읽는 대상 | 020 이전 데이터 | 동작 |
|---|---|---|
| 테스트 정의 | `mismatch` 필드 없음 | `None` — 작성 시점 통과로 다룬다 |
| 실행 결과 | `assertion_class` 필드 없음 | `None` — 분류 없음으로 표시 |
| 공유 번들 | 같음 | 같음 |

**마이그레이션이 없다.** 필드 기본값이 호환을 만든다.
