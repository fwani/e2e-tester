# 005 재검증 진행 대본 (T124·T125)

Phase 12 가 재점검 11건을 닫은 뒤 **다시 걸어** SC-221 을 확정하는 절차다.

**자동 테스트로 대체할 수 없다.** 그 근거는 추측이 아니라 이번에 관측된 것이다 —
T121(「실패한 Step 건너뛰고 계속」)은 계약(`contracts/ui-contract.md` §6-5)과 백엔드
(`skip_failed`)와 통합 테스트(`test_resume_with_failed_step.py`)가 **모두 통과하는 상태에서
화면 절반이 없었다.** 자동 검증은 양쪽 끝을 보고 그 사이의 전선은 보지 않았고, 그것은 사람이
걸어야 드러났다. N-01(새로고침 상태 유실)도 같았다 — 변환 함수 테스트는 초록이었고 변환은
처음부터 옳았다.

> **판정은 이 문서에 들어 있지 않다.** 아래 기록 자리는 비어 있고, 채우는 것은 사람이 한다.

준비물

- 대상 앱: `fixtures/sample-app` (`quickstart.md` §0)
- 자동 검증이 통과 상태여야 한다 — 깨진 채로 걸으면 제품의 UX 가 아니라 결함을 재게 된다
  ```bash
  cd backend && uv run pytest
  cd frontend && npx tsc --noEmit && npx vitest run
  ```
- 기록 시트: [recheck-sheet-005.csv](recheck-sheet-005.csv)
- 비교 기준: [ux-recheck-005.md](ux-recheck-005.md) (직전 관측), [ux-walkthrough-2026-09-07.md](ux-walkthrough-2026-09-07.md) (원 리포트 22건)

## 0. 세션 전 (1회)

1. 깨끗한 프로젝트에서 시작한다. 앞선 세션이 남긴 `.runs/`·저장된 테스트가 있으면 화면이
   다른 것을 보여 주고, 그 차이가 있지도 않은 결함처럼 보인다.
2. 브라우저 창을 하나만 둔다. 두 창에서 같은 세션을 보면 어느 화면의 관측인지 흐려진다.
3. **화면을 캡처한다.** 판정의 근거가 문장뿐이면 다음 사람이 재확인할 수 없다.
   `docs/ux/shots/<날짜>-recheck2/` 에 넣고 시트의 `shot` 열에 파일명을 적는다.

## 1. T124 — 「상」 9건 재확인 (SC-221)

[quickstart.md](../../specs/005-ux-walkthrough-repair/quickstart.md) §2 의 **S1~S8 을 순서대로**
걷는다. 각 U 번호마다 아래 셋 중 하나로 판정한다.

| 판정 | 뜻 |
|---|---|
| `해소` | 원 리포트의 증상이 없고, 그 자리에 요구된 것이 있다 |
| `부분` | 핵심 증상은 없으나 곁가지 문구·잔여 UI 가 남았다 |
| `재발` | 원 리포트의 증상이 그대로 있다 |

**`부분` 도 조용히 넘기지 않는다.** 직전 재점검의 2건이 그 판정이었고, 그것을 등록했기
때문에 Phase 12 가 존재한다 (quickstart §4).

### Phase 12 가 손댄 곳 — 여기를 특히 본다

| U 번호 | 직전 관측 | 이번에 확인할 것 |
|---|---|---|
| **U-03-a** | 부분 — 재실행 세션 제목이 「TC-001 초안」 | 재실행하다 중지한 화면의 제목이 「TC-001 · 저장됨」인지. 그 화면에 **이름 입력칸과 「저장」이 없는지**. 다음 행동이 **네 개**(결과 자세히 보기 · 처음부터 실행 · Step nn부터 실행 · 목록으로)인지 |
| **U-03-b** | 부분 — 종료 세션 404 3건이 오류 배너로, 배너에 세션 UUID | 중지 직후 **붉은 배너가 뜨지 않는지**. 개발자 도구 네트워크 탭에서 종료 후 `GET /api/sessions/*/tabs` 요청이 **0건**인지 |
| **U-04-a** | 부분 — 실행 종료 후에도 「…아직 실행 중입니다」 | Step 하나가 10초를 넘겨 그 안내가 뜬 뒤, 실행이 끝나면 **그 문장이 사라지는지** |
| **U-04-b** | 부분 — 미러 오버레이가 전이 중·종료 후에도 「일시정지」를 단정 | 전이 중에는 「일시정지 중…」, 실행 종료 후에는 「실행 종료」인지. **배지와 오버레이가 같은 말을 하는지** |
| **U-04-c** | 부분 — 「멈추기 전에 실행이 끝났습니다」에 요약 한 줄만 | 그 화면에 **실패 사유**와 **「결과 자세히 보기」** 가 있는지. 같은 요약이 **두 번 나오지 않는지**(T123) |

### 재점검이 새로 찾은 것 — 함께 본다

| N 번호 | 확인할 것 |
|---|---|
| **N-01** | 결과 화면(`?screen=result&test=…`)에서 F5 → 같은 화면·같은 주소인지. 뒤로가기가 앱을 벗어나지 않는지 |
| **N-02** | 실행이 끝난 뒤 목록 행의 칩이 `RUNNING` 이 아니라 저장된 결말(`FAIL` 등)인지. **배너와 행이 같은 말을 하는지**. 그 행에 「결과 보기」가 있는지 |
| **N-03** | **통과한** 실행의 SCREENSHOT 탭이 「불러올 수 없습니다」가 아니라 긍정문인지 |
| **N-06** | Step 5개를 녹화하고 멈추면 부제가 「Step 05 이후 정지」인지 (「Step 06」이면 실패) |

> N-01·N-02·N-03·N-06 은 자동 검증이 함께 지킨다
> (`test_ui_state_restore.py` · `RecheckPhase12.test.tsx`). 그래도 사람이 보는 이유는 자동
> 검증이 **그 조건**을 보고 사람이 **그 화면**을 보기 때문이다 — N-01 이 그 차이로 살아남았다.

## 2. T125 — 「부분 성공」 결말 관측 (FR-137 · quickstart S3-6)

직전 재점검은 이 항목을 **「미검증」** 으로 남겼다. 사유는 "UI 컨트롤이 없어 경로에 도달
불가" 였고 T121 이 그 컨트롤을 만들었다. 그러나 **결말을 제품을 통해 관측한 적은 아직 없다.**

quickstart §3 의 5~6 을 걷는다.

1. TC-FAIL 을 실행해 Step 06 에서 실패시킨다.
2. Step 05 통과 후 「일시정지」를 눌러 정지를 **성립**시킨다.
3. 「계속하기」가 **비활성**이고 옆에 이유가 있는지 본다 (FR-136).
4. 그 옆의 **「실패한 Step 건너뛰고 계속」** 을 찾는다. 보조 문구가 건너뛰는 Step 과
   **결말이 「부분 성공」이 된다는 사실**을 미리 말하는지 본다.
5. 누른다 → 실행이 끝난다.
6. **결말을 세 곳에서 확인한다.** 하나만 보면 화면 한 곳만 고쳐진 상태를 통과시킨다 —
   이것이 U-20 이었다.

   | 자리 | 기대 |
   |---|---|
   | 실행 화면 결말 표시 | 「부분 성공」 |
   | 목록 행 칩 | `PARTIAL` |
   | 결과 화면 요약 | 「부분 성공 · Step 06 건너뜀 · … 통과」 |
   | 저장된 결과 파일 | `.runs/<테스트ID>/result.json` 의 `"outcome": "partial_pass"` |

   마지막 줄이 요구사항의 실제 기준이다 (data-model.md §1). 화면 셋이 맞고 파일이
   다르면 화면이 거짓말하는 것이고, 파일이 맞고 화면이 다르면 005 가 없애려던 어긋남이다.

7. **결말이 `완료`(pass)로 기록되면 실패다** (FR-137). 그것이 U-05 였다.

## 3. 세션 후

1. 시트를 채운다. **비운 칸을 「해소」로 읽지 않는다** — 걷지 못한 항목은 `미검증` 과
   사유를 적는다.
2. `재발`·`부분` 이 하나라도 있으면 [ux-recheck-005.md](ux-recheck-005.md) 형식으로 관측을
   적고, U/N 번호를 들어 `tasks.md` 에 남은 작업으로 등록한다 (quickstart §4).
3. 전부 `해소` 면 SC-221 을 충족으로 기록하고, T124·T125 를 `[X]` 로 닫는다.
4. 결과와 무관하게 **관측 문서를 남긴다.** "전부 통과했다" 만 적힌 커밋은 다음 사람이
   무엇을 걸었는지 알 수 없게 한다.
