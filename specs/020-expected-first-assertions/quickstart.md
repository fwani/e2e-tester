# Quickstart — 020 기대 동작 기준 검증을 직접 확인하는 법

**목적**: 이 기능이 실제로 동작하는지 사람이 손으로 확인하는 순서. 자동 검증은
tasks.md 가 만든다.

---

## 0. 사전 준비

```bash
cd backend && uv sync
cd ../frontend && npm install
```

`ITB_AI_DRIVER` 는 **설정하지 않는다** — 기본 경로(Messages API)가 제품 동작이다.
자격 증명 없이 확인하려면 §4 의 대체 경로를 쓴다.

---

## 1. 고정 대상 준비 — 「결함이 있는 화면」

`fixtures/sample-app` 에 **지시문과 다른 값을 내놓는 화면**을 더한다. 기존 고정 대상은
전부 「정상 동작」을 전제로 만들어져 있어 이 기능을 확인할 수 없다.

필요한 것 하나: 저장 버튼을 누르면 `저장되었습니다` 가 아니라 **`처리 완료`** 가 뜨는 폼.

```bash
cd backend && uv run python ../fixtures/sample-app/serve.py
```

> 이 고정 대상은 **제품이 아니라 테스트 대상**이다. 고치면 안 되는 제품 코드가 아니다
> (`tests/abnormal/boundary_context.py` 의 선례와 같다).

---

## 2. AI 작성 — 기대값이 지켜지는지 (US1)

1. 제품을 띄우고 새 테스트를 만든다.
2. AI 작성에 다음 지시문을 준다.

   > 저장 폼으로 가서 이름에 `가나다` 를 넣고 저장을 누른다.
   > **`저장되었습니다` 문구가 뜨는지 확인한다.**
   > 그 뒤 목록으로 돌아가 방금 만든 항목이 보이는지 확인한다.

3. **확인할 것**

   | | 기대 | 지금(020 이전) |
   |---|---|---|
   | 검증 Step 의 기대값 | `저장되었습니다` | `처리 완료` ← 버그 박제 |
   | 그 Step 의 표시 | 결함 후보 | — |
   | 작성의 결말 | 끝까지 수행하고 완료 | 막힘 또는 버그값으로 완료 |
   | 세션 종료 알림 | 「검증 1건이 통과하지 않았습니다」 | 없음 |

4. Step 상세를 연다. **기대값 `저장되었습니다` 와 관찰값 `처리 완료` 가 함께 보여야 한다.**

---

## 3. 재실행 — 끝까지 도는지 · 분류되는지 (US3·US6)

1. §2 에서 만든 테스트를 저장하고 재실행한다.
2. **확인할 것**

   | | 기대 | 지금(020 이전) |
   |---|---|---|
   | 검증 Step 이후의 Step | **실행된다** | `실행 안 함` ← 거기서 멈춘다 |
   | 그 검증의 분류 | 알려진 결함 | 분류 없음 |
   | 실행 결말 | 실패 | 실패 |

3. 고정 대상을 고쳐 `저장되었습니다` 가 뜨게 한 뒤 다시 실행한다.
   → 그 검증이 **해소됨**으로 표시되고, 표시를 걷어내라는 안내가 보인다 (FR-022).

4. Step 상세에서 표시를 걷어낸다. 고정 대상을 다시 되돌려 실행한다.
   → 같은 실패가 이번에는 **회귀**로 분류된다 (FR-027 · US5).

---

## 4. 자격 증명 없이 확인하기

AI 경로 전체는 드라이버를 갈아 끼워 확인할 수 있다 (`backend/tests/us4_support.py` 의 선례).
`_sdk_driver` 전역을 대체해 「이 도구를 이 순서로 부른다」를 고정한 뒤, 도구 반환값과
기록된 Step 을 확인한다.

§3 의 재실행·분류는 **AI 가 전혀 필요 없다.** 손으로 만든 검증 Step 에 `mismatch` 를
넣은 정의로 확인된다 — 헌법 원칙 I 상 사람이 만든 것과 AI 가 만든 것이 같기 때문이다.

## 5. 자동 검증

```bash
# 백엔드 전량 (병렬 + 타이밍 계층)
backend/scripts/test-backend.sh

# 브라우저 계층 제외한 빠른 루프
cd backend && uv run pytest -m "not browser and not timing"

# 프론트엔드
cd frontend && npm run typecheck && npm test
```

**스키마를 바꾼 뒤에는 반드시 재생성한다.**

```bash
cd backend && uv run python -m itb.schema.export
cd ../frontend && npm run gen:types
```

재생성하지 않으면 프론트엔드가 새 필드를 모른 채 타입 검사를 통과한다 — 헌법의
Cross-language schema duty 가 깨지는 지점이다.

## 6. 확인해야 할 불변식 (사람이 눈으로)

| # | 확인 | 어디서 |
|---|---|---|
| 1 | 동작 Step 실패는 여전히 기록되지 않고 실행을 멈춘다 | 존재하지 않는 버튼을 누르라는 지시 |
| 2 | 내보낸 Playwright 테스트가 같은 검증에서 실패한다 | 내보내기 → `npx playwright test` |
| 3 | 공유 내보내기·가져오기 후 결함 후보 표시가 남는다 | 번들 왕복 |
| 4 | 제품 동작 불일치 막힘에 답변 칸이 열리지 않는다 | 지시문이 요구한 전이가 일어나지 않는 고정 대상 |
| 5 | 민감 값이 관찰값으로 새지 않는다 | 비밀번호 칸을 대상으로 한 검증 |
