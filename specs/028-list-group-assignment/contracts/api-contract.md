# API Contract — 028

**대상**: [../spec.md](../spec.md) · [../data-model.md](../data-model.md)

**새 엔드포인트는 없다.** 이 기능은 기존 계약의 **값 제약**을 넓히고, 화면이 기존
엔드포인트를 이어 부르는 방식을 정한다.

---

## 1. 접두어를 받는 모든 자리 (제약 변경)

| 자리 | 지금 | 이후 |
|---|---|---|
| `POST /api/groups` 의 `prefix` | `pattern=^[A-Z][A-Z0-9]{0,7}$` | 새 패턴 + `max_length=12` |
| `POST /api/tests/move` 의 `to_prefix` | 같음 | 같음 |
| 세션 저장 요청의 `group` | 같음 | 같음 |
| 엑셀 들여오기의 시트 접두어 검증 | `validate_prefix()` | 같은 규칙으로 판정 |
| 공유 받기의 자동 생성 접두어 | 새 값을 만들어 냄 | 만들어 낸 값도 새 규칙을 만족해야 한다 (FR-012) |

**거부 응답은 형태가 바뀌지 않는다.** 규칙을 어긴 값은 지금처럼 422(스키마 검증) 또는
`GROUP_PREFIX_RESERVED`(예약어)로 거절된다. 사람이 읽는 문구만 하이픈을 쓸 수 있다는
사실을 담도록 고친다 (FR-006).

## 2. 「새 그룹으로 옮기기」의 호출 순서 (화면 규약)

```
1. POST /api/groups          { prefix, name }
2. POST /api/tests/move      { test_ids, to_prefix: prefix }
```

- 1이 실패하면 2를 부르지 않는다. 사용자가 보는 것은 그룹 만들기 실패다.
- 2가 실패하면 **1의 결과를 되돌리지 않는다.** 빈 그룹이 남고, 그 사실을 알린다 (FR-026).
  되돌리면 사용자가 방금 지은 이름을 다시 쳐야 한다 — 빈 그룹보다 나쁜 결과다.
- 2는 이미 전부 되거나 전부 안 되거나를 지킨다. 따라서 「셋 중 둘만」은 생기지 않는다.

## 3. 목록 응답 (변화 없음)

`GET /api/tests` 의 `groups` 와 각 행의 접두어는 형태가 그대로다. 접두어 문자열에
하이픈이 포함될 수 있다는 점만 달라진다. 화면은 접두어를 **문자열로만** 다루어야 하고,
접두어에서 그룹을 추측하려고 식별자를 자르지 않는다.

## 4. 하위 호환

- 옛 규칙으로 만들어진 접두어·식별자·파일 이름은 전부 새 규칙 아래에서 유효하다.
- 저장된 프로젝트 파일(`project.yaml`)에 버전 표시를 더하지 않는다.
- 변환 단계를 두지 않는다 (FR-011).
