# 검증 안내: Step 조작 흐름

**기능**: `009-step-editing-flow` | **작성**: 2026-09-08

이 문서는 **이 기능이 동작함을 증명하는 절차**다. 구현 코드는 담지 않는다.

---

## 준비

```bash
# 백엔드
cd backend && uv sync

# 프론트엔드
cd frontend && npm install

# 스키마·타입 재생성 (ManualStepSpec 이 추가되므로 반드시 한다)
cd backend && uv run python -m itb.schema.export
cd ../frontend && npm run gen:types
```

대상 앱은 `fixtures/sample-app/` 를 쓴다 — **녹화 대상 재료이며 이 기능의 평가 대상이
아니다.**

---

## 기계 검증

```bash
# 1. 스키마 드리프트 — ManualStepSpec 스키마가 커밋된 것과 같은가
cd backend && uv run python -m itb.schema.export --check

# 2. 임포트 경계 — domain 이 다른 계층을 임포트하지 않는가 (원칙 I·II·IV)
cd backend && uv run lint-imports

# 3. 백엔드 정적 검사와 테스트 (브라우저·시간 의존 테스트는 CI 와 같게 나눠 돈다)
cd backend && uv run ruff check .
cd backend && uv run pytest -m "not browser and not timing" -q
cd backend && uv run pytest -m "browser and not timing" -q -n 2

# 4. 프론트엔드 타입·테스트
cd frontend && npm run typecheck && npm test -- --run

# 5. 시각 언어 정본 — 18장 시트가 글자 하나까지 같은가
python3 scripts/extract_canon.py --check

# 6. 정본 소비 — 화면 코드가 하드코딩 값을 쓰지 않는가
cd frontend && node scripts/count-violations.mjs
```

**2번이 실패하면 R1 의 결정이 깨진 것이다** — `itb/domain/manual_step.py` 가 domain 밖을
임포트하고 있다.

**5번이 실패하면 `.srow` 격자를 18장 중 일부에만 고친 것이다.** 계약 §6 의 순서를 따른다.

## US1 — 브라우저를 열지 않고 넣는다 (SC-501)

### 1-1. 화면에서

1. 백엔드와 프론트엔드를 띄운다
2. 테스트 목록에서 Step 이 5개 이상인 테스트의 「고치기」를 누른다
3. **브라우저를 열지 않는다**
4. 3번 Step 행의 「이 앞에 추가」를 누른다
5. 「주소로 이동」을 고르고 주소를 입력한다
6. 저장한다

**기대**

- 목록의 3번 자리에 새 Step 이 들어가고 이후 번호가 하나씩 밀린다
- 저장 전에는 그 행에 「미저장」 칩이 있다
- 조작 수가 **3회 이내**다 (「이 앞에 추가」 → 종류 고르기 → 넣기). 저장은 별도 조작이다
- 다시 열어도 그 자리에 있다

### 1-2. 요소가 필요한 종류

4단계에서 「클릭」을 찾는다.

**기대**: 자리에 **있고**, 비활성이며, 「요소는 살아 있는 화면에서만 지목합니다」와
「브라우저 열어 이 Step 앞에서 멈추기」로 가는 길이 함께 보인다. 감춰져 있으면 FR-287
위반이다.

### 1-3. 서버 계약

```bash
# 삽입 연산이 정의에 반영되는가
curl -s -X PUT localhost:8000/api/tests/<TEST_ID>/definition \
  -H 'content-type: application/json' \
  -d '{"revision":"<REV>","edits":[{"op":"insert","at":3,
       "spec":{"kind":"navigate","url":"http://localhost:5173/orders","tab":0}}]}'

# 요소를 요구하는 종류는 거절되는가 — 값이 오류에 실리지 않는지도 본다
curl -s -X PUT localhost:8000/api/tests/<TEST_ID>/definition \
  -H 'content-type: application/json' \
  -d '{"revision":"<REV>","edits":[{"op":"insert","at":0,
       "spec":{"kind":"click","value":"비밀번호1234"}}]}'
```

**기대**: 두 번째 요청은 `DEFINITION_INVALID` 로 거절되고, **응답 본문에
`비밀번호1234` 가 없다** (003 EC-005).

### 1-4. 일시정지 세션에서 (FR-290)

```bash
curl -s -X POST localhost:8000/api/sessions/<SID>/steps:manual \
  -H 'content-type: application/json' \
  -d '{"at":null,"spec":{"kind":"assert_url","url":"/done","match":"contains"}}'
```

**기대**: 일시정지 위치에 들어가고, 브라우저 화면은 **바뀌지 않는다**. 이어서 실행하면
그 Step 부터 수행된다.

## US2 — 「이 앞에 추가」 한 조작 (SC-502)

1. Step 이 10개 이상인 테스트의 「고치기」를 연다
2. 8번 Step 행의 「이 앞에 추가」 → 「브라우저 열어 이 Step 앞에서 멈추기」를 누른다
3. **그 뒤로 아무것도 누르지 않는다**

**기대**

- 미저장 변경이 있었다면 「먼저 저장합니다」가 **누르기 전에** 보였다
- 브라우저가 열리고 재생이 시작된다
- 재생 중 「Step 08 앞에서 멈춥니다 — 지금 Step 03」 형태로 목표와 현재가 함께 보인다
- 7번까지 수행한 뒤 8번 앞에서 멈춘다
- 도착 후 **직접 조작 녹화가 켜져 있고**, 「지금부터 브라우저 조작이 기록됩니다」가 보인다
- 브라우저에서 버튼 하나를 클릭하면 8번 자리에 클릭 Step 이 들어간다

### 2-1. 재연결에도 목표가 남는가 (FR-293)

재생 중 화면을 새로 고친다.

**기대**: 「Step 08 앞에서 멈춥니다」가 **그대로 있다**. 사라지면 목표를 화면 상태로만
들고 있는 것이며 R5 의 결정이 깨진 것이다.

### 2-2. 도달 전 실패 (FR-294)

일부러 실패하는 Step 이 목표 앞에 있는 테스트로 같은 조작을 한다.

**기대**: 실패한 자리에서 멈추고 「Step 08 에 도달하기 전에 Step 05 에서 실패했습니다」가
보인다. **「일시정지됨」만 말하면 위반이다** — 도달한 것과 구분되지 않는다.

### 2-3. 목표가 맨 앞 (FR-296)

1번 Step 앞에서 같은 조작을 한다.

**기대**: 브라우저가 시작 주소를 열고 첫 Step 앞에서 멈춘다. 재생 진행 표시는 나타나지
않거나 즉시 끝난다.

## US3 — 행에서 옮기고 지운다 (SC-503·SC-504·SC-505)

### 3-1. 조작 횟수

Step 10개 목록에서 5번을 8번 자리로 옮긴다.

**기대**: 5번 행의 「아래로」를 **세 번** 누른다. 다른 Step 을 고르는 일이 끼지 않는다.
편집 화면과 일시정지 화면 **양쪽에서** 같다.

### 3-2. 끝단 (FR-300)

첫 행의 「위로」와 마지막 행의 「아래로」를 본다.

**기대**: 자리에 **있고** 비활성이며 「맨 위입니다」·「맨 아래입니다」가 보인다.
해소 방법 링크는 **없다**.

### 3-3. 별도 패널이 없어졌는가 (SC-505)

일시정지 상태에서 순서를 바꾼다.

**기대**: Step 목록이 화면에 **하나만** 있다. 「순서 변경」 패널이 열리면 FR-301 위반이다.

### 3-4. 삭제 (SC-504)

행의 「지우기」를 누른다.

**기대**: 무엇이 지워지는지 확인한 뒤 지워진다. 조작이 **행 안에서 끝난다** — 화면 아래
팔레트로 내려가지 않는다. 확인을 거치지 않고 지워지면 FR-302 위반이다.

(횟수는 이전과 같은 2회다. 이 절이 보는 것은 **자리**와 **확인**이다 — `baseline.md` §2-2)

### 3-5. 키보드만으로 (SC-507)

Tab 과 Enter/Space 만으로 3-1 · 3-4 를 반복한다.

**기대**: 모든 행 조작에 도달하고, 접근 가능한 이름이 「〈이름〉 위로」·「〈이름〉 아래로」
형태다. 조작 순서가 화면 순서와 같다.

## 잠금과 회귀

### 4-1. 실행 중 (SC-508)

실행 중인 세션에서 행 조작과 「이 앞에 추가」를 본다.

**기대**: 전부 비활성이며 「일시정지하세요」로 가는 길이 있다. **활성으로 보이면 위반이다**
— 누르면 서버가 거절하는 경로를 만들지 않는다.

### 4-2. 결과 화면 (FR-297·FR-308)

결과 화면 목록을 본다.

**기대**: **행에는 칸 5 가 없고** 팔레트에 비활성으로 있으며 해소 방법이 「고치기」다 (계약 §3-3-1). 그것을 누르면 편집 화면이 열리고 **그
Step 이 이미 골라져 있다**.

### 4-3. 기존 추가 경로 (SC-509)

일시정지 상태에서 「직접 조작으로 Step 추가」·「자연어로 Step 추가」·「검증 추가」를 각각
쓴다.

**기대**: 자리·문구·동작이 이전과 같다. 하나라도 달라지면 FR-309 위반이다.

## 왕복 무결성 (SC-510)

```bash
cd backend && uv run pytest tests/integration -k manual_insert_roundtrip
```

이 테스트가 하는 일:

1. 저장된 테스트에 `insert` 로 주소 이동 Step 을 중간에 넣고 저장한다
2. `GET /definition` 으로 다시 읽어 그 자리에 있음을 확인한다
3. `replay` 로 돌려 그 Step 이 **실제로 수행됐음**을 확인한다

1·2 만 통과하면 「저장은 되지만 실행되지 않는 Step」을 놓친다 — 헌법 품질 게이트 2번이
3번을 요구하는 이유다.
