# 에이전트 도구 계약 — 026

**도구가 하나도 늘지 않는다.** 016 이 만든 `update_step`·`delete_step`·`move_step`·
`repick_target` 이 그대로 쓰인다. 바뀌는 것은 **그 도구가 무엇에 쓸 수 있는가**이고,
그것을 정하는 것은 코드와 **설명문 둘 다**이다.

---

## §1 권한 범위

```
고칠 수 있는 Step = 이번 세션이 만든 Step ∪ 사용자가 고쳐 달라고 지목한 Step
```

둘째 항은 **세션 시작 시 확정**되고 대화 중에 넓어지지 않는다 (FR-017). 사용자가 대화로
"4번도 고쳐 줘" 라고 해도 범위는 그대로이며, 모델은 거절을 받는다.

고른 Step 이 없는 세션에서는 둘째 항이 공집합이므로 **016 과 완전히 같다** (FR-014).

---

## §2 설명문 — **세 자리를 함께 고친다**

이 저장소에서 모델의 행동을 바꾸려면 세 자리를 같이 고쳐야 한다. 하나라도 빠지면 코드가
넓어져도 모델이 시도하지 않는다.

| # | 자리 | 성격 |
|---|---|---|
| 1 | `tools.py` 의 `TOOL_SCHEMAS` | **모델이 실제로 받는 설명문** — 원천 |
| 2 | `BrowserToolbox` 메서드 docstring | 사람이 읽는 설계 근거 |
| 3 | `agent.py` 의 `SYSTEM_PROMPT` | 전반 지침 |

### 고쳐야 할 문장

| 지금 | 뒤 |
|---|---|
| "**이번에 만든** Step 의 속성 하나를 고친다." | "이번에 만든 Step, **또는 사용자가 고쳐 달라고 지목한 Step** 의 속성 하나를 고친다." |
| "다른 Step 은 고칠 수 없다 — 사람에게 말하라." | "그 밖의 Step 은 고칠 수 없다. 사람에게 **어느 Step 을 고르면 되는지** 말하라." |

`delete_step`·`move_step`·`repick_target` 도 같은 모양으로 고친다.

### 거절문 (FR-016)

```
지금 고칠 수 있는 것은 step-03 (사용자가 지목) 과 이번에 만든 Step 입니다.
step-01 은 그 밖이므로 고칠 수 없습니다 — 사람에게 step-01 을 골라 다시
시작하도록 말하세요.
```

**무엇이 허용되는지 함께 말한다.** 지금 거절문은 「사람에게 말하세요」로 끝나는데, 그것만
받으면 모델은 같은 요청을 다시 시도하거나 엉뚱한 우회를 한다.

## §3 컨텍스트 (FR-011)

에이전트는 매 턴 「어느 Step 을 고치라고 요구받았는가」를 받는다. 016 이 재녹화 구간을
정의 요약에 표시한 것과 **같은 통로**다 (`build_definition_summary` 의 `range_ids`).

```
[지금 테스트]
  1. 로그인 화면 열기 …
  3. 저장 버튼 누르기 (click)   ← 고쳐 달라고 요구받은 Step
  …
```

민감 값은 변수 참조로만 나타난다 (FR-012 · FR-041).

## §4 바뀌지 않는 것

- **도구 표면 16종** — 늘지도 줄지도 않는다. `test_tool_surface.py` 가 고정한다.
- **Step 을 만드는 도구와 Step 종류의 1:1** — 편집 도구는 새 종류를 만들지 않는다 (016 FR-040).
- **`repick_target` 의 규칙** — 후보 묶음은 살아 있는 페이지에서 수집되고 모델이 셀렉터를 지어 넣을 수 없다 (원칙 IV).
- **막힘 보고** — `report_blocked` 그대로.
