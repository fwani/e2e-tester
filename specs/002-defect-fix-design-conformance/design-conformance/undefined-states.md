# 확정 디자인이 정의하지 않은 상태 기록

**요구사항**: DC-009 · 완료 판정 SC-110 (기록 없는 임의 결정 0건)

확정 디자인은 화면당 한 상태만 보여준다. 실제 동작에 필요한 나머지 상태(로딩·빈 목록·
오류·긴 목록·텍스트 넘침)는 구현자가 정해야 한다. **그 결정을 전부 여기 남긴다.**

`근거` 는 필수다. "가장 가까운 확정 디자인 표현을 따른다"(DC-009)를 지켰다는 증거가
근거 없이는 성립하지 않는다. **근거를 댈 수 없는 결정은 해석이고 DC-001 위반이다.**

| 화면 | 상태 | 근거 (어느 확정 디자인의 어느 표현) | 결정 |
|---|---|---|---|
| ProjectSetup | 로딩 | 확정 디자인에 대응 화면이 없다(DC-010). TestList.dc.html 의 흐린 텍스트 색 #9A968A 를 따랐다 | 「프로젝트를 찾는 중…」 을 흐린 색으로 표시 |
| ProjectSetup | 빈 목록 | 확정 디자인에 대응 화면이 없다(DC-010). 8화면의 카드 표현(#FFFDF6 + 3px 잉크 테두리)을 따랐다 | 무엇을 하면 되는지 두 갈래로 안내하는 카드 |
| ProjectSetup | 오류·경고 | 확정 디자인에 오류 배너가 없다. RunResult.dc.html 의 FAIL 색(#D9502F/#FBEEEA)과 경고 노랑(#F5D000/#FFF9D6)을 따랐다 | 화면 상단 배너. 계약 메시지를 그대로 표시 |
| ProjectSetup | 긴 경로 넘침 | 확정 디자인에 경로 표시가 없다. 모노 글꼴과 흐린 색만 따르고 넘침은 말줄임 | ellipsis + title 속성으로 전체 경로 제공 |
| TestList | 로딩 | 확정 디자인은 행이 있는 상태만 보여준다. 목록 테두리 안에 흐린 색(#9A968A) 텍스트로 넣었다 | 「불러오는 중…」 |
| TestList | 빈 목록 | 같음. 검색 결과 없음과 테스트 없음을 구분해야 사용자가 다음 행동을 안다 | 무엇을 하면 되는지 안내하는 한 줄 |
| TestList | 실행한 적 없는 테스트의 상태 칩 | 확정 디자인에 PASS·FAIL 두 상태만 있다. 같은 칩 형태(28px·2px 테두리)에 배경만 #EFEBE0 으로 | 「—」 칩 |
| TestList | `⋯` 메뉴의 내용 | 확정 디자인은 `⋯` 버튼만 그리고 열린 모습은 정의하지 않는다. 8화면의 카드 표현(3px 테두리 + 5px 하드 그림자)을 따랐다 | 정의 보기·이름·삭제 세 항목 |
| TestList | 삭제 확인 | 확정 디자인에 없다. 되돌릴 수 없는 조작이라 확인이 요구사항이다(FR-007). 실패 요약과 같은 자리에 #A83A22 로 | 행 안에서 확인. 어느 테스트인지 보면서 결정하게 한다 |
| TestList | 정의 파일 오류 배너 | 확정 디자인에 없다. 경고 노랑(#F5D000/#FFF9D6)을 따랐다 | 읽지 못한 파일 목록 |
