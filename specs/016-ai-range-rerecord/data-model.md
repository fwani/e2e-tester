# Data Model — 016 편집 중 AI 구간 재녹화

**Date**: 2026-09-11 | **Plan**: [plan.md](./plan.md) | **Research**: [research.md](./research.md)

**이 기능은 저장 형식을 바꾸지 않는다.** `Test`·`Step`·`TargetLocator` 어느 것에도 필드를
더하지 않는다. 여기 적는 엔티티는 전부 **세션의 것**이며 디스크에 닿지 않는다 (FR-014·FR-029).

---

## 1. 엔티티

### 1-1. `StepRange` — 교체 구간

연속된 Step 의 구간. **순번이 아니라 Step 식별자로 잡는다.**

| 필드 | 형 | 설명 |
|---|---|---|
| `step_ids` | `list[str]` | 구간에 속한 Step 의 id, 목록 순서대로. 1개 이상 |

**왜 순번이 아닌가**: 재녹화 도중 새 Step 이 구간 시작 위치에 삽입되므로 옛 구간의 순번이
계속 밀린다. 순번으로 들면 매 삽입마다 구간을 다시 계산해야 하고, 한 번 어긋나면 확정이
엉뚱한 Step 을 지운다.

**검증** (경계에서):
- 모든 id 가 지금 작업 중 목록에 존재한다
- 목록에서 **연속**이다 (FR-016). 사이에 다른 Step 이 끼면 거절
- 비어 있지 않다

### 1-2. `RerecordTransaction` — 교체 트랜잭션

한 번의 「AI 로 다시 만들기」. 세션 하나에 **최대 하나**.

| 필드 | 형 | 설명 |
|---|---|---|
| `range` | `StepRange` | 교체 대상 (옛 Step). 시작부터 끝까지 **바뀌지 않는다** |
| `arrival_index` | `int` | 도착점. 구간 첫 Step 의 시작 시점 순번 (0-based) |
| `created_step_ids` | `list[str]` | 이번 세션이 만든 Step 의 id, 만들어진 순서 |
| `settled` | `bool` | 확정 또는 버리기로 끝났는가 |

**스냅샷이 없다.** FR-037 이 AI 의 편집 권한을 `created_step_ids` 로 한정하므로 구간과
구간 밖은 재녹화 동안 바뀌지 않는다. 바뀌지 않는 것을 복사해 둘 이유가 없다 (R7).

**두 결말이 같은 함수의 다른 인자다**:

| 결말 | 연산 | 결과 |
|---|---|---|
| 확정 | `delete_steps(steps, range.step_ids)` | 1~4 + 새 Step + 뒤 구간 |
| 버리기 | `delete_steps(steps, created_step_ids)` | 시작 전과 동일 |

둘 다 011 FR-388 의 **전부-또는-전무**를 그대로 받는다 (FR-026·FR-027).

### 1-3. `DefinitionSummary` — 정의 요약

에이전트에게 주는 Step 목록의 축약형. **문자열 하나**이며 구조체가 아니다 — 모델에게
가는 것은 결국 텍스트이고, 중간 구조를 두면 값을 어디서 거르는지가 두 곳이 된다.

한 Step 당 읽는 것:

| 읽는다 | 읽지 않는다 |
|---|---|
| 순번 · id · `label` · Step 종류 · 대상 요약(역할·접근가능한 이름) · `tab` · 교체구간 여부 | **`value` (입력값)** |

입력값이 있는 Step 은 `값 있음` 또는 변수 참조 이름(`${로그인_비밀번호}`)만 적는다.

**거르지 않고 읽지 않는다** (R8). 스크러버는 「민감하다고 **알려진** 값」만 아는데, 아직
표시되지 않은 입력값은 통과한다. 접근 자체를 하지 않으면 판정할 필요가 사라진다.

**축약** (FR-006): 예산을 넘으면 구간에서 먼 Step 부터 줄인다. 생략한 구간은
`… (Step 15~38 생략) …` 로 **명시**한다. 조용히 자르지 않는다.

### 1-4. `ChatTurn` — 대화 차례

사용자의 말 또는 AI 의 답 하나.

| 필드 | 형 | 설명 |
|---|---|---|
| `role` | `"user" \| "assistant"` | 누가 말했는가 |
| `text` | `str` | 내용. 사용자 입력은 `MAX_INSTRUCTION_CHARS` 상한 |
| `at` | `datetime` | 시각 |

**저장 위치**: `AuthoringAgent.messages` (기존). 별도 목록을 만들지 않는다 — 두 곳에 두면
막힘 답변(`resume_with_answer`)·인수 후 재개(`resume_after_takeover`)가 어느 쪽에 붙는지
갈린다 (FR-009).

**디스크에 쓰지 않는다** (FR-014). 세션이 끝나면 사라진다. 이것이 FR-013(민감값이 이력에
남지 않는다)의 실질적 방어다 — 사용자가 채팅에 비밀번호를 적는 것을 제품이 막을 수는
없지만, 남기지 않을 수는 있다 (R8).

## 2. `SessionWork` 델타 (서버 내부)

| 필드 | 형 | 설명 |
|---|---|---|
| `rerecord` | `RerecordTransaction \| None` | 진행 중인 교체. 없으면 일반 세션 |

`SessionWork` 는 이미 `steps`·`agent`·`compiler`·`runner`·`toolbox` 를 들고 있다.
트랜잭션은 그 옆에 하나 더 붙는 것이며 새 저장소를 만들지 않는다.

## 3. 상태 기계 델타

### 3-1. 더하는 전이 — 하나

```python
SessionState.PAUSED: {
    ...
    Command.BEGIN_AI: SessionState.AI_RUNNING,   # ★ 016
}
```

이것이 전부다. 새 상태도, 새 명령도, 새 국면도 없다 (R4).

### 3-2. 재녹화 세션의 생애

```
                    ┌─ 사용자가 구간을 골라 「AI 로 다시 만들기」
                    ↓
  STARTING ─BEGIN_REPLAY→ REPLAYING ─(pause_before_index 도달)→ PAUSED ◀─┐
             (러너만 돈다. 에이전트 없음 — 원칙 II)                  │     │
                                                                    │     │
       ┌────────────────────────────────────────────────────────────┘     │
       │ 채팅 턴                                                          │
       ↓                                                                  │
  ─BEGIN_AI→ AI_RUNNING ──────────PAUSE──────────────────────────────────┤
                  │        (턴 완료. 세션은 계속 산다)                     │
                  │                                                       │
                  ├─AI_BLOCK→ AI_BLOCKED ─CHOOSE_TAKEOVER→ TAKEOVER_RECORDING
                  │              │        ─CHOOSE_ANSWER/RETRY/SKIP→ AI_RUNNING
                  │              └─────────CHOOSE_ABORT→ REVIEW
                  │
                  └─STOP→ REVIEW

  PAUSED 에서 하는 것: EDIT_STEPS(확정·버리기·손편집) · SAVE · RUN_FROM · STOP · 채팅
```

**`PAUSED` 가 집이다.** 확정·버리기·교체 대상 보기·손 편집이 전부 그 국면에서 일어나고,
그 국면이 바로 「세션이 살아 있는 채로 멈춰 있고 편집·저장을 받는다」이다.

### 3-3. 확정·버리기는 새 명령이 아니다

둘 다 작업 중 Step 목록을 바꾸는 편집이므로 기존 `Command.EDIT_STEPS`
(`PAUSED → PAUSED`)를 쓴다. 새 명령을 만들면 전이표에 같은 뜻의 줄이 둘 생긴다.

## 4. 불변식

기존 불변식 1~5 (data-model 001 §) 에 더해, 이 기능이 세우는 것들.

### 불변식 6 — 러너와 에이전트는 동시에 살지 않는다

한 세션에서 `work.runner` 가 도는 동안 `work.agent_task` 는 살아 있지 않고, 그 역도 같다.

**왜**: 헌법 원칙 II 가 금지하는 것은 임포트가 아니라 **재실행 중 언어모델 호출**이다.
`itb.api` 는 계약의 `source_modules` 에 없으므로 린터만으로는 이 겹침을 막지 못한다 (R9).

**검사**: 도착점 만들기·버리기 되맞춤 두 구간에서, 가짜 드라이버의 호출 횟수가 0 이다.

### 불변식 7 — 교체 대상은 Step 에 없다

`Step` 은 자기가 교체 대상인지 모른다. 판정은 `SessionView.rerecord.range_step_ids` 와
목록을 대조해 **화면이** 한다.

**왜**: Step 에 그 필드를 두면 (a) 작성 주체 외의 의미가 저장 형식에 생겨 원칙 I 이
흔들리고 (b) 확정되지 않은 상태가 디스크에 내려갈 문이 열린다 (FR-029 위반).

### 불변식 8 — AI 는 자기가 만든 것만 고친다

편집 도구 4종의 `step_id` 인자는 `rerecord.created_step_ids`(또는 재녹화가 아닌 세션에서는
그 세션의 `compiler.step_ids()`)에 있어야 한다. 아니면 도구가 **거절을 반환**한다.

**왜**: FR-037. 그리고 이것이 성립해야 불변식 9(되돌릴 수 있다)가 스냅샷 없이 성립한다.

**거절은 조용하지 않다** (FR-038) — 도구가 거절 사유를 돌려주고, 에이전트가 그것을 읽고,
사용자에게 보인다.

### 불변식 9 — 버리면 시작 전과 같다

`discard` 후의 Step 목록은 재녹화 시작 직전의 목록과 **id·순서·내용이 전부 같다.**

**왜**: FR-027·SC-004. 불변식 8 이 성립하므로 `created_step_ids` 를 지우는 것만으로
충분하다 (R7).

### 불변식 10 — 확정은 빈 것으로 바꾸지 않는다

`created_step_ids` 가 비어 있으면 확정 명령이 거절된다.

**왜**: FR-028. 옛 구간을 빈 것으로 교체하는 것은 「구간 삭제」이고, 그것은 이미 있는
조작(`step.deleteSelected`)이다. 재녹화 버튼으로 삭제가 일어나면 사용자는 무엇이 지워질지
예측할 수 없다.

### 불변식 11 — 어긋난 화면을 조용히 두지 않는다

버리기의 되맞춤 실행이 실패하면, 정의가 이미 원본으로 돌아갔다는 사실과 화면이 그것과
어긋나 있다는 사실을 **함께** 알린다 (FR-031c).

**왜**: 원칙 III 불변식 3. 둘 중 하나만 말하면 사용자는 무엇을 믿어야 할지 모른다.

## 5. 검증 규칙 (경계)

| 대상 | 규칙 | 위반 시 |
|---|---|---|
| `step_ids` | 전부 존재 · 연속 · 1개 이상 | `400 DEFINITION_INVALID` |
| 재녹화 시작 | 그 테스트를 잡은 다른 세션이 없다 | `409 SESSION_BUSY` (기존 코드) |
| 재녹화 시작 | 도착점 순번이 Step 수 범위 안 | `400 DEFINITION_INVALID` (기존 검증 재사용) |
| 채팅 입력 | 비어 있지 않다 · `MAX_INSTRUCTION_CHARS` 이하 | `400 DEFINITION_INVALID` |
| 확정 | `created_step_ids` 가 비어 있지 않다 (불변식 10) | `409` + 사유 |
| 확정·버리기 | 트랜잭션이 있고 아직 `settled` 가 아니다 | `409` + 사유 |
| 편집 도구 | `step_id` 가 이번 세션이 만든 것 (불변식 8) | 도구가 거절 반환 (HTTP 아님) |

새 오류 코드는 003 의 계약을 따른다 — `category`(제품이 막은 것 / 제품이 깨진 것)와
`next_action` 을 함께 싣는다.
