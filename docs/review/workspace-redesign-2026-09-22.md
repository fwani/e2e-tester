# ITB 작업 공간 전면 리디자인

사용자는 첫 가독성 보정이 화면 구성 변경이 아니라고 지적했고, 전체 리디자인을 명시적으로 요청했다. 이번 변경은 이전 `visibility-refresh-2026-09-22.md`를 대체한다.

## 변경

- 프로젝트 이름과 이동 경로를 담는 어두운 고정 내비게이션. 작성·실행 중에는 폭을 줄인다.
- 테스트 라이브러리에서 그룹 탐색과 목록을 분리한다. 좁은 창에서는 그룹을 가로로 배치한다.
- 이름과 ID를 함께 보여주고 마지막 실행 결과는 별도 열에 둔다. 결과 필터는 검색 도구 위로 분리한다.
- Step 목록은 왼쪽, 대상 앱과 작업 영역은 중앙, 선택한 Step 상세는 오른쪽에 배치한다.
- 결과 스크린샷은 최소 높이 400px 영역에서 확인하고 원본 링크로 확대할 수 있다. 진단 영역은 280px로 분리하고 내용이 길면 스크롤한다.
- 작업대 알림은 국면 제목 아래의 전용 영역에 표시한다. 기존 고정 위치 토스트가 왼쪽으로 옮겨진 Step 조작을 덮는 문제를 해결했다. 알림 표시 시 본문 높이는 조정되며 조작 위로 겹치지 않는다.
- 프로젝트 선택은 소개 영역과 선택/생성 영역을 나눴고, 설정 화면에도 같은 내비게이션과 색 체계를 적용했다.
- 청록색 주요 조작, 어두운 남색 내비게이션, 밝은 작업 영역, 7px/5px/12px 모서리 체계를 적용했다.

API, 저장 형식, 테스트 실행·삭제·그룹 이동 등의 동작 계약은 유지했다.

## 검증 기준 변경

과거 `BeforeAfterParity.test.ts`는 Tailwind 마이그레이션 전후 화면이 같은지 검사했다. 사용자가 화면 구조를 바꾸도록 요청했으므로 이 동일성 검사는 폐기하고 `WorkspaceRedesign.test.tsx`의 실제 내비게이션 및 알림 영역 동작 검사로 대체했다. 임의의 차이 전체를 허용 목록에 넣거나 오래된 보고서를 새 보고서로 표시하지 않았다. 기존 L2 보고서는 역사 자료이며 현재 디자인의 동일성 증거로 사용하지 않는다.

Step 위치/폭, 상세 위치, 가변 캔버스와 결과 영역의 명시적 배치 검사는 새 계약으로 갱신했다. CSS 실재 검사는 앱이 실제로 읽는 workspace.css까지 검사한다. 화면 순회에서 폼 정렬은 전체 창이 아닌 내비게이션을 제외한 본문 영역을 기준으로 측정한다.

## 실제 검증

- 최종 Vitest: 122개 파일, 1,469개 테스트 전부 통과. TypeScript 및 Vite 프로덕션 빌드 통과. 기존 500kB 초과 번들 경고는 남는다.

- 실제 로컬 API/샘플 앱으로 19개 화면 × 4개 창 크기 = 76개 조합을 순회했다. 모두 도달했고, 등록되지 않은 검출은 0건이다.
- 허용된 28건은 프로젝트 미선택/결과 없음의 404와 의도적인 연결 끊김 시나리오다. 서버 오류를 정상 화면처럼 숨기지 않았다.
- 녹화, 초안, 통과/실패 결과, 그룹, 긴 이름, 선택, 삭제 확인, 상세, 알림, 비밀 값과 키 관리 화면을 포함한다. 실제 AI 모델 실행·일시정지·인계 등 순회가 지원하지 않는 상태는 런타임 검증 완료로 주장하지 않는다.
- 공통 디자인 참조 렌더 대조: 29형태 × 25속성 = 725칸, 불일치 0. 이것은 부품 참조 시트 일치 검사이며 과거 화면 구도와의 동일성 검사가 아니다.
- Impeccable detector: 검출 0.
- 독립 시각 검토: 첫 판정 FIX. 알림 겹침, 실패 증거 영역, 시간 줄바꿈의 세 지적을 수정했다. 같은 1280px 화면 재검토에서 세 항목 모두 해결 판정(PASS)을 받았다.

실제 화면 캡처: `.sweep/shots/`. 순회 보고서: `frontend/tests/sweep-report.json`. 테스트/빌드 결과는 최종 응답의 실제 실행 결과를 따른다.
