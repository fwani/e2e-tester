## 1. 자동 검증

```bash
# 백엔드
cd backend && uv run ruff check src/ tests/
cd backend && uv run lint-imports
cd backend && uv run python -m itb.schema.export --check
cd backend && uv run pytest -m "not browser" -q      # 빠른 층
cd backend && uv run pytest -q                        # 전체

# 프론트엔드
cd frontend && npx tsc --noEmit && npx vitest run
```

**`--check` 가 실패하면** 도메인 모델(`StepResult`)을 고치고 스키마 생성물을 갱신하지 않은
것이다. 생성물은 커밋 대상이다 (헌법 Cross-language schema duty).

```bash
cd backend && uv run python -m itb.schema.export
cd ../frontend && npm run gen:types
```

### 개정되는 기존 검증

011 은 정본(조작의 집·행 칸 구성·권한표)을 바꾸므로 **그것을 세는 검사가 먼저 깨진다.**
정상이며, 기대값을 새 계약에 맞춰 고치는 것이 작업의 일부다. 지우거나 건너뛰면 안 된다
(헌법 §품질 게이트 4). 목록은 [research.md](research.md) R8 에 있다.

## 2. 사용자 이야기별 손 검증

각 이야기는 **독립적으로** 확인할 수 있다. 하나만 붙어도 그 값이 나온다.

### US1 — 저장이 보이는 자리에 있고 이름을 두 번 묻지 않는다

| # | 하는 일 | 기대 |
|---|---|---|
| 1 | 새 테스트를 녹화한다. 화면을 **스크롤하지 않고** 저장을 찾는다 | 국면 띠에 저장이 보인다 (UC-011-1) |
| 2 | 저장을 누른다 | 이름을 한 번 묻는다 |
| 3 | 저장한 테스트를 목록에서 다시 열어 편집한다. Step 하나를 고치고 저장한다 | 「변경 저장 (1건)」. **이름을 묻지 않는다** |
| 4 | 편집 → 브라우저 열기 → 일시정지 → Step 을 고친다. 저장을 누른다 | 라벨이 「변경 저장」이고 이름 칸이 없다 (UC-011-4) |
| 5 | 같은 상태에서 저장하지 않고 나가기를 시도한다 | 확인에 **이름 입력칸이 없다** (UC-011-5) |
| 6 | 국면 띠의 테스트 이름을 지워 빈 값으로 만들고 저장을 누른다 | 저장이 비활성이고 그 자리에 이유가 붙는다 (UC-011-6) |

### US2 — 어느 Step 을 보고 있는지 분명하다

| # | 하는 일 | 기대 |
|---|---|---|
| 1 | Step 이 10개 이상인 테스트에서 행 하나를 고른다 | 상세가 **Step 목록 왼쪽**에서 대상 앱 위에 겹쳐 열린다. 목록은 그대로 보인다 |
| 2 | 다른 행을 고른다 | 상세 대상만 바뀐다. 자리·크기는 그대로 |
| 3 | 상세를 닫는다 | 대상 앱이 **원래 폭 그대로** 드러난다 (UC-011-8) |
| 4 | 실행한 뒤 **통과한** Step 을 고른다 | 선택 표시와 통과 결말이 **둘 다** 보인다 |
| 5 | 일시정지가 걸린 Step 을 고른다 | 일시정지 위치와 선택이 **둘 다** 보인다 |
| 6 | 녹화 국면에서 상세를 열고, 상세가 덮은 자리를 클릭한다 | 대상 브라우저에 클릭이 전달되지 않는다 (UC-011-9) |
| 7 | 열 국면을 차례로 지나며 상세를 연다 | 자리가 모든 국면에서 같다 |

### US3 — 녹화와 지시문이 대등하다

| # | 하는 일 | 기대 |
|---|---|---|
| 1 | 저장된 테스트를 편집으로 연다 (브라우저 닫힌 상태) | 「녹화로 더하기」와 「지시문으로 더하기」가 같은 자리에 **둘 다 활성** |
| 2 | 「지시문으로 더하기」를 누른다 | 브라우저가 자동으로 열리고 지시문 수행으로 이어진다 (UC-011-23) |
| 3 | 저장하지 않은 변경을 만든 뒤 같은 조작을 누른다 | 기존 「저장하고 열기」 확인이 먼저 걸린다. **새 확인이 생기지 않는다** (UC-011-24) |
| 4 | 대상 앱을 내려 브라우저 열기를 실패시킨다 | 사유를 알리고 진행 표시를 켜지 않는다 (UC-011-25) |
| 5 | 삽입 위치로 Step 을 지목한 뒤 지시문으로 더한다 | 녹화와 같은 규칙으로 그 위치에 삽입된다 |
| 6 | 저장한 정의 파일을 열어 본다 | 결정적 Step 이 들어가 있고, 지시문 자체는 실행 대상이 아니다 (원칙 II) |

### US4 — 여러 Step 을 한 번에 지운다

| # | 하는 일 | 기대 |
|---|---|---|
| 1 | Step 15개 테스트에서 임의의 세 행의 **체크 칸**을 누른다 | 「3개 고름」이 보이고 「고른 것 지우기」가 활성 |
| 2 | 그 상태에서 **행 본문**을 누른다 | 상세가 열리고 **체크 상태는 그대로** (UC-011-15) |
| 3 | 「고른 것 지우기」를 확인한다 | 세 개가 한 번에 사라지고 지운 개수를 알린다 |
| 4 | 5번째 Step 을 지목하고 「이 뒤 전부 지우기」를 쓴다 | 「Step 06 ~ Step 15 · 10개를 지웁니다」처럼 개수와 범위가 확인 문구에 있다 |
| 5 | 마지막 Step 을 지목하고 같은 조작을 본다 | 비활성이고 「마지막 Step 입니다」가 붙는다 (UC-011-19) |
| 6 | 체크한 뒤 순서 변경으로 그 행을 옮긴다 | 선택이 **그 Step 을 따라간다** (UC-011-16) |
| 7 | 상세가 열린 채로 그 Step 을 복수 삭제한다 | 상세가 대상이 없어진 사실을 밝히고 목록은 정상 |
| 8 | 편집 국면에서 세 개를 지우고 저장한다 | 정의 파일에서 세 개가 함께 빠진다. 중간 상태가 저장되지 않는다 |

**원자성 확인 (백엔드)**: 없는 `step_id` 를 하나 섞어 배치 삭제를 호출한다 → `404` 이고
**아무것도 지워지지 않는다** (FR-388).

### US5 — Step 마다 스크린샷이 남는다

| # | 하는 일 | 기대 |
|---|---|---|
| 1 | Step 8개 테스트를 한 번 실행한다 | `.runs/TC-xxx/steps/` 에 실행 대상 Step 수만큼 PNG 가 있다 |
| 2 | 결과보기에서 행을 차례로 고른다 | 상세에 그 Step 의 화면이 보인다 (UC-011-20) |
| 3 | 중간 Step 이 실패하는 테스트를 실행한다 | 실패 이후 Step 은 스크린샷 자리가 비고, 그것이 「미도달」 결말과 일치한다 |
| 4 | 실패한 Step 을 고른다 | 실패 시점 화면이 보인다. `steps/` 에 `failure.png` 와 같은 화면이 **두 벌 있지 않다** |
| 5 | 비밀 값을 입력하는 Step 이 있는 테스트를 실행한다 | 그 Step 의 스크린샷은 남지 않고 사유가 보인다 (UC-011-21) |
| 6 | 같은 테스트를 다시 실행한다 | `steps/` 에 **이번 실행 것만** 있다. 이전 실행 파일이 섞여 있지 않다 (FR-396a) |
| 7 | Step 수를 줄여 저장하고 다시 실행한다 | 남아 있던 높은 인덱스 PNG 가 사라진다 (비우기가 동작한다) |
| 8 | 실행 도중 `.runs/` 를 읽기 전용으로 만든다 | 실행이 **중단되지 않는다.** 사유만 남는다 (FR-398) |

**시간 초과 판정 회귀 확인**: 011 도입 전후로 같은 테스트의 `duration_ms` 와 시간 초과 판정을
비교한다. 촬영 시간이 들어가면 안 된다 (FR-395 · SC-611).

  가려지는 정도가 받아들일 만한지)이 기록돼 있다
