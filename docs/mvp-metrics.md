# MVP 성공 지표 측정 (SC-001~SC-012)

`spec.md` 의 성공 지표를 어디서 어떻게 측정하는지와, 그 결과를 기록하는 문서다 (T155).

**자동 측정과 수동 측정을 구분한다.** 자동으로 잴 수 있는 것을 사람이 재면 매번 결과가
달라지고, 사람이 재야 하는 것을 자동 테스트로 대신하면 재지 않은 것을 잰 것으로 오인한다.

## 자동 측정 — 테스트가 매 실행에서 재고 있다

| 지표 | 내용 | 측정 지점 | 현재 |
|------|------|-----------|------|
| SC-003 | 재실행 결정성 | `tests/integration/test_roundtrip.py` — 10회 연속 동일 결과 | 통과 |
| SC-006 | 재실행 중 언어모델 호출 0건 | `tests/integration/test_replay_no_llm.py` — 클라이언트 생성 스파이 + `ai_*` 이벤트 부재. **AI 로 만든 테스트**와 **자연어로 추가한 Step** 도 각각 확인 | 통과 (호출 0건) |
| SC-007 | 이어서 실행 시 사전 Step 재실행 없음 | `tests/integration/test_pause_resume.py` — Step id 기준으로 중복 실행 0건 | 통과 |
| SC-008 | 후보 2개 이상 확보 비율 ≥ 90% | `tests/integration/test_locator_coverage.py` — 픽스처 앱 녹화 결과 | **100%** (7/7) |
| SC-010 | 민감 값 평문 노출 0건 | `tests/integration/test_secret_leakage.py` — 정의·비밀 파일·로그·API·WS·생성 코드 전수 | 통과 (0건) |
| SC-011 | 비밀키 없이 봉인 가능 | `tests/contract/test_secrets_api.py` | 통과 |
| SC-012 | 멀티 탭 재실행 | `tests/integration/test_multitab_replay.py` | 통과 |
| 성능 (R8) | Step 오버헤드 p95 < 50ms · 녹화 반영 p95 < 200ms | `tests/integration/test_performance.py` | 통과 |

**SC-008 에 대한 기록.** 이 값은 한때 90% 를 "넘고 있었다" 가 실제로는 군더더기 Step 이
분모를 늘린 결과였다. 리코더가 `<button>` 의 blur 를 입력으로 기록하고 `select` 를 두 번
기록하던 결함을 고치자 88% 로 떨어졌고, 원인은 클릭 후보 검증이 화면 이동과 경쟁해 지는
것이었다. CSS·testId 후보를 **동작이 일어난 순간 페이지 안에서** 검증하게 바꿔 100% 가 됐다.
지표가 올라간 것이 아니라, 지표가 그제야 실제를 재기 시작했다.

## 수동 측정 — 아직 수행하지 않았다

**시나리오 20건 규모의 측정 세션이 필요하다. 자동 테스트로 대체할 수 없다.**

| 지표 | 목표 | 왜 자동화할 수 없는가 |
|------|------|----------------------|
| SC-001 | 테스트 1건 작성 시간 | 사람이 실제 앱을 보고 판단하는 시간이 측정 대상이다 |
| SC-002 | 자연어 → 결정적 테스트 변환 성공률 ≥ 70% | 실제 언어모델과 실제 화면이 필요하다. 대본을 쓰면 모델 성능이 아니라 대본을 재게 된다 |
| SC-004 | AI 실패 후 Takeover 완료율 ≥ 80% | 실패 상황이 실제로 발생해야 하고, 이어받는 판단이 사람의 것이다 |
| SC-005 | 실패 원인 파악 시간 | 화면을 읽고 원인을 짚는 사람의 시간이 측정 대상이다 |

### 측정 절차 (수행 시 이 절을 결과로 채운다)

1. **표본 선정** — 사내 앱 또는 픽스처 앱에서 시나리오 20건을 고른다. 선정 기준을 먼저
   적는다: 화면 종류(목록·폼·모달·새 탭)와 난이도(단순 클릭 / 조건부 UI / hover 메뉴)가
   고루 섞이도록 하고, **쉬운 것만 고르지 않는다.** 기준을 뒤에 적으면 결과에 맞춰진다.
2. **SC-001·SC-005** — 각 시나리오의 작성 시간과 실패 원인 파악 시간을 잰다. 도구에 익숙한
   사람과 처음 쓰는 사람을 나눠 기록한다.
3. **SC-002** — 20건을 자연어로 지시해 결정적 Step 으로 변환된 비율을 센다. 변환 실패는
   **왜 실패했는지**를 함께 적는다 (화면을 못 읽음 / 요소를 못 찾음 / 지시가 모호함).
4. **SC-004** — SC-002 에서 막힌 사례마다 Takeover 로 완료했는지 기록한다.
