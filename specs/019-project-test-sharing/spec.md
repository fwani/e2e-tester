# Feature Specification: 프로젝트·테스트 공유용 내보내기·가져오기

**Feature Branch**: `019-project-test-sharing`

**Created**: 2026-09-23

**Status**: Draft

**Input**: User description: "프로젝트, 테스트를 export/import 하는 기능을 추가하려고한다. 다른 사람과 파일을 공유할 수 없기때문에, 테스트 스텝이나 정보를 공유하려고하는것. 비밀키의 경우 공유받은사람이 사용할 수 있게 import 시 뭔가 제공이 되어야한다."

## 개요

이 제품은 단독 로컬 도구다. 한 사람이 만든 테스트는 그 사람의 컴퓨터 안에만 있고, 다른 사람은
볼 방법이 없다. 같은 화면을 두 사람이 테스트하면 같은 테스트를 두 번 만든다.

프로젝트 디렉터리를 그대로 건네는 것으로는 해결되지 않는다. 세 가지가 막는다.

- **민감 값이 열리지 않는다.** 비밀번호 같은 값은 설치마다 다른 키로 봉인되어 있다. 받은 사람의
  키로는 그 암호문을 열 수 없고, 열지 못하면 로그인에서 멈춘다.
- **받는 쪽 목록에 나타나지 않는다.** 어느 디렉터리가 프로젝트인지는 도구가 따로 기억한다.
- **식별자가 겹친다.** 이미 `TC-001` 이 있는 프로젝트에 남의 `TC-001` 을 넣으면 하나가 사라진다.

이 기능은 그 세 가지를 해결한 **전달 가능한 파일 하나**를 만들고, 그 파일을 받아 **실행 가능한
상태까지** 복원한다. 민감 값은 파일에 담지 않는다 — 대신 어떤 민감 변수가 필요한지를 가져오기
화면이 목록으로 보여주고, 받은 사람이 자기 값을 채워 넣으면 그 사람의 키로 다시 봉인된다.

### 이 기능이 하지 않는 것 (범위 밖)

- **서버를 두지 않는다.** 계정, 공유 링크, 실시간 동기화는 범위 밖이다. 전달은 사람이 한다 —
  메신저·메일·사내 저장소 어디로 보내든 이 기능은 관여하지 않는다.
- **Playwright 프로젝트 내보내기(헌법 원칙 V)와 다른 것이다.** 그쪽은 제품 없이 실행하기 위한
  산출물이고, 이쪽은 **제품으로 다시 들어오기 위한** 산출물이다. 서로를 대체하지 않는다.
- **엑셀 왕복(014)과 다른 것이다.** 엑셀은 사람이 읽는 설계서이고 스텝을 복원하지 못한다.
  이쪽은 스텝·로케이터 후보까지 그대로 옮긴다.
- **민감 값을 전달하지 않는다.** 이 기능은 비밀번호를 옮기는 통로가 아니다. 무엇이 필요한지만
  옮기고, 값은 받는 사람이 채운다.
- **버전 관리를 대신하지 않는다.** 두 사람이 같은 테스트를 각자 고친 뒤 합치는 병합(merge)은
  범위 밖이다. 가져오기는 추가하거나 덮어쓸 뿐 세 방향 병합을 하지 않는다.
- **실행 이력을 옮기지 않는다.** 스크린샷·콘솔·네트워크 기록은 재생성 가능한 산출물이고 민감
  정보가 남을 수 있어 내보내기에 포함하지 않는다.

## Clarifications

### Session 2026-09-23

- Q: 내보내기 파일에 민감 값을 어떻게 처리하는가? → A: 값을 전혀 담지 않는다. 암호구로 감싸 함께
  전달하는 선택지도 두지 않는다. 받는 사람이 가져오기 시점에 자기 값을 직접 입력한다.
- Q: 내보내기 산출물의 형태는? → A: 사용자가 내려받는 파일 1개. 복사해 붙여넣는 텍스트 형태는
  제공하지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 만든 테스트를 파일 하나로 내보낸다 (Priority: P1)

테스트를 만든 사람이 프로젝트 전체 또는 일부 테스트를 골라 내보내기를 실행한다. 파일 하나가
내려받아지고, 그 파일을 메신저나 메일로 동료에게 보낸다.

**Why this priority**: 내보내기가 없으면 공유 자체가 시작되지 않는다. 이 기능의 입구다.

**Independent Test**: 프로젝트를 하나 열고 내보내기를 실행해 파일이 생성되는지, 그 파일이 선택한
테스트를 모두 담고 있는지 확인하면 단독으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 테스트 3개가 있는 프로젝트를 열었을 때, **When** 「프로젝트 내보내기」를 실행하면,
   **Then** 파일 하나가 만들어지고 그 안에 프로젝트 설정·그룹 구성·테스트 3개가 모두 담긴다.
2. **Given** 테스트 목록에서 테스트 2개만 선택했을 때, **When** 「선택 항목 내보내기」를 실행하면,
   **Then** 선택한 2개만 담긴 파일이 만들어진다.
3. **Given** 내보낼 테스트가 민감 변수를 참조할 때, **When** 내보내기를 실행하면, **Then** 만들어진
   파일에는 그 변수의 **이름만** 있고 값이나 암호문은 어떤 형태로도 들어 있지 않다.
4. **Given** 테스트가 한 건도 없는 빈 프로젝트일 때, **When** 내보내기를 실행하면, **Then** 내보낼
   것이 없다는 안내가 나오고 파일은 만들어지지 않는다.

---

### User Story 2 - 받은 파일을 가져와 내 목록에서 본다 (Priority: P1)

파일을 받은 사람이 가져오기를 실행해 파일을 고른다. 무엇이 들어오는지 요약을 확인하고 진행하면,
새 프로젝트가 만들어지고 테스트 목록에 그대로 나타난다.

**Why this priority**: 내보내기와 짝을 이루어야 공유가 성립한다. 이 둘이 최소 제품이다.

**Independent Test**: 내보낸 파일을 다른 작업 공간에서 가져와 테스트 목록·스텝 내용이 원본과
일치하는지 확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 내보내기 파일을 받았을 때, **When** 프로젝트 목록에서 「가져오기」로 그 파일을 고르면,
   **Then** 들어올 프로젝트 이름·테스트 개수·필요한 민감 변수 목록이 **진행 전에** 요약으로 보인다.
2. **Given** 요약을 확인하고 진행했을 때, **When** 가져오기가 끝나면, **Then** 새 프로젝트가 목록에
   나타나고 그 안의 테스트 스텝·로케이터 후보·검증 스텝이 원본과 같다.
3. **Given** 같은 이름의 프로젝트가 이미 있을 때, **When** 가져오기를 진행하면, **Then** 기존
   프로젝트를 덮어쓰지 않고 구분되는 이름으로 만들어지며 그 사실이 안내된다.
4. **Given** 파일이 손상되었거나 이 도구가 만든 것이 아닐 때, **When** 가져오기를 시도하면,
   **Then** 무엇이 잘못됐는지 알 수 있는 오류가 나오고 **아무것도 만들어지지 않는다**.
5. **Given** 파일이 이 도구가 읽을 수 없는 더 새로운 형식일 때, **When** 가져오기를 시도하면,
   **Then** 형식 버전이 맞지 않는다는 안내가 나오고 부분 복원을 시도하지 않는다.

### User Story 3 - 받은 테스트를 내 비밀값으로 실행 가능하게 만든다 (Priority: P1)

가져온 테스트는 로그인 비밀번호 같은 값이 비어 있다. 받은 사람은 그 목록을 보고 자기 계정의 값을
채워 넣는다. 채워 넣은 값은 그 사람의 키로 봉인되어 저장되고, 테스트가 그대로 실행된다.

**Why this priority**: 사용자가 명시적으로 요구한 지점이다. 이것이 없으면 가져온 테스트는 로그인
단계에서 멈추고, 받은 사람은 왜 멈췄는지 알 수 없다. 공유의 가치가 여기서 완성된다.

**Independent Test**: 민감 변수를 쓰는 테스트를 가져온 뒤, 값을 채우기 전에는 「값 필요」 상태로
표시되고 값을 채운 뒤 실행이 통과하는지 확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 민감 변수 2개를 참조하는 테스트를 가져왔을 때, **When** 가져오기가 끝나면, **Then**
   채워야 할 변수 2개가 **이름과 어느 테스트의 어느 스텝에서 쓰이는지와 함께** 제시된다.
2. **Given** 값이 비어 있는 민감 변수가 있을 때, **When** 그 테스트를 실행하려 하면, **Then**
   실행 전에 「값이 필요합니다」로 막히고 어느 변수인지 알려 준다. 빈 값으로 실행해 실패하지 않는다.
3. **Given** 사용자가 값을 입력했을 때, **When** 저장하면, **Then** 값은 **그 사용자의 키로 봉인되어**
   저장되고, 화면·로그·오류 메시지 어디에도 평문으로 다시 나타나지 않는다.
4. **Given** 이 설치에 아직 키가 없을 때, **When** 민감 값을 채우려 하면, **Then** 키를 먼저 만들어야
   한다는 안내와 키 관리 화면으로 가는 경로가 제시된다.
5. **Given** 이미 같은 이름의 민감 변수에 값이 있을 때, **When** 같은 변수를 요구하는 테스트를
   가져오면, **Then** 기존 값을 조용히 덮어쓰지 않고 그대로 쓸지 다시 입력할지 고를 수 있다.

### User Story 4 - 내보내기 전에 무엇이 나가는지 확인한다 (Priority: P2)

내보내는 사람이 파일을 만들기 전에, 그 파일에 어떤 값이 평문으로 들어가는지 확인한다. 민감 표시가
되지 않은 입력값(사번, 사용자 계정, 사내 주소 등)이 섞여 있으면 여기서 발견한다.

**Why this priority**: 내보내기는 되돌릴 수 없다. 파일이 나간 뒤에는 회수할 방법이 없으므로, 나가기
전에 보이는 것이 유일한 방어선이다. P1 없이는 성립하지 않지만 P1의 가치를 지킨다.

**Independent Test**: 민감 표시가 없는 평문 입력값을 가진 테스트를 내보낼 때 그 값이 확인 화면에
나열되는지 확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 스텝에 평문 입력값이 있는 테스트를 내보낼 때, **When** 내보내기 확인 화면이 뜨면,
   **Then** 파일에 그대로 들어갈 평문 입력값이 스텝 위치와 함께 나열된다.
2. **Given** 확인 화면에서 값을 보고 문제를 발견했을 때, **When** 취소하면, **Then** 파일은 만들어지지
   않고 프로젝트는 아무것도 바뀌지 않는다.
3. **Given** 시작 URL이 사내 주소일 때, **When** 확인 화면이 뜨면, **Then** 그 주소도 함께 나가는
   정보로 표시된다.

---

### User Story 5 - 이미 있는 프로젝트에 받은 테스트를 더한다 (Priority: P3)

같은 대상을 테스트하는 프로젝트를 이미 갖고 있는 사람이, 동료가 만든 테스트 몇 개만 자기 프로젝트에
더한다. 식별자가 겹쳐도 기존 테스트는 사라지지 않는다.

**Why this priority**: 새 프로젝트로 받는 것(US2)만으로도 공유는 성립한다. 같은 프로젝트로 합치는
것은 그다음의 편의다.

**Independent Test**: `TC-001` 이 이미 있는 프로젝트에 `TC-001` 을 담은 파일을 가져와, 두 테스트가
모두 남아 있는지 확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 프로젝트를 열어 둔 상태일 때, **When** 「이 프로젝트로 가져오기」를 실행하면, **Then**
   파일 안의 테스트가 현재 프로젝트에 추가된다.
2. **Given** 들어오는 테스트의 식별자가 기존 테스트와 겹칠 때, **When** 가져오기를 진행하면,
   **Then** 들어오는 테스트에 **새 식별자가 부여되고** 기존 테스트는 그대로 남으며, 어느 것이
   번호를 바꿨는지 결과에 표시된다.
3. **Given** 파일 안에 그룹 구성이 있을 때, **When** 기존 프로젝트로 가져오면, **Then** 같은 이름의
   그룹이 있으면 그 그룹으로 들어가고 없으면 그룹이 새로 만들어진다.
4. **Given** 가져오기 도중 오류가 났을 때, **When** 처리가 중단되면, **Then** 일부만 들어간 상태로
   남지 않는다 — 전부 들어가거나 하나도 들어가지 않는다.

---

### Edge Cases

- **파일에 테스트가 매우 많을 때** — 내보내기·가져오기가 화면을 멈추지 않고 진행 상황이 보여야 한다.
- **가져오는 사람의 도구가 더 오래된 버전일 때** — 읽을 수 없는 형식이면 거부한다. 모르는 필드를
  버리고 억지로 복원하면 실행되지 않는 테스트가 조용히 만들어진다.
- **파일 안 테스트가 이 도구가 모르는 스텝 종류를 쓸 때** — 그 테스트를 어떻게 처리했는지 결과에
  명시한다. 조용히 빠뜨리지 않는다.
- **민감 변수를 참조하는 스텝이 있는데 변수 선언이 파일에 없을 때** — 가져오기가 그 사실을 알리고,
  필요한 변수 목록에 포함시킨다.
- **가져오기 대상 위치에 쓸 수 없을 때(권한·디스크 부족)** — 부분 생성물을 남기지 않고 원인을 알린다.
- **같은 파일을 두 번 가져올 때** — 두 번째임을 알리고, 그대로 또 만들지 사용자가 정한다.
- **내보낸 사람과 받는 사람의 대상 환경이 다를 때** — 시작 URL이 받는 쪽에서 열리지 않을 수 있다.
  가져오기 결과에 시작 URL을 보여 주고 바꿀 수 있는 경로를 안내한다.
- **파일 이름이나 프로젝트 이름에 파일 시스템이 허용하지 않는 문자가 있을 때** — 거부하지 말고
  안전한 이름으로 바꾸되 무엇을 바꿨는지 알린다.

## Requirements *(mandatory)*

### Functional Requirements

#### 내보내기

- **FR-001**: 시스템은 열린 프로젝트 전체를 전달 가능한 **파일 하나**로 내보낼 수 있어야 한다.
- **FR-002**: 시스템은 테스트 목록에서 사용자가 고른 테스트만 내보낼 수 있어야 한다.
- **FR-003**: 내보내기 파일은 프로젝트 설정(이름, 시작 URL, 브라우저, 테스트 ID 속성, 최대 탭 수),
  그룹 구성, 각 테스트의 전체 정의(스텝, 로케이터 후보 전부, 검증 스텝, 변수 선언)를 담아야 한다.
- **FR-004**: 내보내기 파일은 **민감 값을 어떤 형태로도 담지 않아야 한다** — 평문도, 암호문도,
  암호구로 감싼 형태도 담지 않는다. 민감 변수는 **이름과 민감 표시, 쓰이는 위치만** 전달된다.
  값은 받는 사람이 가져오기 시점에 직접 입력한다 (FR-040~FR-042). 민감 값을 파일에 담는 선택지는
  제공하지 않는다 — 선택지로 두면 실수로 담아 보내는 경로가 열린다.
- **FR-005**: 내보내기 파일은 실행 산출물(스크린샷, 콘솔·네트워크 기록, 실행 결과)을 담지 않아야 한다.
- **FR-006**: 시스템은 파일을 만들기 전에 **무엇이 나가는지 요약**을 보여야 한다 — 테스트 개수,
  포함되는 평문 입력값과 그 위치, 시작 URL, 필요한 민감 변수 이름. 사용자는 여기서 취소할 수 있다.
- **FR-007**: 내보내기 파일은 형식 버전과 만든 도구 버전을 담아야 한다. 받는 쪽이 읽을 수 있는지
  판단할 근거가 파일 안에 있어야 한다.
- **FR-008**: 내보내기는 원본 프로젝트를 **읽기만** 해야 한다. 내보내기 때문에 프로젝트 파일이
  바뀌어서는 안 된다.
- **FR-009**: 시스템은 내보낼 대상이 하나도 없을 때 파일을 만들지 않고 그 사실을 알려야 한다.
- **FR-010**: 내보내기 산출물은 **사용자가 내려받는 파일 1개**다. 전달 수단은 사용자에게 맡긴다 —
  시스템은 어떤 외부 서비스로도 전송하지 않는다. 화면에서 복사해 붙여넣는 텍스트 형태는 제공하지
  않는다.

#### 가져오기

- **FR-020**: 시스템은 내보내기 파일을 골라 **새 프로젝트로** 가져올 수 있어야 한다.
- **FR-021**: 시스템은 내보내기 파일을 **현재 열린 프로젝트로** 가져올 수 있어야 한다.
- **FR-022**: 시스템은 가져오기를 실행하기 전에 요약을 보여야 한다 — 프로젝트 이름, 테스트 개수와
  이름, 그룹, 필요한 민감 변수, 시작 URL, 예상되는 식별자 충돌. 사용자는 여기서 취소할 수 있다.
- **FR-023**: 시스템은 가져오기 전에 파일을 검증해야 한다 — 형식 버전 호환, 구조 유효성, 스텝 정의
  유효성. 검증에 실패하면 **아무것도 만들지 않고** 무엇이 왜 실패했는지 알려야 한다.
- **FR-024**: 가져오기는 전부 성공하거나 전부 취소되어야 한다. 중간에 실패해도 절반만 들어간 상태를
  남겨서는 안 된다.
- **FR-025**: 들어오는 테스트의 식별자가 기존 테스트와 겹치면 시스템은 **들어오는 쪽에 새 식별자를
  부여**해야 한다. 기존 테스트를 덮어쓰지 않는다. 바뀐 식별자는 결과에 표시한다.
- **FR-026**: 새 프로젝트로 가져올 때 같은 이름의 프로젝트가 이미 있으면 구분되는 이름으로 만들고
  그 사실을 알려야 한다. 기존 프로젝트를 덮어쓰지 않는다.
- **FR-027**: 그룹은 이름으로 대응시킨다. 같은 이름의 그룹이 있으면 그 그룹에 넣고, 없으면 만든다.
- **FR-028**: 가져온 테스트에는 **가져온 것임을 나타내는 표시**(출처 파일, 가져온 시각, 원본 식별자)가
  남아야 한다. 이 표시는 테스트가 실행되는 방식에 영향을 주지 않는다.
- **FR-029**: 가져오기가 끝나면 시스템은 결과 요약을 보여야 한다 — 만들어진 테스트, 바뀐 식별자,
  채워야 할 민감 변수, 확인이 필요한 항목(시작 URL 등).
- **FR-030**: 시스템은 이 도구가 만들지 않은 파일, 손상된 파일, 읽을 수 없는 형식 버전을 거부해야
  하며 부분 복원을 시도해서는 안 된다.

#### 민감 값 인계

- **FR-040**: 가져오기 요약과 결과는 **채워야 할 민감 변수 목록**을 제시해야 한다. 각 변수는 이름과
  함께 **어느 테스트의 어느 스텝에서 쓰이는지**를 보여야 한다. 이름만으로는 무엇을 넣을지 모른다.
- **FR-041**: 사용자는 가져오기 직후 그 화면에서 민감 값을 입력할 수 있어야 한다. 나중에 채우는
  것도 가능해야 한다 — 값을 채우지 않아도 가져오기 자체는 완료된다.
- **FR-042**: 입력된 민감 값은 **그 설치의 키로 봉인되어** 저장되어야 한다. 프로젝트 정의 파일에는
  값도 암호문도 들어가지 않는다.
- **FR-043**: 입력된 민감 값은 화면, 로그, 오류 메시지, 스크린샷 메타데이터, 이후의 내보내기 어디에도
  평문으로 나타나서는 안 된다.
- **FR-044**: 값이 비어 있는 민감 변수를 참조하는 테스트는 **실행 전에** 막혀야 하며, 어느 변수가
  비었는지 알려야 한다. 빈 값으로 실행해 알 수 없는 실패를 내서는 안 된다.
- **FR-045**: 이 설치에 키가 없으면 시스템은 그 사실과 키를 만드는 경로를 안내해야 한다. 가져오기
  자체는 키 없이도 완료될 수 있어야 한다 — 막히는 것은 값 입력 시점이다.
- **FR-046**: 같은 이름의 민감 변수에 이미 값이 있으면 시스템은 조용히 덮어쓰지 않고 사용자에게
  기존 값을 유지할지 새로 입력할지 물어야 한다.

### Key Entities

- **공유 묶음(Share Bundle)**: 전달 가능한 파일 하나. 형식 버전, 만든 도구 버전, 만든 시각,
  프로젝트 설정, 그룹 구성, 테스트 정의 목록, 필요한 민감 변수 이름 목록을 담는다. 민감 값은 담지
  않는다.
- **묶음 안의 테스트 정의**: 제품이 저장하는 테스트와 같은 구조 — 스텝, 로케이터 후보 전부, 검증
  스텝, 변수 선언. 값이 아닌 구조가 전달의 대상이다.
- **필요 민감 변수(Required Secret)**: 이름, 민감 표시, 쓰이는 위치(테스트 식별자 + 스텝 식별자).
  받는 사람이 무엇을 채워야 하는지 알기 위한 최소 정보다.
- **가져오기 계획(Import Plan)**: 실행 전에 사용자에게 보이는 예고 — 만들어질 프로젝트/테스트,
  예상 식별자 충돌과 재부여 결과, 필요 민감 변수, 확인 필요 항목. 사용자가 승인해야 실행된다.
- **가져오기 결과(Import Report)**: 실행 후 결과 — 만들어진 것, 바뀐 식별자, 남은 할 일.
- **가져오기 출처 표시(Import Provenance)**: 테스트에 남는 메타데이터. 출처 파일, 가져온 시각, 원본
  식별자. 실행 방식에는 영향을 주지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 테스트를 만든 사람이 내보내기를 시작해 전달 가능한 파일을 얻기까지 **1분 이내**,
  화면 조작 **3회 이하**로 끝난다.
- **SC-002**: 파일을 받은 사람이 가져오기를 시작해 테스트가 목록에 나타나기까지 **2분 이내**에
  끝난다. 민감 값 입력을 포함해도 **5분 이내**에 첫 실행을 시작할 수 있다.
- **SC-003**: 내보내고 다시 가져온 테스트를 실행한 결과가 원본 테스트를 같은 대상에 대해 실행한
  결과와 **100% 일치**한다 — 스텝 수, 스텝 순서, 각 스텝의 성공/실패가 같다.
- **SC-004**: 민감 값이 내보내기 파일에 담기는 경우가 **0건**이다. 내보내기 파일을 평문으로 검사해
  민감 변수의 값이나 암호문이 발견되면 실패로 간주한다.
- **SC-005**: 식별자가 겹치는 상황에서 기존 테스트가 사라지거나 덮어써지는 경우가 **0건**이다.
- **SC-006**: 손상·비호환 파일을 가져올 때 절반만 들어간 상태가 만들어지는 경우가 **0건**이다.
- **SC-007**: 민감 값이 비어 있는 테스트를 실행했을 때, 사용자가 원인을 화면만 보고 파악할 수 있다 —
  "무엇을 해야 하는지 알겠다"고 답한 사용자가 **90% 이상**이다.
- **SC-008**: 테스트 50개 규모의 프로젝트를 내보내고 가져오는 동안 화면이 응답하지 않는 구간이
  **없다**.

## Assumptions

- **"파일을 공유할 수 없다"는 제품의 한계를 가리킨다.** 이 도구는 단독 로컬 도구이고 각자의 자산이
  각자의 컴퓨터에만 있어, 프로젝트 디렉터리를 그대로 건네도 상대가 쓸 수 없다는 뜻으로 읽었다.
  파일 전달 자체는 가능한 환경으로 보고 산출물을 파일 1개로 정했다 (2026-09-23 확인).
- **"비밀키"는 비밀번호 같은 민감 값을 가리킨다.** 제품이 쓰는 암복호화 키쌍 자체를 넘기는 것이
  아니라고 읽었다. 키쌍을 넘기는 것은 그 사람의 다른 모든 프로젝트의 값까지 열어 주므로 어떤
  경우에도 하지 않는다.
- 내보내기·가져오기의 정본은 지금과 같은 테스트 정의 구조다. 공유 묶음은 그 구조를 옮기는 그릇이며
  새로운 저장 형식이 아니다.
- 받는 사람의 도구 버전이 보내는 사람과 같거나 더 새롭다고 가정한다. 더 오래된 경우는 거부한다.
- 민감 값 저장·봉인·잠금 해제는 이미 제품에 있는 구조를 그대로 쓴다. 이 기능은 새 암호 방식을
  도입하지 않는다.
- 전달 과정(메신저·메일·저장소)의 보안은 이 기능의 책임 밖이다. 그래서 민감 값을 담지 않는 것이
  기본값이다.
- 그룹·초안(draft)·테스트 실행 설정 등 기존 프로젝트 구성요소는 현재 구조를 그대로 따른다.
