## R1. 접두어 규칙의 새 형태

**결정**: `^[A-Z][A-Z0-9]*(?:-[A-Z][A-Z0-9]*)*$`, 길이 상한 12자, `TC` 예약 유지.

말로 하면 **「하이픈으로 이은 마디들, 각 마디는 영문 대문자로 시작」**이다.

**근거**

1. **옛 규칙의 상위집합이다.** `^[A-Z][A-Z0-9]{0,7}$` 에 맞는 값은 모두 새 규칙에도 맞는다
   (하이픈 0개인 한 마디). 그래서 저장된 그룹·식별자가 그대로 유효하다 (FR-011).
2. **마디가 영문으로 시작하므로 접두어 안에 숫자만의 마디가 올 수 없다.** 이것이
   FR-004(마지막 마디가 3자리 숫자일 수 없다)를 자동으로 만족시키고, 더 중요하게는
   **식별자의 접두어·번호 경계를 모호하지 않게** 만든다. `A-001-001` 같은 값이 애초에
   만들어질 수 없다.
3. **선읽기(lookahead)를 쓰지 않는다.** Pydantic v2 의 `pattern` 은 기본적으로 Rust
   `regex` 크레이트로 컴파일되며 선읽기·후읽기를 지원하지 않는다. 길이 상한을 정규식
   안에 `(?=.{1,12}$)` 로 넣으면 API 경계 검증이 깨진다. 그래서 **길이는 정규식 밖의
   `max_length` 로** 표현한다 — JSON Schema 에도 `maxLength` 로 실려 화면까지 전달된다.

**실측** (설계 시점에 돌려 확인함)

| 입력 | 판정 |
|---|---|
| `IT-PM` · `IT-DM` · `A-B-C` | 통과 |
| `USER` · `TC` · `DATA9` · `AB12CD34` (옛 규칙 표본) | 통과 — 상위집합 확인 |
| `IT-` · `-PM` · `IT--PM` · `it-pm` | 거부 |
| `IT-001` · `A-001-B` (숫자만의 마디) | 거부 |

**검토한 대안**

- `^[A-Z][A-Z0-9-]{0,11}$` — 가장 짧지만 `IT-`·`IT--PM` 을 통과시킨다. 규칙이 아니라 구멍이다.
- 후읽기로 3자리 숫자 마디만 금지 — Rust regex 에서 컴파일되지 않는다. 또한 `IT-01` 같은
  값을 허용하게 되어 경계 모호성이 남는다.
- 길이 상한 8자 유지 — `IT-PM`(5자)에는 충분하지만 여유가 없다. 파일 이름에 들어가는
  제약을 고려해 12자로 넓힌다. `IT-PM-001-<이름 slug>.yaml` 에서 식별자 몫은 16자다.

## R2. 규칙의 단일 출처 — 화면과 서버가 같은 판정을 하는 법

**결정**: 도메인의 Pydantic 모델이 정본이고, JSON Schema 를 거쳐 **생성된 상수**로 화면에
내린다. `frontend/scripts/gen-types.mjs` 가 타입과 함께 제약 상수를 뽑는다.

**문제**: 지금 `frontend/src/components/TestGroupBar.tsx` 가 `/^[A-Z][A-Z0-9]{0,7}$/` 를
손으로 적어 두고 있다. 헌법의 Cross-language schema duty 는 **두 벌의 손 유지를 금지**한다.
지금까지 드러나지 않은 이유는 두 벌이 우연히 같았기 때문이고, 이번에 한쪽만 고치면 바로
갈린다.

**경로**: `backend/src/itb/domain/test_case.py` (Pydantic) → `uv run python -m itb.schema.export`
→ `backend/schema/project.schema.json` (`$defs.TestGroup.properties.prefix.pattern` ·
`maxLength`) → `npm run gen:types` → 프론트.

**보완**: 현재 `gen-types.mjs` 는 **타입만** 만든다. TypeScript 타입에는 정규식이 실리지
않으므로 제약을 쓰려면 값이 필요하다. 그래서 생성 대상에 제약 상수 모듈을 하나 더한다.
이름과 형태는 data-model 이 정한다. 드리프트는 이미 있는
`uv run python -m itb.schema.export --check` 와 CI 의 schema-drift 잡이 잡는다.

**검토한 대안**

- 규칙을 알려 주는 API 를 새로 만든다 — 화면이 규칙을 물어보려고 서버를 한 번 더 부른다.
  값이 배포 시점에 고정된 상수인데 실행 시점에 가져올 이유가 없다.
- 프론트 정규식을 남기고 두 벌이 같은지 보는 검증을 붙인다 — 갈림을 **막지** 못하고
  갈린 뒤에 알려 줄 뿐이다. 헌법은 「한쪽에서 생성」을 요구한다.

## R3. 식별자에서 접두어를 읽는 자리 — 전수와 중앙화

**결정**: `split("-", 1)` 을 자리마다 `rsplit` 으로 바꾸지 않는다. **도메인에 읽기 함수를
두고 전부 그것을 부르게 한다.**

**전수 조사 결과 — 17곳**

| 파일 | 줄 | 지금 하는 일 |
|---|---|---|
| `sharing/planner.py` | 244 · 249 | 접두어 · 번호 |
| `sharing/builder.py` | 45 | 접두어 |
| `storage/test_moves.py` | 162 | 번호 |
| `storage/repository.py` | 330 | 파일명 매치의 `id` 에서 접두어 |
| `portability/importer.py` | 211 · 231 · 372 · 455 · 498 | 번호 · 접두어 |
| `portability/exporter.py` | 85 | 접두어 |
| `api/routes/sharing.py` | 499 | **파일 이름**에서 접두어 |
| `api/routes/groups.py` | 81 | 접두어 |
| `api/routes/groups.py` | 177 | **파일 이름에서 식별자 복원** — `split("-", 2)[0] + "-" + [1]` |
| `api/routes/tests.py` | 519 · 531 | 접두어 · 번호 |
| `domain/draft.py` | 135 | 접두어 |

`groups.py:177` 이 가장 위험하다. 파일 이름 `IT-PM-001-로그인.yaml` 에서 식별자를 `IT-PM`
으로 복원한다 — 그룹 해체가 존재하지 않는 테스트를 옮기려 든다.

**근거**: 같은 규칙을 17곳에 손으로 적는 것이 이 결함의 원인이었다. `rsplit` 으로 바꿔
심어도 18번째 자리가 생기면 같은 일이 반복된다. 헌법의 단일 출처 원칙이 스키마에만
적용될 이유가 없다.

**검토한 대안**: 자리마다 `rsplit` — 변경량은 같고 재발을 막지 못한다.

## R4. 파일 이름에서 식별자 끊기

**결정**: 접두어 부분을 **최소 일치(non-greedy)** 로 읽는다.

```
^(?P<id>[A-Z][A-Z0-9]*(?:-[A-Z][A-Z0-9]*)*?-(?P<number>\d{3}))-.*\.yaml$
```

**왜 최소 일치인가**: 파일 이름은 `<식별자>-<이름 slug>.yaml` 이고 slug 에도 하이픈과
숫자가 들어간다 (`_SLUG_STRIP` 이 영문·숫자·한글만 남긴다). 최대 일치로 읽으면
`IT-PM-001-ABC-002.yaml` 의 식별자를 `IT-PM-001-ABC-002` 로 읽는다.

**왜 최소 일치가 안전한가**: 접두어의 모든 마디가 영문으로 시작하므로(R1) **접두어 안에
3자리 숫자 마디가 존재할 수 없다.** 따라서 왼쪽에서 처음 만나는 「하이픈 + 3자리 숫자」
마디가 언제나 진짜 번호다.

**실측**

| 파일 이름 | 읽은 식별자 |
|---|---|
| `IT-PM-001-단계-002-확인.yaml` | `IT-PM-001` |
| `IT-PM-001-ABC-002.yaml` | `IT-PM-001` |
| `IT-PM-DM-003-x.yaml` | `IT-PM-DM-003` |
| `USER-001-로그인.yaml` (옛 자산) | `USER-001` — 옛 정규식과 같은 결과 |
| `TC-999-a.yaml` (옛 자산) | `TC-999` |

## R5. 끌어 놓기 구현 방식

**결정**: 브라우저 기본 끌어 놓기(HTML5 drag and drop)를 쓴다. **라이브러리를 더하지 않는다.**

**근거**

1. 지금 프론트 런타임 의존성은 `@base-ui/react` · `class-variance-authority` · `react` ·
   `react-dom` · `react-router` 넷뿐이다. 헌법의 단순성 원칙은 「원칙이나 요구가 강제하지
   않는 복잡도는 정당화하거나 없앤다」다. 이 기능이 필요로 하는 것은 **행을 끌어 표적에
   놓기** 하나이고, 순서 바꾸기·중첩·가상 목록 같은 것이 없다 (Assumptions: 순서 바꾸기는
   범위 밖).
2. 끌기 표적은 **끌기 중에만** 나타나야 한다 (FR-014). 이것은 `dragstart`/`dragend` 상태
   하나로 끝난다.
3. 검증 환경이 jsdom 이다. `@testing-library/user-event` 는 끌어 놓기를 지원하지 않으므로
   어느 방식이든 `fireEvent` 로 `dragStart`·`dragOver`·`drop` 을 직접 쏘게 된다. 라이브러리를
   넣으면 검증이 오히려 라이브러리 내부에 의존한다.

**끌기 중 스크롤**: 표적 띠를 목록 위에 고정(sticky)으로 두어 목록을 스크롤해도 표적이
화면에 남게 한다 (FR-022). 끌면서 목록 자동 스크롤을 구현하지 않는다 — 표적이 고정이면
필요하지 않다.

**검토한 대안**: `dnd-kit` · `react-dnd` — 포인터 센서·키보드 센서·접근성 발표를 함께
준다. 그러나 키보드 경로는 이미 선택칸으로 존재하고(FR-027·FR-028) 이번에 그 구멍도
막는다. 런타임 의존성 하나를 이 기능 하나 때문에 더하는 것은 정당화되지 않는다.

## R6. 「새 그룹으로」 — 만들기와 옮기기를 잇는 법

**결정**: 화면이 `POST /api/groups` 다음 `POST /api/tests/move` 를 순서대로 부른다.
**백엔드에 합친 엔드포인트를 만들지 않는다.**

**근거**

- `tests.move` 는 이미 전부 되거나 전부 안 되거나를 지킨다 (`storage/test_moves.py`).
  그러므로 「셋 중 둘만 옮겨진」 상태는 생기지 않는다.
- 갈라질 수 있는 상태는 **「그룹은 만들어졌는데 옮기지 못했다」 하나뿐**이고, 그 결과물은
  빈 그룹이다. 빈 그룹은 해롭지 않고 사용자가 지울 수 있다. FR-026 이 요구하는 것도
  원자성이 아니라 **그 사실을 알리는 것**이다.
- 합친 엔드포인트는 새 계약·새 오류 코드·새 검증 경로를 만든다. 얻는 것은 빈 그룹이 남지
  않는 것뿐이다.

**알림 문구**: 「그룹 「프로젝트 관리」는 만들어졌지만 테스트를 옮기지 못했습니다: <사유>」
— 무엇이 되었고 무엇이 안 되었는지를 한 문장에 담는다.

## R7. 하위 호환을 무엇으로 증명하는가

**결정**: 마이그레이션 없음. 세 가지 검증으로 고정한다.

1. **상위집합 검증** — 옛 접두어 규칙을 만족하는 값은 새 규칙도 만족한다. 규칙 두 개를
   나란히 두고 표본으로 확인한다.
2. **읽기 동치 검증** — 하이픈이 하나뿐인 옛 식별자(`USER-001`)에서 새 읽기 함수가 옛
   `split("-", 1)` 과 같은 결과를 낸다.
3. **옛 파일 이름 검증** — 옛 규칙으로 만들어진 파일 이름에서 새 정규식이 같은 식별자를
   읽는다.

이 셋이 통과하면 저장된 자산에 손댈 이유가 없다. 별도의 변환 단계나 버전 표시를 도입하지
않는다.

## R8. 검증 명령

이 저장소의 전량 검증은 아래다. `uv run pytest` 와 `npm test` 는 쓰지 않는다 —
전자는 시간을 재는 계층을 병렬에 섞어 거짓 실패를 내고, 후자는 감시 모드라 끝나지 않는다.

```bash
cd backend && bash scripts/test-backend.sh
cd backend && uv run ruff check src/ tests/
cd backend && uv run lint-imports
cd backend && uv run python -m itb.schema.export --check
cd frontend && npx tsc --noEmit
cd frontend && npx vitest run
```
