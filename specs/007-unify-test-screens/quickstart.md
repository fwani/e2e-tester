## 1. 기계로 셀 수 있는 것 — 자동 검사

### 1-1. 구현 개수 (SC-001)

```bash
cd frontend
npm test -- ImplementationCount
```

**기대**: Step 목록을 그리는 구현 1개, Step 상세를 그리는 구현 1개.

검사 방법은 파일 존재와 참조 개수다 — 옛 구현이 남아 있으면 실패한다.

```bash
# 이행이 끝나면 아래는 전부 0 이어야 한다
grep -rc "from \"./Runner\"\|from \"./RunnerPaused\"\|from \"./Takeover\"\|from \"./AiRecord\"" src | grep -v ":0"
ls src/pages/Runner.tsx src/pages/RunnerPaused.tsx src/pages/Takeover.tsx src/pages/AiRecord.tsx 2>&1
```

### 1-2. Step 행의 칸 자리 (SC-002)

```bash
npm test -- StepRowLayout
```

**기대**: 일곱 국면 각각으로 같은 Step 을 렌더했을 때 칸의 **순서와 개수**가 같다.
값이 없는 칸은 비어 있고 다른 칸이 그 자리로 당겨지지 않는다 (FR-222·FR-223).

### 1-3. 껍데기 (SC-003)

```bash
npm test -- WorkbenchShell
```

**기대**: 일곱 국면 전부가 60px 헤더 · 74px 국면 띠 · 460px Step 패널 · 최소 기준 폭
1440px 을 쓴다. 넓은 창에서 늘어나는 것은 좌측 대상 앱 영역뿐이다 (FR-218a).

### 1-4. 조작 손실 0건 (SC-007 · FR-247)

```bash
npm test -- CapabilityCoverage
```

**기대**:
- `contracts/ui-contract.md` §2 의 33개 조작 전부가 권한표에 있다
- 권한표의 모든 `–` 셀이 §4-2 의 근거(N1·N2·N3) 중 하나를 갖는다
- ○ 셀 전부가 이유를 갖고, 해소 방법이 있으면 그 `ActionId` 가 33개 목록 안에 있다

세 번째가 006 E-03("화면에 없는 조작을 지시함")의 재발을 막는 검사다.

### 1-5. 회귀 (기존 테스트)

```bash
npm test          # 프런트엔드 전량
cd ../backend && bash scripts/test-backend.sh   # 백엔드 전량
```

**기대**: 기존 테스트는 **고쳐서 통과**시킨다. 삭제·건너뛰기로 통과시키지 않는다
(헌법 품질 게이트 4).

007 이 화면 구조를 바꾸므로 `Runner*.test.tsx` · `RunResult.test.tsx` ·
`TestDefinition.test.tsx` · `AiRecord.test.tsx` 는 **선택자와 구조 기대를 갱신해야 한다.**
검증하는 **행동**은 바뀌지 않는다 — 바뀌면 그것은 회귀다.

## 2. 사람이 걸어야 하는 것 — 손 검증

각 항목은 `docs/ux/` 의 걷기 기록 형식으로 남긴다.

### W-1. 국면을 넘어도 문법이 그대로다 (US1 · SC-002·SC-003)

1. 저장된 테스트를 **편집**으로 연다 → Step 목록의 칸 자리를 기록한다
2. 「처음부터 실행」 → **실행 중** 국면 → 같은 칸 자리인지 대조
3. 실행이 끝나 **결과** 국면 → 같은 칸 자리인지 대조
4. 「Step nn 고치기」 → **편집** 국면 → 같은 칸 자리인지 대조

**통과 조건**: 네 국면에서 번호 · 이름 · 동작 종류 · 대상 요약 · 값 · 소요 시간 ·
결말 표식의 **자리가 같다.** 헤더 구성과 기준 폭도 같다.

**지금 실패하는 것**(대조용): 결말 표식이 실행에서는 오른쪽 끝, 결과에서는 왼쪽 첫 칸이다
(S-02). 편집은 껍데기 자체가 다르다 (S-06).

### W-2. 쓸 수 없는 조작이 남아 있다 (US2 · SC-004)

1. 테스트를 **실행**한다 → 실행 중에 값 수정 · 삭제 · 순서 변경을 찾는다
   **통과**: 같은 자리에 비활성으로 있고 이유 + 「실행 중인 세션 보기」가 붙어 있다
2. **결과** 국면에서 Step 편집을 찾는다
   **통과**: 비활성 + 「편집으로 이동」
3. **편집** 국면(세션 없음)에서 「요소 다시 집기」를 찾는다
   **통과**: 비활성 + 「브라우저 열어 Step nn 에서 멈추기」
4. **편집** 국면에서 아무것도 저장하지 않은 채 실행 조작을 찾는다
   **통과**: 처음부터 보인다. 저장에 성공해야 나타나는 조작이 아니다 (S-07)

### W-3. 지목한 Step 을 잃지 않는다 (US3 · SC-005)

1. **결과**에서 실패한 Step 06 을 지목한다
2. 「Step 06 고치기」 → **편집** → Step 06 이 지목된 채인지 확인
3. 「브라우저 열어 Step 06 에서 멈추기」 → **일시정지** → Step 06 이 지목된 채인지 확인
4. 「중지」 → **결과** → **Step 06 이 지목된 채인지 확인**

**통과 조건**: 왕복 전 구간에서 Step 06 을 다시 찾는 조작이 **0회**.
**지금 실패하는 것**: 4번 구간에서 끊긴다 (S-10).

### W-4. 대상 앱 영역이 한 자리다 (US4)

1. **실행 중** → 좌측에 미러
2. 실행이 끝나 **결과** → 좌측 **같은 자리**에 산출물 (스크린샷 · 콘솔 · 네트워크)
3. **편집**(세션 없음) → 좌측 같은 자리에 「브라우저 열어 Step nn 에서 멈추기」
4. 콘솔 기록이 없는 실행의 결과 → **왜 비었는지**가 밝혀진다 (수집 안 함 / 비었음 / 유실)

### W-5. 새로 고침·뒤로 가기 (SC-006)

**결과** 국면과 **편집** 국면에서 각각 Step 을 지목하고 새로 고침 → 같은 국면 · 같은 지목
Step. 10회 시도 10회 성공.

세션 국면은 새로 고침하면 목록으로 간다 — 005 FR-168 의 규칙이며 007 이 바꾸지 않는다.
**단 세션 배너로 돌아왔을 때 지목 Step 이 살아 있어야 한다.**

### W-6. AI 실패가 보인다 (FR-253 · 001 R2 회귀)

AI 작성을 실패하게 만든 뒤(대상 앱을 끄거나 도달 불가한 지시문), 세션 상태가 `paused` 로
바뀐 뒤에도 **실패 사유가 계속 보이는지** 확인한다. 접힘 · 탭 · 겹침 뒤에 있으면 실패다.

### W-7. 확정 디자인 대조 (FR-254 · DC-012)

`specs/007-unify-test-screens/design-conformance/Workbench.md` 의 `관측값` · `판정` 칸을
**사람이** 채운다. 구현자가 자기 구현을 판정하면 대조가 아니다 (002 §4).

**통과 조건**: `불일치` · `미판정` 0건. 단 artboard 가 승인된 뒤에만 이 판정이 성립한다
(FR-254c).
