# Contract: 정본 토큰 ↔ Tailwind 테마

**Feature**: 015 | **Status**: 계약 (구현이 지켜야 할 것)

## C-1 — 값은 정본 한 곳에만 있다

`frontend/src/theme/tokens.css` 의 `:root` 가 유일한 값의 출처다.
Tailwind 테마 파일은 **이름을 다시 붙이기만** 한다.

```css
/* frontend/src/theme/tailwind.css */
@theme inline {
  --color-pass: var(--pass);   /* ✅ 참조 */
  --color-pass: #1A7F45;       /* ❌ 값. C-1 위반 */
}
```

## C-2 — 정본 파일을 수정하지 않는다

`tokens.css` 는 `scripts/extract_canon.py` 의 출력이다. Tailwind 지시문을 그 안에 넣으면
다음 추출에서 사라진다. 모든 Tailwind 관련 선언은 `tailwind.css` 에 둔다.

## C-3 — 이름 규약

| 정본 축 | Tailwind 이름공간 | 예 |
|---|---|---|
| 색 | `--color-*` | `--pass` → `--color-pass` → `bg-pass` `text-pass` |
| 간격 | `--spacing-*` | 정본 간격 토큰 → `p-*` `gap-*` |
| 타이포 | `--font-*` `--text-*` | `--font-sans` → `--font-sans` (그대로) |
| 모서리 | `--radius-*` | `--radius` → `--radius-DEFAULT` |
| 그림자 | `--shadow-*` | `--e-1` `--e-2` → `--shadow-e1` `--shadow-e2` |

**정본에 없는 이름을 만들지 않는다.** 대응표에 없는 Tailwind 이름이 필요해지면,
그것은 정본에 없는 값을 쓰려 한다는 신호다 — 멈추고 기록한다 (FR-003).

## C-4 — 임의값 문법의 제한

`bg-[#1A7F45]` 같은 임의값 표기는 **색과 시각 속성에 금지**한다. 값 리터럴을 화면 코드로
되돌리는 것이고, 008 이 고친 문제의 재발이다.

**배치 치수의 임의값은 허용한다** — `basis-[460px]` 처럼. 다만 그 숫자는 `lib/layout.ts`
또는 상수 모듈에서 와야 하며, 화면 파일이 지어낼 수 없다 (007 계약에서 그대로 이어짐).

## C-6 — preflight 를 쓰지 않는다

`tokens.css` 가 이미 자기 리셋을 갖고 있다 — `*{box-sizing:border-box}`, `body{margin:0;…}`,
그리고 `button`·`input,select,textarea` 의 요소 기본 스타일까지. 그 값들은 확정 디자인에서
추출된 정본이다.

preflight 를 얹으면 **정본이 아닌 곳에서 온 리셋 값이 화면에 영향을 준다.** 겹치는 선언은
나중에 오는 정본이 이기지만, **preflight 만 지정하고 정본이 지정하지 않는 속성은 그대로
남는다** — `h1~h6` 상속, `ul/ol` 마커 제거, `img{display:block}` 같은 것들이다.

실측: preflight 포함 시 CSS 15.04 → 21.30 kB. 그 6.26 kB 가 전부 「우리가 정하지 않은 값」이다.
제외하면 17.52 kB.

리셋이 필요해지면 정본에 넣는다.

## C-8 — 정본은 `layer(base)` 로 들인다

```css
@import "./tokens.css" layer(base);   /* ✅ */
@import "./tokens.css";               /* ❌ 유틸리티가 전부 진다 */
```

**레이어에 속하지 않은 규칙은 CSS 레이어 규칙상 어떤 레이어보다도 이긴다.** 정본에는
`button{…}`·`input,select,textarea{…}` 같은 요소 선택자 규칙이 있으므로, 레이어 밖에
두면 `@layer utilities` 의 `bg-ink`·`h-control-sm` 이 그것들에 **진다.**

그러면 부품에 유틸리티를 붙여도 적용되지 않는다. `<button className="bg-ink">` 가
여전히 `var(--panel)` 배경으로 그려진다. **015 가 하려는 일이 통째로 막힌다.**

정본 파일은 한 글자도 고치지 않는다 — 들이는 방식만 바꾼 것이다 (C-2 유지).

**대가**: 요소 규칙의 상태 스타일(`button:hover` 등)도 base 로 내려가 유틸리티에 진다.
그것을 부품으로 옮기는 것이 [state-styles.md](state-styles.md) 의 목록이고, 아직 해체되지
않은 의미 클래스도 함께 내려가므로 LC-5(한 요소는 한 체계만)가 규칙이 아니라 **필수**가
된다. 가드 G-C 가 감시한다.

## C-7 — 이름 충돌

Tailwind 유틸리티와 이름이 같은 의미 클래스가 있으면 같은 이름이 두 가지를 뜻하게 된다.

**전환 착수 시점 실측: `.table` 1개.** (정본 `.table` = 표 스타일 / Tailwind `.table` =
`display:table`) CSS 레이어 규칙상 레이어 밖의 `tokens.css` 가 `@layer utilities` 를 이기므로
현재 화면은 영향받지 않지만, **전환 중 이 이름을 유틸리티로 쓰려 하면 어느 쪽이 적용되는지
헷갈린다.** 해당 클래스를 해체할 때 부품 이름을 다르게 준다.

가드 G-C 가 이 충돌도 센다.

## C-9 — 한 요소에 같은 속성을 두 번 선언하지 않는다

**`className` 의 순서는 승부를 정하지 않는다.** 같은 속성을 두 유틸리티가 선언하면
이기는 쪽은 **산출 CSS 에서 뒤에 오는 것**이고, 그 순서는 Tailwind 가 자기 규칙으로
정한다. 우리가 적은 순서와 무관하다.

### 이 조항이 생긴 이유

2026-09-11 사용자 신고: 「버튼과 글자가 모두 흰색이라 안 보인다」. `ui/Button` 이
BASE 에 `bg-panel text-ink` 를 두고 변종이 `bg-ink text-panel` 로 덮어쓰게 만들었는데,
덮이지 않았다.

```
.bg-ink   @7152   ← VARIANT.primary 가 나중에 적은 것인데 진다
.bg-panel @7188   ← BASE 가 이긴다
```

**강조 버튼이 흰 배경 위의 흰 글자가 됐다.** 같은 함정에서 `danger` 는 테두리도 글자도
빨갛지 않았고, `ui/Chip` 의 상태색(통과·실패·실행·AI)은 전부 회색으로 죽어 있었다.
실측 65곳 중 **43곳이 이미 뒤집혀 있었다.**

`toHaveClass("bg-ink")` 는 통과했다. 클래스는 실제로 붙어 있었기 때문이다. G-B 도
통과했다. `bg-ink` 는 실재하는 유틸리티이기 때문이다. **둘 다 사실이고 화면만 틀렸다** —
빠진 질문은 「이 요소에 배경이 몇 개 붙었는가」였다.

### 규율

**변종이 건드리는 속성은 BASE 가 아예 갖지 않는다.** 배경·테두리색·글자색·그림자·
글자굵기·hover 배경은 변종 표가, 높이·좌우 여백·글자 크기는 크기 표가 **각자 온전히**
갖는다. 표의 항목마다 같은 속성을 다 적어야 하므로 길어지지만, 한 요소에 같은 속성이
두 번 붙는 일이 없어진다.

**다투는 값을 `layout` prop 으로 넘기지 않는다.** `layout` 은 표 뒤에 이어 붙지만
승부는 산출 CSS 가 정한다 — 호출부가 `layout="px-[7px]"` 로 넘겼는데 부품의 `px-[9px]`
이 이겨 여백이 바뀌지 않는 일이 실제로 있었다. 크기를 다투면 **표에 항목을 만든다**
(`ui/Button` 의 `size="icon"`).

### 가드 G-E (`frontend/tests/ClassConflict.test.ts`)

리터럴뿐 아니라 부품이 **조립하는 조합 전부**를 본다 —
`[BASE, SIZE[size], VARIANT[variant]].filter(Boolean).join(" ")` 의 모든 경우다.
흰 버튼은 조립 결과에만 나타나므로 리터럴만 보는 검사는 영원히 못 본다.

판정은 **「나중에 적은 쪽이 지는가」**다. 그래야 `border border-dashed` 처럼 뒤엣것이
앞엣것을 다듬는 정상 조합을 잡지 않는다.

**한계를 적어 둔다.** (1) 역전이 아닌 중복(우연히 맞게 그려지는 것)은 통과한다 —
화면은 지금 옳지만 판이 올라가면 뒤집힐 수 있어, 실패 메시지에 참고로 함께 싣는다.
(2) 호출부가 넘기는 `layout` 은 보지 못한다 — 그래서 위의 「다투는 값은 표에」가 규율로
있다.

## C-10 — 앱은 정본의 **변수와 요소 규칙만** 들인다

전환이 끝나 화면 코드가 의미 클래스를 하나도 쓰지 않으면, 정본의 클래스 규칙 148개는
**아무도 읽지 않는 채 사용자에게 내려간다** — 실측 12.48 kB, 산출 CSS 의 3분의 1이었다.

지울 수는 없다. `scripts/extract_canon.py` 가 확정 디자인에서 추출한 기록이자 L1 대조의
기준이다 (C-2 는 그대로다). 그래서 **지우는 대신 번들에서 뺀다.**

```
scripts/split-canon.mjs    정본에서 `:root` 변수와 요소 규칙만 뽑는다
src/theme/tokens.app.css   그 산출물 (3.2 kB). 앱이 들이는 것
src/theme/tokens.css       그대로 (42 kB). L1 대조가 읽는다
```

`tailwind.css` 의 `@import` 대상만 바뀐다. **정본 파일은 한 글자도 고치지 않는다.**

### 판정 규칙

선택자에 `.` 가 있으면 의미 클래스 규칙으로 보고 뺀다. 요소·의사클래스·변수 선언은
남긴다. `button.danger` 처럼 섞인 것도 뺀다 — 그 모양은 부품의 변종이 갖는다.

### 왜 가드가 필요한가 (G-A6 · `tests/CanonSplit.test.ts`)

생성물을 저장소에 두면 **원본이 바뀌어도 조용히 옛 값을 쓴다.** 정본의 색 하나를 고치고
다시 뽑는 것을 잊으면 화면은 옛 색으로 그려지는데 **L1 대조는 정본을 읽으므로 통과한다** —
아무 검사도 실패하지 않는 회귀다. 가드가 다시 뽑아 글자 단위로 맞춰 본다.

### 파생 구획에 관한 주의

이 조항은 **「화면이 쓰지 않는 파생 구획의 정의는 지운다」(class-migration.md)의 전제를
바꾼다.** 그 조항은 정의가 사용자에게 내려간다는 전제 위에 있었는데, 이제 내려가지
않는다 — 지워도 번들은 1 바이트도 줄지 않는다. 조항을 고칠지는 계약 변경이므로
`contracts/class-migration.md` 의 최종 판정에 사용자 결정 항목으로 남겨 두었다.
