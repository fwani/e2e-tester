# Contract: 화면 깨짐 순회

**Feature**: 017 | **Status**: 계약 | **요구**: FR-018~FR-026 · SC-001~SC-004 · US4 시나리오 3

## 왜 이 계약이 있는가

015 의 L2 대조는 **전환 전과 같은가**를 잰다. 그것은 전환 전 화면이 이미 깨져 있으면 그
깨짐까지 「같다」로 통과시킨다. B-01(토스트가 국면 띠를 덮는다)이 바로 그 경우였다 —
015 가 정본 `.toast-layer` 의 `top` 을 옮기면서 국면 띠 몫을 빠뜨렸고, L2 는 **양쪽 다 빠진
상태를 기준선으로** 재기 전에 대조를 끝냈다.

**그리고 L2 는 자리를 재지 않는다** (2026-09-15 확인). 비교하는 56개 속성은 색·선·글꼴·상자 크기이고
`top`·`max-height` 가 없다. US1 이 알림 층의 `top` 을 64px → 112px 로 바꿨는데 L2 는 불일치 0 이었다 —
015 가 같은 이유로 B-01 을 보지 못했다.

그래서 017 은 축을 하나 더 둔다. **전환 전과 같은가(L2)** 와 별개로 **화면이 그 자체로
깨지지 않았는가(순회)** 를 잰다. 둘은 서로를 대신하지 않는다.

| | L2 대조 | 화면 깨짐 순회 |
|---|---|---|
| 질문 | 전후 계산 스타일이 같은가 | 조작이 덮이지 않고, 넘치거나 끊기지 않는가 |
| 기준 | 전환 전 코드 | 판정 규칙 (SW-6) |
| 잡는 것 | 조용한 시각 회귀 | 원래부터 있던 깨짐, 폭·데이터에 따라서만 나오는 깨짐 |
| 못 잡는 것 | 전환 전부터 깨진 곳 | 색 한 톤 차이 같은 미세 회귀 |

## SW-1 — 격리

순회는 임시 `XDG_DATA_HOME`·`XDG_CONFIG_HOME` 아래에서만 제품 서버를 띄운다. 사용자의 실제
프로젝트·키·비밀 값을 **읽지도 쓰지도 않는다.** 캡처와 보고서에 사용자 경로가 나오지 않는다.

데이터 루트 이름은 **고정**한다 (`.sweep/data`). 임시 디렉터리 이름이 화면에 경로 글자로
나오므로 매번 다르면 글자 폭이 달라져 없는 넘침이 생긴다 — L2 가 같은 이유로 고정했다.

## SW-2 — 시드는 실제 동작으로 만든다

| 무엇 | 왜 |
|---|---|
| 프로젝트 1 · 그룹 2 (그중 하나는 긴 이름) | 그룹 줄·필터 칩의 잘림 |
| 테스트 6 — 17 Step 1 · 200자에 가까운 이름 1 · 미실행 3 | 목록·국면 띠의 잘림, Step 패널 높이 |
| 초안 1 | 초안 표 (B-09) |
| **통과 2 · 실패 1 결과** | 결과 화면, 목록의 결말 표식 |

결과는 **픽스처 앱을 상대로 재실행 세션을 실제로 돌려** 만든다. 결과 파일을 손으로 짓지
않는다 — 손으로 지은 결과는 실제 실패 메시지의 길이·형태를 갖지 못한다.

픽스처 앱 포트는 기본 4300 을 쓰고, 이미 픽스처가 떠 있으면 재사용한다. 포트가 테스트
정의의 시작 주소에 들어가 화면에 글자로 나오므로 SW-1 과 같은 이유로 고정한다.

## SW-3 — 화면은 개발 서버로 띄운다

제품 서버는 빈 포트에, 화면은 **Vite 개발 서버**를 `ITB_API_PORT`·`ITB_UI_PORT` 로 띄운다
(`backend/tests/abnormal/product_ui.py` 와 같은 방식). `ITB_HEADLESS=1`.

**정적 서버를 쓰지 않는다.** 전환 전 실측은 정적 서버로 떴고, WebSocket 업그레이드가
프록시되지 않아 녹화 화면이 「실시간 연결이 끊겼습니다」 상태로만 그려졌다 (baseline.md).
연결된 상태의 화면을 재지 못하는 순회는 가장 자주 쓰는 화면을 비워 둔 것이다.

## SW-5 — 화면 목록과 「닿았다」의 확인

화면마다 **닿는 법**과 **닿았다는 증거**를 함께 적는다. 증거가 확인되지 않으면 그 화면은
「잰 것」이 아니라 **실패**다 — 조용히 같은 화면을 두 번 재는 것을 막는다 (L2 1회차가
다섯 화면을 같은 32개 요소로 잰 사고).

| 이름 | 닿는 법 | 닿았다는 증거 |
|---|---|---|
| `project-list` | 프로젝트를 열지 않고 첫 화면 | 「새 프로젝트 만들기」 버튼 |
| `project-create` | 「새 프로젝트 만들기」 | 프로젝트 이름 입력칸 |
| `test-list` | 프로젝트를 연 뒤 첫 화면 | 행 6개 |
| `test-list-selected` | 행 체크박스 둘 | 「2개 선택됨」 |
| `test-list-bulk-confirm` | 행 하나 → 「선택한 항목 삭제」 | 확인 조작 「지우기」 |
| `test-list-row-menu` | 행 메뉴 트리거(⋮) | 메뉴 항목 「이름 바꾸기」 |
| `test-list-session` | 녹화 세션을 연 채 목록 | 「진행 중인 세션이 있습니다」 |
| `test-create` | 「테스트 만들기」 | 만들기 국면 표시 |
| `secrets` · `keys` | 「비밀 값」 · 「키 관리」 | 각 화면 제목 |
| `result-pass` · `result-fail` | `?screen=result&test=…` | 결과 국면 표시 · 실패 Step 행 |
| `edit` · `edit-long-name` | `?screen=definition&test=…` | 편집 국면 표시 |
| `edit-step-detail` | `…&step=step-02` | Step 상세 판 |
| `edit-delete-confirm` | 편집 국면에서 Step 체크 → 「고른 것 지우기」 | 확인 조작 |
| `runner-record` | 녹화 세션 → 「실행 화면 보기」 | 녹화 국면 표시 · **실시간 연결됨** |
| `runner-disconnected` | 녹화 세션을 연 채 제품 서버의 이벤트 소켓을 끊는다 | 연결 끊김 알림 |
| `edit-notice` **(09-16)** | 편집 국면(`?screen=definition&test=TC-001`)에서 Step 하나를 골라 「고른 것 지우기」 → 「지우기」. 저장하지 않은 변경이 생겨 알림이 뜬다. 마지막에 알림 위로 포인터를 올려 **5초 시계를 멈춘다**(`hover`) | 편집 국면 표시 · 「먼저 저장해야 합니다」 |

**검토 국면(녹화를 멈춘 뒤)은 순회로 잴 수 없다** (2026-09-16 실측). 둘이 막는다 — ① 순회는 녹화
세션을 **한 번** 만들어 폭 넷에 재사용하는데 「중지」가 그 세션을 끝낸다(두 번째 폭부터 단추 없음),
② 순회는 대상 앱을 조작하지 않아 기록된 Step 이 0개라 「저장되지 않았습니다」 알림이 뜨지 않는다.
편집 국면이 같은 것(알림이 Step 패널 머리 줄의 조작을 덮는가)을 재고, 검토 국면의 알림 쌓임은
사람이 본다 (quickstart H-9).

**알림이 떠 있는 화면을 재는 이유** (09-16 · N-02): 지금 목록에서 알림을 만나는 화면은 결과·연결
끊김 둘뿐이고, **그 둘은 알림이 덮는 자리에 조작이 없다.** 알림에 가려지는 조작(Step 패널 머리 줄의
「전부 고르기」 · 행 체크 칸 · 패널 바닥)은 편집·검토 국면에만 있다. 그래서 순회가 N-02 를 놓쳤다.

**알림은 5초 뒤 사라진다** — 순회는 그 안에 재거나, 알림 위에 포인터를 올려 시간을 멈춘 뒤 잰다
(조작에 `hover` 를 더한다).

**닿지 않는 화면을 적어 둔다** — 가져오기 미리보기(엑셀 파일), 일시정지·AI 작성·사람 인수
(대상 앱 조작·언어모델). 여기 없는 화면은 순회되지 않았다는 뜻이며, 보고서가 그 목록을 함께
싣는다. 그 화면들은 같은 부품을 쓰므로 부품 층의 깨짐은 다른 화면에서 잡히고, 남는 것은 그
화면 고유의 배치뿐이다 — 사람 판정으로 넘긴다 (quickstart §H).

## SW-6 — 판정 규칙

| 종류 | 규칙 | 전환 전 오탐에서 배운 것 |
|---|---|---|
| **덮임** | 조작 요소(버튼·링크·입력·선택·체크박스·라디오·`role=button`·`role=tab`·`role=menuitem`)의 **보이는 중심점**에서 `elementFromPoint` 가 그 요소·자손·조상·연결된 라벨이 아니다. 스크롤 컨테이너 밖으로 밀려난 요소는 재지 않는다 | 사각형 겹침으로 재면 부모-자식·인접 요소가 전부 잡혔다 (편집 화면 31건) |
| **넘침** | `overflow: visible` 인데 `scrollWidth > clientWidth + 1` | |
| **잘림** | `overflow: hidden|clip` 이고 말줄임이 없는데 `scrollWidth > clientWidth + 1` | |
| **줄바꿈** | 조작·칩·표 머리의 글자 조각 사각형을 **세로로 절반 이상 겹치는 것끼리 한 줄로 묶었을 때** 줄이 둘 이상 | 조각의 `top` 으로 세면 크기가 다른 개수 글자(`전체 6`)가 두 줄로 셈해졌다 |
| **창 밖** | 고정 위치가 아닌 요소가 뷰포트 좌우 밖에 있고 어떤 조상도 자르지 않는다 | |
| **콘솔** | `console.error`, 잡히지 않은 예외, 4xx·5xx 응답 | |

세로 넘침은 규칙에 넣지 않는다 — `line-height:1` 한글 글리프의 위아래 2~3px 여유가 전부
잡혔고 화면에 보이는 것은 하나도 없었다. 세로로 **잘리는** 것은 캡처로 본다 (quickstart §H).

## SW-7 — 허용은 사유와 함께 등록한다

판정에 걸리지만 깨짐이 아닌 것은 **등록부**에 `screen`·`kind`·`selector`·`reason` 으로
적는다. 등록부에 없는 검출은 전부 깨짐이다. 사유 없이 등록할 수 없다 (L2 `INTENDED` 와 같다).

전환 전 실측에서 확정된 허용:

| 종류 | 대상 | 사유 |
|---|---|---|
| 덮임 | 대화상자·Step 상세 판·**열린 메뉴·목록 상자·툴팁**이 떠 있을 때 **그 뒤**의 조작 | 뒤를 가리는 것이 그 부품의 목적이다. 가린 요소가 그 층(대화상자·겹침 판·가림막·메뉴·팝오버) 안에 있을 때만 허용한다. 메뉴는 1회차 순회의 오탐(열린 행 메뉴가 아래 행을 가림)에서 더했다 |
| 정렬 | 글자가 없는 표 머리 칸 | 정렬이 화면에 나타나지 않는다 (1회차 오탐) |
| 화면 정책 | 머리띠(`[data-shell]`)의 가로 범위 | 머리띠는 창 폭 전체다. 본문의 범위로 정책을 잰다 (1회차 오탐 — 가운데 선 폼 화면을 제품 표시 때문에 치우쳤다고 봤다) |
| 잘림 | 보조기술 전용으로 1px 에 숨긴 라벨 | 보이지 않게 두는 것이 목적이다 |
| 콘솔 | 프로젝트를 열지 않은 첫 화면의 `404 /api/project` · 결과 없는 테스트의 `404 /api/tests/{id}/result` | 요청 계약의 문제로 범위 밖이다 (spec Assumptions) |

## SW-8 — 산출물과 낡음 판정

| 산출물 | 자리 | 커밋 |
|---|---|---|
| 캡처 (화면 × 폭) | `.sweep/shots/` | 하지 않는다 (`.gitignore`) |
| 보고서 | `frontend/tests/sweep-report.json` | **한다** |

보고서는 화면 코드·테마의 **digest** 와 순회한 화면·폭 목록, 허용된 검출, 허용되지 않은 검출을
담는다. 프론트엔드 테스트가 그 보고서를 읽어

1. digest 가 지금 소스와 같은가 — 다르면 **낡은 보고서**이므로 실패한다
2. 허용되지 않은 검출이 0건인가
3. SW-5 의 화면 × SW-4 의 폭이 전부 들어 있는가

를 본다. L2(`BeforeAfterParity.test.ts`)와 같은 방식이다 — 브라우저가 필요한 검사를 매 테스트
실행마다 돌리지 않되, 낡은 결과로 통과할 수는 없게 한다.

순회는 허용되지 않은 검출이 있으면 종료 코드 1 로 끝난다.
