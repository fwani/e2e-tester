# Phase 0 Research — 엑셀로 프로젝트 내보내기·가져오기

**Feature**: `014-excel-project-io` | **Date**: 2026-09-10

이 문서는 계획을 세우기 전에 정해야 했던 것들과, 그렇게 정한 이유를 기록한다.
「확인 필요」로 표시한 것은 구현 중에 실물로 확인해야 하며, 추측을 사실처럼 다루지 않는다.

---

## R1. 스프레드시트 라이브러리

**결정**: `openpyxl` 하나를 백엔드 런타임 의존성으로 추가한다.

**근거**:

- 읽기와 쓰기가 **둘 다** 필요하다. `xlsxwriter` 는 쓰기 전용이라 읽기용을 또 들여야 한다.
- 순수 Python 이라 빌드 도구·C 확장이 필요 없다. 이 저장소는 백엔드 런타임 의존성이 7개뿐이고
  전부 순수 Python 이거나 휠이 갖춰진 것들이다. 그 결을 깨지 않는다.
- 큰 파일에 필요한 두 가지 모드를 모두 가진다 — 읽기는 `read_only=True`(행 스트리밍),
  쓰기는 `write_only=True`(행을 append 하며 흘려보내기). 5,000행 상한에서 메모리가 문제되지 않는다.

**기각한 대안**:

| 대안 | 기각 이유 |
|---|---|
| `pandas` + `openpyxl` | pandas 는 numpy 를 끌고 오는 큰 의존성이다. 우리가 쓰는 건 "행을 읽고 쓴다"뿐이라 값을 치르는 만큼 얻는 게 없다 |
| `xlsxwriter` + `openpyxl` | 의존성이 둘로 늘고, 쓰기와 읽기가 서로 다른 라이브러리의 셀 표현을 쓰게 된다 |
| 프론트엔드에서 SheetJS | 프론트 런타임 의존성이 React 둘뿐이라는 방침과 정면으로 어긋난다. 또 민감값 필터링을 브라우저에 맡기게 되는데, 그것은 서버가 이미 알고 있는 판단을 클라이언트에 옮기는 일이다 |
| CSV 로 대체 | 시트 = 그룹이라는 이 기능의 뼈대가 CSV 에는 없다 |

**확인 필요**: `openpyxl` 이 XML 폭탄(billion laughs·quadratic blowup)에 대해 `defusedxml` 이
설치돼 있으면 그것을 쓰는지는 버전에 따라 다르다고 알려져 있다. 구현 시 실제 버전의 동작을
확인하고, 자동으로 쓰지 않는다면 R3 의 자체 방어에 XML 엔티티 검사를 더한다.

## R2. 새 코드의 계층 배치

**결정**: 최상위 패키지 `itb.portability` 를 새로 만든다. `.importlinter` 의
`execution-no-llm` 계약 `source_modules` 에 `itb.portability` 를 **추가한다**.

```
itb/portability/
├── limits.py       # 이 기능의 상한. 제품 공통 상한은 여기서 정의하지 않고 domain 에서 가져온다
├── columns.py      # 7개 컬럼의 이름·순서·머리글 대조 규칙 (내보내기와 가져오기가 공유하는 단일 출처)
├── sheet_name.py   # 그룹 이름 ↔ 시트 이름 변환 (순수 함수)
├── workbook.py     # openpyxl 과 닿는 유일한 지점. 읽기/쓰기 두 방향
├── exporter.py     # Project + Test[] + 최근 결과 → 시트 행
└── importer.py     # 워크북 → ImportPlan (openpyxl 타입을 밖으로 흘리지 않는다)
```

**근거**:

- `itb.domain` 에 둘 수 없다 — `domain-is-pure` 계약이 domain 의 외부 의존을 막고, openpyxl 은
  외부 패키지다. 도메인 모델(`Draft`)만 `itb.domain` 에 두고 파일 처리는 밖에 둔다.
- `itb.storage` 에 섞지 않는다 — storage 는 이 제품의 자산 형식(YAML)을 다루는 곳이다. 남의 형식을
  읽고 쓰는 일을 같은 곳에 두면 "정본이 무엇인가"가 코드 배치에서 흐려진다. 원칙 V 가 걸린 지점이다.
- `execution-no-llm` 에 추가하는 이유: 가져오기는 **테스트를 만들지 않는다**. 초안만 만든다.
  이 패키지가 `itb.authoring` 을 임포트할 수 있게 되면, "가져오면서 바로 AI 를 돌린다"는 지름길이
  언젠가 생긴다. 그 지름길은 원칙 I 을 깬다 — 계약으로 막는 것이 주석으로 막는 것보다 싸다.

**초안 저장은 `itb.storage.drafts`** 에 둔다. 그것은 우리 자산이고 우리 형식(YAML)이다.

## R3. 파일 방어 — 상한과 폭탄

**결정**: 세 겹으로 막는다. 순서가 중요하다 — 싼 검사가 먼저다.

| 겹 | 검사 | 값 | 근거 |
|---|---|---|---|
| 1 | 업로드 바이트 | 100MB | 상한+1 바이트만 읽어 판정한다 (`session_files.py:66` 의 기존 수법) |
| 2 | 압축 해제 총량 | 압축 해제 합계 500MB, 압축비 100:1 | `zipfile.ZipFile.infolist()` 의 `file_size` 합으로, **열기 전에** 판정한다. zip 폭탄 방어 |
| 3 | 구조 상한 | 시트 200, 전체 데이터 행 5,000 | `read_only=True` 로 흘려 읽으며 세다가 넘으면 즉시 중단 |

**근거**: `openpyxl` 은 `.xlsx` 가 zip 이라는 사실 위에 서 있다. 100MB 짜리 파일이 압축을 풀면
수십 GB 가 될 수 있으므로 바이트 상한만으로는 부족하다. 3겹은 마지막 방어선이며, 여기까지 오는
파일은 이미 정상 크기다.

**기각한 대안**: "openpyxl 에 맡기고 예외를 잡는다" — 예외가 나기 전에 메모리를 다 쓴다.
막는 시점이 늦으면 막지 않은 것과 같다.

## R4. 「이 기능이 상한을 따로 들지 않는다」를 어떻게 지키는가

**결정**: 두 종류의 상한을 구분하고, 제품 공통 상한은 **한 곳으로 모아 참조**한다.

- **파일 상한** (100MB·시트 200·행 5,000): 이 기능이 새로 도입하는 것이므로
  `itb/portability/limits.py` 에 정의한다. 다른 곳에 같은 값이 없다.
- **제품 공통 상한** (테스트 번호 999, 접두어 형식, 이름 길이 등): 이미 있다. 다만 **999 가 지금 두
  곳에 매직 넘버로 박혀 있다** — `storage/repository.py:323` 과 `api/routes/tests.py:482`.
  이 기능이 세 번째 사본을 만들지 않도록, 먼저 `domain/test_case.py` 에 `MAX_TEST_NUMBER = 999`
  를 두고 그 두 곳이 그것을 쓰게 고친 뒤, 가져오기가 같은 상수를 참조한다.

**근거**: FR-036c 가 요구하는 것은 "값이 같다"가 아니라 "출처가 하나다"이다. 값만 맞춰 두면
누군가 999 를 바꿀 때 세 곳 중 두 곳만 바뀐다. 매직 넘버를 상수로 끌어올리는 작은 정리가
이 기능의 요구를 구조로 만족시킨다.

**부수 효과**: `Project.next_test_number` 의 `le=999` 도 같은 상수를 쓰게 된다.

## R5. 「결과」 컬럼 — 네 값을 어떻게 접는가

**문제**: spec FR-006 은 `P`·`F`·빈 칸 세 가지만 말한다. 그러나 제품의 `Outcome` 은 네 값이다 —
`pass`, `fail`, `stopped`(사용자가 중지), `partial_pass`(실패 스텝을 건너뛰고 완료).

**결정**:

| Outcome | 셀 값 | 근거 |
|---|---|---|
| `pass` | `P` | — |
| `fail` | `F` | — |
| `partial_pass` | `P(부분)` | `P` 로 접으면 거짓말이다 — 실패한 스텝을 건너뛰고 얻은 통과다 |
| `stopped` | `중지` | 판정이 아니다. `F` 로 접으면 실패하지 않은 것을 실패로 보고하게 된다 |
| 결과 없음·읽기 실패 | 빈 칸 | FR-006 |

**근거**: 이 파일은 보고서가 된다. 보고서에서 "부분 통과"를 "통과"로 적는 것은 요약이 아니라
오보다. 컬럼 이름이 「결과(P/F)」인 것은 흔한 두 값을 가리킬 뿐, 다른 값을 P·F 중 하나로
욱여넣으라는 뜻이 아니다.

**후속**: spec FR-006 이 세 가지만 말하고 있으므로 네 값을 모두 덮도록 보완해야 한다.
이것은 계획 단계에서 발견한 명세의 빈틈이다 — 구현이 임의로 정하게 두지 않는다.

## R6. 시트 이름 ↔ 그룹 이름

**결정**: 다음 순서로 변환한다. 변환이 일어나면 사용자에게 알린다 (FR-008).

1. 금지 문자 `: \ / ? * [ ]` 를 `_` 로 바꾼다
2. 앞뒤의 작은따옴표(`'`)를 제거한다 — 엑셀이 시트 이름의 양 끝 작은따옴표를 거부한다
3. 31자로 자른다 (엑셀 시트 이름 상한)
4. 빈 문자열이 되면 `시트`
5. 예약어 `History`(대소문자 무관)와 같으면 뒤에 `_` 를 붙인다
6. 이미 쓴 이름과 겹치면 뒤에 `~2`, `~3` … 을 붙인다. 31자를 넘지 않도록 앞을 자른다

그룹이 없는 테스트의 시트 이름은 **`그룹 없음`** 으로 고정한다. 화면에서 이미 쓰는 말이다
(`TestGroupBar.tsx:75`).

**시트 순서**: `그룹 없음` 시트를 맨 앞에 두고, 그 뒤로 `Project.groups` 에 담긴 순서
(= 만들어진 순서)를 따른다.

**근거**: 그룹 목록 API 는 삽입 순서를, 테스트 목록 API 는 접두어 정렬을 쓴다 — 두 규칙이 이미
어긋나 있다(조사에서 확인). 내보내기는 **저장된 순서**인 `Project.groups` 를 따른다. 그것이 정본이고,
정렬은 화면이 보기 좋으려고 하는 일이지 자산의 순서가 아니다.

**접두어 왕복**: 시트 이름은 그룹 **이름**만 담는다. 접두어는 각 행의 TC ID 에서 읽는다(FR-022).
행이 없는 빈 그룹은 접두어를 실을 곳이 없으므로, 가져올 때 사용자에게 묻는다(FR-022a) —
clarify 에서 확정한 그대로다.

**기각한 대안**: 시트 이름을 `USER 사용자관리` 처럼 접두어+이름으로 만들기 — 왕복은 쉬워지지만
사람이 쓰는 설계서에 우리 내부 접두어를 강요하게 된다. 이 기능의 목적은 남의 설계서를 받는 것이다.

## R7. 초안의 디스크 배치

**결정**: `<프로젝트>/drafts/` 디렉터리에 초안 하나당 파일 하나. 이름은 `<초안ID>-<slug>.yaml`.
초안 ID 는 `^D-\d{4}$` (최대 9,999개, 테스트 번호와 다른 공간).

```
<프로젝트>/
├── itb-project.yaml
├── tests/TC-001-....yaml        ← 테스트 (정본)
├── drafts/D-0001-로그인.yaml     ← 초안 (신규)
└── .runs/                        ← 실행 결과 (gitignore)
```

**근거**:

- **파일 하나에 다 담지 않는 이유**: 초안 999개 × (절차 2,000자 + 기대결과 2,000자) 는
  `yaml_io.MAX_FILE_BYTES`(4MB)를 넘긴다. 한 파일에 몰면 상한을 이 기능 때문에 올려야 하고,
  그러면 "정의 파일 하나가 4MB 를 넘으면 이상하다"는 기존 판단이 무너진다.
- **`tests/` 와 섞지 않는 이유**: FR-027·FR-028. `repository.list_test_paths()` 는 `*.yaml` 을 훑어
  `_TEST_FILE_RE` 로 거른다. 같은 디렉터리에 두면 그 정규식 하나가 초안과 테스트를 가르는 유일한
  벽이 된다. 디렉터리를 나누면 벽이 파일시스템이 된다.
- **버전 관리 대상**: 초안은 사용자 자산이다(FR-028). `.gitignore` 에 넣지 않는다.
  프로젝트를 만들 때 쓰는 `.gitignore` 템플릿을 건드리지 않으면 자동으로 그렇게 된다.
- 파일 하나씩이므로 `storage/test_moves.run_all()` 의 전부-아니면-전무 규약이 그대로 맞는다 —
  `do` 는 파일 쓰기, `undo` 는 파일 삭제.

**기각한 대안**: `itb-project.yaml` 안에 초안 목록을 넣기 — 프로젝트 설정 파일이 사용자 데이터로
부풀고, 초안 하나를 지울 때마다 프로젝트 파일 전체를 다시 쓰게 된다.

## R8. 가져오기를 두 걸음으로 나누는 방법 (미리보기 → 확정)

**결정**: 미리보기가 **계획 ID** 를 돌려주고, 서버가 해석 결과를 메모리에 잠시 들고 있는다.
확정은 파일이 아니라 계획 ID 와 사용자의 결정(시트별 접두어)만 보낸다.

- 보관 위치: 앱 상태(`api/state.py`)의 메모리. 디스크에 쓰지 않는다 — 확정 전에는 아무것도
  만들지 않아야 하고(FR-016), 디스크에 쓰면 그 자체가 "만든 것"이 된다.
- 수명: 30분, 최대 8개. 넘으면 오래된 것부터 버린다.
- 만료된 계획으로 확정하면 `IMPORT_PLAN_NOT_FOUND` 로 거절하고 파일을 다시 고르게 한다.

**근거**: 확정할 때 파일을 다시 올리게 하면 (a) 사용자가 100MB 를 두 번 올려야 하고,
(b) 미리보기에서 본 것과 확정하는 것이 같은 파일이라는 보장이 없다. 계획 ID 는 그 둘을 묶는다.

**기각한 대안**: 업로드한 파일을 디스크 임시 위치에 두기 — 정리 책임이 생기고, 세션 파일 저장소와
비슷하지만 다른 두 번째 임시 저장 개념이 된다.

## R9. 파일 내려받기 — Content-Disposition

**결정**: `Response(content=<bytes>, media_type=..., headers={...})` 로 돌려주고
`Content-Disposition` 을 직접 만든다. ASCII 대체 이름과 RFC 5987 이름을 **둘 다** 넣는다.

```
Content-Disposition: attachment; filename="itb-export-20260910.xlsx";
                     filename*=UTF-8''<퍼센트 인코딩된 한글 이름>
```

MIME: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`

**근거**: 이 저장소에 `Content-Disposition` 선례가 없다(조사 확인). 그리고 HTTP 헤더가 ASCII 로
제한된다는 함정을 이 저장소는 이미 `X-ITB-Project-Root` 에서 겪었다(`client.ts:69-85`).
프로젝트 이름은 한글일 수 있으므로 같은 함정이 그대로 재현된다. 두 이름을 함께 보내면
`filename*` 을 이해하는 브라우저는 한글 이름을, 아닌 쪽은 ASCII 이름을 쓴다.

**메모리 vs 임시 파일**: 워크북을 `BytesIO` 에 만들어 바이트로 돌려준다. 테스트 999개 규모에서도
수 MB 이므로 임시 파일과 그 정리 책임을 만들 이유가 없다.

## R10. 프론트엔드 — 새 의존성 없이 올리고 내려받기

**내려받기**: `fetch` → `blob()` → `URL.createObjectURL` → 보이지 않는 `<a download>` 클릭 →
`revokeObjectURL`. 이 저장소에 선례가 없는 첫 사례다.

`<a href="/api/project/export">` 로 끝내지 **않는다**. 그러면 `X-ITB-Project-Root` 헤더가 붙지 않아
서버의 프로젝트 가드를 지나칠 수 없다.

**올리기**: `FormData` + `fetch`. 다만 기존 `sessions.uploadFile`(`client.ts:893-901`)을 그대로
베끼지 않는다 — 그것은 `send()` 를 우회하느라 `X-ITB-Project-Root` 가드가 빠져 있다.
새 코드는 `Content-Type` 만 브라우저에 맡기고 프로젝트 헤더는 손으로 붙인다.

**확인 필요**: 기존 `sessions.uploadFile` 의 가드 누락이 의도된 것인지(세션 ID 로 이미 프로젝트가
정해지므로 불필요) 빠뜨린 것인지. 이 기능의 범위 밖이므로 고치지 않고, 발견 사실만 남긴다.

## R11. 도메인 확장 — `description` 과 `actor`

**결정**: `Test` 에 두 필드를 더한다. `dsl_version` 은 **올리지 않는다**.

```python
description: str | None = Field(default=None, max_length=2000)
actor: str | None = Field(default=None, max_length=100)
```

**근거**:

- 기본값이 `None` 이므로 이미 저장된 테스트 파일은 그대로 읽힌다. 하위호환이 깨지지 않는다.
- `dsl_version` 을 올리면 `Test._check_refs` 가 `dsl_version != 1` 을 거절하므로 옛 파일이 전부
  못 읽히게 된다. 필드 추가는 판올림이 아니다.
- `actor` 를 자유 텍스트로 두는 것은 clarify 에서 확정했다. 패턴 제약을 걸지 않는다 —
  「관리자」·「일반 사용자 A」 같은 말이 들어온다.
- `max_length` 값: `description` 2,000 은 `Variable.value`(4,000)보다 작고 `Test.name`(200)보다 크게
  잡은 것으로, 한 문단 분량이다. `actor` 100 은 `TestGroup.name` 과 같다.

**따라오는 일** (건너뛰면 CI 가 막는다):

1. `uv run python -m itb.schema.export` — `step-dsl.schema.json` 재생성
2. `cd frontend && npm run gen:types` — `step-dsl.d.ts` 재생성
3. 두 산출물을 커밋

**초안이 아니라 테스트에 두는 이유**: 이 두 값은 녹화가 끝난 뒤에도 남아야 한다.
초안에만 두면 저장하는 순간 사라지고, 다시 내보낼 때 빈 칸이 된다 — 왕복이 끊긴다.

## R12. 초안에서 세션을 시작하는 방법

**결정**: `POST /api/sessions` 에 `draft_id: str | None` 을 더한다. `mode="ai"` 일 때만 허용한다.
새 실행 경로를 만들지 않는다.

- 서버가 초안에서 지시문을 짓는다. 프론트는 `GET /api/drafts/{id}` 응답의 `suggested_instruction`
  으로 그 결과를 미리 보고 고칠 수 있다(FR-031). 고친 값을 보내면 그것이 쓰인다.
- 세션은 `draft_id` 를 들고 있다가 저장할 때 (a) 초안의 희망 TC ID 를 부여하려 시도하고
  (b) 성공하면 초안 파일을 지운다(FR-032·FR-033).

**지시문 구성** (`itb.portability` 가 아니라 초안 모델 곁의 순수 함수로 둔다):

```
제목: {name}
설명: {description}
수행자: {actor} 역할로 수행한다.

수행 절차:
{procedure}

기대 결과:
{expectation}
```

빈 항목은 줄째로 뺀다. 결과 길이가 `MAX_INSTRUCTION_LENGTH`(8,000)를 넘으면 초안을 만들 때
이미 거절했어야 한다 — 그래서 초안의 `procedure`·`expectation` 상한을 각 2,000 으로 잡는다
(제목·설명·수행자·머리말을 더해도 8,000 안에 든다).

**기각한 대안**: 초안 전용 세션 모드(`mode="draft"`)를 만들기 — 상태 기계에 갈래가 하나 늘고,
원칙 I 이 막으려는 "두 번째 작성 경로"에 한 발 들여놓는 일이다.

## R13. 수식 주입 차단

**결정**: 셀에 넣는 문자열이 `=`, `+`, `-`, `@`, 탭, 캐리지리턴으로 시작하면 앞에 `'`(작은따옴표)를
붙여 텍스트로 고정한다.

**근거**: 스텝 라벨과 테스트 이름은 사용자가 쓴 글이고, 녹화 중 페이지에서 읽어 온 글자가 섞일 수
있다(원칙: 페이지 유래 텍스트는 데이터로 다룬다). `=cmd|...` 로 시작하는 셀은 일부 스프레드시트에서
실행 가능한 것으로 해석된다. 내보낸 파일은 다른 사람이 연다 — 우리 손을 떠난 곳에서 터진다.

`openpyxl` 은 값을 그대로 쓰므로 이 처리를 우리가 해야 한다.

## R14. 새 오류 코드

**결정**: 7개를 더한다. 전부 `Category.BLOCKED` 다 — 사용자가 파일이나 선택을 고쳐 다시 할 수 있다.

| 코드 | 언제 |
|---|---|
| `IMPORT_FILE_REJECTED` | 상한 초과, 스프레드시트가 아님, 손상 |
| `IMPORT_PLAN_NOT_FOUND` | 계획 ID 가 만료됐거나 없음 |
| `IMPORT_CAPACITY_EXCEEDED` | 만들 초안 수 > 프로젝트에 남은 번호 (FR-036b) |
| `IMPORT_FAILED` | 도중 실패, **전부 되돌렸다** |
| `IMPORT_PARTIAL` | 도중 실패, **되돌리지 못했다** (`stranded` 동반) |
| `DRAFT_NOT_FOUND` | 없는 초안을 가리킴 |
| `EXPORT_FAILED` | 워크북을 만들지 못함 |

`IMPORT_FAILED` 와 `IMPORT_PARTIAL` 을 나누는 것은 기존 `TEST_MOVE_FAILED`/`TEST_MOVE_PARTIAL`
와 같은 이유다 — 사용자가 "다시 시도하면 되는가"에 답할 수 있어야 한다.

`CATEGORY` 와 `NEXT_ACTION` 표는 전수 대응이며 빠지면 `tests/abnormal/test_error_contract.py` 가
실패한다. 코드 추가 시 두 표를 함께 채운다.
