# Contract: 화면 어휘와 컨트롤 상태 (005)

**Feature**: `specs/005-ux-walkthrough-repair` | **Date**: 2026-09-07

리포트 22건 중 **12건 이상이 화면 표시·문구 문제**다. 그것들은 개별 화면의 취향이 아니라
**하나의 계약**으로 다뤄야 같은 실수가 다시 나지 않는다. 이 문서가 그 계약이다.

권위 지점은 `frontend/src/lib/wording.ts`(신규) 하나다. 화면은 문구를 직접 만들지 않고
이 모듈에서 받는다.

---

## 1. 결말 어휘 — 하나의 사전

| `Outcome` | 사용자 문장 | 칩 라벨 | 색 역할 |
|---|---|---|---|
| `pass` | 통과 | `PASS` | 성공 |
| `fail` | 실패 | `FAIL` | 실패 |
| `stopped` | 중지 | `STOPPED` | 중립 |
| `partial_pass` | 부분 성공 | `PARTIAL` | 주의 |

**규칙**

1. **한 화면에 두 어휘 체계를 동시에 쓰지 않는다** (FR-141). 칩은 기술 라벨
   (`PASS`/`FAIL`), 문장은 한국어. 칩 옆에 같은 뜻의 한국어 배지를 또 두지 않는다.
2. 확정 디자인이 쓰는 대문자 칩은 **유지한다** (`docs/design/RunResult.dc.html` 에
   `FAIL`, `통과 / 전체`).
3. 세션 상태 배지(「실행 중」·「검토 중」)는 결말이 아니다. 결말과 같은 자리에 함께
   두지 않는다.
4. 색만으로 구분하지 않는다 — 칩에는 항상 텍스트 라벨이 있다.

### 결말 요약 문장

| 상황 | 문장 |
|---|---|
전체 실행 통과 | `통과 · 5 / 5 · 2.28 s`
전체 실행 실패 | `실패 · Step 06 에서 실패 · 5 / 7 통과 · 3.21 s`
사용자 중지 | `중지 · Step 06 에서 중지 · 5 / 7 통과 · 3.21 s`
부분 실행 통과 | `통과 · 부분 실행 Step 06~07 · 2 / 2 · (01~05 건너뜀)`
부분 실행 실패 | `실패 · 부분 실행 Step 06~07 · 0 / 2 · (01~05 건너뜀)`
실패 건너뛰고 계속 | `부분 성공 · Step 06 건너뜀 · 6 / 7 통과`

통과 수의 분모는 **`attempted_count`** 다(전체 − 건너뜀). `total_count` 를 분모로 쓰면
부분 실행이 `0 / 7` 로 보인다 (U-02).

**요약은 한 화면에 한 번만 나온다** (FR-140). 실행 화면의 얇은 회색 띠는 없애고 결말 바
하나만 남긴다 — 확정 디자인에 얇은 띠는 정의돼 있지 않다(research R10).

## 2. Step 표기 — 변환 지점은 하나

```
stepLabel(index0)  →  "Step 06"
```

- 저장·API·이벤트의 Step 인덱스는 **0-기반**이다. 바꾸지 않는다.
- 사용자에게 보이는 번호는 **이 함수만** 만든다 (FR-138).
- 표기는 `Step 06` 한 형태. `step 06`·`STEP 06`·`단계 6` 을 쓰지 않는다.

지금 저장소의 8곳이 `index + 1` 을 각자 하고 한 곳만 빠뜨렸다 (U-07). 한 줄 고치는 것으로
증상은 사라지지만 같은 실수가 다시 난다.

## 3. Step 실행 상태 표시

| `StepOutcome` | 표시 | 기호 | 소요시간 |
|---|---|---|---|
| `pass` | 통과 | ✓ | 표시 |
| `fail` | 실패 | ✕ | 표시 |
| `skipped` | **건너뜀** | 회색 칩 `건너뜀` | `—` |
| `not_run` | **미실행** | 점선 테두리 + `미실행` | `—` |
| (실행 중) | 실행 중 | 진행 표시 | 경과 |

건너뜀과 미실행은 **서로 다른 표시**여야 한다 (FR-151·U-21). 지금은 둘 다 "빈 체크박스 +
—" 여서 "안 돌린 것"과 "도달 못한 것"을 구분할 수 없다.

## 4. 진행 표시와 결말 표시

| 세션 상태 | 헤더 |
|---|---|
| 실행 중 | `Step 04 / 07` (현재 실행 중인 Step) |
| 일시정지 전이 중 | `일시정지 중… · Step 06 대기 12s / 20s` |
| 일시정지(성립) | `일시정지 · Step 05 이후 정지` |
| 종료 | **진행 표시를 쓰지 않는다.** 결말 요약을 쓴다 |

종료 후 `Step 07 / 07` 은 전부 처리한 것으로 읽힌다 (U-14). 끝난 실행에서는 진행 표시
자리에 결말이 온다.

---

## 5. 실행 트리거 버튼

| 버튼 | 라벨 | 진행 중 라벨 |
|---|---|---|
| 처음부터 | `처음부터 실행` | `실행을 준비하는 중…` |
| 실패 지점부터 | `Step 06부터 실행` | `실행을 준비하는 중…` |
| 목록 행 | `실행` | `준비 중…` |

**규칙**

1. 시작점이 라벨에 드러난다 (FR-149). 「실패한 Step부터 실행」처럼 번호가 없는 라벨을
   쓰지 않는다.
2. 첫 클릭에 즉시 비활성 + 라벨 교체. **0.3초 안에** 화면이 변한다 (FR-127·FR-129).
3. 부분 실행 버튼 옆에 보조 문구를 둔다 (FR-150):
   > Step 01~05 는 건너뜁니다. 로그인 같은 앞선 상태가 필요하면 「처음부터 실행」을 쓰세요.

   모달로 막지 않는다 — 보조 문구로 충분하다.
4. 목록 행은 결말과 무관하게 `실행` 에 도달할 수 있고, 결과가 있으면 `결과 보기` 에도
   도달할 수 있다 (FR-130). 한 자리에 둘 중 하나만 두지 않는다.

## 6. 멈춤 계열 버튼 — 라벨이 동작을 말한다

| 세션 상태 | 「일시정지」 | 「중지」 | 「계속하기」 |
|---|---|---|---|
| 실행 중 | 활성 | 활성 | 없음 |
| 일시정지 전이 중 | `일시정지 중…` (비활성) | **활성** | 없음 |
| 일시정지(성립) | 없음 | 활성 | 활성 |
| 일시정지 + 실패 Step 있음 | 없음 | 활성 | **비활성 + 이유** |
| 종료 | 없음 | **`닫기`** (강조 없음) | 없음 |

**규칙**

1. 중지 요청 중에는 `중지 중…` 으로 바뀌고 비활성 (FR-147).
2. **종료 후의 버튼은 「중지」가 아니다.** 라벨을 `닫기` 로 바꾸고 파괴적 동작 자리
   (오른쪽 보조)로 내리고 강조를 뺀다. 같은 위치의 같은 버튼이 두 동작을 갖지 않는다
   (U-08).
3. 세션 정리가 결과 접근을 끊을 수 있으면 한 번 묻는다 (FR-148):
   > 이 실행 화면을 닫습니다. 결과는 목록의 「결과 보기」에서 다시 볼 수 있습니다.
4. 전이 중에도 「중지」는 살린다 — 기다리다 포기하는 것이 가장 자연스러운 다음 행동이다
   (FR-144).
5. 실패 Step 이 있는 일시정지에서 「계속하기」는 비활성이고 옆에 이유가 온다 (FR-136):
   > Step 06 이 실패해 이어서 갈 수 없습니다. 「Step 06 고치기」 또는 「Step 06부터
   > 실행」을 쓰세요.

   그래도 넘기고 싶으면 **별도 버튼** 「실패한 Step 건너뛰고 계속」 을 쓴다. 그 결말은
   `부분 성공` 이다 (FR-137).

## 7. 일시정지 전이 표시

요청 직후(응답 전) 화면이 켜는 것:

- 배지: `일시정지 중…`
- 문구: `현재 Step 이 끝나면 멈춥니다.` — **즉시** 표시한다. 10초 뒤 경고를 기다리지
  않는다 (FR-142)
- 대기 중인 Step 의 남은 시간: `Step 06 대기 12s / 20s` (FR-145)
- **Step 편집 팔레트를 열지 않는다.** 대신 `정지되면 편집할 수 있습니다.` (FR-143)

전이 중 실행이 끝난 경우 (FR-146):

- 배지를 결말(`실패`·`통과`)로 바꾼다
- `멈추기 전에 실행이 끝났습니다.` 를 알린다
- 실패 사유와 「결과 자세히 보기」를 붙인다
- **낡은 전이 안내는 지운다**

## 8. 중지 결과 화면

중지는 화면을 떠나지 않는다(DR-010). 다만 **저장 프롬프트가 아니라 중지 결과**를 보여준다
(FR-133).

```
중지했습니다.
중지 · Step 06 에서 중지 · 5 / 7 통과 · 3.21 s

[결과 자세히 보기]  [처음부터 실행]  [Step 06부터 실행]  [목록으로]
```

**금지**

- 「초안」 표기 — 저장된 테스트를 실행하는 세션이다 (FR-134)
- 세션 유실 오류 배너 (FR-132)
- 사용자에게 보이는 문구의 세션 식별자 (FR-135)
- 이름 입력칸과 「저장」을 결말 화면의 주요 요소로 두는 것

## 9. 저장 표시

성공 시 저장 영역에 **인라인 확인**이 온다 (FR-154).

```
저장했습니다 · TC-001
[목록에서 보기]
```

**규칙**

1. 화면을 옮기지 않고도 알 수 있다. 토스트만으로 끝내지 않는다(사라지면 근거가 없다).
2. 제목의 「초안」을 뗀다 → `TC-001 · 저장됨` (FR-155)
3. 저장 버튼 라벨을 `변경 저장` 으로 바꾸고, 바뀐 것이 없으면 비활성 (FR-156)
4. 실패 시 사실과 사유를 표시한다 (FR-157)
5. 성공 시 이전 오류 배너를 걷어낸다 (FR-158)
6. 저장 이력이 있는 세션의 정리 확인 문구 (FR-159):
   > TC-001 로 저장돼 있습니다. 이 작업 창만 닫습니다.

   `Step 6개가 사라집니다` 를 쓰지 않는다 — 저장된 테스트는 사라지지 않는다.

## 10. 미리보기(미러) 안내

| 상황 | 문구 |
|---|---|
| 프레임 있음 · 관찰 국면 | `읽기 전용` 배지 + `실행 중인 화면을 관찰합니다.` |
| 프레임 있음 · 조작 국면 | `실제 브라우저 창에서 조작 중` + `이 영역은 관찰용이며 조작 대상이 아닙니다.` |
| 프레임 없음 | **`대상 화면이 표시되기를 기다리고 있습니다. 대상 브라우저 창은 이미 열려 있습니다.`** |
| 미러 중단 | 중단 사유 (기존) |

기존 문구 `미러 프레임을 기다리고 있습니다` 는 곧 올 것처럼 말하지만 정적 화면에서는
오지 않았다 (FR-163·U-24). 수정 후에는 실제로 오므로 대기 문구가 짧게만 보이지만,
문구 자체도 사실에 맞춘다.

## 11. 증거 탭

| 상황 | 표시 |
|---|---|
| 비활성 탭(`TRACE`) | 비활성 + 이유: `이 실행에는 trace 가 남지 않았습니다 (MVP 미지원).` (FR-172) |
| 기록 없는 탭 | `콘솔 오류가 없었습니다.` + 수집 조건 한 줄 (FR-173) |

`(기록 없음)` 처럼 무엇이 없는지 알 수 없는 문구를 쓰지 않는다.

## 12. 속도 컨트롤

| 국면 | 라벨 |
|---|---|
| 실행·일시정지 | `속도` (기존) |
| 녹화·사람 인수 | **`다음 실행 속도`** (FR-174) |

감추지 않고 밝힌다 — 004 FR-109 가 "속도 선택은 실행 간에 유지되고 다음 실행의 기본값"
이므로 녹화 중에 고른 값도 쓰인다. 감추면 그 정보를 잃는다(research R10).

## 13. 목록 화면

| 요소 | 규칙 |
|---|---|
| 행 버튼 | `실행` 은 항상. 결과가 있으면 `결과 보기` 도 (FR-130) |
| 실행 중인 테스트의 행 | `RUNNING` 칩 + `실행 화면 보기` (FR-168) |
| 실패 Step 번호 | `stepLabel()` 로 만든다 (FR-138) |
| 세션 배너 | 실제 상태를 따라 갱신 (FR-169) |
| 같은 테스트의 배너 여럿 | 시작 시각으로 구분 (FR-170) |
| 저장 이력 있는 세션의 정리 | §9-6 문구 |

## 14. URL 반영

| 화면 | URL |
|---|---|
| 목록 | `/` |
| 결과 | `?screen=result&test=TC-002` |
| 실행 | `?screen=runner&session=<id>` |
| 정의 | `?screen=definition&test=TC-002` |

- 새로고침하면 같은 화면으로 복원된다 (FR-166)
- 뒤로가기는 앱 내부 이동이며 앱을 이탈하지 않는다 (FR-167)
- 라우팅 라이브러리를 추가하지 않는다 — `history.pushState`/`popstate` 를 쓰는 얇은 훅
  하나다(research R8)
