# Quickstart — 026 을 직접 확인하는 법

자동 검증이 덮지 못하는 것은 하나다 — **모델이 고른 Step 을 실제로 고치는가.**

가짜 드라이버는 대본대로 도구를 부르므로 「권한이 넓어진 것을 모델이 안다」를 흉내 낼 수
없다. 그것은 실제 모델이 실제 설명문을 읽을 때만 드러난다.

**§2 와 §3 이 가장 중요하다.**

| | 왜 |
|---|---|
| **§2 대상 재지정** | 이 기능이 있는 이유. 재녹화로는 보존되지 않는 것이 여기서 보존된다 |
| **§3 버리기** | 되돌리기가 016 과 다르게 성립하는 자리. 여기가 깨지면 이 기능은 쓸 수 없다 |

---

## 0. 띄운다

```bash
python fixtures/sample-app/serve.py --port 4300     # 대상 화면
cd backend && uv run itb                            # 제품 서버
cd frontend && npm run dev                          # http://127.0.0.1:4310
```

모델 자격 증명이 필요하다 (`ANTHROPIC_API_KEY` 또는 `ant auth login`).

준비물: **Step 이 5개 이상인 저장된 테스트** 하나. 가운데에 버튼을 누르는 Step 이 있어야
한다.

---

## 1. 두 입구가 갈리는가

1. 저장된 테스트의 편집 화면을 연다.
2. Step 을 **아무것도 고르지 않은 채** AI 조작 자리를 본다.

**보여야 하는 것**

- 「AI 로 다시 만들기」와 「AI 에게 고쳐 달라기」가 **둘 다 보이고 둘 다 잠겨 있다.**
- 잠금 사유가 **서로 다르다** — 「다시 만들 Step 을 고르세요」 / 「고칠 Step 을 고르세요」.

3. Step 두 개를 **이어서** 고른다.

**보여야 하는 것**

- 「다시 만들기」는 풀린다.
- 「고쳐 달라기」는 잠기고 **「한 번에 한 Step 만」** 이라고 말한다.

4. 하나만 고른다 → 둘 다 풀린다.

**보이면 안 되는 것**

- 두 조작이 같은 문장으로 잠기는 것 (FR-032 위반)
- 어느 쪽이 고른 Step 을 버리는지 읽어서 알 수 없는 것 (FR-031 위반)

---

## 2. 대상 재지정 — **이 기능의 핵심**

1. 버튼을 누르는 Step 하나를 고르고 「AI 에게 고쳐 달라기」를 누른다.

**보여야 하는 것**

- 브라우저가 열리고 앞 Step 들이 실행되어 **그 Step 이 동작할 화면**에서 멈춘다.
- 대화 자리가 열린다.
- 목록에서 그 Step 이 **수정 대상으로 구분되어** 보인다.

2. "이 버튼 말고 머리말의 저장 버튼을 눌러" 라고 보낸다.

**보여야 하는 것**

- AI 가 화면을 관찰하고 그 Step 의 **대상만** 바꾼다.
- **표시 이름·값·종류가 그대로다.** 이것이 재녹화와 갈리는 자리다 — 재녹화는 전부 새로 만든다.
- 무엇이 바뀌었는지 화면에서 보인다 (FR-034).

3. 「확정」을 누르고 「저장」한다. 다시 불러온다.

**보여야 하는 것**

- 고친 Step 의 **식별자가 그대로다** (`step-03` 이 `step-07` 이 되지 않는다).
- 저장 형식이 사람이 같은 편집을 한 것과 구별되지 않는다.

**보이면 안 되는 것**

- AI 가 「그건 제 권한 밖입니다」라고 답하는 것 — 설명문 세 자리 중 하나가 덜 고쳐졌다는 뜻이다 (research R8)
- Step 이 지워지고 새로 생기는 것

같은 확인을 **표시 이름 바꾸기**("이름을 '주문 저장'으로")로도 해 본다.

---

## 3. 버리기 — 원래대로 돌아오는가

1. §2 를 다시 하되 확정하지 말고, AI 가 고친 뒤 **「버리기」**를 누른다.

**보여야 하는 것**

- 그 Step 이 **고치기 전 모습 그대로** 돌아온다 — 대상·이름·값 전부.
- **식별자도 같다.**
- AI 가 그 과정에서 만든 Step 이 있으면 함께 사라진다.
- 브라우저 화면이 **다시 그 Step 직전 상태**로 맞춰진다.
- **세션이 살아 있다** — 곧바로 다른 말로 다시 시도할 수 있다.

2. AI 에게 "이 Step 지워" 라고 시킨 뒤 버리기를 누른다.

**보여야 하는 것**

- 지워졌던 Step 이 **원래 자리에** 되돌아온다. 이것이 `restore_step` 의 둘째 경우다.

**보이면 안 되는 것**

- 새 Step 은 사라졌는데 대상은 고쳐진 채 남는 것 (research R7 위반 — 부분 적용)
- 버리기가 세션을 끝내는 것 (FR-026 위반)

---

## 4. 권한 경계

1. Step 3 을 골라 시작한 뒤 "앞쪽 로그인 Step 이름도 정리해 줘" 라고 보낸다.

**보여야 하는 것**

- AI 가 **거절**하고, 거절 사실이 사용자에게 보인다.
- Step 1 이 바뀌지 않는다.
- 거절문이 **무엇이 허용되는지** 말한다 — 모델이 같은 요청을 반복하지 않는다 (FR-016).

2. 016 「AI 로 다시 만들기」로 세션을 열고 구간 밖 Step 을 고치라고 해 본다.

**보여야 하는 것**

- 016 의 거절이 **그대로** 동작한다. 이 기능이 그 경로를 넓히지 않았다 (FR-014).

## 5. 전량 검증

```bash
cd backend  && bash scripts/test-backend.sh
cd backend  && uv run ruff check src/ tests/
cd backend  && uv run lint-imports
cd frontend && npx vitest run
cd frontend && npx tsc --noEmit
```

`uv run pytest` 와 `npm test` 는 **쓰지 않는다** — 앞은 이 저장소의 설정을 지나지 않고,
뒤는 감시 모드로 들어가 끝나지 않는다.

기존 실패와 새 실패를 섞지 않기 위해 시작 시점 결과를 `baseline.md` 에 먼저 적는다.
