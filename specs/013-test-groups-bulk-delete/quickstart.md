## 2. 손 검증 — 일곱 이야기

### 이야기 1 — 기존 테스트가 그대로다 (SC-629 · **가장 먼저 본다**)

013 이전에 만든 프로젝트를 연다. (없으면 이 기능을 붙이기 **전** 커밋으로 만들어 둔다.)

**보여야 하는 것**

- 목록에 `TC-001` 테스트들이 그대로 있다. **파일 이름도 식별자도 바뀌지 않았다.**
- 열리고 실행되고 결과가 보인다.
- 그룹을 하나도 만들지 않았으므로 **그룹 띠도 소제목도 없다.** 목록이 이전과 같은 모습이다
  (SC-627).

```bash
ls ~/.local/share/itb/projects/<프로젝트>/tests/    # TC-001-*.yaml 그대로
git -C <프로젝트> status                              # 업그레이드만으로는 변경 0줄
```

**막히면**: 목록이 비었다면 `list_test_paths()` 의 glob 을 넓히지 않은 것이다 (research R1 —
「가장 조용한 함정」).

### 이야기 2 — 여러 개를 한 번에 지운다 (US1 · SC-623)

테스트 5개 중 3개를 체크해 삭제한다.

**보여야 하는 것**

- 체크하면 목록 위에 「3개 선택됨」 띠가 나타난다. 체크를 다 풀면 **띠가 사라진다.**
- 「선택한 항목 삭제」 → 확인이 **한 번**. 확인 문구에 **개수와 이름**이 함께 있다.
- 확인 전에는 디스크가 그대로다:
  ```bash
  ls ~/.local/share/itb/projects/<프로젝트>/tests/
  ls ~/.local/share/itb/trash/ 2>/dev/null
  ```
- 확인하면 셋만 사라지고 나머지 둘은 그대로다. 선택이 비워진다.
- **옮겨진 위치들이 화면에 남는다.** 자동으로 사라지지 않는다.
- 그 자리에 정의가 온전하다 (SC-631):
  ```bash
  cat ~/.local/share/itb/trash/*/TC-*.yaml
  ```

### 이야기 3 — 보이지 않는 것은 지워지지 않는다 (FR-428·FR-429 · SC-625)

1. 테스트 5개를 전부 체크한다.
2. 검색어를 넣어 2개만 보이게 한다.

**보여야 하는 것**: 개수 표시가 **2개로 줄어든다.** 그 상태에서 삭제하면 그 2개만 사라진다.
「보이는 것 전부 선택」도 보이는 2개만 고른다.

### 이야기 4 — 실행 중이면 하나도 안 지워진다 (FR-432·FR-433 · SC-624·SC-630)

1. 테스트 하나를 실행해 브라우저를 띄운 채로 둔다.
2. 그 테스트를 포함해 셋을 골라 삭제한다.

**보여야 하는 것**

- **하나도 지워지지 않는다.** 목록이 그대로다.
- 사유와 다음 행동이 뜬다. **선택은 그대로 남는다** — 다시 고르게 만들지 않는다.
- **브라우저가 닫히지 않고 세션도 살아 있다** (SC-630).

### 이야기 5 — 그룹으로 묶어 본다 (US2)

1. 「+ 그룹」으로 그룹 둘을 만든다 — 「사용자관리 테스트」/`USER`, 「데이터 관리 테스트」/`DATA`.
2. 테스트 몇 개를 골라 각 그룹으로 옮긴다.

**보여야 하는 것**

- 목록이 그룹별로 묶여 보이고 각 그룹의 개수가 함께 보인다.
- 그룹 칩을 누르면 그 그룹만 보인다. 검색어와 **함께** 걸린다.
- 그룹에 넣지 않은 테스트는 **「그룹 없음」** 아래에 남는다 — 사라지지 않는다.
- **식별자가 바뀌었다**: `TC-003` → `USER-003`. **번호는 그대로다.**
  ```bash
  ls ~/.local/share/itb/projects/<프로젝트>/tests/     # USER-003-*.yaml
  ls ~/.local/share/itb/projects/<프로젝트>/.runs/     # USER-003/
  ```

### 이야기 6 — 그룹을 옮겨도 결과가 따라온다 (US3 · SC-628)

결과가 있는 테스트(한 번 실행한 것)를 다른 그룹으로 옮긴다.

**보여야 하는 것**: 옮긴 뒤에도 **결과 보기가 그대로 열린다.** Step 수도 같다.
`.runs/<옛ID>/` 가 남아 있지 않고 `.runs/<새ID>/` 에 있다.

**막히면**: 결과가 사라졌다면 순서가 뒤집힌 것이다 — 산출물이 먼저, 정의가 나중이다
(api-contract §4 불변식).

### 이야기 7 — 그룹을 없애도 테스트는 남는다 (FR-451)

테스트가 든 그룹을 없앤다.

**보여야 하는 것**

- 확인 단계가 **「테스트 N개가 그룹 없음으로 돌아가고 식별자가 `TC-###` 로 바뀝니다 ·
  지워지지 않습니다」**를 말한다.
- 확인하면 그 테스트들이 「그룹 없음」에 남는다. **하나도 지워지지 않는다.**
- 식별자가 `TC-###` 로 돌아왔고 번호는 그대로다.

## 3. 회귀 — 깨지지 않아야 하는 것

| 확인 | 방법 |
|---|---|
| 한 줄 삭제가 그대로 있다 (FR-435) | 행의 삭제로 하나를 지운다. 조작 수가 늘지 않았다 |
| 한 줄 삭제도 휴지통으로 간다 (SC-632) | 그 하나가 `trash/` 에 있다 — 복수와 결과가 같다 |
| 이름 변경이 식별자를 바꾸지 않는다 | 이름을 고친 뒤 `ls tests/` — 식별자 부분이 그대로 |
| 그룹을 안 쓰면 화면이 이전과 같다 (SC-627) | 그룹 0개 프로젝트에서 띠·소제목이 없다 |
| 검색이 그대로 된다 | `q` 로 이름·식별자 부분 일치 |
| 999번을 넘기면 알린다 | `next_test_number` 상한은 그대로다 |
| 되돌리기가 한 걸음이다 | 휴지통의 `.yaml` 을 `tests/` 로 옮기면 목록에 다시 나타난다 |
