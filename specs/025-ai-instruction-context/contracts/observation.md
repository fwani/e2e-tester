# 관찰 계약 — 사람이 보는 것을 AI 도 본다 (025 US3)

**Date**: 2026-09-29 | **Spec**: [spec.md](../spec.md) | **Research**: [research.md](../research.md) R13

`observe_page` 가 돌려주는 것의 범위와 모양을 정한다. 기존 필드를 **하나도 없애지 않는다** —
더할 뿐이다.

---

## §1. 무엇을 수집하는가

두 단계로 모은다.

### 1단계 — 지금과 같다

```
button, a, input, select, textarea, label, [role], [tabindex], [onclick]
```

이 선택자에 걸리는 것. **커서를 보지 않는다** — 태그가 이미 확실한 근거다.

### 2단계 — 사람이 누를 수 있다고 인지하는 것

1단계에 안 걸린 요소 중,

1. **보이는 텍스트를 갖거나** 이미지·아이콘이고
2. computed `cursor` 가 `pointer` 이며
3. **조상 중에 같은 판정을 받은 것이 없는** 가장 바깥 요소

세 번째 조건이 핵심이다. **`cursor` 는 상속된다** — `<div style="cursor:pointer"><span>글자
</span></div>` 에서 `<span>` 의 computed cursor 도 `pointer` 다. 이것을 걸러 내지 않으면
조상과 자손이 모두 실려 목록이 몇 배로 부풀고, 모델은 어느 것을 눌러야 할지 알 수 없다.

가장 바깥만 취하는 것은 녹화가 이미 쓰는 개념과 같다 — 「조작의 의미 단위까지 올라간다」.

---

## §2. 각 요소에 실리는 것

기존 필드에 하나가 더해진다.

```json
{
  "element_ref": "e17",
  "tag": "div",
  "role": null,
  "name": "메뉴관리",
  "visible": true,
  "disabled": false,
  "actionability": "cursor",
  "id": "menu-tree-node-7",
  "context": "메뉴 트리"
}
```

| `actionability` | 뜻 | 확실성 |
|---|---|---|
| `semantic` | `<button>`·`<a>`·`<input>` 등 태그 자체가 조작 요소 | 높다 |
| `role` | `[role]`·`[tabindex]` 가 붙어 있다 | 높다 |
| `cursor` | 커서가 손가락으로 바뀐다 | **짐작이 섞였다** |

`cursor` 로 잡힌 것은 장식일 수 있다. 그 사실을 모델이 알아야 잘못 잡힌 것과 제대로 잡힌
것을 구별하고, 실패했을 때 무엇을 의심할지 안다.

**기존 필드는 그대로다.** `duplicate_with`·`unique`·`id`·`placeholder`·`label`·`context` 가
2단계로 잡힌 요소에도 같은 규칙으로 붙는다.

## §3. 목록이 잘렸을 때

관찰 범위가 넓어지면 상한(200)에 걸리는 화면이 는다.

```json
{
  "tab": 0,
  "url": "…",
  "elements": [ … 200개 … ],
  "truncated": true,
  "note": "조작 가능한 요소가 상한(200)을 넘어 잘렸습니다. 찾는 것이 목록에 없으면 find_by_text 로 화면의 글자를 직접 찾으세요."
}
```

**잘렸다는 사실을 반드시 싣는다** (FR-044). 말하지 않으면 모델은 목록이 전부라고 믿고,
화면에 있는 것을 「없다」고 판단한다.

---

## §4. 새 도구 — `find_by_text`

사람이 쓰는 낱말로 요소를 찾는다 (FR-041·FR-042).

```
find_by_text(text: str, tab: int = 0)
```

### 응답

```json
{
  "matches": [
    {
      "text_element": { "element_ref": "e41", "tag": "span", "name": "메뉴관리" },
      "actionable": { "element_ref": "e40", "tag": "div", "actionability": "cursor", "name": "메뉴관리" },
      "context": "메뉴 트리"
    }
  ]
}
```

| 필드 | 뜻 |
|---|---|
| `text_element` | 그 글자를 실제로 담고 있는 요소 |
| `actionable` | **눌렀을 때 반응하는 요소.** 조작에 넘겨야 하는 것은 이쪽이다 |

**둘을 갈라 싣는 이유**: 텍스트는 `<span>` 에 있고 핸들러는 조상 `<div>` 에 붙은 것이 흔하다.
하나로 합쳐 주면 모델은 어느 쪽을 받았는지 모른 채 조작하고, 잘못된 쪽이면 아무 일도
일어나지 않는다.

`actionable` 을 찾지 못하면 `null` 이다 — 그 글자가 화면에 있지만 누를 수 있는 것이
아니라는 뜻이고, 그것도 알아야 할 사실이다.

### 규칙

| 규칙 | 내용 |
|---|---|
| 예산 | **쓴다.** `observe_page` 와 같은 성격이다 — 남용되면 헛돈다 (`mark_item` 과 다른 판단) |
| 일치 방식 | 부분 일치. 사람은 화면 글자를 정확히 옮겨 적지 않는다 |
| 후보가 여럿 | 전부 돌려준다. 고르는 것은 기존 중복 판정 규칙이 받는다 — **짐작하지 말고 묻는다** |
| 후보가 없음 | 빈 배열. 「화면에 그 글자가 없다」는 사실이다 |
| 상한 | 10건. 그 이상이면 낱말이 너무 흔한 것이고, 더 구체적으로 물어야 한다 |

## §5. 못 찾았을 때 — 시스템 프롬프트에 더해지는 규칙

```
- 요소 목록의 `actionability` 가 `cursor` 인 것은 커서 모양으로 짐작한 것입니다.
  조작이 실패하면 그 요소가 실제 대상이 아닐 수 있습니다.
- 지시가 가리키는 것이 목록에 없으면 find_by_text 로 화면의 글자를 직접 찾으세요.
- 그래도 없으면 report_blocked 로 알리세요. 비슷해 보이는 다른 요소를 대신 누르지
  마세요 — 화면에 보이는데 잡히지 않는 것은 제품이 알아야 할 사실입니다.
```

마지막 줄이 FR-043 이다. 020 의 `product_mismatch` 와 다른 종류다 — 그쪽은 제품에 기능이
없는 것이고, 이것은 **있는데 찾지 못한 것**이다.

## §6. 녹화 경로는 바뀌지 않는다

`INTERACTIVE` 상수는 관찰뿐 아니라 녹화에서도 쓰인다 (`closest(INTERACTIVE)`). **그 자리는
건드리지 않는다** (FR-045).

| 경로 | 쓰는 것 | 이 기능의 영향 |
|---|---|---|
| 관찰 (`__itbObserve`) | 1단계 + 2단계 | 넓어진다 |
| 녹화 — 조작의 의미 단위 찾기 | `INTERACTIVE` | 없음 |
| 녹화 — 요소 서술 | `describe` | 없음 |

녹화는 사람이 실제로 누른 요소에서 올라간다. 사람이 눌렀다는 사실이 이미 확실한 근거이므로
짐작을 섞을 이유가 없다.

---

## §7. 조작 거절 규칙은 그대로다

넓힌 범위가 헌법 원칙 IV 를 약화시키지 않는다 (FR-046).

- 가리키는 경로가 요소 하나로 좁혀지지 않으면 **지금과 같이 거절**된다 (`unique: false`).
- 로케이터 후보 수집과 우선순위(`testId` → `role`+이름 → `label` → `text` → 속성 → CSS)는
  그대로다.
- `cursor` 로 잡힌 요소도 같은 후보 수집을 지난다. 그것이 Step 으로 저장될 때 다른 취급을
  받지 않는다 — 헌법 원칙 I 이 요구하는 단일 Step 모델이다.
