# 대체 관계 — 기존 artboard 6종 → 통합 화면 artboard (FR-254b)

**기준**: `docs/design/Workbench.dc.html` (초안 · 승인 대기)
**대체 대상**: `Main` · `RunnerPaused` · `Takeover` · `AiRecord` · `RunResult` ·
`StepInspector`
**대체하지 않는 것**: `TestList` · `CreateTest` — 한 테스트의 국면이 아니다 (FR-217a)

기존 artboard 를 **조용히 폐기하지 않는다.** 6종의 모든 영역이 어디로 갔는지 적는다.
판정 값은 넷뿐이다 — `그대로` / `이동` / `분리` / `옮기지 않음`.
`옮기지 않음` 은 **이유가 필수**다. 이유를 댈 수 없으면 요소를 잃은 것이며 DC-007 위반이다.

|---|---|---|---|---|

## 3. 분리 — 한 영역이 둘로 갈린 것

| 기존 artboard | 영역 | 새 위치 | 판정 | 근거 |
|---|---|---|---|---|
| AiRecord | 우측 `flex: 0 0 540px` (Step 목록 + AI 진행 로그 + 지시문 + 저장) | ③ 우 Step 목록 **460px** / ③ 좌 아래 국면 보조 영역 (지시문 · 로그 · 차단 선택지) | **분리** | 460px 은 Step 패널의 정본값이고(3종 공통), 540 은 로그를 함께 담은 폭이다. 로그를 좌측으로 옮기면 540 을 유지할 근거가 사라진다. 진행 로그는 대상 앱과 함께 봐야 하는 내용이다 (FR-218e) |
| AiRecord | 우측 패널 헤더 `flex: 0 0 46px` (AI CONTROL) | ③ 우 Step 패널 헤더 50px 로 흡수 | **분리** | 헤더가 둘이던 것이 하나가 된다. 작성 배지가 이미 AI 세션임을 말한다 |
| RunResult | Step 결과 행 (결말 표식이 **행의 왼쪽 첫 칸**) | Step 행 칸 4 (**오른쪽 끝**) | **분리** | S-02 — 같은 정보가 국면에 따라 정반대 자리에 있던 것이 사용자가 제기한 문제의 가장 구체적인 형태다. 세션 3종의 자리(오른쪽 끝)를 정본으로 채택했다 |

## 4. 옮기지 않음 — 이유 필수

| 기존 artboard | 영역 | 판정 | 이유 |
|---|---|---|---|
| AiRecord | Step 행의 초록/보라 **체크 표식** | **옮기지 않음** | 그것은 결말 표시가 아니라 **작성 주체** 표시였고, 작성 주체는 Step 패널 헤더의 배지가 이미 담당한다 (FR-228). 결말을 모르는 국면에서 통과 체크를 그리면 통과처럼 보인다 (S-09 · FR-225). 대신 「기록됨」 중립 표식을 둔다 — 승인 대상 A2 |
| Main · RunnerPaused · Takeover · AiRecord | 미러 흰 영역 **안쪽**의 표본 화면 (`flex: 0 0 170px` 사이드바 · 목록 행 · 버튼 등) | **옮기지 않음** | **우리 UI 가 아니다.** 확정 디자인의 흰 영역은 대상 앱의 미러이며 그 안의 표본은 데이터다. 우리가 그리면 안 된다 (002 가 이미 같은 판단을 했다) |
| RunResult | `TRACE` 탭 | **옮기지 않음 (형태는 유지)** | 서버가 501 을 준다(001 의 알려진 차이). 확정 디자인에 있는 것을 빼지 않으려고 그리되 비활성 + 이유로 둔다 (DC-007 · FR-246) |

## 5. 빠짐없음 검사

002 §3 이 쓴 방법을 따른다 — `<div>`·`<svg>` 총계를 세어 이 표가 그 전부를 다루는지 본다.

|---|---|---|
| `Main.dc.html` | 102 | 14 |
| `RunnerPaused.dc.html` | 102 | 19 |
| `Takeover.dc.html` | 108 | 18 |
| `AiRecord.dc.html` | 96 | 14 |
| `RunResult.dc.html` | 96 | 9 |
| `StepInspector.dc.html` | 55 | 3 |
| **대체 대상 합계** | **559** | **77** |

**개수 차이는 그 자체로 불일치가 아니다.** 002 §4 가 이미 같은 주의를 적었다 — 확정
디자인은 표본 데이터가 든 정적 목업이므로 개수는 표본의 양에 따라 달라진다. 위 표의
용도는 **§1~§4 가 다루지 않은 영역이 있는지** 사람이 훑을 때의 눈금이다.

`<svg>` 가 77 → 34 로 줄어든 것은 §4 의 둘째 항목 때문이다. 미러 흰 영역 안쪽의 표본
화면(대상 앱의 아이콘들)을 옮기지 않으므로 그 SVG 는 초안에 없다. **우리 UI 의 SVG 는
전부 옮겼다** — 제품 표시 · 브라우저 툴바 화살표 · 작성 배지 · 결말 표식 · 조작 아이콘.

## 6. 사람이 확인해야 하는 것

이 표는 **구현자가 작성했다.** 002 §4 의 규칙대로 판정은 사람 몫이다.

- §1 의 `그대로` 9건 — 값이 실제로 기존 artboard 의 것인지
- §2 의 `이동` 8건 — 옮긴 자리가 맞는지, 특히 A3·A4, 그리고 **RunnerPaused 조작 블록이
  좌측 보조 영역이 아니라 Step 패널 바닥으로 간 것**(converge T092 가 초안과 구현의
  차이를 찾아 고친 자리다)
- §3 의 `분리` 3건 — 540 → 460 + 좌측이 맞는지
- §4 의 `옮기지 않음` 3건 — **이유가 성립하는지.** 여기가 요소를 잃는 지점이다

승인 절차는 `docs/PENDING-HUMAN-VERIFICATION.md` §6 이 갖는다.
