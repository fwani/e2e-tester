# Contract: 배치 계약 v2 — 007/008 개정판

**Feature**: 015 | **Status**: 계약 | **개정 대상**:
`specs/008-visual-language/contracts/visual-language.md` §2 「허용되는 인라인 `style`」

## 무엇이 바뀌고 무엇이 남는가

2026-09-10 사용자 결정으로 배치 속성도 클래스로 옮긴다. **표현이 바뀔 뿐 구조는 남는다.**

| | v1 (007/008) | v2 (이 계약) |
|---|---|---|
| 배치 판단이 사는 곳 | `lib/layout.ts` 의 `Record<Phase, …>` | **같음** |
| 판단을 내려주는 주체 | 부모(`Workbench`)가 자식에 | **같음** |
| 자식이 자기 크기를 아는가 | 모른다 | **같음 — 모른다** |
| DOM 에 도달하는 형식 | 인라인 `style` 객체 | **클래스 문자열** |
| 허용되는 인라인 `style` | 배치 속성 25종 열거 | **런타임 계산값만** |
| 도달을 검증하는 방법 | `element.style.flex` 읽기 | 3겹 (LC-4) |

## LC-1 — 배치 판단은 표에만 있다

국면별 배치는 `Record<Phase, …>` 표로 표현한다. 표시 컴포넌트가 자기 자리 크기를
스스로 정하지 않는다.

**이 조항이 v1 에서 그대로 옮겨 온 이유**: 007 1회차에 `TargetPane` 이 `flex:"1"` 을,
`PhaseAside` 가 `flex:0 0 auto` 를 각자 하드코딩했고, 각 파일 안에서는 옳았던 둘이 합쳐지자
편집 국면에서 뒤바뀌었다 — 두 줄짜리 안내가 700px 를 가져가고 편집 폼이 42px 띠에 들어갔다
(결함 S-12). **계약을 개정한다는 것이 이 결함을 다시 허용한다는 뜻은 아니다.**

## LC-2 — 표에서 클래스로 가는 길도 전수 표다

```ts
const SPLIT_CLASS: Record<VerticalSplit, string> = { fill: …, content: … };
```

배치 종류가 유한 합집합 타입이므로 이 대응도 컴파일 시점에 전수를 요구한다.
국면이 늘어나도, 배치 종류가 늘어나도 빠뜨릴 수 없다 (FR-020a).

## LC-3 — 인라인 `style` 은 런타임 계산값만

v1 의 허용 목록 25종은 폐지된다. 남는 자격은 하나다 — **렌더 시점에야 값이 정해지는 것**.

| 자격 있음 | 자격 없음 |
|---|---|
| 진행률 막대 너비 (`width: ${pct}%`) | "옮기기 번거로워서" |
| 드래그 중 위치 | "이 화면만 예외로" |
| 실측 기반 크기 (미러 스케일 등) | "나중에 정리" |

모든 예외는 `theme/exceptions.ts` 에 `reason` 과 함께 등록한다. 등록되지 않은 예외는
존재할 수 없다 (008 C-11~C-14 를 그대로 승계).

## LC-4 — 도달 검증의 3겹

v1 의 `expect(panel.style.flex).toBe("0 0 460px")` 한 줄은 세 가지를 한꺼번에 봤다.
클래스로 바뀌면 그중 하나가 사라지므로 셋으로 나눈다.

| 겹 | 무엇을 보나 | 어디서 |
|---|---|---|
| ① 판단 | 배치 결정이 옳은가 (한 국면에 두 자리가 동시에 `fill` 일 수 없다 등) | `layout.ts` 순수 단위 테스트 |
| ② 도달 | 표의 값이 그 DOM 요소까지 갔는가 | `toHaveClass(...)` — 기존 단언 자리 |
| ③ 실재 | 그 클래스가 실제로 CSS 를 만드는가 | 빌드 산출 CSS 조회 (G-B) |

**③ 이 없으면 ② 는 거짓말을 할 수 있다.** `toHaveClass("basis-[460px]")` 는 오타가 있어도
통과하고, Tailwind 가 그 이름을 스캔하지 못했으면 화면은 스타일 없이 렌더된다.

## LC-5 — 한 요소는 한 체계만

전환 중에도 같은 요소에 의미 클래스와 Tailwind 유틸리티를 동시에 걸지 않는다.

**근거**: `tokens.css` 주석이 기록한 두 번의 특이도 사고 — `.tint-*` 가 져서 모든 토스트가
흰색이 됐던 일, `flex-basis` 가 `height` 를 이겨 두 줄 알림이 잘렸던 일. 다투는 규칙이
하나 더 늘어나는 상황에서, 우선순위를 이해하는 것보다 겹치지 않는 것이 안전하다.

가드 G-C 가 이것을 센다. 전환이 끝나면 의미 클래스가 사라지므로 이 가드는
**전환 진행률 계기**이기도 하다.

## LC-6 — 단언을 무르게 만들지 않는다

판정 방법이 바뀌어도 **무엇을 검증하던 테스트인지는 바뀌지 않는다.**
단언 총수가 줄면 그 자리를 지목하고 이유를 대야 한다 (헌법 Quality Gate 4).
