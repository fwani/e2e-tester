# 배선 계약 — 027

이 증분은 **외부 계약을 바꾸지 않는다.** 서버 API 도 저장 형식도 그대로다. 여기 적는
것은 **화면 코드 사이의 계약**이다.

---

## §1 능력 묶음이 지켜야 할 것

1. **선택적이다.** 화면이 어떤 능력을 주지 않는 것은 정상이며, 그 조작이 그 국면에서 「해당 없음」이라는 뜻이다 (FR-003).
2. **국면을 모른다.** 능력은 「할 수 있는 일」이고 「언제 쓸 수 있는가」가 아니다 (FR-006).
3. **선행 확인을 품는다.** 「먼저 저장하고 열기」 같은 절차는 능력 구현 안에 있다 (FR-005).
4. **화면이 소유한다.** 능력 구현은 화면의 상태(고른 Step·미저장 편집)를 읽을 수 있다.

---

## §2 배선 모듈이 **하지 않을** 것

| 하지 않는다 | 왜 |
|---|---|
| 국면을 인자로 받는다 | 판정이 조작표 밖에 하나 더 생긴다 (011 이 막은 것) |
| 「이 조작은 이 국면에서만」을 안다 | 같은 이유 |
| 화면 상태를 직접 읽는다 | 소유가 어댑터에 있다는 007 의 결정을 깬다 |
| 없는 능력을 만들어 낸다 | 없는 것은 없는 채로 둔다 — 조작표가 이미 「해당 없음」이라고 말한다 |

**이 목록이 깨지면 R7 의 「실패의 정의」에 해당한다.**

---

## §3 화면이 노출할 것

```
<루트 요소 data-wired-actions="step.delete,step.moveUp,…">
```

| | |
|---|---|
| 누가 만드나 | 배선 모듈. 화면이 손으로 적지 않는다 |
| 언제 | 렌더할 때마다 |
| 무엇이 들어가나 | 그 화면이 **실제로 이어 둔** 조작 |

**검사가 이것을 조작표와 대조한다.** 표가 활성이라고 말하는데 여기 없으면 실패한다
(FR-014).

---

## §4 편집면 계약

| | |
|---|---|
| 정본 | `StepEditFields` |
| 읽기 전용 | `editable={false}` |
| 항목 판정 | `StepEditFields` 안의 타입 판별자 하나 (FR-010) |
| 값 변경 | `onChange(patch)` — 바뀐 항목만 |

**화면은 편집면을 고르지 않는다.** 「어느 편집면을 쓸까」라는 선택지가 없어지는 것이 이
증분의 요점 중 하나다.

---

## §5 이행 중의 계약 (FR-022)

- 배선 표에 없는 조작은 **기존 경로로 떨어진다.**
- 두 경로가 공존하는 동안에도 **사용자가 보는 것은 같다.**
- 이행이 끝나면 `fallback` 통로가 비워지고, 비어 있음을 검사가 확인한다.
