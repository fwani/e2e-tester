# Data Model: 대상 브라우저를 제품 화면 안에서 조작한다

**Feature**: 010-headless-mirror-control | **Date**: 2026-09-09

이 기능은 **Step DSL 을 바꾸지 않는다.** 미러에서 한 조작은 기존 리코더를 통해 기존
Step 이 된다 (research R1). 따라서 아래 모델은 전부 **전송·표시용**이며 저장되지 않는다.

> 헌법 원칙 I — 미러 조작이 Step 모델에 새 표현을 만들지 않는다는 것이 이 문서의 요지다.
> 새 엔티티가 하나도 저장되지 않는 것이 그 증거다.

---

## 1. 조작 사건 (InputEvent) — 전송용, 저장 안 함

클라이언트 → 서버, 조작 채널로 흐른다. 서버는 이것을 CDP 명령으로 변환해 대상 브라우저에
보낸다. **Step 으로 변환하지 않는다** — Step 은 대상 페이지의 리코더가 만든다.

| 필드 | 형 | 규칙 |
|---|---|---|
| `kind` | 열거 | 아래 목록 중 하나. 목록 밖은 거절 (FR-344) |
| `tab` | 정수 | 지금 보고 있는 탭 번호. 서버가 그 탭에 보낸다 (FR-317) |
| `x`, `y` | 실수 | **표시 좌표계** 기준. 포인터 사건에만 있다 |
| `button` | 열거 | `left`·`middle`·`right`. 포인터 누름·놓음에만 |
| `deltaX`, `deltaY` | 실수 | 휠에만 |
| `key`, `code`, `modifiers` | 문자열·정수 | 키 사건에만 |
| `text` | 문자열 | 문자 입력·조합에만. 길이 상한 있음 |
| `compositionRange` | 정수 2개 | 조합 중 선택 구간. 조합에만 |
| `frameSeq` | 정수 | 이 좌표를 계산한 근거가 된 프레임의 일련번호 |

**`kind` 목록** (이 밖은 채널이 받지 않는다):

```
pointer.down  pointer.up  pointer.move  wheel
key.down      key.up      text.insert   ime.compose  ime.commit
file.attach
```

**검증 규칙** (FR-341):
- `x`·`y` 는 그 프레임의 표시 크기 범위 안이어야 한다. 벗어나면 거절.
- `text` 는 길이 상한을 넘으면 거절.
- `modifiers` 는 알려진 비트 조합만 허용.
- `tab` 은 그 세션에 실제로 있는 탭이어야 한다.
- 세션이 조작 국면이 아니면 **채널 자체가 사건을 받지 않는다** (FR-342).

**`frameSeq` 를 두는 이유**: 사용자가 본 프레임과 서버의 현재 화면이 다를 수 있다.
서버는 이 값으로 **오래된 프레임을 근거로 한 좌표**를 알아낼 수 있다. 이번 범위에서
그것을 근거로 조작을 거절하지는 않는다 — 원격 조작의 본질적 한계는 감출 수 없다(명세
Edge Cases). 다만 진단에 필요하고, 나중에 정책을 넣을 자리를 남긴다.

## 2. 프레임 좌표계 (FrameGeometry) — 기존 프레임 이벤트의 확장

서버 → 클라이언트, 기존 관찰 WS 의 `mirror_frame` 이벤트에 **필드를 더한다.**
현재는 `tab`·`data`·`width`·`height` 뿐이다 (M-06).

| 필드 | 현재 | 이 기능 이후 |
|---|---|---|
| `tab` | 있음 | 그대로 |
| `data` | 있음 (base64 JPEG) | 그대로 |
| `width`, `height` | 있음 (= `deviceWidth`/`deviceHeight`) | 그대로 — **대상 화면 크기다** |
| `pageScale` | 없음 | 추가. `pageScaleFactor` |
| `offsetTop` | 없음 | 추가. 화면 상단 오프셋 |
| `seq` | 없음 | 추가. 프레임 일련번호 (`InputEvent.frameSeq` 의 근거) |

**프레임의 실제 픽셀 크기는 보내지 않는다.** 클라이언트가 이미지에서 직접 읽을 수 있고
(`naturalWidth`/`naturalHeight`), 서버가 보낸 값과 이미지가 어긋날 여지를 만들지 않는
편이 낫다. 요청한 `maxWidth`/`maxHeight` 와 실제 프레임 크기는 **다르다** — 실측에서
1280×800 을 요청해 1067×800 을 받았다 (research R3).

**역변환식** (클라이언트):

```
표시 좌표 (dx, dy)  →  대상 화면 좌표 (x, y)

sx = width  / img.naturalWidth
sy = height / img.naturalHeight

x = round((dx - img.offsetLeft) * (img.naturalWidth  / img.clientWidth ) * sx)
y = round((dy - img.offsetTop ) * (img.naturalHeight / img.clientHeight) * sy) / pageScale + offsetTop
```

식의 형태는 구현이 정한다. **고정해야 하는 것은 「상수 1280·800 을 쓰지 않는다」와
「pageScale·offsetTop 을 변환에 포함한다」** 두 가지다 (FR-331).

## 3. 조작 채널 (ControlChannel) — 서버 런타임 상태

세션마다 최대 하나. 저장되지 않는다.

**상태**

| 상태 | 의미 | 사건을 받는가 |
|---|---|---|
| `closed` | 열려 있지 않다 | 아니오 |
| `open` | 조작 국면이고 채널이 붙어 있다 | 예 |
| `suspended` | 붙어 있으나 지금은 받지 않는다 (프레임 끊김·강등 판단) | 아니오 — 사유를 돌려준다 |

**전이**

```
closed ──(조작 국면 진입 + 클라이언트 접속)──▶ open
open   ──(관찰 국면 전이)──────────────────▶ closed   [FR-342]
open   ──(세션 종료·유실)──────────────────▶ closed   [FR-347]
open   ──(프레임 끊김)────────────────────▶ suspended [FR-346]
suspended ──(프레임 회복)─────────────────▶ open
```

**불변식**
- 관찰 국면에서 `open` 인 채널은 존재할 수 없다 (FR-315·FR-342).
- 채널의 어떤 상태 전이도 실행 상태 기계를 전이시키지 않는다 (FR-348).
- 채널 장애는 실행 실패가 아니다 — 미러 프레임과 같은 성질이다 (FR-047b 유지).

## 4. 브라우저 요구 (BrowserPrompt) — 전송용, 저장 안 함

대상 브라우저가 사용자에게 요구하는 것 중 **페이지 화면이 아닌 것.** 서버가 가로채
관찰 WS 로 알리고, 사용자의 응답을 REST 로 받는다 (research R6·R7).

| 필드 | 형 | 비고 |
|---|---|---|
| `promptId` | 문자열 | 서버 발급. 응답이 어느 요구에 대한 것인지 |
| `kind` | 열거 | `dialog.alert`·`dialog.confirm`·`dialog.prompt`·`file.choose`·`unsupported` |
| `message` | 문자열 | 대화상자 문구. 대상 페이지에서 온 값이므로 **표시 시 이스케이프** |
| `multiple` | 논리 | 파일 선택이 여럿을 받는가 |
| `blocking` | 논리 | 응답이 없으면 대상 페이지가 멈추는가 (대화상자는 참) |

**`unsupported`** 는 제품이 대신 받을 수 없는 요구다 (인증 요구 팝업 등). 화면은 무엇이
막혔고 실제 창으로 전환하면 처리할 수 있다는 것을 말한다 (FR-339·FR-353a).

**응답** (클라이언트 → 서버, REST):

| 필드 | 형 |
|---|---|
| `promptId` | 문자열 |
| `accept` | 논리 |
| `text` | 문자열 (prompt 응답) |
| `fileIds` | 문자열 배열 (파일 선택 응답 — 업로드로 얻은 식별자) |

## 5. 업로드된 파일 (SessionFile) — 세션 범위, 세션과 함께 사라진다

| 필드 | 형 | 규칙 |
|---|---|---|
| `fileId` | 문자열 | **서버 발급.** 저장 경로는 이 값으로 만든다 |
| `displayName` | 문자열 | 사용자에게 보이는 이름. 정리된 값 (FR-337c) |
| `size` | 정수 | 파일당 상한 이하 (FR-337a) |
| `sessionId` | 문자열 | 소속 세션 |

**규칙**
- 저장 경로는 **사용자가 보낸 이름을 쓰지 않는다.** `fileId` 로 만든다 — 경로 구분자·상위
  참조가 이름에 들어와도 무해해진다 (FR-337c).
- 세션당 개수 상한, 파일당 크기 상한을 둔다. 초과는 업로드 단계에서 사유와 함께 거절한다.
- **세션 종료·유실 시 지운다** (FR-337b). 비정상 종료로 남은 것을 정리하는 경로도 둔다.
- 업로드된 파일은 그 세션의 조작에만 쓸 수 있다. 다른 세션이 `fileId` 로 접근할 수 없다
  (FR-340).

## 6. 조작 위치 (ControlSurface) — 화면 상태

| 값 | 의미 |
|---|---|
| `mirror` | 제품 화면 안 미러에서 조작한다 (기본) |
| `window` | 실제 브라우저 창에서 조작한다 (폴백, 사용자가 명시적으로 전환) |

**전이는 사용자 조작으로만 일어난다** (FR-353). 제품이 상황을 판단해 바꾸지 않는다.

`window` 일 때 미러의 안내 문구는 **현재 문구가 그대로 맞다** — 「실제 브라우저 창에서
조작 중 · 이 영역은 관찰용입니다」 (M-05·FR-350). 이 기능은 그 문구를 지우지 않고,
**그 문구가 참인 상태를 `window` 로 좁힌다.**

## 저장 형식 변경 요약

| 대상 | 변경 |
|---|---|
| Step DSL | **없음** |
| 저장된 테스트 파일 | **없음** |
| 세션 저장 상태 | **없음** |
| 사용자 설정 | 조작 위치 기본값을 기억할 필요가 생기면 추가 — 이번 범위에서는 두지 않는다 |

이 표가 비어 있는 것이 헌법 원칙 I·V 준수의 증거다. 내보내기(Export)에 영향이 없고,
기존에 저장된 테스트가 이 기능으로 달라지지 않는다.
