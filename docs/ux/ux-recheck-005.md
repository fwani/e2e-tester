### U-01. 결과 화면의 재실행 두 버튼 — **해소**

- **관찰**: 노란 경고 없이 `POST /api/sessions` **201**, 즉시 새 세션의 러너로 이동

### U-02. 부분 실행 표기 — **해소** (진단 첫 줄만 잔존)

- **조작**: 결과 화면에서 「Step 06부터 실행」 → 완료까지 관찰 → 결과 화면 재확인.
- **해소된 것**
  - 버튼 라벨에 시작점이 박혔다 — 「**Step 06부터 실행**」. 옆에 보조 문구
    「01~05 는 건너뜁니다. 로그인 같은 앞선 상태가 필요하면 「처음부터 실행」을 쓰세요.」
  - 실행 중 Step 목록에서 01~05 가 「**건너뜀**」 칩으로 표시된다.
  - 요약이 「실패 · **부분 실행 Step 06~07** · Step 06 에서 실패 · **0 / 2 통과** ·
    **(01~05 건너뜀)** · 20.03 s」. `0 / 7` 이 아니다.
  - 결과 화면에 「최근 전체 실행: 실패 · Step 06 에서 실패 · 5 / 7 통과 · 22.81 s」 보조
    표시가 남는다 (전체 결과를 덮지 않음).
  - 건너뜀(회색 체크박스 + 「건너뜀」)과 미실행(점선 + 「미실행」)이 다른 표시다.
  - 요약 바로 아래에 노란 경고 「앞선 Step(01~05)을 건너뛰었기 때문에 로그인 같은 선행
    상태가 없을 수 있습니다. 먼저 「처음부터 실행」으로 확인하세요.」
  - 증거 스크린샷도 실제 상태(로그인 화면)를 보여준다.
- **잔존**: 「Step 06 실패」 진단 상자 **안쪽 첫 줄**은 여전히
  「기다렸지만 요소가 나타나지 않았습니다. 대상 화면이 느릴 수 있습니다 — 실행 속도를
  '느림'으로 낮추거나 … 대기 시간을 늘린 뒤 …」다. quickstart S4-5 는 진단 첫 줄이 선행
  Step 건너뜀을 먼저 지시하라고 적어 두었다. 다만 그 지시는 **진단 상자보다 위에**
  노란 경고로 이미 나오므로 사용자가 잘못된 방향으로 끌려갈 위험은 크게 줄었다.
  → 판정은 **해소**, 문구 정리만 남은 것으로 본다.

### U-03. 중지 — **부분 재발**

- **조작**: TC-001 실행 → Step 06(20초 대기) 진입 → 「중지」 1회.
- **해소된 것 (핵심)**
  - 「브라우저 세션이 유실됐습니다」 오류가 **사라졌다**.
  - 결과가 **FAIL 로 기록되지 않는다** — `GET /api/tests` 의 `outcome = "stopped"`,
    목록 상단 FAIL 카운트 **0**.
  - 요약이 「**중지 · Step 06 에서 중지 · 5 / 7 통과 · 2.94 s**」, 본문 「실행을
    중지했습니다.」 + 다음 행동 「처음부터 실행」「Step 06부터 실행」「목록으로」.
- **재발/미해소로 남은 것**
  1. **제목이 「TC-001 초안」** 이다. 저장된 테스트를 재실행했을 뿐인데 작성 중 초안으로
     보인다 (원 리포트 개선안 4 미반영). quickstart S2-3 은 「초안」 없음을 기대로 적었다.
  2. **세션 UUID 가 그대로 노출된다** — 경고 배너
     「세션을 찾을 수 없습니다: 5044d30354884c3f9c35feaf3f4bfa00 / 세션이 이미 끝났습니다.
     새 세션을 시작하세요.」 중지 직후 프론트가 `GET /api/sessions/{id}/tabs` 를 계속
     폴링해 **404 를 오류 배너로 띄우는 것**을 실측했다(응답 로그에 404 3건). 원 리포트
     개선안 5 미반영, quickstart S2-3 의 「세션 식별자 노출 없음」 미달.
  3. 하단에 **「테스트 이름」 입력칸 + 「저장」(비활성)** 저장 프롬프트가 여전히 뜬다.
     배지도 `REVIEW`(내부 상태명 영문 노출).
  4. 다음 행동 버튼이 **3개**다(quickstart 기대는 4개). 「결과 자세히 보기」가 없어 이
     화면에서 실패/중지 진단으로 바로 갈 수 없다.
- **증거**: ![](shots/2026-09-07-recheck/s2-02-stopp3s.png)
- **참고**: 「중지 중…」 전이 라벨은 **관찰하지 못했다**. 중지가 0.15초 안에 끝나 전이
  구간이 화면에 남지 않았다 — 결함으로 보지 않는다.

### U-04. 일시정지 — **부분 재발**

- **조작**: TC-001 실행 → Step 06 진입 → 「일시정지」 1회 → +0.3s / +3s / +8s / 종료까지 관찰.
- **해소된 것 (핵심)**
  - **+0.3초에 전이 상태가 보인다** — 배지 「**일시정지 중…**」, 부제
    「**현재 Step 이 끝나면 멈춥니다 · Step 06 대기 중 (최대 20s)**」. 10초를 기다리지
    않는다. 남은 대기 예산도 같이 나온다.
  - **편집 팔레트가 열리지 않는다** — 그 자리에 「정지되면 편집할 수 있습니다. 현재 Step 이
    끝나기를 기다리고 있습니다.」 안내 상자.
  - **전이 중에도 「중지」가 활성**이다. 「계속하기」는 비활성.
  - 실행이 끝난 뒤 배지가 「**실행 종료**」로 바뀌고 머리글이
    「**멈추기 전에 실행이 끝났습니다** · 실패 · Step 06 에서 실패 · 5 / 7 통과 · 22.81 s」.
    `PAUSED` 배지와 결말이 동시에 뜨는 일은 없어졌다.
- **재발/미해소로 남은 것**
  1. **낡은 배너가 지워지지 않는다.** 실행이 끝난 화면에 여전히
     「Step 하나가 10초 안에 끝나지 않아 **아직 실행 중입니다**. 그 Step 이 끝나면 멈춥니다
     — 지금 편집한 내용은 끝난 뒤의 목록에 적용됩니다.」가 남아 있다 (개선안 5 의
     "낡은 배너는 지운다" 미반영).
  2. **미리보기 오버레이가 상태와 어긋난다.** 전이 중(+0.3초)에도, 실행이 끝난 뒤에도
     미러 머리줄이 「**일시정지** 브라우저 세션과 화면 상태를 그대로 유지하고 있습니다.」
     라고 단정한다. 배지는 「일시정지 중…」 / 「실행 종료」인데 같은 화면 안에서 다른 말을
     한다 — U-04(a) "아직 아닌 것을 됐다고 말한다" 가 이 영역에 남아 있다.
  3. **「결과 자세히 보기」와 실패 사유 본문이 없다.** 요약 한 줄만 있어 일시정지를
     눌렀다는 이유로 진단 경로를 잃는 문제가 그대로다 (quickstart S3-4 기대 미달).
  4. 제목이 「TC-001 초안」 (U-03 잔존 1 과 같은 뿌리).

### U-06. 「처음부터 실행」 연타 — **해소**

- **조작 (a) 실제 클릭**: 결과 화면의 「처음부터 실행」 1회 클릭 후 +0.15초 화면.
  → 두 버튼 모두 **비활성 + 라벨 「실행을 준비하는 중…」**. 목록 행의 「실행」도 같은 방식으로
  +0.1초에 「준비 중…」 비활성이 된다(S1-1 통과).
- **조작 (b) 최악 조건**: `button.click()` 을 **한 JS 태스크 안에서 5회** 동기 호출해
  React 의 비활성 반영을 앞질렀다. → `POST /api/sessions` 5건이 나갔고 그중
  **201 정확히 1건, 409 4건**. 실제 브라우저 창은 **1개**만 떴고, 목록에 배너가 두 줄로
  뜨는 현상도 없었다. 백엔드 직렬화(FR-128)가 실제로 동작한다.

### U-08. 끝난 실행의 「중지」 — **해소**

- **조작**: TC-002(PASS) 실행 → 완료 화면 관찰 → 우상단 버튼 클릭.
- **관찰**

### U-24. 미리보기(미러) — **해소**

### 부분 재발 2건의 공통 원인

U-03·U-04 의 곁가지는 전부 같은 형태였다 — **고친 곳 옆에 같은 사실을 말하는 다른 곳이
있었다.** 배지는 고쳐지고 부제는 남았고, 저장 경로는 고쳐지고 재실행 경로는 남았고,
`work_of` 는 고쳐지고 `tabs.py` 는 남았다.

한 번의 수정이 한 자리만 고치는 것이 문제였고, 그래서 이번 수정은 **문구와 판정을 한 곳으로
모으는 쪽**을 골랐다. `wording.ts` 에 `sessionTitle()`·`pausedAfterLabel()`·`mirrorNotice()`,
신규 `sessionState.ts` 에 `isRunning()`. 한 줄을 고쳐 증상을 없애는 것보다 비용이 크지만,
증상이 하나 남았을 때 그것이 마지막인지 알 수 있다.

### 재점검이 새로 알려 준 것

**N-04 는 결함이 아니라 빠진 작업이었다.** 「실패한 Step 건너뛰고 계속」은 FR-137·
ui-contract §6-5·quickstart §3-6 이 모두 요구하고 백엔드(`skip_failed`)도 서 있었는데,
그것을 보내는 화면 작업이 tasks.md 에 **없었다**. 계약과 백엔드만 있으면 "구현했다" 로
보이고 자동 테스트도 통과한다 — 그 절반은 사람이 걸어야 드러난다. 이것이 T110·T092 같은
수동 검증을 자동 테스트로 대체할 수 없는 이유의 구체적인 사례다.

**AS-027 은 결함에 기대어 통과하고 있었다.** 「이미 종료된 세션에 조작을 보낸다」 시나리오는
화면의 오류 배너를 근거로 통과했는데, 그 배너의 출처는 그 조작이 아니라 U-03-b 가 지적한
탭 404 였다. 그 배너를 없애자 시나리오가 깨졌고, 실제 처리(화면이 조작을 거두어 간다)는
더 강한 것이었다. **이상 조작 테스트는 "무엇이 떴는가" 가 아니라 "어느 통로로 떴는가" 를
봐야 한다** — 그러지 않으면 결함이 테스트를 지탱한다.
