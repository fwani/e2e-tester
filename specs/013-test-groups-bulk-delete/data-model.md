# Data Model — 테스트 복수 삭제와 그룹

**Feature**: 013-test-groups-bulk-delete | **Date**: 2026-09-10

## §0 한눈에 — 무엇이 바뀌는가

| 층 | 변경 |
|---|---|
| **Step DSL** | **없음.** Step 을 읽지도 쓰지도 않는다 |
| 테스트 정의(`Test`) | **`id` 의 형식이 넓어진다.** 필드는 늘지 않는다 |
| 프로젝트 파일(`Project`) | `groups` 목록이 **생긴다.** 기본값 빈 목록 — 기존 파일이 그대로 읽힌다 |
| 디스크 배치 | `tests/<ID>-<이름>.yaml` 과 `.runs/<ID>/` 의 **`<ID>` 가 `TC-` 로 시작하지 않을 수 있다** |
| 휴지통 | 012 의 `trash/` 아래에 **테스트 항목**이 생긴다 |

**호환**: 이 기능 이전에 만든 프로젝트·테스트를 그대로 읽고 실행한다. 새 필수 필드가 없고,
`TC-001` 은 넓어진 식별자 형식을 그대로 만족한다 (SC-629).

## §1 테스트 식별자

```
USER-003
└─┬─┘ └┬┘
접두어  번호
```

| 성질 | 값 |
|---|---|
| 형식 | `^[A-Z][A-Z0-9]{0,7}-\d{3}$` — 대문자 ASCII 접두어(1~8자) + `-` + 3자리 번호 |
| 접두어 | 그 테스트가 **지금 속한 그룹**을 나타낸다. 그룹 없음은 `TC` |
| 번호 | **프로젝트 전체에서 고유하다.** 접두어가 달라도 같은 번호를 두 번 쓰지 않는다 |
| 쓰이는 자리 | 정의 파일 이름(`tests/USER-003-로그인.yaml`), 실행 산출물(`.runs/USER-003/`), 결과 파일 |
| 바뀔 때 | **그룹을 옮길 때만** (FR-444a). 이름을 바꾸는 것으로는 바뀌지 않는다 |

**왜 대문자 ASCII 인가**: 식별자가 파일 이름과 디렉터리 이름이 된다. macOS 의 기본 파일
시스템은 대소문자를 구별하지 않으므로, `user-001` 과 `USER-001` 을 둘 다 허용하면 한 자리를
두 식별자가 다투는 경로가 생긴다 (research R1).

**왜 번호가 프로젝트 전체 고유인가**: 그룹을 옮길 때 **접두어만 바뀌고 번호는 그대로**여서
(`USER-003` → `DATA-003`) 새 자리가 이미 차 있을 수 없다. FR-444c(식별자 고유)를 규칙이
아니라 **구조로** 만족시킨다 (research R3).

## §2 테스트 그룹

프로젝트 파일(`itb-project.yaml`)의 `groups` 에 산다.

```yaml
groups:
  - prefix: USER
    name: 사용자관리 테스트
  - prefix: DATA
    name: 데이터 관리 테스트
```

| 필드 | 규칙 |
|---|---|
| `prefix` | `^[A-Z][A-Z0-9]{0,7}$`. 프로젝트 안에서 고유. **`TC` 는 예약** (FR-445a) |
| `name` | 앞뒤 공백 제거 후 1~100자. 프로젝트 안에서 고유 (FR-442) |

**저장 위치가 프로젝트 파일인 이유** (research R2):

- 테스트에서 유도할 수 없다 — 접두어는 식별자에서 읽히지만 **사람이 읽는 이름은 어디에도 없다.**
- **테스트가 없는 그룹**이 존재해야 한다. 사용자는 그룹을 먼저 만들고 그 안에 테스트를 만든다.
- 프로젝트 파일은 **커밋 대상**이다. 그룹 구성은 팀이 공유할 정보다.

**기존 프로젝트 파일에는 `groups` 가 없다.** 기본값이 빈 목록이어야 그대로 읽힌다.

## §3 그룹과 테스트의 관계

**테스트 하나는 그룹 0개 또는 1개에 속한다.** 소속은 **별도 필드로 저장하지 않는다** —
식별자의 접두어가 곧 소속이다.

| 접두어 | 뜻 |
|---|---|
| `TC` | 그룹 없음. 기존 테스트와, 그룹을 지정하지 않고 만든 테스트 |
| 그 외 | `groups` 에서 그 접두어를 가진 그룹 |

**진실을 하나로 두는 것이 요점이다.** 소속을 `Test.group` 같은 필드로도 저장하면 접두어와
필드가 어긋날 수 있고, 어긋났을 때 어느 쪽이 맞는지 정할 근거가 없다.

**접두어가 `groups` 에 없는 테스트** — 사용자가 그룹을 지웠거나 파일을 손으로 옮긴 경우다.
목록을 막지 않는다. 그 접두어를 이름 삼아 보여주고, **그룹 정의가 없다는 사실**을 함께
표시한다. 「목록을 그리는 일이 파일 하나 때문에 통째로 실패하면 안 된다」는 기존 규칙과 같다.

## §4 휴지통 안의 테스트 항목

```
~/.local/share/itb/trash/20260910-143000-USER-003-로그인/
├── USER-003-로그인.yaml     ← 정의. **원래 파일명 그대로**
└── runs/                    ← .runs/USER-003/ 의 내용 (있을 때만)
```

| 성질 | 값 |
|---|---|
| 부모 | `paths.trash_dir()` — 012 가 만든 것을 그대로 쓴다 |
| 항목 이름 | `<YYYYMMDD-HHMMSS>-<ID>-<이름>`, 겹치면 `-2`·`-3` (`allocate_trash_path`) |
| 되돌리기 | `.yaml` 을 프로젝트의 `tests/` 로, `runs/` 를 `.runs/<ID>/` 로 옮긴다 |

**원래 파일명을 그대로 두는 것이 요점이다** (research R6). 되돌리기가 「이 `.yaml` 을 `tests/`
로 옮긴다」 한 걸음이 된다. 이름을 바꿔 두면 사용자가 원래 이름을 알아내야 한다.

**도구는 휴지통을 읽지도 비우지도 않는다** — 012 와 같다.

## §5 선택 상태

지금 삭제·그룹 이동 대상으로 고른 테스트들. **화면에만 있고 저장되지 않는다.**

| 성질 | 값 |
|---|---|
| 사는 곳 | 목록 화면의 상태. 서버에 보내지 않는다 |
| 새로 고치면 | 비어 있다. **정상이다** — 잃어도 막히지 않는 정보만 화면에 둔다 |
| 걸러 보기가 바뀌면 | 화면에서 사라진 항목은 선택에서도 빠진다 (FR-429) |

**보이지 않는 것이 선택에 남으면 안 되는 이유**: 사용자가 검색어를 바꾼 뒤 「선택한 항목
삭제」를 누르면, 지금 화면에 없는 테스트가 지워진다. 무엇을 지웠는지 볼 수 없는 삭제가 된다.

## §6 이 기능이 만들지 않는 것

- **`Test` 에 그룹 필드** — 접두어가 정본이다 (§3).
- **그룹 식별자(UUID 등)** — 접두어가 그 역할을 한다.
- **휴지통 항목의 목록·복구 상태** — 도구는 휴지통을 읽지 않는다.
- **중첩 그룹·태그** — spec Out of Scope.
