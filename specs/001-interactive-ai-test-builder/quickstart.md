# Quickstart & Validation Guide

**Feature**: `001-interactive-ai-test-builder` | **Date**: 2026-09-03

이 문서는 기능이 실제로 동작함을 **끝에서 끝까지 증명하는 실행 절차**다. 구현 코드는 담지 않는다.
각 시나리오는 spec의 사용자 스토리와 성공 기준에 1:1로 대응하며, 통과 여부를 눈으로 확인할 수 있다.

---

## 0. 사전 준비

### 확인된 개발 환경

Python 3.13.0 (pyenv) · Node 23.7.0 / npm 10.9.2 · uv 0.9.7 · macOS 26.2 arm64

> Playwright for Python이 Python 3.13을 지원하지 않으면 3.12로 내린다 (research R1 검증 항목).
> 첫 설치에서 확인한다.

### 설치

```bash
# 백엔드
uv sync                          # pyproject.toml 기준
uv run playwright install chromium

# 프론트엔드
npm --prefix frontend install

# 스키마 생성물 최신화 (research R6)
uv run python -m itb.schema.export
npm --prefix frontend run gen:types
```

### 테스트 대상 앱

실제 웹 앱이 필요하다. 두 가지 중 하나를 준비한다.

1. **권장 — 저장소에 포함된 픽스처 앱**: 로그인 화면, 프로젝트 목록·생성·삭제(⋮ 메뉴 안 삭제),
   새 창으로 열리는 약관 화면(`target="_blank"` 와 `window.open` 두 경로), 파일 입력을 가진 최소 정적 앱.
   `data-testid` 가 붙은 요소와 붙지 않은 요소를 약 6:4로 섞어 두어 SC-008 이 자동으로 통과하지 않게 했다.

   **표준 라이브러리만 쓰므로 npm 설치가 필요 없다.**
   ```bash
   python fixtures/sample-app/serve.py --port 4300   # http://127.0.0.1:4300/login.html
   ```
   통합·종단 테스트는 이 서버를 자동으로 띄운다 (`backend/tests/conftest.py`).
2. 사내 개발·스테이징 환경 (접근 권한 필요, spec Dependencies)

**아래 시나리오는 픽스처 앱 기준으로 기술한다.** 사내 앱을 쓰면 요소 이름을 바꿔 읽는다.

### 자격 증명 (US4 이후 필요)

```bash
ant auth status                  # 활성 프로필이 있으면 그대로 사용
# 없으면
ant auth login                   # 또는 export ANTHROPIC_API_KEY=...
```

키를 코드나 설정 파일에 넣지 않는다 (FR-084).

### 실행

```bash
# 백엔드 — 로컬 인터페이스에만 바인딩 (FR-088a)
cd backend && uv run uvicorn itb.api.app:app --host 127.0.0.1 --port 4320

# 프론트엔드
cd frontend && npm run dev       # http://127.0.0.1:4310
```

## 1. 자동 검증 — 먼저 이것이 통과해야 한다

```bash
uv run pytest tests/unit          # Recorder / Runner 상태 기계 / Generator / Locator / Secrets
uv run pytest tests/contract      # REST·WebSocket·DSL 계약
uv run pytest tests/integration   # 픽스처 앱 대상 통합
uv run pytest tests/e2e           # 사용자 향 흐름당 최소 1개 (헌법 품질 게이트 3)
npm --prefix frontend test
```

### 헌법 게이트 전용 검사 — 별도로 돌려 결과를 확인한다

```bash
# 원칙 II: 실행 경로에서 언어모델 도달 불가 (정적)
uv run lint-imports
#   → execution-no-llm 계약 통과해야 함. 실패 시 빌드 실패가 정상 동작이다.

# 원칙 II: 재실행 시 언어모델 호출 0건 (동적, SC-006)
uv run pytest tests/integration/test_replay_no_llm.py -v

# 원칙 I: 라운드트립 정합성 (헌법 품질 게이트 2)
uv run pytest tests/integration/test_roundtrip.py -v
#   → 녹화 → 저장 → 재실행 → (P2 Export 준비 검증) 결과 일치

# 원칙 IV: 후보 수집률 (SC-008)
uv run pytest tests/integration/test_locator_coverage.py -v
#   → verified 후보 2개 이상인 Step 비율 90% 이상

# 보안: 민감 값 평문 노출 0건 (SC-010)
uv run pytest tests/integration/test_secret_leakage.py -v

# DSL 스키마 드리프트 (research R6)
uv run pytest tests/contract/test_schema_drift.py -v
```

**`lint-imports` 가 실패하면 다른 검증을 진행하지 않는다.** 원칙 II가 깨진 상태에서 나머지 결과는 의미가 없다.

## 2. US1 — 직접 녹화로 테스트 만들기

| 단계 | 조작 | 기대 결과 |
|------|------|-----------|
| 1 | 프로젝트 생성 (경로 지정, 시작 URL `http://localhost:4300/login`) | `itb-project.yaml` 과 `.gitignore` 생성. `.gitignore` 에 `secrets.local.yaml`, `.runs/` 포함 |
| 2 | "테스트 만들기" → "직접 녹화" → 녹화 시작 | **실제 Chromium 창**이 앞으로 나오고 시작 URL이 열린다 (FR-023a) |
| 3 | 창에서 로그인 → 프로젝트 메뉴 → 프로젝트 생성 → 이름 `TEST` 입력 → 저장 클릭 | 제품 화면 Step 목록에 동작마다 Step이 **p95 200ms 안에** 추가된다 (R8) |
| 4 | 이름 입력을 여러 번 고쳐 본다 | Step이 늘지 않고 **최종 값 하나**로 유지된다 (FR-025) |
| 5 | 한글로 프로젝트 이름을 입력해 본다 | 조합 중인 자모가 아니라 **완성된 문자열**이 Step 값에 들어간다 (research R2) |
| 6 | 녹화 정지 → 이름 "프로젝트 생성" 으로 저장 | `tests/TC-001-*.yaml` 생성. 목록에 `TC-001`, Step 수, `RECORD` 배지 표시 |
| 7 | Step 0개로 저장 시도 | 거절되고 사유가 표시된다 (FR-029) |

**파일로 확인**:

```bash
cat <프로젝트>/tests/TC-001-*.yaml
```
→ `contracts/step-dsl.md` 의 단일 탭 예와 같은 형태여야 한다. 각 `target` 에 후보가 2개 이상,
비밀번호 Step의 `value` 가 `{{...}}` 참조여야 한다 (FR-082).

## 4. US2 — 재실행과 실패 진단

| 단계 | 조작 | 기대 결과 |
|------|------|-----------|
| 1 | `TC-001` 실행 | Step별 통과 표시와 소요 시간이 실시간으로 나온다. 미러가 5~10 fps로 갱신 (R8) |
| 2 | 결과 확인 | `PASS`. 목록 상태와 마지막 실행 시각 갱신 |
| 3 | **10회 연속 실행** | 10회 모두 `PASS` (SC-003) |
| 4 | 실행 중 미러 WebSocket을 끊는다 (개발자 도구에서 연결 차단) | **실행이 계속 진행되어 정상 완료된다** (FR-047b) |
| 5 | 픽스처 앱의 "저장" 버튼 텍스트를 "적용"으로 바꾼다 | |
| 6 | 다시 실행 | 해당 Step에서 `FAIL`. 실행 중단 |
| 7 | 결과 화면 확인 | 총 시간·통과/전체·멈춘 Step 표시. 실패 상세에 **시도한 후보가 우선순위 순으로 각각 실패 표시**되고 대기 시간 초과값이 나온다 (FR-021) |
| 8 | `SCREENSHOT`·`CONSOLE`·`NETWORK` 탭 전환 | 각각 내용이 보인다. **`TRACE` 탭은 비활성** (spec 디자인 차이 1) |
| 9 | "실패한 Step부터 실행" | 이전 Step을 재실행하지 않는다 (FR-055) |
| 10 | "Step 05 고치기" → "다시 집기" → 브라우저에서 "적용" 버튼 지정 | 후보가 갱신되고 재실행이 통과한다 (FR-020) |
| 11 | 대상 앱을 정지시킨 뒤 실행 | 대기 시간 초과 후 실패로 기록되고 **응답 없이 멈추지 않는다** (FR-057) |

**1분 안에 원인 파악**(SC-009): 7~8단계만 보고 "버튼 이름이 바뀌었다"를 판단할 수 있어야 한다.

## 5. US3 — Pause → Edit → Resume (원칙 III의 핵심 검증)

로그인을 포함해 사전 Step이 5개 이상인 시나리오로 검증한다 (SC-007).

| 단계 | 조작 | 기대 결과 |
|------|------|-----------|
| 1 | 녹화 시작 → 로그인 → 프로젝트 메뉴 → **실수로 데이터 메뉴** 클릭 | Step 3개 기록 |
| 2 | 일시정지 | 배지 `PAUSED`. 브라우저 창이 닫히지 않는다. "세션과 화면 상태를 유지하고 있습니다" 안내 (FR-033) |
| 3 | 브라우저 창을 직접 확인 | 데이터 화면 그대로. 로그인 상태 유지 |
| 4 | **이미 실행된** Step 03(데이터 메뉴) 삭제 | 삭제되고 번호가 다시 매겨진다. **경고 표시**: 이 편집은 현재 화면에 적용되지 않았음 (FR-040b) |
| 5 | 브라우저 화면 확인 | **되돌아가지 않았다.** 여전히 데이터 화면 (FR-040a) |
| 6 | "직접 동작 추가" → 창에서 프로젝트 메뉴 → 생성 → 이름 입력 → 저장 | Step이 일시정지 위치에 삽입된다 (FR-036) |
| 7 | "Assertion 추가" → 요소 보임 → `TEST` | 검증 Step 삽입 (FR-037) |
| 8 | 순서 변경 | 반영된다 (FR-035) |
| 9 | **"계속하기"** | **로그인이 재실행되지 않는다.** 현재 상태에서 이어서 진행 (FR-038, SC-007) |
| 10 | 저장 후 재실행 | 처음부터 통과한다 |
| 11 | 4종 Assertion 각각 추가해 본다 | 보임 / 안 보임·없음 / 텍스트 / URL 모두 동작 (FR-013a) |
| 12 | 항목을 삭제한 뒤 '안 보임' 검증 | 통과. 처음부터 없던 요소에도 통과 (spec 엣지 케이스) |
| 13 | 일시정지 중 브라우저 창을 직접 닫는다 | 세션 유실을 알리고 **Step은 보존**된다 (FR-041) |

**9단계가 이 기능 전체의 핵심 증거다.** 로그인이 다시 돌면 원칙 III가 구현되지 않은 것이다.

## 6. US4 — 자연어로 테스트 만들기

| 단계 | 조작 | 기대 결과 |
|------|------|-----------|
| 1 | "테스트 만들기" → "AI로 만들기" → 지시문 입력 (PRD §6 예시) | 브라우저가 열리고 `AI 수행 중` 배지 |
| 2 | 진행 관찰 | 미러에 AI 조작이 보이고, **성공한 동작만** Step으로 쌓인다 (FR-061) |
| 3 | 완료 후 안내 문구 확인 | "지시문은 저장되지 않으며 재실행 시 AI를 쓰지 않습니다" (FR-064) |
| 4 | "테스트로 저장" | `authoring_mode: ai` 로 저장. 목록에 `AI` 배지 |
| 5 | 저장 파일 확인 | `ai_instruction` 에 원문이 있고, `steps` 는 결정적 Step이다 (FR-063) |
| 6 | **저장한 테스트 재실행** | 통과하며, 언어모델 호출 **0건** (SC-006) |
| 7 | 네트워크를 끊고 재실행 | **통과한다.** 실행이 언어모델에 의존하지 않음의 증거 |
| 8 | 수행 불가능한 지시문 입력 | 시도 상한 안에서 중단하고 무엇을 못 했는지 알린다 (FR-066) |
| 9 | AI 수행 중 일시정지 | US3와 동일하게 편집 가능 (FR-065) |
| 10 | 언어모델 자격 증명을 잘못 설정하고 시도 | 실패를 알리고 그때까지의 Step을 보존한다 (FR-067) |

**7단계가 원칙 II의 가장 직관적인 증거다.** 네트워크 없이 저장된 테스트가 돌아야 한다.

**SC-002 측정**: 자연어 시나리오 20건을 실행해 결정적 테스트로 변환 성공한 비율이 70% 이상인지 기록한다.

## 7. US5 — AI 실패 → 사람이 이어받기

픽스처 앱에 AI가 찾기 어려운 요소(⋮ 메뉴 안의 삭제)를 두어 실패를 유도한다.

| 단계 | 조작 | 기대 결과 |
|------|------|-----------|
| 1 | "TEST 프로젝트를 삭제해" 지시문으로 AI 실행 | 삭제 단계에서 막힌다 |
| 2 | 화면 확인 | **브라우저가 닫히지 않았다.** 실패 이유와 4선택지 (FR-069, FR-070) |
| 3 | "직접 수행" 선택 | `사람이 녹화 중` + `세션 유지` 표시. **AI가 남긴 화면 그대로** (FR-071) |
| 4 | ⋮ → 삭제 → 확인 클릭 | Step이 `HUMAN` 배지로 기록된다 (FR-075) |
| 5 | Step 목록 확인 | AI Step과 HUMAN Step이 **같은 형태**로 한 목록에 있다 (원칙 I) |
| 6 | "계속하기" | AI가 남은 지시를 현재 상태에서 이어서 수행 (FR-076) |
| 7 | 1단계로 돌아가 "AI에게 다시" 선택 | 현재 상태에서 재시도 (FR-072) |
| 8 | "건너뛰기" 선택 | 실패한 동작을 Step으로 남기지 않고 다음으로 (FR-073) |
| 9 | "종료" 선택 | 세션 종료 후 저장 여부 확인 (FR-074) |
| 10 | 저장 후 재실행 | 통과하며 언어모델 호출 0건 |

**SC-004 측정**: AI 실패 사례에서 Takeover로 완료한 비율이 80% 이상인지 기록한다.

## 10. 민감 값과 키 (FR-089)

| 단계 | 조작 | 기대 결과 |
|------|------|-----------|
| 1 | 키 상태 확인 → 키 쌍 생성 | 공개키 지문 표시. `private.key` 권한이 `0600` |
| 2 | 녹화 중 비밀번호 입력 | Step 값이 `{{...}}` 참조. 화면에 마스킹 표시 (FR-083) |
| 3 | `tests/*.yaml` 을 `grep` 으로 검사 | **비밀번호 평문이 없다** (SC-010) |
| 4 | `secrets.local.yaml` 확인 | base64 암호문과 공개키 지문만 있다 (FR-089c) |
| 5 | `.gitignore` 확인 | `secrets.local.yaml` 이 제외 대상 |
| 6 | 비밀키를 임시로 옮기고 재실행 | 해당 Step이 **명확한 사유와 함께 실패**. 빈 값으로 통과하지 않는다 (FR-089f, SC-011) |
| 7 | 비밀키를 되돌리고 재실행 | 통과 |
| 8 | 동일 이름 환경 변수를 설정하고 재실행 | 복호화 대신 환경 변수 값을 쓴다 (FR-089g) |
| 9 | 비밀키를 지우고 **녹화**만 해 본다 | **녹화는 정상 동작한다** — 공개키만 필요 (FR-089b) |
| 10 | 실행 산출물 전체를 `grep` | 로그·실패 메시지·스크린샷 메타데이터에 평문 없음 (FR-089d) |
| 11 | 공개키를 교체하고 비밀 목록 확인 | 지문 불일치를 알리고 재입력을 안내 (spec 엣지 케이스) |

**9단계가 비대칭 방식을 택한 이유의 직접적 증거다.**
