# Quickstart — 024 를 직접 확인하는 법

**목적**: 자동 검증이 덮지 못하는 것을 사람이 손으로 본다. 이 기능에서 자동 검증이
덮지 못하는 것은 하나로 모인다 — **테두리가 진짜 그 요소 위에 있는가.**

좌표가 한 칸 어긋나도 단위 검증은 전부 통과한다. 변환식은 자기 자신과만 맞으면 되기
때문이다. 실제 브라우저·실제 프레임·실제 요소가 있어야만 드러난다.

**§3 과 §4 가 가장 중요하다.**

| | 왜 |
|---|---|
| **§3 밀집 화면** | 좌표가 조금 틀려도 넓은 버튼에서는 안 드러난다. 작은 요소가 드러낸다 |
| **§4 스크롤** | 스크롤은 좌표가 **낡는** 유일한 경로다. 여기가 FR-002 의 시험대다 |

---

## 0. 띄운다

```bash
python fixtures/sample-app/serve.py --port 4300     # 대상 화면
cd backend && uv run itb                            # 제품 서버
cd frontend && npm run dev                          # http://127.0.0.1:4310
```

---

## 1. 기본 — 테두리가 뜨는가

1. 프로젝트를 만들고 대상 주소를 `http://127.0.0.1:4300/login.html` 로 둔다.
2. AI 작성을 시작하고 지시한다 — 「아이디 칸에 `demo` 를 입력하고 로그인 버튼을 누른다」
3. 미러를 본다.

**보여야 하는 것**

- 입력 칸에 테두리가 뜬다. 이어서 로그인 버튼에 테두리가 옮겨 간다.
- 테두리는 **한 번에 하나**다. 앞의 것이 남아 쌓이지 않는다.
- AI 가 멈춘 뒤 **2~3초 안에** 테두리가 사라진다.

**보이면 안 되는 것**

- 「화면을 살펴보는 중」일 때 여러 요소에 테두리가 뜨는 것 (FR-011)
- 진행 문구가 줄어든 것 — 문구는 **지금과 똑같이** 나와야 한다 (FR-023)

---

## 2. 진행 문구와 짝이 맞는가

같은 실행에서 진행 문구와 테두리를 함께 본다.

문구가 「로그인 버튼 클릭 — 완료」일 때, 테두리 안에 있는 것이 **로그인 버튼**이어야
한다. 다른 것이면 그것이 이 기능이 막으려던 바로 그 상황이며, 좌표 변환이 틀린 것이다.

---

## 3. 밀집 화면 — 좌표가 정말 맞는가 ★

대상 화면 중 **요소가 촘촘하고 작은 것**을 고른다. `fixtures/sample-app/` 을 열어
체크박스·아이콘 버튼처럼 한 변이 30픽셀 이하인 요소가 여럿 있는 화면을 찾는다 —
`label-checkbox.html`·`interactions.html` 부터 본다.

**작은 요소 셋을 차례로 조작하게 시킨다.** 넓은 버튼에서는 좌표가 틀려도 안 드러난다.

**확인**

- 셋 다 테두리가 **정확히 그 요소를 감싼다.** 옆 요소로 새지 않는다.
- 테두리와 요소의 어긋남이 눈에 띄지 않는다.

**창 크기를 바꿔 가며 반복한다.** 미러가 축소되어 표시될 때 배율이 비정수가 되고, 그때
어긋나는 경우가 있다. 좁은 창·넓은 창에서 각각 본다.

> 여기서 어긋나면 정변환식이 역변환식과 짝이 맞지 않는 것이다. 미러를 직접 클릭해
> 보라 — 클릭이 맞는 요소에 가는데 테두리만 어긋나면 정변환 쪽이 틀렸다.

---

## 4. 스크롤 — 자리가 낡지 않는가 ★

세로로 긴 화면을 대상으로 둔다 (`projects.html` 목록 등).

1. 「화면 맨 아래의 ○○ 버튼을 누른다」처럼 **스크롤이 필요한 지시**를 준다.
2. AI 가 살펴본 뒤 스크롤하고 조작하는 과정을 미러로 본다.

**확인**

- 테두리가 **스크롤한 뒤의 자리**에 뜬다. 살펴본 시점의 자리가 아니다.
- 스크롤 전 위치에 테두리가 뜨면 FR-002 가 깨진 것이다.

---

## 5. 실패한 자리가 구분되는가

`locked-controls.html` 처럼 비활성 요소가 있는 화면을 대상으로 둔다.

「비활성 버튼을 누른다」를 지시한다.

**확인**

- 조작이 실패한 자리에 테두리가 뜨고, **성공했을 때와 눈으로 구분된다.**
- 이어서 다른 요소를 조작하면 실패 테두리는 사라진다.

**요소가 아예 없는 실패는 다르다.** 「있지도 않은 버튼을 누른다」를 지시하면 테두리가
**뜨지 않아야 한다.** 자리를 모르는데 그리면 거짓말이다 (FR-010).

---

## 6. 그리지 않아야 하는 자리들

| 상황 | 만드는 법 | 확인 |
|---|---|---|
| 프레임이 아직 없다 | 작성 시작 직후 미러가 뜨기 전 | 테두리 없음 |
| 미러가 중단됐다 | 미러가 멈춘 상태를 만든다 | 테두리 없음 + 중단 사유가 가려지지 않음 |
| 다른 탭 | AI 가 새 탭에서 조작하게 하고 첫 탭을 보고 있는다 | 보고 있는 화면에 테두리 없음 |
| 화면 새로 고침 | 테두리가 떠 있을 때 새로 고친다 | 테두리가 복원되지 않음 |

---

## 7. 조작을 가로채지 않는가

1. AI 작성을 **일시정지**한다 (미러에서 직접 조작할 수 있는 국면).
2. 테두리가 아직 떠 있는 동안 **그 테두리 위를 클릭**한다.

**확인**: 클릭이 대상 화면에 그대로 전달된다. 아무 일도 일어나지 않으면 오버레이가
포인터를 먹은 것이다 (FR-020).

---

## 8. 대상 화면이 바뀌지 않았는가

이 기능이 대상 페이지에 아무것도 심지 않는다는 것을 직접 본다.

1. AI 작성 중 아무 때나 브라우저 개발자 도구로 대상 페이지의 DOM 을 본다.
2. 제품이 넣은 테두리 요소가 **하나도 없어야 한다.**

실패 스크린샷에도 테두리가 찍히면 안 된다 — 증거는 대상 화면 그대로여야 한다.

---

## 9. 재생에는 없다

저장된 테스트를 **재생**한다.

**확인**: 재생 내내 테두리가 한 번도 뜨지 않는다. 뜬다면 헌법 원칙 II 경계가 깨진
것이며, 이 기능에서 가장 심각한 결함이다.

---

## 10. 자동 검증

```bash
cd backend && uv run pytest
cd backend && uv run lint-imports        # 원칙 II 임포트 계약
cd backend && uv run ruff check src/ tests/
cd frontend && npm test
cd frontend && npm run build
```
