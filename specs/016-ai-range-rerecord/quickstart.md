## 0. 준비

```bash
# 대상 앱
python fixtures/sample-app/serve.py --port 4300

# 백엔드
cd backend && uv run itb

# 프론트엔드
cd frontend && npm run dev     # http://127.0.0.1:4310
```

**언어모델**: `ANTHROPIC_API_KEY` 또는 `ant auth login`. 자격 증명 없이 검증하려면
개발용 드라이버를 쓴다 — 단 **품질 근거로 쓰지 않는다** (SC-003 측정은 기본 드라이버로만).

```bash
cd backend && uv sync --extra claude-code
ITB_AI_DRIVER=claude-code uv run itb
```

**준비 확인**: 화면에서 `GET /api/ai/availability` 가 `available: true` 인지 본다.
거짓이면 그 `reason` 이 그대로 화면에 보여야 한다 (FR-012).

## 1. 자동 검증 (먼저 돌린다)

```bash
# ★ 헌법 원칙 II — 이것이 실패하면 나머지는 의미가 없다
cd backend && uv run lint-imports

cd backend && uv run ruff check src/ tests/
cd backend && bash scripts/test-backend.sh          # ← `uv run pytest` 가 아니다
cd backend && uv run python -m itb.schema.export --check   # 변경 없이 통과해야 한다
cd frontend && npx tsc --noEmit && npx vitest run
```

> **`uv run pytest` 를 그대로 쓰지 않는다.** 48건이 오류로 나오는데 회귀가 아니라
> 명령 오용이다 — 경과 시간을 단언하는 모듈(`tests/tiers.py` 의 `TIMING_MODULES`)이
> 병렬 실행을 **스스로 거부한다**. 프로세스 8개가 CPU 를 나눠 쓰면 재는 값이 제품의
> 성질이 아니라 그 순간의 부하가 되기 때문이다. 정규 명령은 위의 스크립트이며, 병렬
> 계층과 순차 계층을 모두 돈다 (`baseline.md` T001-a).

`design_compare_ba.py --compare` 도 함께 돌린다 — 016 은 화면을 건드리므로 015 의
L2 대조 보고서가 낡는다. 「불일치 0건」이 지금 화면에 대한 말이 되려면 다시 재야 한다.

```bash
backend/.venv/bin/python scripts/design_compare_ba.py --compare
```

`schema.export --check` 가 **변경을 보고하면 실패다.** 이 기능은 저장 형식을 건드리지
않기로 했고(계획 §Technical Context), 드리프트가 났다면 그 결정을 어긴 것이다.

## 2. US1 — 테스트를 아는 AI 와 대화한다

> **주의**: R6 의 결정으로 채팅은 **세션 안에서만** 산다. 편집 화면에서 바로 말을 거는
> 경로는 없다. 「AI 로 다시 만들기」로 세션을 연 뒤 대화한다.

| # | 절차 | 기대 |
|---|---|---|
| 1 | Step 12개 이상인 테스트를 만들거나 연다 | — |
| 2 | 편집 화면에서 대화 패널을 본다 | 자리가 **보이되 잠겨** 있고, 「먼저 AI 로 다시 만들기로 시작하세요」를 말한다 (FR-234) |
| 3 | Step 5~9 를 체크하고 「AI 로 다시 만들기」 | 브라우저가 열리고 1~4 실행 후 멈춘다 |
| 4 | "이 테스트가 뭘 하는지 요약해 줘" | 답변이 **실제 Step 을 근거로** 나온다. Step 목록은 **변하지 않는다** |
| 5 | "비밀번호 칸에 뭐가 들어가냐" | 실제 값이 **나오지 않는다.** 변수 참조로만 표현된다 (FR-002) |
| 6 | 브라우저를 새로 고친다 | 대화 이력이 그대로 되살아난다 (`GET /chat`) |
| 7 | 같은 테스트를 다른 창에서 열고 「AI 로 다시 만들기」 | 조작이 **잠겨** 있고 해소 방법을 말한다 (FR-017) |

**판정**: 4·5 를 통과하면 US1 성립. 이 시점에 Step 을 하나도 만들지 않았어도 가치가
검증된다.

## 3. US2 — Step n~m 을 AI 로 다시 만든다

### 3-1. 정상 경로

| # | 절차 | 기대 |
|---|---|---|
| 1 | US1 의 세션을 이어 쓴다 (Step 5~9 교체 중) | 재녹화 띠에 「교체 중 — Step 5~9 (5개)」 |
| 2 | Step 목록을 본다 | 5~9 가 「교체 대상」으로 구분되어 보인다 (FR-024) |
| 3 | "이번엔 SSO 로 로그인해" 를 보낸다 | `ai_progress` 가 흐르고, 성공한 동작마다 새 Step 이 **5번 자리부터** 들어간다 |
| 4 | 목록을 본다 | 새 Step + 옛 5~9(교체 대상) + 옛 10~12 가 **함께** 있다 |
| 5 | 「확정」 | 옛 5~9 가 **한 번에** 사라진다. 목록의 번호가 1부터 빈자리 없이 이어진다 (FR-030). **식별자는 빈자리를 남긴다** — 상세를 열면 `step-04` 다음이 `step-12` 일 수 있고 그것이 정상이다 (FR-030a) |
| 6 | 「저장」 | 디스크에 내려간다. 확정 전에는 내려가지 않았음을 확인한다 (FR-029) |
| 7 | 처음부터 실행 | **성공한다** (SC-005) |

### 3-2. 버리기 (SC-004 — 20회 반복)

| # | 절차 | 기대 |
|---|---|---|
| 1 | 3-1 의 3번까지 진행 | 새 Step 이 몇 개 생김 |
| 2 | 목록을 **기록해 둔다** | — |
| 3 | 「버리기」 | 새 Step 이 전부 사라지고 목록이 2번의 기록과 **id·순서·내용까지 동일** |
| 4 | 화면을 본다 | 도착점으로 **되맞춰져** 있고 세션은 **살아 있다** (FR-031·FR-031a) |
| 5 | 곧바로 다른 지시를 보낸다 | 그대로 동작한다 |
| 6 | 1~5 를 20회 반복 | 20회 모두 3번이 성립 (SC-004) |

### 3-3. 이상 경로

| 상황 | 기대 |
|---|---|
| 구간을 고르지 않고 「AI 로 다시 만들기」 | 조작이 잠겨 있고 무엇이 필요한지 말한다 (FR-017) |
| 3번과 7번만 체크 (사이가 빔) | 연속 구간이 아님을 알리고 **시작하지 않는다** (FR-016) |
| 앞 구간에 깨진 Step 이 있다 | 어느 Step 에서 왜 실패했는지 말하고 시작하지 않는다 (FR-020) |
| AI 가 막힌다 | 브라우저가 **닫히지 않고** 5선택지가 뜬다 (FR-041) |
| Step 을 하나도 못 만든 채 「확정」 | 확정이 **잠겨** 있다 (FR-028 · 불변식 10) |
| 재녹화 중 「저장」 | 확정되지 않은 교체가 디스크에 **가지 않는다** (FR-029) |
| 브라우저 창을 사용자가 닫는다 | 세션 유실 처리가 돌고, 확정되지 않은 Step 의 운명을 말한다 (FR-044) |
| 구간이 Step 1 부터 | 도착점이 「시작 주소를 연 상태」다 (FR-021) |
| 구간 끝이 목록 끝 | 「이 뒤 전부 지우기」와 결과가 같다 |
| 「버리기」 연타 | 두 번째가 거절된다 |

## 4. US3 — AI 가 만든 Step 을 AI 가 고친다

| # | 절차 | 기대 |
|---|---|---|
| 1 | 재녹화로 Step 3개를 만든다 | — |
| 2 | "두 번째 표시 이름을 '주문 저장'으로 바꿔" | 표시 이름만 바뀐다. 대상·값·종류 그대로 |
| 3 | "마지막 두 개 순서 바꿔" | 순서만 바뀐다 |
| 4 | "그 버튼 말고 머리말의 저장 버튼" | 대상이 바뀌고 **후보 묶음이 새로 수집**된다 (후보 종류가 2개 이상) |
| 5 | "4번 스텝(구간 밖) 이름도 바꿔" | **거절되고 그 사실이 보인다** (FR-038 · 불변식 8) |
| 6 | "교체 대상 5번을 지워" | **거절된다** — 옛 구간은 AI 가 못 지운다 |
| 7 | 확정 후 저장 → 다시 열기 | 사람이 같은 편집을 한 결과와 **저장 형식에서 구별되지 않는다** (SC-006) |

## 8. 회귀 확인 (SC-009)

이 기능이 기존 흐름을 건드리지 않았는지 본다.

- [ ] 직접 녹화로 테스트 만들기 — 조작 횟수·화면 구성 동일
- [ ] 저장된 테스트 재실행 — 동일
- [ ] 일시정지 → 편집 → 이어서 — 동일
- [ ] 기존 AI 작성(지시문 1개) — 동일. **단 정의 요약이 컨텍스트에 붙는다** (FR-005)
- [ ] 일시정지 중 자연어 Step 추가 — 동일. 같은 요약이 붙는다
- [ ] 복수 삭제 — 조작 이름이 바뀌었을 뿐 동작 동일 (`step.toggleSelection`)
