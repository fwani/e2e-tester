# 확정 디자인이 정의하지 않은 상태 기록

**요구사항**: DC-009 · FR-266 · FR-276 · 완료 판정 SC-110 (기록 없는 임의 결정 0건)

확정 디자인은 화면당 한 상태만 보여준다. 실제 동작에 필요한 나머지 상태(로딩·빈 목록·
오류·확인·유실)는 구현자가 정해야 한다. **그 결정을 전부 여기 남긴다.**

**`그린 형태` 는 필수다.** 008 의 규칙은 「미정의 상태를 그리려고 정본에 새 형태를 추가할
수 없다」이므로(FR-266 · US-1), 기존 형태의 조합으로 그렸다는 것을 보여야 기록이 성립한다.
근거를 댈 수 없는 결정은 해석이고 DC-001 위반이다.

## 2. 확정 디자인에 있으나 만들지 않은 것

**하나뿐이다.** 이것은 L3-1(가감) 판정에서 `불일치`로 잡히는 것이 정상이며, 숨기지 않고
여기 적는다.

| 화면 | 요소 | 왜 만들지 않았나 |
|---|---|---|
| TestList | 바닥 띠의 **「전체 실행」** | 여러 테스트를 잇달아 돌리는 것은 화면 작업이 아니라 **실행 기능**이다. 실행 순서·중간 실패 처리·중지 의미를 새로 정해야 하고 백엔드가 그것을 받지 않는다. 008 의 범위는 시각 언어 적용이며 백엔드 무변경이다 (spec Out of Scope · research R7). 디자인에 있는 것을 뺀 상태이므로 **별도 기능으로 다뤄야 한다** |

같은 띠의 「Playwright 로 내보내기」는 **만들었다** — 비활성으로 두고 「MVP 미지원」 사유를
붙였다. 헌법 원칙 V 가 출시 전까지의 약속으로 두었고, 006 ui-contract §2 가 「감추지 않고
비활성으로 두고 이유를 붙인다」를 정했기 때문이다.

## 3. 확정 디자인과 다르게 그린 것

### 결말 표식의 문구

| 자리 | 확정 디자인 | 제품 | 왜 |
|---|---|---|---|
| 목록 행의 결말 표식 문구 | 「통과」「실패」「실행 중」「미실행」 | `PASS`·`FAIL`·`RUNNING`·「미실행」 | 005 FR-140·U-20 이 **화면 사이** 결말 어휘를 통일해 뒀다 (`lib/wording.ts`). 이 화면에서만 바꾸면 화면마다 다른 말이 다시 생긴다. 어휘를 바꾸려면 모든 화면을 함께 바꿔야 하고 그것은 어휘 계약의 개정이다 — 시각 언어 적용의 범위가 아니다 |

### FR-269 — 명세가 확정 디자인보다 엄격하다

**충돌이며, 코드가 아니라 문장 쪽이 어긋났다.**

`spec.md` FR-269 는 이렇게 적혀 있다 — 「**잉크 채움은 한 화면에 주 동작 하나**에만 쓴다」.
확정 디자인을 세어 보면 그렇지 않다.

| 화면 | `.btn.primary` 개수 | 무엇 |
|---|---|---|
| TestList | **2** | 헤더 「테스트 만들기」 + 고른 결말 필터 |
| EmptyList | **2** | 「녹화로 시작하기」 + 헤더 「테스트 만들기」 |
| Run · Paused · Main · ProjectSetup | **2** | 각각 |
| Secrets | **3** | |
| Result · Create | 1 | |
| Keys | **0** | 주 동작이 없는 화면도 있다 |

제품은 디자인을 따랐다. 그것이 옳다 — 「코드가 디자인과 다르면 코드를 고친다」(spec
Assumptions). 따라서 **고칠 것은 FR-269 의 문장이다.**

읽어 보면 디자인의 실제 규칙은 두 갈래다.

1. **주 동작은 화면당 하나다.** 「테스트 만들기」·「녹화로 시작하기」처럼 그 화면에서 사용자가
   하려는 일. 없는 화면도 있다 (Keys)
2. **고른 상태는 채움으로 표시한다.** 결말 필터의 「전체」처럼 여럿 중 하나를 고른 자리.
   이것은 동작의 강조가 아니라 **지금 무엇이 골라져 있는가**이며 다른 축이다

008 이 실제로 고친 결함은 그 둘 어느 쪽도 아닌 것이 채워져 있던 것이다 — 목록 행의
「실행」·「결과 보기」·「실행 화면 보기」가 **셋 다** 잉크였다. 그것은 지금 전부 중립이다.

**개정안**: 「주 동작은 화면당 하나이며, 고른 상태의 표시는 그와 별개다. 그 둘 어느 쪽도
아닌 조작은 채우지 않는다.」

`spec.md` 는 이 기록으로 고치지 않는다 — 명세 개정은 판단을 받아야 한다 (008 수렴 T086).

## 4. 확정 디자인 파일 자체에 대한 관찰

기록만 하고 고치지 않는다 — 확정 디자인은 이 기능의 **입력**이다 (spec Assumptions).

| 관찰 | 영향 | 처리 |
|---|---|---|
| `*.dc.html` 19개가 `./support.js` 를 참조하는데 그 파일이 저장소에 없다 | **없다.** chromium 으로 렌더해 확인했다 — `<helmet>` 안의 `<style>` 과 `<link>` 는 정상 적용되고 아트보드가 1440×900 으로 선다. 콘솔 오류는 404 하나뿐이다 (research R2) | 그대로 둔다 |
| `Language.dc.html` 이 v1 을 대조 예시로 함께 그린다 (「03 · 기하」) — `#F5D000` · `#14130F` · `3px solid` · `5px 5px 0` | **크다.** 「확정 디자인 파일에 있는 값」을 그대로 정본으로 가져오면 폐기한 언어가 되살아난다 | 정본은 `<style>` 시트에서만 뽑는다. 인라인에서 값을 가져올 때는 그 값이 무엇을 그리는지 확인한다. 회귀 검사를 붙였다 (`DesignTokens.test.tsx`) |
| 국면 화면의 ③-a 안에 `#1F2A37`·`#2563EB`·`#DDE3EA` 등이 있다 | **없다.** 그것은 **미러되는 예시 앱**의 색이지 ITB 의 시각 언어가 아니다 | 정본에 들이지 않았다 (FR-266) |
| `#E5D3AC`·`#EFC7BC` 가 시트가 아니라 인라인에만 있다 | 옅은 바탕(`--warn-t`·`--fail-t`) 옆의 경계선으로 7장·3장에서 쓰인다. **진짜 v2 값인데 이름이 없었다** | `--warn-line`·`--fail-line` 으로 정본에 이름을 붙였다 |

## 5. 2026-09-10 UI/UX 점검이 더한 것 — 확정 디자인이 정의하지 않는 상태

014(엑셀 통로)와 2026-09-10 의 AI 답변 칸은 **확정 디자인 18장보다 나중에 생겼다.**
그래서 아래 형태들은 대조할 기준 그림이 없다. 정본을 임의로 늘리지 않는다는 규칙
(FR-266·DC-009)에 따라 **무엇을 왜 더했는지** 여기 적는다. 값은 하나도 지어내지 않았다 —
아래 전부가 기존 토큰의 `var()` 참조이거나 확정 디자인에 이미 있는 치수다.

| 더한 형태 | 왜 필요했나 | 값의 출처 |
|---|---|---|
| `.file-input` · `.btn.file` | 파일 선택은 `<label>` + 감춘 `<input type=file>` 짝이다. 칸을 `display:none` 으로 감추면 **Tab 순서에서 사라지고** 라벨은 원래 초점을 받지 않으므로, 「엑셀에서 가져오기」·「엑셀에서 새 프로젝트」에 키보드로 도달할 수 없었다. 확정 디자인에 파일 선택 화면이 없어 이 짝이 정의된 적이 없다 | 초점 링은 `:focus-visible` 의 값 그대로 (`2px solid var(--run)`, offset 2) |
| `.btn.disabled` | `<label>` 은 `:disabled` 를 받지 못한다. `button:disabled`(점선·자리 유지)와 **같은 형태**를 라벨에도 주려면 클래스가 필요하다. 없으면 「읽는 중」인 버튼이 평소와 똑같이 보인다 | `button:disabled` 선언을 그대로 옮김 |
| `.grid-head th` | 가져오기 미리보기·초안 목록의 표. 확정 디자인의 `.thead` 는 **행 목록**의 머리이고 `<table>` 머리가 아니다 — `<th>` 가 클래스 없이도 그렇게 보여야 한다 (기본 요소 구획과 같은 판단) | `.thead` + `.lbl` 의 값 조합 |
| `.answer-q` | AI 의 질문을 그리는 자리. 이전에는 질문이 `.lbl`(11px 대문자 모노) 안에 들어가 있었다 — **한 문장을 읽는 형태가 아니다.** 확정 디자인의 `AiBlocked.dc.html` 은 선택지 셋만 그리고 질문·답 칸이 없다 (그 기능은 2026-09-10 에 생겼다) | `.line` 과 같은 값 (`400 13px/1.4 var(--font-sans)`) |
| `.hint-line` | 힌트가 조건부로 그려지면 첫 글자를 치는 순간 그 줄이 사라지고 아래가 위로 튄다. 자리를 고정한다 | 치수만. 색·서체 없음 |
| `.commit-bar` | 가져오기 미리보기는 시트 200개를 받는다. 확정 버튼이 스크롤 수천 픽셀 아래로 밀려, 시트 하나를 고친 사용자가 확정하거나 되돌리려면 목록 끝까지 내려가야 했다. 확정 디자인에 「목록이 수백 줄인 확정 화면」이 없다 | `var(--panel)` + `1px solid var(--hair-2)` |

### 문구가 갈리는 자리 하나

`EmptyList.dc.html` 은 「아직 테스트가 없습니다 / 브라우저를 직접 조작하거나, 할 일을
말로 적으면 됩니다」를 그린다. **그 문장은 맨 처음 온 사용자를 위한 것이다.** 설계서에서
스무 건을 들여온 사용자에게는 다음에 할 일이 이미 정해져 있고(초안 하나를 녹화하는 것),
그 사용자에게 이 문장을 그대로 보이면 화면이 자기가 방금 한 일을 모르는 것처럼 읽힌다.

초안이 있을 때만 문구가 초안을 가리키고, 초안 구획이 이 안내보다 **위**에 온다 —
안내가 `flex:1` 로 화면을 채우므로 아래에 두면 들여온 스무 건이 스크롤 밖에 있었다
(FR-035 가 막으려던 것이다). 초안이 0건이면 확정 디자인의 문구가 그대로다.
