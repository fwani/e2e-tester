# Contract: UI (006 라운드)

**Feature**: `specs/006-edit-saved-test` | **Date**: 2026-09-07

**신규 화면은 없다.** 기존 `TestDefinition` 화면이 편집 모드를 얻고, 진입점 3개가 그 화면으로
모인다 (research R1). 이 문서는 그 화면의 계약과, 이 기능이 만드는 문구 규칙을 적는다.

005 가 만든 어휘 사전(`frontend/src/lib/wording.ts`)을 확장한다. **문구를 화면마다 적지
않는다** — 005 가 결말 어휘를 한 곳에 모은 것과 같은 이유다.

---

## 1. 진입점 3개 — 모두 같은 화면으로

| 출발 | 컨트롤 | 도착 | 요구 |
|---|---|---|---|
| 목록 행 「⋮」 메뉴 | **「편집」** (신규, `정의 보기` 자리를 대체) | 편집 화면, Step 미지목 | FR-175 |
| 결과 화면 실패 진단 | 「Step nn 고치기」 (기존, **도착지 변경**) | 편집 화면, Step nn 지목·펼침 | FR-176·FR-180 |
| 편집 화면 자체 | 읽기 전용 모드의 「편집하기」 | 같은 화면의 편집 모드 | FR-177 |

**「정의 보기」는 없어진다.** 보기만 하는 별도 항목을 남기면 사용자는 다시 "고치려면 어디로
가지" 를 묻게 된다 — 그것이 E-01·E-03 이었다. 편집 화면은 저장하지 않으면 아무것도 바꾸지
않으므로, 보기 위해 들어가도 안전하다.

**금지**: 「편집」·「고치기」라는 이름의 컨트롤이 읽기 전용 화면에 도착하는 것 (FR-178·SC-304).

---

## 2. 편집 화면의 두 모드

같은 화면, 같은 URL. **모드 전환은 화면 이동이 아니다.**

| | 편집 가능 (`editable: true`) | 읽기 전용 (`editable: false`) |
|---|---|---|
| 언제 | 평상시 | 그 테스트가 실행 중 (`blocked_by: "running"`) |
| Step 목록 | 값·라벨·대기시간·탭 입력 가능, 삭제·순서 변경 가능 | 표시만 |
| 상단 | 「변경 저장」 · 변경 건수 | 「실행 중이어서 편집할 수 없습니다」 + **「실행 중인 세션 보기」** |
| 브라우저 열기 | 활성 | 비활성 (이미 세션이 있다) |

읽기 전용 모드에서 편집 컨트롤을 **감추지 않고 비활성으로 두고 이유를 붙인다.** 감추면
사용자는 자기가 잘못 들어온 줄 안다 — 005 가 속도 컨트롤에 대해 내린 것과 같은 판단
(`PacingControl` 의 `disabled` 주석).

## 3. 저장 어휘 — 005 규칙을 그대로 쓴다

| 상태 | 버튼 라벨 | 활성 | 근거 |
|---|---|---|---|
| 변경 없음 | 「변경 저장」 | **비활성** | FR-195 · 005 FR-156 |
| 변경 있음 | 「변경 저장 (3건)」 | 활성 | FR-189 |
| 저장 진행 중 | 「저장 중…」 | 비활성 | 연타 방지 (005 FR-129 의 규칙) |
| 저장 직후 | 「변경 저장」 비활성 + **초록 확인줄** 「✓ 저장했습니다 · TC-001」 | | FR-194 · 005 FR-158 |

**화면을 옮기지 않는다.** 저장 성공으로 목록으로 튀지 않는다 — 사용자는 대개 계속 고친다.

**「초안」을 쓰지 않는다.** 저장된 테스트를 편집하는 화면이므로 초안이 아니다 (005 U-03 잔존
1번과 같은 뿌리).

## 4. 편집 불가 항목의 표시 (FR-191)

`locked_fields[].reason` 별 문구. **회색 버튼만 두지 않는다** — 회색 버튼은 "곧 될 것" 처럼
읽힌다 (`TestDefinition.tsx` 머리 주석의 판단).

| reason | 문구 | 따라오는 것 |
|---|---|---|
| `live_browser_required` | 「이 대상은 살아 있는 화면에서만 다시 집을 수 있습니다.」 | **「브라우저 열어 Step nn 에서 멈추기」 버튼** |
| `delete_and_insert_instead` | 「Step 종류는 바꿀 수 없습니다. 지우고 새로 넣으세요.」 | 「Step nn 삭제」 |
| `record_only` | 「기록입니다. 편집 대상이 아닙니다.」 | 없음 |

`live_browser_required` 만 경로를 준다. 나머지에 억지로 버튼을 붙이지 않는다.

## 5. 「브라우저 열어 Step nn 에서 멈추기」

| 조건 | 화면 |
|---|---|
| 저장하지 않은 변경 없음 | 버튼 활성. 누르면 `POST /api/sessions` (`pause_before_index: nn`) → 러너 화면 |
| 저장하지 않은 변경 있음 | 버튼 활성이지만 **먼저 저장을 요구한다** — 「먼저 저장해야 합니다. 저장한 내용으로 브라우저를 엽니다.」 + 「저장하고 열기」 (FR-203) |
| 그 테스트가 실행 중 | 비활성 + 「이미 실행 중입니다」 + 「실행 중인 세션 보기」 |
| Step 미지목 | 「먼저 Step 을 고르세요」 — 어디서 멈출지 알 수 없다 |

**버튼 라벨에 Step 번호를 박는다.** 005 가 「Step 06부터 실행」으로 시작점을 라벨에 박은 것과
같은 이유다 — 어디서 멈추는지를 누르기 전에 알아야 한다.

세션에 도달한 뒤의 편집은 **지금의 일시정지 팔레트 그대로**다. 새 편집 UI 를 만들지 않는다
(FR-205).

## 6. 이탈 확인 (FR-208)

| 이탈 경로 | 처리 |
|---|---|
| 앱 안 이동 (「목록으로」, 진입점, 뒤로가기) | 인앱 확인 — 「저장하지 않은 변경 3건이 있습니다」 + 「저장하고 나가기」·「버리고 나가기」·「머무르기」 |
| 새로고침·탭 닫기 | 브라우저 기본 이탈 확인 (문구는 브라우저가 정한다) |
| 변경 0건 | **확인 없이 바로 나간다** (FR-208 의 반대 방향 — 물어볼 것이 없을 때 묻지 않는다) |

초안은 저장소에 남기지 않는다 (R8). 「버리고 나가기」 후 다시 열면 원본 그대로다.

## 7. 외부 변경 충돌 (FR-209)

`DEFINITION_STALE` 을 받으면 저장 버튼 자리에 그대로 띄운다. **화면을 옮기지 않는다.**

```
⚠ 이 테스트의 정의 파일이 편집을 시작한 뒤에 바뀌었습니다.
  파일 밖에서 고친 내용이 있습니다. 어떻게 할지 고르세요.

  [바뀐 내용으로 다시 읽기]   ← 내 편집 3건을 버린다 (건수를 밝힌다)
  [내 편집으로 덮어쓰기]      ← 파일의 변경을 버린다
```

두 버튼 모두 **무엇을 버리는지 라벨 옆에 적는다.** 어느 쪽도 되돌릴 수 없으므로 고르기 전에
알아야 한다.

## 8. URL 규칙 (FR-181)

005 의 `useScreenUrl` 규칙을 따른다. 편집 화면은 기존 `definition` 화면의 주소를 그대로 쓴다 —
화면이 하나이므로 주소도 하나다.

```
?screen=definition&test=TC-001            편집 화면
?screen=definition&test=TC-001&step=step-06   Step 지목 (결과 화면에서 들어온 경우)
```

새로고침하면 같은 테스트의 편집 화면으로 복원된다. 지목된 Step 도 복원된다. 저장하지 않은
변경은 §6 의 브라우저 이탈 확인이 막는다.

---

## 9. 어휘 사전에 더할 것

`frontend/src/lib/wording.ts` 에 모은다. 화면 파일에 문장을 직접 쓰지 않는다.

| 키 | 값 |
|---|---|
| 편집 진입 | 「편집」 |
| 저장 (미저장) | 「변경 저장」 |
| 저장 건수 | 「변경 저장 (N건)」 |
| 저장 중 | 「저장 중…」 |
| 저장 성공 | 「✓ 저장했습니다 · {테스트 이름}」 |
| 실행 중 차단 | 「실행 중이어서 편집할 수 없습니다」 |
| 세션 이동 | 「실행 중인 세션 보기」 (005 와 같은 문구를 재사용한다) |
| 브라우저 열기 | 「브라우저 열어 Step {번호} 에서 멈추기」 |
| 이탈 확인 | 「저장하지 않은 변경 {N}건이 있습니다」 |

Step 번호는 기존 `stepNumber(index)` 를 쓴다 — 005 가 번호 표기를 한 곳으로 모았고(U-07),
여기서 다시 `index + 1` 을 쓰면 그 결함이 되살아난다.
