# API 계약 — 테스트 복수 삭제와 그룹

**Feature**: 013-test-groups-bulk-delete | 기존 계약에 **더하고**, 기존 라우트 하나의 **의미가
바뀐다**(`DELETE /api/tests/{id}` — 파괴 → 휴지통 이동).

## §0 라우트 전체 (신규는 ★, 의미가 바뀌는 것은 ⚠)

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| GET | `/api/tests` | 목록. **`group` 질의와 그룹 정보가 는다** |
| GET | `/api/tests/{id}` | 조회 |
| PATCH | `/api/tests/{id}` | 이름 변경 |
| ⚠ DELETE | `/api/tests/{id}` | 한 개 삭제 → **휴지통으로 옮긴다** |
| ★ POST | `/api/tests:delete` | **복수 삭제** (휴지통으로) |
| ★ POST | `/api/tests:move` | **복수 그룹 이동** |
| ★ GET | `/api/groups` | 그룹 목록 |
| ★ POST | `/api/groups` | 그룹 만들기 |
| ★ PATCH | `/api/groups/{prefix}` | 그룹 이름 변경 |
| ★ DELETE | `/api/groups/{prefix}` | 그룹 없애기 (테스트는 지우지 않는다) |

**`POST …:delete` 형태를 쓰는 이유**는 011 이 정했다 — `DELETE` 에 본문을 실으면 프록시·
클라이언트에 따라 벗겨지고, 쿼리에 실으면 목록이 길 때 URL 길이에 걸리며 삭제 대상이 접근
로그에 남는다. 이 저장소는 이미 `steps:delete`·`steps:manual`·`steps:reorder` 를 쓴다.

## §1 `GET /api/tests` — 목록 (변경)

**요청**: 기존 `q` 에 더해 `group` 질의를 받는다.

| 질의 | 뜻 |
|---|---|
| `q` | 이름·식별자 부분 일치 (기존 그대로) |
| `group` | 접두어. `TC` 를 주면 **그룹 없음**만. 생략하면 전부 |

두 질의는 **함께 적용된다** (FR-441).

**응답**: 기존 형태에 두 가지가 는다.

```json
{
  "counts": { "total": 12, "passed": 5, "failed": 2 },
  "groups": [
    { "prefix": "USER", "name": "사용자관리 테스트", "count": 4 },
    { "prefix": "DATA", "name": "데이터 관리 테스트", "count": 6 },
    { "prefix": "TC",   "name": null,                "count": 2 }
  ],
  "tests": [ { "id": "USER-001", "group_prefix": "USER", "...": "기존 필드 그대로" } ],
  "problems": []
}
```

| 필드 | 규칙 |
|---|---|
| `groups[].count` | **걸러 보기를 적용하기 전**의 개수다. 걸러 본 뒤에도 다른 그룹의 개수를 알아야 그리로 갈 수 있다 |
| `groups` | 테스트가 하나도 없는 그룹은 **싣지 않는다** (FR-450) |
| `groups` 의 `TC` 항목 | 그룹 없는 테스트가 있을 때만. `name` 은 `null` — 이름이 없는 것이 사실이다 |
| `tests[].group_prefix` | 식별자에서 유도한 값. 저장된 필드가 아니다 (data-model §3) |

**기존 클라이언트가 읽던 필드는 하나도 바뀌지 않는다.**

## §2 `DELETE /api/tests/{id}` — 한 개 삭제 (의미 변경)

**응답 204 → 200.** 옮겨진 위치를 돌려줘야 한다 (FR-437a).

```json
{ "id": "USER-003", "name": "로그인", "trashed_to": "/Users/me/.local/share/itb/trash/20260910-143000-USER-003-로그인" }
```

| 상황 | HTTP | code |
|---|---|---|
| 그런 테스트가 없다 | 404 | `TEST_NOT_FOUND` |
| 실행 중인 세션이 있다 | 409 | `TEST_IN_USE` (신규) |
| 옮기지 못했다 | 500 | `TEST_DELETE_FAILED` (신규) |

**204 를 버리는 것이 이 계약의 핵심 변경이다.** 옮겨진 위치를 돌려주지 않으면 사용자는
되돌릴 수 없고, 그러면 「파괴하지 않는다」는 결정이 사용자에게는 삭제와 구별되지 않는다.

## §3 `POST /api/tests:delete` — 복수 삭제

**요청**

```json
{ "test_ids": ["USER-001", "USER-003", "DATA-002"] }
```

`test_ids` 는 1개 이상. 중복은 거절한다.

**응답 200**

```json
{
  "deleted": [
    { "id": "USER-001", "name": "로그인",  "trashed_to": "/…/20260910-143000-USER-001-로그인" },
    { "id": "USER-003", "name": "회원가입", "trashed_to": "/…/20260910-143000-USER-003-회원가입" }
  ]
}
```

**오류**

| 상황 | HTTP | code |
|---|---|---|
| 목록에 없는 식별자가 섞여 있다 | 404 | `TEST_NOT_FOUND` |
| 하나라도 실행 중이다 | 409 | `TEST_IN_USE` |
| 옮기다 실패했고 **되돌렸다** | 500 | `TEST_DELETE_FAILED` |
| 옮기다 실패했고 **되돌리지도 못했다** | 500 | `TEST_DELETE_PARTIAL` (신규) |

**불변식 — 「전부 되거나 전부 안 되거나」를 어떻게 지키는가** (FR-432 · research R4)

1. **먼저 전부 검증한다** (존재·실행 중). 하나라도 걸리면 **아무것도 건드리지 않고** 거절한다.
2. 하나씩 휴지통으로 옮기고, 옮긴 자리를 기억한다.
3. 도중에 실패하면 **이미 옮긴 것을 되돌린다.** 그리고 `TEST_DELETE_FAILED` 로 답한다 —
   이때 디스크는 요청 전과 같다.
4. 되돌리기까지 실패하면 `TEST_DELETE_PARTIAL` 로 답하고, **어느 것이 어디에 있는지**를
   `detail` 에 담는다.

**4가 존재하는 이유**: 파일 시스템에 여러 경로에 걸친 원자적 연산은 없다. 여기서 보장하는
것은 「모든 자산이 휴지통 아니면 원래 자리에 있다」이며, **파괴는 어느 경로에서도 일어나지
않는다.** 그 사실을 조용히 통과시키지 않고 코드를 갈라 알린다.

## §4 `POST /api/tests:move` — 그룹 이동

**요청**

```json
{ "test_ids": ["TC-001", "TC-002"], "to_prefix": "USER" }
```

`to_prefix` 에 `TC` 를 주면 **그룹에서 뺀다**.

**응답 200**

```json
{ "moved": [ { "from_id": "TC-001", "to_id": "USER-001", "name": "로그인" } ] }
```

**번호는 그대로다** (`TC-001` → `USER-001`). 접두어만 바뀐다 (data-model §1).

**오류**

| 상황 | HTTP | code |
|---|---|---|
| 그런 그룹이 없다 | 404 | `GROUP_NOT_FOUND` (신규) |
| 대상 테스트가 없다 | 404 | `TEST_NOT_FOUND` |
| 하나라도 실행 중이다 | 409 | `TEST_IN_USE` |
| 옮기다 실패 | 500 | `TEST_MOVE_FAILED` (신규) |

**불변식 — 테스트 하나를 옮기는 순서** (FR-444b · research R5)

1. 검증 (새 식별자가 비어 있는가 · 그룹이 있는가 · 실행 중이 아닌가)
2. `.runs/<옛ID>/` → `.runs/<새ID>/` (있을 때만)
3. 새 정의 파일 쓰기 (원자적, 내용의 `id` 도 새 값)
4. 옛 정의 파일 지우기
5. 3·4 가 실패하면 **2를 되돌리고** 새로 쓴 파일이 있으면 치운다

**산출물이 먼저인 이유**: 반대로 하면 「테스트는 새 자리, 결과는 옛 자리」가 되어 사용자에게는
**결과가 사라진 것**으로 보인다. 이 순서의 실패는 새 식별자 자리에 산출물만 남기고, 그것은
목록에 나타나지 않는다 — 목록은 정의 파일에서 나온다. **눈에 보이지 않는 흔적이 눈에 보이는
손실보다 낫다.**

**알려진 창**: 3과 4 사이에 정의 파일이 두 자리에 있다. 로컬 단독 실행이라 그 사이에 목록을
읽는 요청이 사실상 없지만, 없는 것처럼 적지 않는다.

여러 개를 옮길 때는 §3 과 같은 3단계(전부 검증 → 하나씩 → 실패 시 되돌림)를 쓴다.

## §5 그룹 라우트

| 메서드·경로 | 요청 | 응답 |
|---|---|---|
| `GET /api/groups` | — | `{ "groups": [{prefix, name, count}] }` — **테스트가 없는 그룹도 싣는다** |
| `POST /api/groups` | `{prefix, name}` | 201 + 만든 그룹 |
| `PATCH /api/groups/{prefix}` | `{name}` | 200 + 갱신된 그룹 |
| `DELETE /api/groups/{prefix}` | — | 200 + `{"ungrouped": ["TC-001", …]}` |

`GET /api/tests` 의 `groups` 와 **개수 규칙이 다르다**: 목록 응답은 비어 있는 그룹을 빼지만
(FR-450 — 목록을 어지럽히지 않는다), `GET /api/groups` 는 **전부 싣는다** — 그룹을 고르는
자리에서는 비어 있는 그룹도 골라야 한다.

**오류**

| 상황 | HTTP | code |
|---|---|---|
| 접두어 형식이 틀렸다 | 422 | (검증 실패 계약 형태) |
| 접두어가 `TC` 다 | 409 | `GROUP_PREFIX_RESERVED` (신규) |
| 접두어·이름이 겹친다 | 409 | `GROUP_ALREADY_EXISTS` (신규) |
| 그런 그룹이 없다 | 404 | `GROUP_NOT_FOUND` |

**`DELETE /api/groups/{prefix}` 는 테스트를 지우지 않는다** (FR-451). 그 안의 테스트를 모두
`TC-###` 로 되돌리고 어느 것이 풀렸는지 응답에 담는다. **묶음을 푸는 것과 자산을 지우는 것은
다른 조작이다** — 012 가 「목록에서 치우기」와 「삭제」를 가른 것과 같은 규칙이다.

그러므로 그룹 삭제는 §4 의 이동을 그 그룹의 테스트 전부에 적용하는 것이며, **같은 원자성
규약을 따른다.**

## §6 신규 오류 코드

| 코드 | HTTP | Category | 뜻 |
|---|---|---|---|
| `TEST_IN_USE` | 409 | `BLOCKED` | 실행 중인 세션이 있어 지우거나 옮길 수 없다 |
| `TEST_DELETE_FAILED` | 500 | `BLOCKED` | 옮기지 못했다. **되돌렸으므로 요청 전과 같다** |
| `TEST_DELETE_PARTIAL` | 500 | `BLOCKED` | 옮기다 실패했고 되돌리지도 못했다. 무엇이 어디에 있는지 `detail` 에 있다 |
| `TEST_MOVE_FAILED` | 500 | `BLOCKED` | 그룹 이동에 실패했다. 되돌렸다 |
| `GROUP_NOT_FOUND` | 404 | `BLOCKED` | 그런 그룹이 없다 |
| `GROUP_ALREADY_EXISTS` | 409 | `BLOCKED` | 접두어나 이름이 겹친다 |
| `GROUP_PREFIX_RESERVED` | 409 | `BLOCKED` | `TC` 는 그룹 없음이 쓴다 |

**전부 `BLOCKED` 다.** 이 저장소에서 `BROKEN` 은 **처리되지 않은 오류** 하나뿐이고
(`INTERNAL_ERROR`, `tests/abnormal/test_error_contract.py` 가 센다), 위는 모두 제품이 붙잡아
사유를 말한 정상 거부다 — 012 에서 같은 실수를 하고 그 검사에 걸렸다.

**필수**: 새 코드는 `CATEGORY`·`NEXT_ACTION` 대응표에 **둘 다** 들어가야 한다. 빠지면
`error_payload()` 가 `KeyError` 로 죽어 오류 응답 자체가 깨진다.
