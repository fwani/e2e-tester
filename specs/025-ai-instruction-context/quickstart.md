# Quickstart — 025 를 직접 확인하는 법

**목적**: 자동 검증이 덮지 못하는 것을 사람이 손으로 본다. 이 기능에서 자동 검증이 덮지
못하는 것은 하나로 모인다 — **모델이 실제로 이어서 하는가.**

가짜 드라이버는 대본대로 도구를 부르므로 「이어서 한다」를 흉내 낼 수 없다. 이어가기가
성립하는지는 **실제 모델이 실제 화면을 보고 판단할 때만** 드러난다.

**§2 · §3 · §3-A 가 가장 중요하다.**

| | 왜 |
|---|---|
| **§2 막힘 후 재개** | 이 기능이 고치려는 바로 그 실패다. 지난 턴이 이어지지 않으면 여기서 드러난다 |
| **§3 긴 시나리오** | 구획이 반복되는 실제 지시문이라야 되풀이·건너뜀이 나타난다 |
| **§3-A 클릭되는 div** | 실제 웹 앱에서 가장 자주 부딪히는 자리다. 여기서 막히면 나머지가 값을 내지 못한다 |

---

## 0. 띄운다

```bash
python fixtures/sample-app/serve.py --port 4300     # 대상 화면
cd backend && uv run itb                            # 제품 서버
cd frontend && npm run dev                          # http://127.0.0.1:4310
```

모델 자격 증명이 필요하다 (`ANTHROPIC_API_KEY` 또는 `ant auth login`). 이 확인은 실제 모델
경로를 보는 것이 목적이므로 가짜 드라이버로는 대신할 수 없다.

---

## 1. 정제 — 사용자의 뜻이 남는가

1. 새 테스트 만들기로 들어가 지시문을 붙여 넣는다. 구획이 반복되고 구체값이 자리마다 다른
   것이라야 한다 (아래 §3 의 지시문을 그대로 써도 된다).
2. 정제 결과가 뜬다.

**보여야 하는 것**

- 반복되던 로그인·화면 이동 전제가 **한 번만** 남았다.
- 등록의 연결 주소와 수정의 연결 주소가 **각각 다른 값으로** 남았다. 하나로 합쳐졌다면
  실패다 — FR-015 가 막으려는 바로 그것이다.
- 「기존 데이터는 검증에 쓰지 않는다」가 `[반드시 지킬 것]` 자리에 있다.
- 비밀번호가 값이 아니라 변수 참조로 바뀌었고, 그 사실이 안내로 떴다.

**해 볼 것**

- 항목 하나를 고치고 확정한다. 고친 내용이 작성에 쓰이는지는 §3 에서 드러난다.
- 「원문으로 진행」을 골라 본다. 작성이 시작되어야 한다 (FR-019).

---

## 2. 막힘 후 재개 — 지난 턴이 이어지는가

**이 기능의 핵심이다.**

1. 여러 동작이 필요한 지시를 준다. 중간에 AI 가 막히도록 모호한 자리를 하나 둔다 —
   예: 같은 이름의 버튼이 여럿인 화면.
2. AI 가 막혀서 물으면 답을 준다.

**보여야 하는 것**

- AI 가 **막힌 그 자리에서** 이어서 한다.
- 앞서 이미 한 동작(로그인·이동 등)을 **다시 하지 않는다.**
- 진행 문구가 처음부터 다시 흐르지 않는다.

**보이면 안 되는 것**

- 「화면을 살펴보는 중」 뒤에 이미 만든 Step 과 같은 동작이 다시 생기는 것
- AI 가 무엇을 하다 막혔는지 모르는 듯한 말 — 「무엇을 도와드릴까요」 같은 시작

같은 확인을 **사람이 이어받은 뒤 재개**로도 해 본다 (인수 → 직접 조작 → 재개).

---

## 3. 긴 시나리오 — 되풀이와 건너뜀이 멈추는가

구획이 넷인 지시문을 쓴다. 각 구획이 같은 전제로 시작하고, 구체값이 자리마다 다른 것.

```
관리자 계정 (아이디/비밀번호)로 로그인한 후 (메뉴 경로)로 이동한다.
중요!: 기존 등록된 데이터는 검증으로 사용하지 않는다.

[등록] … 연결 주소는 (주소 A) 를 입력한다 …
[목록] 관리자 계정 (아이디/비밀번호)로 로그인한 후 (메뉴 경로)로 이동한다 …
[수정] … 연결 주소 (주소 B) 로 변경하고 …
[삭제] … 먼저 취소를 선택한다 … 다시 삭제를 선택한 뒤 확인을 클릭한다 …
```

**보여야 하는 것**

- 로그인과 화면 이동이 **한 번만** 일어난다. 구획마다 되풀이하지 않는다.
- 등록에서는 주소 A 가, 수정에서는 주소 B 가 들어간다. **둘이 같으면 실패다.**
- 진척 목록에서 `✓` 가 차례로 늘어난다.
- 네 구획이 모두 시작된다. 삭제 구획이 조용히 넘어가지 않는다.

**끝났을 때 보여야 하는 것**

- 남은 항목이 있으면 **그것이 무엇인지 화면에 뜬다** (FR-028). 「완료」만 뜨고 삭제 구획이
  안 되어 있으면 실패다.

---

## 3-A. 사람이 가리킨 것을 찾는가 — **가장 자주 부딪히는 자리**

실제 웹 앱은 클릭되는 `<div>`·`<li>`·`<td>` 로 가득하다. 이것이 되지 않으면 나머지가
값을 내지 못한다.

1. 트리·표·카드가 있는 화면을 연다. **`<button>` 이 아닌 것을 누르는 화면이라야 한다** —
   메뉴 트리 항목, 표의 행, 카드 전체가 눌리는 목록 같은 것.
2. 화면에 보이는 글자로 지시한다 — 「메뉴관리를 클릭한다」.

**보여야 하는 것**

- AI 가 그 요소를 찾아 누른다.
- 관찰 목록에 그 요소가 실려 있고, 근거가 `cursor` 로 표시되어 있다.
- 조상과 자손이 **중복으로 실리지 않는다.** `<div>` 와 그 안의 `<span>` 이 둘 다 목록에
  있으면 실패다 — 커서 상속을 걸러 내지 못한 것이다.

**해 볼 것**

- 화면에 글자는 있는데 누를 수 없는 것을 가리켜 본다 (본문 설명 문구 같은 것).
  AI 가 **비슷한 다른 것을 누르지 않고 알려야** 한다.
- 요소가 아주 많은 화면에서 관찰시켜 본다. 목록이 잘렸으면 **잘렸다는 표시가 있어야** 한다.

**회귀로 확인할 것**

- 같은 화면에서 **사람이 직접 녹화**해 본다. 지금과 같이 동작해야 한다 — 관찰 범위 변경이
  녹화를 건드리지 않는다.

---

## 3-B. 진척 표시가 자리를 빼앗지 않는가 (2026-09-29 사용자 보고)

**이것이 깨지면 막힌 AI 를 풀 수 없다.**

초안은 계획을 항상 펼쳐 두었고, 항목이 21개인 실제 계획에서 대화 기록과 답변 자리를
밀어냈다. 사용자가 겪은 것:

> 「반드시 지킬 것, 할일 부분이 고정되어서 대화 2차례 · 자취 74줄 부분이 제대로
> 안보인다. 답변 대기시 답변을 클릭할수도 없다.」

1. 항목이 스무 개 넘는 계획으로 작성을 시작한다.
2. AI 가 도는 동안 사이드 패널을 본다.

**보여야 하는 것**

- 「할 일 3/21 · 남은 것 18」 머리줄과 **다음 할 일 한 줄**만 보인다.
- 대화 기록(자취)이 **그대로 읽힌다.** 스크롤이 살아 있다.
- 펼치면 목록이 보이고, 그때도 화면의 절반을 넘지 않는다.

**막혔을 때**

- 계획과 「아직 하지 않은 일」이 **사라진다.**
- 답변 칸과 선택지가 **눌린다.** 이것이 이 절의 요점이다.

## 4. 진척 되돌리기

1. §3 이 도는 중에 완료된 항목 하나를 화면에서 `pending` 으로 되돌린다.
2. AI 에게 대화로 「그 항목을 다시 해 달라」고 말한다.

**보여야 하는 것**

- 되돌린 항목이 `▶` 로 바뀐다.
- AI 가 그 항목을 다시 수행한다.

## 5. 정제 없이도 도는가 — 회귀 확인

**이 기능이 기존 경로를 막지 않는지 본다.**

| 해 볼 것 | 기대 |
|---|---|
| 정제를 거절하고 원문으로 작성 | 지금과 같이 동작한다 |
| 초안에서 시작하는 작성 (014) | 지금과 같이 동작한다 |
| 자연어 Step 추가 (001 US6) | 지금과 같이 동작한다 |
| 구간 재녹화 (016) | 지금과 같이 동작한다 — 계획 없이 시작한다 |
| 손으로 녹화 | 아무 영향 없다 |
| 저장한 테스트 재실행 | 아무 영향 없다 |

## 6. 전량 검증

**저장소 표준 명령으로 돈다.** `uv run pytest` 와 `npm test` 는 틀린 결과를 준다
(`docs/DEVELOPMENT.md`).

```bash
cd backend && bash scripts/test-backend.sh
cd backend && uv run ruff check src/ tests/
cd backend && uv run lint-imports          # 헌법 원칙 II — execution 이 llm 에 닿지 않는가
cd frontend && npx vitest run
cd frontend && npx tsc --noEmit
cd frontend && npm run build
```

**기준선과 대조한다.** 이 저장소에는 기능과 무관한 기존 실패가 있다 — `test_ui_surface.py`
의 AS-009 계열, ruff 2건, `ScreenSweep.test.ts` 2건. 시작 시점에 한 번 돌려 기준선을 잡고,
끝에 돌린 결과와의 **차이만** 이 기능의 것으로 본다.

`lint-imports` 가 특히 중요하다. 이 기능은 `itb.authoring` 에 언어모델을 부르는 자리를
하나 더한다 — 그것이 실행 계층에서 도달 가능해지면 헌법 원칙 II 위반이고, 그 계약이
빌드를 실패시켜야 한다.
