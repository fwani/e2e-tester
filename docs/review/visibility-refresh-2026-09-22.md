# 전체 화면 가시성 개선 — 2026-09-22

사용자가 승인한 우선순위는 테스트 목록에서 대상과 실행 결과를 빠르게 구분하는 것이다. 공통 부품과 프로젝트·목록·작성·편집·실행·결과·가져오기·키 관리·비밀 값 화면의 표시 코드를 함께 변경했다. API와 실행 명령은 변경하지 않았다.

## 확인한 문제와 변경

| 문제 | 변경 |
| --- | --- |
| 11px 설명과 13px 본문이 조밀하게 표시됨 | 설명 12px, 본문 14px, 기본 조작 36px·작은 조작 30px |
| 목록에서 이름·ID·실패 메시지의 위계가 약함 | 제목과 작업 안내, 이름 15px 굵게, 행 최소 64px, 실패 요약 강조 |
| 선택된 필터 개수가 어두운 배경에 묻힘 | 개수가 버튼의 전경색을 상속 |
| 목록과 결과에서 영어 상태를 해석해야 함 | 공통 사전에서 한국어 상태를 제공하고 결과 배지에 아이콘 추가 |
| 선택 여부와 결과를 함께 식별하기 어려움 | 목록 선택은 별도 내부 윤곽선으로 표시 |
| Step 행에 의도하지 않은 위·오른쪽 3px 테두리가 생김 | 위·오른쪽 테두리 폭을 0으로 명시 |
| Step 부가정보 줄에서 배지 테두리가 잘림 | 20px 배지 변종과 부가정보 줄 높이를 함께 적용 |
| 커진 상세 내용이 낮은 창에서 넘침 | 상세 패널 포털도 display:contents로 연결해 기존 flex 스크롤을 복원 |
| 결과 탭의 선택 상태가 약함 | 선택된 탭에 밑줄과 색상 강조 |

Step 행은 52px, 우측 패널은 460px로 유지해 20–50개 Step을 다루는 작업대의 밀도를 지킨다. 1440px보다 좁은 창에서 데이터 영역을 가로 스크롤하는 기존 정책을 유지한다.

## 검증 범위

- 실제 backend와 sample-app을 실행한 `scripts/screen_sweep.py`: 19개 화면/상태 × 1280·1440·1920·2560px. 저장된 통과·실패 결과는 실제 재실행으로 생성한다.
- 직접 캡처 검토: 프로젝트 생성, 목록, 작성, Step 상세, 실패 결과, 키 관리. 전체 순회는 선택·삭제 확인·행 메뉴·연결 끊김·긴 이름도 포함한다.
- 가져오기 미리보기와 AI 작성·인수·일시정지는 기존 순회의 미도달 항목이다. 표시 코드는 공통 규격으로 변경하고 단위 테스트로 확인했지만, 이 작업에서 해당 상태의 실제 브라우저 검증을 완료했다고 주장하지 않는다.
- Vitest 최종 결과: 1,471개 중 1,470개 통과. 남은 1개는 아래의 기존 디자인 동일성 보고서 최신성 검사다.
- `npm run build`: 통과. 기존 큰 청크 경고는 남는다.
- 화면 순회 최종 결과: 76개 측정, 미도달 0, 미등록 검출 0. 알림 한 건은 타이밍 실패 후 동일 소스에서 단독 재검증하여 통과했고, 보고서는 합쳐진 전체 결과로 재생성했다.
- 정본 시트 대조(L1): 725개 속성 비교, 불일치 0.
- Impeccable detector: 0건.

## 이전 디자인 동일성 검사

`BeforeAfterParity.test.ts`는 과거 UI와의 시각적 동일성을 요구한다. 이번 작업은 의도적으로 글자·행·조작 크기와 목록 구조를 바꾸므로 그 기준을 충족하지 않는다. 실제 비교도 실행했으며 1,307개 차이를 보고했다. 기존 기준선과 동일성 검사는 삭제하거나 허용 범위를 넓히지 않았다. 최종 전체 테스트 결과를 완전 통과로 해석하면 안 된다.

최신 화면 순회의 상세 결과와 미도달 사유는 `frontend/tests/sweep-report.json`에 있다. 변경 전후 이미지 비교는 작업의 로컬 HTML 산출물로 제공한다.
