# 공유 묶음 형식 (`.itbshare.yaml`)

기능 019 가 만든 전달 형식이다. 이 도구로 만든 프로젝트·테스트를 **파일 하나로** 다른
사람에게 건네고, 받은 사람이 자기 도구로 복원하기 위한 것이다.

이 문서가 헌법 원칙 V 의 **"문서화된, 사람이 읽을 수 있는 평문 형식"** 의무를 받는다.
정본 스키마는 [`backend/schema/share-bundle.schema.json`](../backend/schema/share-bundle.schema.json)
이며, 그것은 `itb.sharing.bundle.ShareBundle` 에서 생성된다 — 손으로 유지하는 두 번째
정의를 두지 않는다.

---

## 이 파일에 무엇이 없는가 (먼저 읽을 것)

**비밀번호·API 키 같은 민감 값이 들어 있지 않다.** 평문도, 암호문도, 암호구로 감싼 형태도
없다. 그것이 선택의 결과가 아니라 **구조의 결과**다.

- `Variable` 모델이 `sensitive: true` 인 변수에 `value` 를 허용하지 않는다. 테스트 정의를
  그대로 직렬화하는 한 값이 실릴 자리가 없다.
- 묶음을 만드는 `itb.sharing` 패키지는 import-linter 계약(`sharing-cannot-reach-secrets`)
  으로 `itb.secrets` 를 임포트하지 못한다. 암호문을 읽을 경로 자체가 없다.

받는 사람은 가져오기 화면에서 **무엇을 채워야 하는지**를 보고 자기 값을 입력한다. 입력한
값은 그 사람의 키로 봉인되어 `secrets.local.yaml` 에 저장되며, 이 파일에는 돌아오지 않는다.

**민감하지 않은 값은 그대로 들어 있다.** 스텝에 직접 적힌 입력값(계정 아이디, 사번, 사내
주소 등)은 정의의 일부이므로 따라간다. 내보내기 확인 화면이 그 목록을 **가리지 않고**
보여 주므로, 나가면 안 되는 것이 섞여 있으면 그 자리에서 발견할 수 있다.

## 파일 모양

UTF-8 로 인코딩된 YAML 문서 하나. 한글은 이스케이프하지 않는다 — **열어 볼 수 있다는 것이
이 형식을 고른 근거**이기 때문이다.

```yaml
# 이 파일에는 비밀번호·API 키 등 민감 값이 들어 있지 않습니다.
# 가져온 뒤 필요한 값은 받는 분이 직접 입력합니다. (required_values 참고)
bundle_version: 1
generator: itb
created_at: '2026-09-23T04:12:00Z'
project:
  name: dev-graphio
  default_start_url: https://example.internal
  browser: chromium
  test_id_attribute: data-testid
  max_tabs: 10
  groups:
  - prefix: USER
    name: 사용자관리
required_values:
- name: SECRET_INPUT_LOGIN_PW
  sensitive: true
  declared: true
  usages:
  - test_id: TC-001
    step_id: step-02
    step_label: 비밀번호 입력
    field: value
tests:
- dsl_version: 1
  id: TC-001
  name: 운영 관리 메뉴 진입
  # ... itb.domain.test_case.Test 그대로
```

### 최상위 키

| 키 | 설명 |
|---|---|
| `bundle_version` | 이 **봉투**의 형식 버전. 현재 `1`. |
| `generator` | 만든 도구 이름·버전. 표시·진단용이며 판정에 쓰지 않는다. |
| `created_at` | 만든 시각 (UTC). |
| `project` | 프로젝트 설정과 그룹 구성. |
| `required_values` | 받는 사람이 채워야 할 값의 요약. **참고용이며 정본이 아니다.** |
| `tests` | 테스트 정의 목록. `tests/*.yaml` 에 저장되는 것과 **같은 모양**이다. |

### `tests` 가 저장 형식 그대로인 이유

묶음은 **봉투**이지 테스트의 두 번째 표현이 아니다. 안에 실리는 것을 별도 모델로 다시
정의하면 두 모양이 갈리고, 갈린 순간 헌법 원칙 I 이 깨진다 — 같은 테스트가 어디를 거쳤느냐에
따라 다르게 실행된다. 로케이터 후보도 **전부** 옮긴다. 축약하면 받은 쪽의 복원력이 보낸
쪽보다 낮아지고, 그것은 「같은 테스트」가 아니다 (원칙 IV).

### `required_values` 를 믿지 않는 이유

파일은 손으로 편집될 수 있다. 가져오는 쪽은 이 목록을 참고만 하고 **테스트 정의에서 다시
계산한다.** 매니페스트를 정본으로 삼으면 참조는 있는데 목록에 없는 변수가 조용히 빠진다.

| 필드 | 설명 |
|---|---|
| `name` | 변수 이름. |
| `sensitive` | 참이면 봉인 저장소로, 거짓이면 테스트 정의로 값이 들어간다. |
| `declared` | 묶음에 변수 선언이 있었는가. 거짓이면 참조만 있어 가져오기가 **보충한 것**이다. |
| `usages` | 어느 테스트의 어느 스텝에서 쓰이는지. 이름만으로는 무엇을 넣을지 모른다. |

## 버전 정책

`bundle_version` 은 **테스트 정의의 `dsl_version` 과 별개다.** 봉투가 바뀌는 주기와 스텝
모델이 바뀌는 주기가 다르기 때문이다 — 한 숫자로 묶으면 봉투에 필드를 하나 더할 때마다
모든 테스트 파일의 버전을 올려야 한다.

가져오기는 두 가지를 따로 본다.

- `bundle_version` 이 이 도구가 아는 값과 다르면 **거부한다.** 모르는 필드를 버리고 억지로
  복원하면 실행되지 않는 테스트가 조용히 만들어진다.
- 각 테스트의 `dsl_version` 은 기존 `Test` 검증이 거부한다.

**아래로는 호환하지 않는다.** 더 새로운 도구가 만든 묶음을 옛 도구가 읽을 수 없는 것은
의도한 방향이며, 그때 사용자가 받는 안내는 "도구를 올리세요" 다.

## 읽을 때의 검증 (다섯 겹)

앞의 겹을 통과하지 못하면 뒤를 시도하지 않는다.

1. **바이트** — 20MB 초과면 읽지 않는다. 파싱 **전에** 판정한다.
2. **YAML** — 파싱, 최상위가 매핑인지, **별칭(anchor/alias) 사용 여부**.
3. **묶음 모델** — 형식 버전, 건수·그룹 수 상한, 필드 구성.
4. **선언 보충** — 참조는 있는데 선언이 없는 변수를 채운다.
5. **도메인** — 각 테스트를 `Test` 모델로 검증.

### YAML 별칭을 거부하는 이유

`yaml.safe_load` 는 임의 객체 생성은 막지만 **별칭 폭탄**(billion laughs)은 막지 못한다 —
수백 바이트짜리 문서가 전개되면서 수 GB 가 될 수 있다. 이 파일은 사람이 보낸 외부 입력이고,
정상적인 묶음은 별칭을 쓰지 않으므로 잃는 것이 없다.

### 선언 없는 참조를 거부하지 않는 이유 (4단계)

`Test` 검증은 선언 없는 `{{변수}}` 참조를 거부한다. 손으로 편집된 묶음이 거기 걸리면
사용자는 「무엇을 고쳐야 하는지」 대신 「읽을 수 없다」만 받는다.

그래서 검증 **앞에서** 선언을 보충한다. 이름이 `SECRET_` 로 시작하면 민감 변수로, 아니면
값이 빈 비민감 변수로 채운다. 보충한 것은 가져오기 결과에 `declared: false` 로 남는다.

**보충은 없는 값을 지어내는 것이 아니라 빈 자리를 드러내는 것이다.** 채우는 것은 사용자이며,
민감 변수라면 채우기 전까지 실행이 막힌다.

## 상한

| 값 | 크기 | 근거 |
|---|---|---|
| 파일 크기 | 20MB | 테스트 약 1,000건. 그 이상은 한 번에 공유할 단위가 아니다. |
| 테스트 수 | 2,000 | 바이트를 통과해도 건수로 다시 막는다. 둘은 다른 것을 잰다. |
| 그룹 수 | 100 | |

그룹당 테스트 999 는 이 형식의 상한이 아니라 **제품 공통 상한**(`MAX_TEST_NUMBER`)이며,
가져오기가 그것을 참조한다. 여기 베껴 두지 않는다.

| | 공유 묶음 (019) | 엑셀 왕복 (014) | Playwright Export (원칙 V) |
|---|---|---|---|
| 목적 | 제품으로 **되돌아오기** | 사람이 읽는 설계서 | 제품 **없이** 실행하기 |
| 담는 것 | 스텝·로케이터 후보 전부 | 제목·절차 요약 | 생성된 spec 파일 |
| 가져오면 | 실행 가능한 테스트 | 녹화가 필요한 **초안** | (돌아오지 않는다) |
| 형식 | `.itbshare.yaml` | `.xlsx` | Playwright 프로젝트 |

셋은 서로를 대체하지 않는다. 이름이 섞이지 않도록 화면에서도 「공유용」·「엑셀로」를 앞에 둔다.
