# 에이전트 컨텍스트 계약 — 모델에게 무엇이 가는가 (025)

**Date**: 2026-09-29 | **Spec**: [spec.md](../spec.md) | **Research**: [research.md](../research.md)

016 이 `[지금 테스트]` 하나를 정했다. 이 문서는 그 자리에 무엇이 함께 가고, 턴과 턴 사이에
무엇이 남는지를 정한다.

---

## §1. 매 사용자 메시지 앞에 붙는 것

순서가 정해져 있다. **제약이 맨 앞이다** — 가장 자주 어겨지는 것이고, 앞머리가 가장 잘
읽힌다.

```
[반드시 지킬 것]
- 기존 등록된 데이터는 검증에 사용하지 않는다
- 4번 항목의 연결 주소는 {{menu_url_create}} 를 쓴다

[할 일]
  1. ✓ 관리자 계정으로 로그인한다
  2. ✓ 운영 관리 > 메뉴관리로 이동한다
  3. ▶ 새 메뉴 추가 버튼을 클릭한다
  4.   각 필드에 값을 입력한다
  5. — 사용 여부를 전환한다  (건너뜀: 제품에 해당 설정이 없다)

[지금 테스트]
  1  s1  「로그인」 버튼 클릭  click  button "로그인"
  …

[사용자] …사용자가 한 말…
```

| 표시 | 뜻 |
|---|---|
| `✓` | 했음 |
| `▶` | 다음에 할 것 (가장 앞선 `pending`) |
| (없음) | 아직 안 함 |
| `—` | 건너뜀. 사유가 괄호로 붙는다 |

**`▶` 를 두는 이유**: 목록만 주면 모델이 어디서 이어야 하는지를 스스로 판정해야 하고, 그
판정이 「되풀이」와 「건너뜀」이 생기는 자리다. 다음 할 일을 제품이 지목한다.

### 예산

| 조각 | 예산 | 넘으면 |
|---|---|---|
| 제약 + 할 일 | 6KB | 완료된 항목부터 접는다. **생략을 명시한다** |
| 지금 테스트 | 10KB | 016 이 정한 방식 그대로 (교체 구간 중심 축약) |

합 16KB 는 016 이 정한 총량과 같다. 새로 더하지 않고 나눈다 (research R6).

**완료된 항목부터 접는 이유**: 남은 일이 무엇인지가 끝난 일보다 중요하다. 다만 접힌 구간에
`✓` 가 몇 개였는지는 남긴다 — 「1~6 완료, 생략」.

### 계획이 없는 세션

`[반드시 지킬 것]`·`[할 일]` 이 통째로 빠지고 `[지금 테스트]` 만 붙는다. 016 이전과 정확히
같은 모양이다 (FR-012).

## §2. 턴이 끝날 때 이력에 남는 것

한 턴의 끝에 **어시스턴트 차례 하나**가 이력에 들어간다 (research R3).

```
[내가 한 일]
- 화면 관찰 (탭 0)
- 「로그인」 버튼 클릭 — 완료 · Step「로그인 버튼 클릭」
- 「아이디」 입력 — 완료 · Step「아이디 입력」
- 「저장」 클릭 — 실패: 가리키는 요소가 하나로 좁혀지지 않는다
- 막힘: 「저장」 버튼이 셋이고 지시문이 어느 것인지 말하지 않는다
  (물음: 어느 저장 버튼을 눌러야 합니까?)

로그인까지 마쳤고 저장 단계에서 막혔습니다. 화면에 저장 버튼이 셋 있습니다.
```

마지막 문단은 모델이 낸 답(`last_reply`)이다. 한 메시지로 합친다 — 나누면 어시스턴트 차례가
연달아 오고, 그것은 다시 대화가 아닌 더미다.

### 남기지 않는 것

| 남기지 않음 | 이유 |
|---|---|
| 요소 참조 (`e17`) | 화면이 바뀌면 낡는다. 낡은 참조를 본 모델이 관찰 없이 쓰려 든다 |
| 화면 요소 목록·본문 텍스트 | 이 기능이 없애려는 바로 그 크기다 |
| `fill` 에 넘긴 값 | 016 정의 요약과 같은 민감값 규칙 |

### 상한

수행 기록의 총량 상한은 32KB. 넘으면 **오래된 턴부터** 접는다.

```
[앞선 3개 턴 생략]
```

생략을 명시한다 — 조용히 사라지면 모델은 그것이 전부라고 믿는다 (FR-006).

**진척은 기록이 줄어도 남는다.** §1 의 `[할 일]` 이 그것을 들고 있다. 둘은 서로를 대신하지
않는다.

## §3. 턴 안에서 낡은 화면 관찰이 접히는 모양

가장 최근 관찰만 온전히 남고, 지난 것은 이렇게 바뀐다.

```json
{
  "folded": true,
  "note": "이 화면 관찰은 낡았습니다. 지금 화면이 필요하면 observe_page 를 다시 부르세요."
}
```

| 접는다 | 접지 않는다 |
|---|---|
| `observe_page` 의 결과 | 조작 결과 (`click`·`fill`·…) |
| | 검증 결과 |
| | 막힘 신고 |
| | 계획 항목 표시 |

접지 않는 것들은 「무엇을 했는가」의 기록이고, 그것이 사라지면 이 기능이 고치려는 문제가
턴 안에서 다시 생긴다 (FR-034).

**온전히 남기는 개수의 기본값은 1.** 값 하나로 두어 실측으로 조정한다 (FR-032).

**모델에게 보내는 사본에만 적용된다** (FR-033). 제품이 든 기록과 사용자에게 보이는 대화는
접히지 않는다.

## §4. 새 도구 — `mark_item`

모델이 계획 항목의 상태를 표시하는 수단 (FR-024).

```
mark_item(item_id: str, status: "done" | "skipped", reason: str | None = None)
```

| 규칙 | 내용 |
|---|---|
| 예산 | **쓰지 않는다.** `record_call()` 을 지나지 않는다 (research R9) |
| 연속 실패 상한 | 중립. 이 도구의 실패는 화면 조작의 실패가 아니다 |
| `skipped` | `reason` 이 없으면 거절 |
| 없는 `item_id` | 거절하고 사유를 돌려준다 |
| 되돌리기 | **할 수 없다.** `pending` 으로 돌리는 것은 사용자만 (데이터 모델 §2) |
| 계획이 없는 세션 | 도구 자체가 주어지지 않는다 |

**예산을 쓰지 않는 이유**: 도구 호출 상한의 뜻은 「화면을 조작하며 헛돌지 않게」다. 표시는
화면을 건드리지 않는다. 예산을 쓰게 하면 성실히 표시할수록 할 수 있는 일이 줄어든다.

### 시스템 프롬프트에 더해지는 안내

```
- 할 일 목록이 `[할 일]` 로 주어집니다. `▶` 가 다음에 할 것입니다.
- 항목 하나를 끝낼 때마다 mark_item 으로 표시하세요. 표시는 예산을 쓰지 않습니다.
- 제품에 그 기능이 없어 할 수 없으면 mark_item 의 status 를 skipped 로 주고
  사유를 적으세요. 다른 경로로 대체하지 마세요.
- 표시하지 않은 항목이 남아 있으면 끝났다고 말하지 마세요.
```

마지막 줄이 FR-028 의 모델 쪽 절반이다. 제품 쪽 절반은 `ai_finished` 에 남은 항목을 싣는
것이다 — **둘 다 필요하다.** 모델의 말만 믿으면 조용히 넘어가고, 제품만 세면 모델이 끝났다고
말하는 것을 막지 못한다.

## §5. 드라이버 사이의 차이

| 규칙 | 기본 드라이버 (Messages API) | 개발용 (`ITB_AI_DRIVER=claude-code`) |
|---|---|---|
| §1 앞머리 주입 | 적용 | 적용 (같은 사용자 메시지를 쓴다) |
| §2 턴 기록 | 적용 | 적용 (같은 이력에 쌓인다) |
| §3 턴 내부 접기 | 적용 | **대상 없음** — 도구 결과가 이력에 실리는 구조가 아니다 |
| §4 `mark_item` | 적용 | 적용 (`TOOL_SCHEMAS` 를 통해 자동으로 실린다) |

FR-038 은 「규칙이 같아야 한다」를 요구한다. 접을 것이 없는 곳에서 접지 않는 것은 규칙이
다른 것이 아니다. 그 사실을 해당 모듈 주석에 남긴다.
