# 검증 안내: 대상 브라우저를 제품 화면 안에서 조작한다

**기능**: `010-headless-mirror-control` | **작성**: 2026-09-09

이 문서는 **이 기능이 동작함을 증명하는 절차**다. 구현 코드는 담지 않는다.

---

## 준비

```bash
# 백엔드
cd backend && uv sync

# 프론트엔드
cd frontend && npm install
```

대상 앱은 `fixtures/sample-app/` 를 쓴다 — **녹화 대상 재료이며 이 기능의 평가 대상이
아니다.**

**이 기능 이후 대상 브라우저는 창 없이 뜨는 것이 기본이다** (FR-352). 창을 보고 싶으면
환경 변수로 명시한다.

```bash
# 창을 띄우고 싶을 때만
ITB_HEADLESS=0 uv run itb serve
```

---

## 기계 검증

```bash
# 1. 임포트 경계 — 읽기 전용 미러 모듈이 Input 을 여전히 모르는가
cd backend && uv run lint-imports

# 2. screencast.py 가 Input 명령을 보내지 않는가 (research R5 의 결정)
#    명령 문자열 리터럴만 본다 — 주석의 `Input.*` 언급은 잡지 않는다
cd backend && ! grep -n '"Input\.' src/itb/mirror/screencast.py

# 3. 백엔드 정적 검사와 테스트
cd backend && uv run ruff check .
cd backend && uv run pytest -m "not browser and not timing" -q
cd backend && uv run pytest -m "browser and not timing" -q -n 2

# 4. 프론트엔드 타입·테스트
cd frontend && npm run typecheck && npm test -- --run

# 5. 시각 언어 정본
python3 scripts/extract_canon.py --check
```

**2번이 실패하면 research R5 의 결정이 깨진 것이다** — 조작 명령이 미러 모듈로 새어
들어갔다. `mirror/input.py` 로 옮긴다.

**3번의 `test_test_tiers.py` 가 실패하면** 헤드리스 기본값 검증 2건의 개정이 빠졌거나
(FR-352), 반대로 개정만 하고 `session.py` 의 기본값을 바꾸지 않았다.

## US1 — 제품 화면을 벗어나지 않고 녹화한다 (SC-511·SC-512)

```bash
cd fixtures/sample-app && python3 -m http.server 5173 &
cd backend && uv run itb serve
```

1. 제품 화면에서 새 테스트를 만들고 대상 주소를 `http://localhost:5173` 으로 둔다.
2. 녹화를 시작한다. **크롬 창이 뜨지 않아야 한다.**
3. 미러 영역에 화면이 보이고, 상단에 「조작할 수 있다」는 상태가 표시된다.
4. 미러에서 버튼 세 개를 순서대로 클릭한다.

**통과 조건**
- 클릭한 요소가 눌린다 — 옆 요소가 아니다 (SC-512)
- Step 목록에 클릭 Step 이 **셋** 쌓인다 (FR-321)
- 같은 자리를 빠르게 두 번 눌렀을 때 Step 은 **하나만** 쌓인다 (기존 접기 규칙)
- 미러에서 휠을 굴리면 페이지가 스크롤되고, **그 스크롤만으로는 Step 이 쌓이지 않는다**
- 브라우저 창으로 전환한 횟수 **0회** (SC-511)

### 밀집 요소 확인 (SC-512)

대상 화면을 미러 표시 크기보다 크게 만든 상태에서(브라우저 창을 좁히면 된다) 서로 붙어
있는 작은 아이콘을 각각 클릭한다. **의도한 것이 눌려야 한다.**

> 실측 근거: 뷰포트 1600×1200 을 1067×800 프레임으로 받은 상태에서 12px 요소 3개를
> 왕복 변환해 클릭했을 때 3/3 정확했다 (research R3).

## US2 — 미러에서 한글을 입력한다 (SC-515·SC-515a·SC-515b)

1. 미러에서 검색 입력 요소를 클릭한다.
2. 「주문 내역」을 평소처럼 타이핑한다.

**통과 조건**
- 타이핑하는 동안 **대상 입력 요소의 값이 글자마다 바뀐다** — `주` → `주문` (FR-327)
- 자동완성이 붙은 입력 요소라면 **후보 목록이 다 치기 전에 뜬다** (SC-515a)
- 조합 중인 값이 Step 으로 확정되지 않는다 (FR-326)
- 다른 요소를 클릭하면 입력 Step 이 그 값으로 확정된다
- 연속 타이핑에서 키 유실·순서 뒤바뀜이 없다 (SC-515b)

### 민감 값 확인 (FR-329)

비밀번호 입력 요소에 값을 넣는다.

```bash
# 이벤트·로그에 평문이 없는지 확인
cd backend && uv run pytest -q -k "sensitive or scrub"
```

**통과 조건**: Step 에 변수 참조가 저장되고, 화면·이벤트·로그 어디에도 평문이 없다.

## US3 — 실패한 실행을 화면 안에서 이어받는다

1. 저장된 테스트를 실행한다.
2. **실행 중에 미러 영역을 클릭한다.**

**통과 조건 (관찰 국면)**
- 조작이 전달되지 않는다 (FR-315)
- **왜 지금 조작할 수 없는지가 화면에 있다** (SC-516)

3. 일시정지한다.

**통과 조건 (조작 국면)**
- 미러가 조작을 받는 상태로 바뀌고 그것이 화면에 표시된다 (FR-319)
- 미러에서 조작하면 대상 페이지에 반영되고 세션 상태가 유지된다
- 재개하면 그 화면을 전제로 실행이 이어진다 (원칙 III)

## US4 — 화면에 나타나지 않는 것 (SC-517)

### 파일 첨부

1. 파일 선택 요소가 있는 화면에서 미러로 그것을 클릭한다.
2. 제품 화면이 제시한 수단으로 파일을 고른다.

**통과 조건**
- 운영체제 파일 선택 창이 뜨지 않는다 (창이 없다)
- 고른 파일이 대상 페이지에 전달되고 Step 이 쌓인다
- 크기·개수 상한을 넘기면 **사유와 함께 거절된다** (FR-337a)
- **세션을 종료하면 업로드된 파일이 사라진다** (FR-337b)

```bash
# 세션 종료 후 남은 파일이 없는지 확인
cd backend && uv run pytest -q -k "session_file"
```

### 대화상자

1. `confirm` 을 띄우는 버튼을 미러에서 클릭한다.

**통과 조건**
- 대화상자가 떴다는 사실과 선택지가 제품 화면에 나타난다 (FR-338)
- 고른 결과가 대상 페이지에 전달된다
- **아무 일도 일어나지 않는 상태로 멈추지 않는다** (FR-339 · SC-516)

> 가로채지 않으면 대상 페이지가 멈춘다. 헤드리스에서는 화면에도 안 나오므로 사용자에게는
> 「클릭했는데 아무 일도 없다」로 보인다 (research R7).

## US5 — 실제 창 폴백

1. 조작 국면에서 실제 창 전환을 누른다.

**통과 조건**
- 창이 열리고 세션 상태(인증·화면)가 유지되며 녹화가 끊기지 않는다 (FR-349)
- 미러가 「실제 브라우저 창에서 조작 중 · 이 영역은 관찰용입니다」로 바뀐다 (FR-350)
- **제품이 스스로 창을 열지 않는다** — 누르지 않으면 열리지 않는다 (FR-353)

### 화면 없는 환경 (FR-351 · SC-518)

화면 없는 기계(또는 `DISPLAY` 없는 환경)에서 같은 절차를 밟는다.

**통과 조건**
- 녹화·인수를 포함한 **전체 흐름이 동작한다** (SC-518)
- 실제 창 전환을 요청하면 **불가능한 이유가 표시된다** (FR-351)

## 미러가 끊기거나 강등된 상태 (SC-516·SC-519)

### 강등 (1 FPS)

```bash
cd backend && uv run pytest -q -k "degrade"
```

**통과 조건**: 「1 FPS」 표시와 함께 **지금 조작은 정확하지 않을 수 있다는 것과 전환
수단이 같은 자리에 있다** (FR-345·FR-353a).

### 프레임 끊김

**통과 조건**: 조작이 전달되지 않고, **화면이 멈춘 것과 페이지가 멈춘 것을 사용자가
구분할 수 있다** (FR-346).

### 채널 장애가 실행을 깨지 않는다 (SC-519)

```bash
cd backend && uv run pytest -q -k "control_channel_failure"
```

**통과 조건**: 조작 채널에 장애를 주입해도 진행 중인 실행이 **10회 중 10회 완주**한다
(FR-348 · FR-047b 유지).

## 원칙 I 증거 — 두 경로 동등성 (FR-324)

이 기능에서 **가장 중요한 검증**이다. 미러 조작이 Step 모델에 새 표현을 만들지 않는다는
것을 이것이 증명한다.

```bash
cd backend && uv run pytest -q -k "recording_parity"
```

**통과 조건**: 같은 화면·같은 조작을 미러와 실제 창 두 경로로 했을 때 만들어지는 Step 이
**종류·값·요소 후보 집합·검증 상태 전부 동일**하다 (SC-513).

> 이것이 깨지면 미러 조작을 켜 둘 수 없다. 헌법 원칙 I 위반이며, 기능이 아니라 결함이다.

## 지연 확인 (SC-514)

미러에서 클릭한 뒤 결과가 화면에 나타나는 것을 10회 관찰한다.

**통과 조건**: 10회 중 9회 이상에서 사용자가 같은 곳을 다시 누르지 않는다.

> 실측 기준선: 로컬 헤드리스에서 클릭 → 프레임 도착 중앙값 약 25ms, 최대 43ms, 12/12
> 성공 (research R8). 이 값에서 멀어지면 프레임 ack 가 흐르지 않는 상태를 먼저 의심한다 —
> ack 가 멈추면 3프레임 뒤 프레임 밀기가 정지한다.

### 화면이 변하지 않는 조작 (FR-335)

포커스만 옮기는 조작이나 같은 값을 다시 넣는 입력을 한다.

**통과 조건**: 화면 변화가 없어도 **현재 화면이 확인된다.** 2초를 기다리게 하지 않는다.
