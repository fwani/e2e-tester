# 디자인 준수 계약 — 확정 디자인 8종을 옮기는 절차

**기준**: `docs/design/*.dc.html` 8종 + `docs/design/canvas.json`
**요구사항**: DC-001 ~ DC-012

이 문서는 **UI 계약**이다. REST 계약이 서버와 클라이언트 사이의 약속이듯, 이것은 확정
디자인과 구현 사이의 약속이다.

> **DC-001 — 확정 디자인은 해석 대상이 아니다.**
> 아래 절차의 목적 하나뿐이다: 옮기는 사람의 판단이 들어갈 자리를 없애는 것.

## 2. 전사 절차 — 화면마다 똑같이 반복한다

1. **최상위 컨테이너부터 DOM 순서대로 JSX 로 옮긴다.**
   인라인 `style` 의 값을 손대지 않는다. 축약·재해석·토큰 치환을 하지 않는다.

2. **SVG 는 `viewBox`·`stroke-width`·`d` 까지 그대로 옮긴다.**
   아이콘 라이브러리로 대체하지 않는다 — 대체는 해석이다. (8종 합계 98개)

3. **데이터에서 오는 문자열만 props 로 바꾼다.**
   레이블·제목·안내 문구·버튼 글자는 dc.html 의 것을 그대로 둔다 (DC-007).
   dc.html 의 `테스트 4` 같은 표본 숫자는 데이터이므로 props 다.

4. **상호작용을 붙인다.** 이 단계에서 구조를 바꾸지 않는다.
   `<div>` 로 그려진 버튼을 `<button>` 으로 바꾸는 것은 허용한다 — 접근성이자 기존
   테스트의 `getByRole` 이 의존한다. **단 인라인 style 은 그대로 옮긴다.**

5. **대조 기록을 작성한다** (§4).

### 금지

| 금지 | 이유 |
|---|---|
| dc.html 에 없는 값을 토큰으로 만들기 | `--radius` 가 그렇게 들어왔다 |
| 여러 화면의 공통 부분을 미리 추상화하기 | 추상화 층에서 다시 해석이 일어난다 |
| "더 나은" 간격·정렬로 바꾸기 | DC-001 |
| dc.html 에 없는 요소 추가, 있는 요소 제거 | DC-007 |
| 반응형으로 재배치 | DC-011 — 기준 폭 유지하고 스크롤 |

## 3. 시각 언어 — 8종에서 기계적으로 추출한 사실

`docs/design/*.dc.html` 8개 파일 전체를 훑어 센 값이다. 추정이 아니다.

### 기하 — 여기가 어긋났다

| 항목 | 확정 디자인 | 현재 `tokens.css` | 조치 |
|---|---|---|---|

| 테두리 | `3px solid` 67회, `2px solid` 43회 | `button`·`input` 이 `1px solid` | 3px / 2px 로 |
| 그림자 | 하드 오프셋 26회 — `5px 5px 0 #14130F`(11), `5px 5px 0 #F5D000`(5), `6px 6px 0`(4), `4px 4px 0`(4), `7px 7px 0`(1), `10px 10px 0`(1) | 없음 | 도입 |

## 4. 대조 기록 (DC-012)

**위치**: `specs/002-defect-fix-design-conformance/design-conformance/<Screen>.md` — 8개

**형식**

```markdown
# 디자인 대조 — TestList

**기준**: docs/design/TestList.dc.html (1440×760)
**대상**: frontend/src/pages/TestList.tsx

| 축 | 항목 | 기준값 | 관측값 | 판정 | 비고 |
|---|---|---|---|---|---|
| 구조 | 최상위 영역 순서 | 헤더(60px) → 본문 | | 미판정 | |
| 치수 | 헤더 높이 | 60px | | 미판정 | |
| 치수 | 헤더 하단 테두리 | 3px solid #14130F | | 미판정 | |
| 타이포·색 | 화면 배경 | #EFEBE0 | | 미판정 | |
| 가감 | dc.html 에 없는 요소 | 0개 | | 미판정 | |
```

| 칸 | 채우는 주체 |
|---|---|
| `축`·`항목`·`기준값` | **스크립트가 dc.html 에서 기계적으로 추출** |
| `관측값`·`판정`·`비고` | **사람이 채운다** |

**구현자가 자기 구현을 판정하면 대조가 아니라 자기 확인이다.** 001 의 T156 이 같은
문제로 미완으로 남았다.

**축은 6개** — DC-002 구조 / DC-003 컴포넌트 / DC-004 치수 / DC-005 타이포·색 /
DC-006 상태 / DC-007 가감.

**완료 판정 (SC-108)**: 8화면 전부에서 `불일치`·`미판정`이 0건.

### 자동 보조의 한계

추출 스크립트는 **기준값 칸만 채운다.** 픽셀 단위 스크린샷 비교는 하지 않는다 —
확정 디자인은 표본 데이터가 든 정적 목업이고 제품은 실제 데이터가 든 화면이라, 자동
비교는 **내용 차이를 디자인 불일치로 오판한다.** spec 의 Assumptions 도 사람 판정을
전제한다.

## 5. 미정의 상태 기록 (DC-009)

**위치**: `specs/002-defect-fix-design-conformance/design-conformance/undefined-states.md`
— **한 파일에 모은다.** 흩어 두면 SC-110("기록 없는 임의 결정 0건")을 셀 수 없다.

```markdown
| 화면 | 상태 | 근거 | 결정 |
|---|---|---|---|
| TestList | 빈 목록 | dc.html 의 검색 결과 없음 표현(…행 …)을 따랐다 | … |
```

`근거` 는 필수다. **근거를 댈 수 없는 결정은 해석이고 DC-001 위반이다.**

기록 대상: 로딩 / 빈 목록 / 오류 / 목록이 기준 높이를 넘음 / 텍스트가 넘침 등
확정 디자인이 한 상태만 보여 주어 나머지를 구현자가 정해야 했던 모든 경우.

## 6. 화면 전이 (DC-008)

`App.tsx` 의 화면 상태를 확정 디자인 8종 + 미대응 4종에 맞춰 늘린다.

**세션 상태(`view.state`)와 화면 선택을 분리한다.** 현재는 `Runner` 하나가 세션 상태
조합으로 4개 화면을 그린다 — research R2 가 규명한 "AI 실패가 보이지 않는" 원인이
바로 이 얽힘이다.

```
setup ─▶ list ─▶ create ─┬─▶ runner(D4) ⇄ paused(D5) ─▶ result(D7)
                         └─▶ ai(D3) ─▶ takeover(D6)
                                    ↘
  임의 화면 ─▶ inspector(D8)          (모두 저장 후 list 로)
```

화면 선택은 세션 상태를 **읽어 정하되**, 렌더 조건이 세션 상태 조합에 직접 매달리지
않게 한다. AI 세션인지는 `view.state` 가 아니라 `authoring_mode` 로 판정한다 —
그것이 세션의 불변 속성이다 (research R2).
