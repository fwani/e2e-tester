# Data Model: 지난 턴이 이어진다 (025)

**Date**: 2026-09-29 | **Spec**: [spec.md](./spec.md) | **Research**: [research.md](./research.md)

이 기능이 더하는 것은 전부 **세션에 사는 값**이다. 디스크에 쓰이는 것은 정제 기록 하나뿐이며,
그것도 실행 정보가 아니라 의도 기록이다 (헌법 원칙 II).

---

## 1. 작업 계획 (WorkPlan)

한 작성 세션이 요구받은 것의 정본. `SessionWork` 가 소유한다 (research R5).

| 필드 | 형 | 설명 |
|---|---|---|
| `constraints` | `list[Constraint]` | 모든 항목에 걸리는 규칙 |
| `items` | `list[PlanItem]` | 순서 있는 할 일 |
| `source` | `PlanSource` | 이 계획이 어디서 왔는가 — `refined`(정제) · `manual`(사용자가 고침) |

**불변 조건**

- `items` 의 순번은 1부터 끊기지 않는다. 사용자가 항목을 지우면 다시 매긴다 — 사용자가
  보는 번호와 모델에게 가는 번호가 같아야 한다 (016 정의 요약이 1부터 매긴 것과 같은 판단).
- 계획은 **비어 있을 수 있다.** 정제에 실패했거나 사용자가 거절한 세션이 그렇다. 그때
  주입은 지금과 같이 정의 요약만 붙는다 (FR-012).
- 계획은 Step 을 참조하지 않는다. 항목과 Step 은 1:N 도 아니고 1:1 도 아니다 — 검증만 하는
  항목은 Step 을 만들지 않고, 한 항목이 여러 Step 이 되기도 한다 (spec Assumptions).

---

## 2. 계획 항목 (PlanItem)

| 필드 | 형 | 설명 |
|---|---|---|
| `id` | `str` | 항목 식별자. 모델이 완료를 표시할 때 지목한다 |
| `order` | `int` | 1부터. 사용자가 보는 번호 |
| `text` | `str` | 할 일 한 줄 |
| `status` | `ItemStatus` | `pending` · `done` · `skipped` |
| `skip_reason` | `str \| None` | 건너뛴 사유. `status == skipped` 일 때만 값이 있다 |

### 상태 전이

```
pending ──(모델이 완료 표시)──▶ done
pending ──(모델이 건너뜀 신고)─▶ skipped
done ────(사용자가 되돌림)────▶ pending
skipped ─(사용자가 되돌림)────▶ pending
```

- **모델은 `done` 과 `skipped` 로만 옮길 수 있다.** 되돌리는 것은 사용자만 한다 — 모델이
  자기 표시를 취소할 수 있으면 「했다」가 무엇을 뜻하는지 알 수 없다.
- `skipped` 로 옮길 때 사유가 없으면 거절한다 (FR-027).
- 같은 항목을 여러 번 표시해도 상태는 한 번만 바뀐다 (research R9).
- 없는 `id` 를 지목하면 거절하고, 거절 사유를 모델에게 돌려준다.

**상태의 소유자는 제품이다** (FR-025). 모델의 표시는 입력이며, 그것만으로 Step 이 생기지
않는다.

## 3. 제약 (Constraint)

| 필드 | 형 | 설명 |
|---|---|---|
| `text` | `str` | 지켜야 할 것 한 줄 |
| `scope` | `ConstraintScope` | `global`(모든 항목) · `item`(특정 항목) |
| `item_id` | `str \| None` | `scope == item` 일 때 걸리는 항목 |

**구체값도 제약이다.** 「연결 주소는 (주소 A) 를 쓴다」는 특정 항목에 걸린 제약이고,
「기존 데이터는 검증에 쓰지 않는다」는 전역 제약이다. 둘을 다른 종류로 나누지 않는 이유는,
모델에게는 둘 다 「어겨서는 안 되는 것」 하나이기 때문이다.

**정제를 지나도 글자 그대로 남는다** (FR-015·FR-016). 같은 성격의 값이 자리마다 다르면
각각 별개의 제약이다 — 하나로 합치면 그 차이를 요점으로 삼는 테스트가 무의미해진다.

## 4. 수행 기록 (TurnRecord)

한 턴에 무엇을 했는가. 턴이 끝날 때 만들어져 **대화 이력에 어시스턴트 차례로** 들어간다
(research R2·R3).

| 필드 | 형 | 설명 |
|---|---|---|
| `actions` | `list[ActionNote]` | 그 턴에 부른 도구와 결과 요지 |
| `blocked` | `BlockedNote \| None` | 막혔다면 그 지점과 사유·질문 |
| `reply` | `str` | 모델이 낸 마지막 답 (016 `last_reply`) |

### ActionNote

| 필드 | 형 | 설명 |
|---|---|---|
| `tool` | `str` | 부른 도구 이름 |
| `target` | `str \| None` | 대상의 **사람이 읽는 이름**. 요소 참조가 아니다 |
| `outcome` | `str` | 성공·실패와 사유 요지 |
| `step_label` | `str \| None` | Step 이 만들어졌다면 그 이름 |

**요소 참조(`e17`)를 남기지 않는다** (research R2). 참조는 화면이 바뀌면 낡고, 낡은 참조를
본 모델은 관찰 없이 그것을 쓰려 든다.

**값을 남기지 않는다.** `fill` 의 입력값은 `outcome` 에도 `target` 에도 실리지 않는다 —
016 정의 요약과 같은 규칙이다 (research R10).

**Step 이 생기지 않은 동작도 남긴다** (FR-004). 관찰·실패한 시도·거절된 조작이 「이미 해 본
일」이고, 그것을 모르면 다음 턴이 같은 시도를 되풀이한다.

### 이력에서의 수명

- 수행 기록은 턴마다 하나씩 쌓인다.
- 총량이 상한을 넘으면 **오래된 턴부터** 생략 표시로 접는다 (FR-006). 생략을 명시한다 —
  조용히 사라지면 모델은 그것이 전부라고 믿는다.
- 기록이 줄어도 **작업 계획의 진척은 남는다.** 둘은 서로를 대신하지 않는다 — 기록은 「방금
  무엇을 했는가」이고 진척은 「전체에서 어디쯤인가」다.

## 5. 정제 기록 (RefinementRecord)

원문 지시문과 정제 결과의 쌍. 사용자가 무엇이 바뀌었는지 확인하는 근거 (FR-022).

| 필드 | 형 | 설명 |
|---|---|---|
| `original` | `str` | 사용자가 쓴 지시문 원문 |
| `plan` | `WorkPlan` | 정제 결과 |
| `accepted` | `bool` | 사용자가 확정했는가 |

**저장 시점**: 테스트를 저장할 때 의도 기록으로 함께 남긴다. 헌법 원칙 II 는 「지시문을
실행 가능한 테스트로 저장하지 말 것」을 요구하며 문서로 남기는 것은 명시적으로 허용한다.

**실행 경로에서 읽히지 않는다** (FR-035). `itb.authoring` 아래 두면 `.importlinter` 의
`execution-no-llm` 계약이 이것을 구조로 보장한다.

## 6. 조작 가능 근거 (Actionability)

관찰된 요소가 **왜 조작 가능으로 판정됐는가**. 기존 `ObservedElement` 에 더해지는 한 필드다.

| 값 | 근거 | 확실성 |
|---|---|---|
| `semantic` | 태그 자체가 조작 요소 (`button`·`a`·`input`·`select`·`textarea`·`label`) | 높다 |
| `role` | `[role]`·`[tabindex]`·`[onclick]` 이 붙어 있다 | 높다 |
| `cursor` | computed `cursor` 가 `pointer` 다 | **짐작이 섞였다** |

**세션에만 산다.** Step 에 저장되지 않는다 — Step 이 들고 있어야 하는 것은 로케이터 후보이지
「어떻게 발견했는가」가 아니다. 저장하면 같은 요소가 발견 경로에 따라 다른 Step 이 되고,
그것은 헌법 원칙 I 위반이다.

**`cursor` 는 상속되는 속성이다.** 조상과 자손이 모두 `pointer` 로 계산되므로, 그 판정을
받은 조상이 없는 **가장 바깥 요소**만 목록에 실린다 (research R13).

## 7. 무엇이 어디에 사는가

| 값 | 소유자 | 수명 | 디스크 |
|---|---|---|---|
| 작업 계획 | `SessionWork` | 세션 | 정제 기록의 일부로만 |
| 수행 기록 | `AuthoringAgent.messages` | 세션 | 아니오 |
| 정제 기록 | 세션 → 저장된 테스트 | 영구 | 예 (의도 기록) |
| 대화 기록 (`chat_turns`) | `SessionWork` | 세션 | 아니오 (016 이 정한 대로) |
| 조작 가능 근거 | `BrowserToolbox.refs` | 관찰 한 번 | 아니오 |

`chat_turns` 와 수행 기록은 **다른 것이다.** 016 이 「사람이 읽는 기록」과 「모델에게 가는
컨텍스트」를 갈라 둔 판단을 뒤집지 않는다. 수행 기록은 후자에 속한다.
