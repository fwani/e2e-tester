# Data Model — 027

**저장 형식이 하나도 바뀌지 않는다.** 이 증분은 프론트 구조 변경이며, 서버로 가는 요청도
디스크에 남는 것도 그대로다.

여기서 「모델」은 **화면 코드가 주고받는 모양**이다.

---

## 1. `ScreenCapabilities` — 화면이 할 수 있는 일의 묶음

**자리**: `frontend/src/lib/actionWiring.ts` (신설).

화면이 「내가 할 수 있는 일」을 이 모양으로 제공한다. **전부 선택적이다** — 국면이 그
일을 갖지 않으면 주지 않는다 (FR-003).

| 능력 | 뜻 | 화면마다 다른가 |
|---|---|---|
| `deleteStep(stepId)` | Step 하나 지우기 | 구현이 다르다 (세션 API vs 편집 연산) |
| `deleteSteps(stepIds)` | 여러 Step 지우기 | 〃 |
| `moveStep(index, dir)` | 한 칸 옮기기 | 〃 |
| `insertManual()` | 삽입 입력면 열기 | 〃 |
| `save()` | 저장 | **하는 일이 다르다** (FR-004) |
| `runAll()` · `runFrom(index)` | 실행 | 〃 |
| `showResult()` · `goBack()` | 화면 이동 | 〃 |
| `recordStart()` | 녹화 시작 | **선행 확인이 다르다** (FR-005) |
| `addNaturalLanguage()` | 자연어로 Step 추가 | 〃 |
| … | | |

### 성질

- **선택적이다** — 주지 않으면 그 조작이 이어지지 않는다. 그것이 정상이다 (FR-003).
- **국면을 모른다** — 능력은 「할 수 있는 일」이고 「언제 쓸 수 있는가」가 아니다. 뒤는 조작표가 정한다 (FR-006).
- **화면이 소유한다** — 007 이 「어댑터가 소유한다」로 세운 것을 바꾸지 않는다 (R6).
- **선행 확인을 품는다** — 「먼저 저장하고 열기」 같은 화면 고유의 절차는 능력 구현 안에 있다 (FR-005).

## 2. `ACTION_WIRING` — 조작 하나를 어떤 능력에 잇는가

**자리**: 같은 모듈.

| | |
|---|---|
| 모양 | 조작 식별자 → 그 조작이 부를 능력 |
| 갖지 않는 것 | **국면 판정** · 권한 · 화면 상태 |
| 늘어날 때 | 조작을 더하면 **여기 한 줄**을 더한다 (SC-001) |

**표에 없는 조작**은 기존 경로(어댑터의 `switch`)로 떨어진다 — 그것이 중간 상태를
가능하게 한다 (FR-022 · R5).

---

## 3. `runAction` — 배선의 결과

```
makeRunAction(capabilities, fallback?) → (action: ActionId) => void
```

화면은 이 하나를 받아 기존과 같은 자리에 넘긴다 (`ActionPalette` 의 `onRun`·`onRemedy`).
**호출부의 모양이 바뀌지 않는다** — 그래서 겉모습도 바뀌지 않는다 (FR-021).

`fallback` 은 아직 옮기지 않은 조작을 기존 `switch` 로 보내는 통로다. 이행이 끝나면
비워진다.

---

## 4. 이어진 조작의 노출 — `data-wired-actions`

**자리**: 화면 뿌리 요소의 속성.

| | |
|---|---|
| 값 | 그 화면이 실제로 이어 둔 조작 식별자들 |
| 누가 만드나 | 배선 모듈 (화면이 손으로 적지 않는다) |
| 왜 DOM 인가 | **렌더 결과**이므로 소스 모양과 무관하다. 검사가 목록을 따로 들 필요가 없다 (FR-016 · R2) |

**이것이 이 증분의 안전장치다.** 조작표가 활성이라고 말하는데 이 목록에 없으면 검사가
실패하고, 어느 조작이 어느 화면에서 빠졌는지 말한다 (FR-014·FR-015).

## 5. Step 편집면 — 하나로 합쳐진 뒤

**정본**: `frontend/src/components/StepEditFields.tsx` (기존 · R3).

| props | 뜻 |
|---|---|
| `step` | 고칠 Step |
| `sensitiveNames` | 민감 변수 이름. 그 참조를 담은 칸은 읽기 전용이 된다 |
| `editable` | **읽기 전용 표현** (FR-011). 이미 있다 |
| `onChange(patch)` | 바뀐 항목만 담은 조각 |

### 무엇이 없어지는가

| 없어지는 것 | 왜 |
|---|---|
| `StepDetail` 의 `ownFields` 갈래 | 편집면이 하나가 되므로 갈래가 필요 없다 |
| `Workbench` 의 `stepDetailOwnFields` | 「공용 편집면을 끈다」가 필요 없다 |
| `Workbench` 의 `stepDetailExtra` | 「자기 것을 끼운다」가 필요 없다 |

**추상이 줄어드는 자리다** (R7).

### 어떤 항목을 그릴지의 판정

`StepEditFields` 가 이미 **생성된 타입의 판별자**를 쓴다 (`step.type === "fill"` 등).
판정이 거기 하나이므로 FR-010 이 성립한다 — 새로 만들 것이 없다.

## 6. 바뀌지 않는 것

- **`WorkbenchModel`** — 007 이 정한 모양 그대로다.
- **조작표** (`capabilities.ts`) — 국면 × 조작 행렬이 그대로다 (FR-020).
- **`Workbench` 의 3층 구조** (FR-019).
- **서버로 가는 요청과 저장 형식** — 하나도 바뀌지 않는다.
- **국면 고유의 것** — 결과의 스크린샷·산출물, 편집의 충돌 해소, AI 작성의 곁줄·작업 계획 (FR-018).
