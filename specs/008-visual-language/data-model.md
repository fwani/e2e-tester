# Data Model — 008 시각 언어 v2

이 기능은 제품의 저장 데이터를 만들지 않는다. Step DSL·테스트 정의·실행 결과는 **읽지도 쓰지도
않는다** (plan 헌법 점검 I·II). 여기서 정의하는 것은 **개발 산출물의 구조** 넷이다.

## 2. 예외 등록부 (Exception Registry)

**자리**: `frontend/src/theme/exceptions.ts`
**읽는 쪽**: L2 가드 (`tests/VisualLanguage.test.tsx`)

정본을 벗어나야 하는 값의 유일한 등록처다. **등록되지 않은 예외는 존재할 수 없다** —
등록부에 없으면 가드가 잡는다 (FR-267).

### 항목

| 필드 | 뜻 | 필수 |
|---|---|---|
| `file` | 저장소 기준 경로 | ✅ |
| `pattern` | 허용할 값 또는 정규식 | ✅ |
| `axis` | 어느 축의 예외인가 — `color` · `inline-style` · `class-name` | ✅ |
| `reason` | **왜 정본으로 표현할 수 없는가.** 빈 문자열 불가 | ✅ |
| `requirement` | 근거 요구사항 번호 (있으면) | — |

### 알려진 예외 — 배치 계약 하나

| file | axis | reason |
|---|---|---|
| `components/workbench/Workbench.tsx` 외 껍데기 | `inline-style` | 껍데기 골격 수치(48·460·1440)는 시각 언어가 아니라 **배치 계약**이다. 007 이 `lib/layout.ts` 표를 정본으로 세워 컴포넌트가 스스로 판단하지 못하게 막아 두었고, 클래스로 옮기면 `Record<Phase, …>` 의 컴파일 시점 강제력을 잃는다 (research R3). 값의 출처는 정본 토큰이며 중복이 아니다 |

**불변식**

- **EX-1** `reason` 이 빈 항목은 등록으로 인정되지 않는다
- **EX-2** 등록부에 있으나 해당 파일에서 실제로 쓰이지 않는 항목은 **죽은 예외**이며 가드가
  보고한다. 예외가 관성으로 쌓이는 것을 막는다

## 3. 대조 기록 (Conformance Record)

**자리**: `docs/design/008-visual-language/conformance/<Screen>.md` — 화면당 1장, 18장
**생성**: `scripts/design_baseline.py --write` 가 축과 기준값을 채운다. 판정 칸은 비워 둔다

### 3층 구조 (research R6)

| 층 | 항목 예 | 기준값 출처 | 판정 주체 | 항목 수/화면 |
|---|---|---|---|---|
| **L1 값** | `.btn` 계산 높이 32px · `.chip` 모서리 2px · `body` 배경 `#F2F4F7` | chromium 이 dc.html 을 렌더한 `getComputedStyle` | 기계 | 전 화면 공통 1벌 |
| **L2 소비** | 이 화면의 색 리터럴 0 · 시각 언어 인라인 선언 0 · 미등록 클래스 0 | 가드 | 기계 | 3 |
| **L3 구조·가감** | 디자인이 정의한 요소가 전부 있는가 / 없는 것을 더하지 않았는가 / 상태가 색과 형태를 함께 쓰는가 | 확정 디자인을 열어서 | **사람** | **3** |

### 판정 값

| 값 | 뜻 |
|---|---|
| `일치` | 기준과 같다 |
| `불일치` | 다르다. `비고`에 차이를 적는다 |
| `미판정` | 아직 보지 않았다 |

**불변식**

- **CR-1** 완료 조건은 `불일치` 0건 **그리고** `미판정` 0건 (FR-284·SC-401)
- **CR-2** L1·L2 는 검사가 채운다. 사람이 손으로 적지 않는다
- **CR-3** L3 항목은 화면당 3개를 넘지 않는다 (FR-282). 넘으면 기계가 셀 수 있는 축으로
  옮길 수 있는지 먼저 검토한다
- **CR-4** 구현자가 자기 구현의 L3 를 판정하면 대조가 아니라 자기 확인이다. 이 규칙은 002 가
  세웠고 유지한다

## 4. 미정의 상태 기록 (Undefined States)

**자리**: `docs/design/008-visual-language/conformance/undefined-states.md`

확정 디자인 18장에 대응 화면이 없는 화면 상태를 근거와 함께 적는다 (DC-009·FR-276).

| 필드 | 뜻 |
|---|---|
| `screen` | 어느 화면의 상태인가 |
| `state` | 상태 이름 (로딩 · 삭제 확인 · 정의 읽기 실패 · 세션 유실 …) |
| `why_undefined` | 확정 디자인에 왜 없는가 |
| `drawn_with` | 어떤 정본 형태로 그렸는가 — 새 형태를 만들지 않았음을 보인다 |

**불변식**

- **US-1** 미정의 상태를 그리려고 정본에 새 형태를 추가할 수 없다 (FR-266). 기존 형태의 조합으로만 그린다
- **US-2** 기록되지 않은 미정의 상태는 L3 의 `가감` 항목에서 "없는 것을 더했다"로 잡힌다

## 상태 전이

이 기능에는 런타임 상태 기계가 없다. 전이가 있는 것은 **가드의 엄격도**뿐이다.

```
경고 모드 (상한 327)  ──0단계──▶  상한을 단계마다 내린다  ──4단계──▶  실패 모드 (상한 0)
```

- 상한은 **내려가기만 한다.** 올리려면 커밋 본문에 이유를 적어야 한다
- 4단계 이후 상한은 0으로 고정되고, 위반 1건이면 검사가 실패한다
